## 1. 关闭对象与非目标

关闭 F02 行：`isTopmostModal`/焦点陷阱/滚动锁全部下沉 `useFocusTrap`（BaseDialog/BaseDrawer 内聚），**28 个组件**的手写模态/抽屉外壳迁移到 BaseDialog/BaseDrawer，离场动效消费 F01 落的 `--cs-ease-in`（§10.4 第二档随组件自动获得）。

非目标：

- 下拉收敛与 queryParams 治理（F03）；双胞胎骨架（F04）；store 层（F05）；
- 17 处非模态「关闭」钮（toast/横幅/内嵌详情面板）不在收敛范围——它们本来就不是模态（§4 分类明细）；
- WorkPage 页面级焦点兜底 `querySelectorAll('[role="dialog"][aria-modal="true"]')` 保留——它读的是 BaseDialog/BaseDrawer teleport 后的实例，是消费者不是外壳。

## 2. 基础件合同（base 层升级，2 文件）

**BaseDialog** 新增两个布局 prop（既有 prop 面：`open/title/eyebrow/subtitle/width/role/describedBy/closeOnBackdrop/closeDisabled/closeLabel` + `#icon/#header/默认/#footer` slot）：

- `anchor?: 'center' | 'top'`——命令面板类需要顶部锚定：backdrop `--top` 变体 `place-items: start center; padding: 12vh 20 24`，767px 内仍保持顶部（不落底 sheet）；
- `padding?: string`（默认 `var(--cs-space-20)`）——body 内联 padding，高密度工作区（Task 详情 12px 网格）经 prop 传参。

**BaseDrawer** 同步加 `padding` prop（默认同上）。

> **为什么不走 `:deep`**：实测（临时 spec + `throw attrs` 读属性）确认——根为 `<Teleport>` 的子组件 teleport 后的 DOM 只带子组件自己的 `data-v-x`，**不继承父 scope id**，父组件 scoped `:deep(.base-drawer__body)` 编译产物永不命中；jsdom 不跑 CSS，单测全绿但视觉静默失效。布局定制一律走 prop（width/padding 先例），此坑已入记忆（vue-teleport-root-no-parent-scope）。

**动效**：`.cs-fade-leave-active`/`.cs-drawer-leave-active`（backdrop 与 surface 两层）离场曲线 `var(--cs-ease-in)`——F01 落的 token 在此消费，`tokens.spec.ts` 三曲线断言闭环。

## 5. 焦点合同变更（有意，逐条）

`useFocusTrap` 初始焦点策略=组件自定聚焦 → `[autofocus]` 优先（DOM 序）→ 第一个 focusable → 容器。由此产生四类合同变更：

1. **危险确认初始焦点安全侧**（AccountWorkspace 退出本设备、ModelConnectionDetail 撤销、KnowledgeBasePage 删除、MemberLifecycleDialog、ResponsibilityHandoverDialog、ConfirmHost）：footer 取消钮 `autofocus`——原实现聚焦破坏性主钮或容器。e2e `m12-account-sessions` 相应断言已随契约更新。
2. **移动端主导航**：初始焦点从 drawer 容器变为 header 关闭钮（第一个 focusable）；焦点归还合同不变（归还汉堡钮）。`e2e/m9-mobile-reach.spec.ts` 断言从 `activeElement.id` 改为 `aria-label='关闭主导航'` 轮询。
3. **CommandPalette**：搜索框 `autofocus` 承接初始焦点（原为容器自聚焦）；Escape 分支从组件 keydown 删除，交还 BaseDialog trap（归还触发钮的合同不变）。
4. **Esc 层叠**：全站 `isTopmostModal` 守卫随下沉消失——唯一模态栈仲裁者是 trap 的注册表（teleport to body 后 DOM 位置不再参与层叠判定）。

## 6. 门禁与测试连锁

**spec 适配三件套**（29 个 spec 文件）：`global: { stubs: { teleport: true } }`；滚动锁断言改 `document.body.classList.contains('cs-modal-open')`；jsdom click 不聚焦的场景先 `element.focus()` 再 trigger（附注释）。断言逐条从契约推导（如 SkillActionConfirmDialog 的 `aria-describedby` 改为「指向含披露扫描文案的元素」而不锁死 useId 值）。

**disabled-reason 门禁漏检转显式**：旧模板 footer 多为单行多钮，行级扫描只命中第一个 `:disabled`（transient 的 pending/submitting），业务绑定从未被扫到；迁移拆行后首次显形，四处处置：

- ModelConnectionDetail 撤销主钮补 `:aria-describedby="revokeImpactId"`（真关联影响说明，替代旧版靠模板距离的偶然通过）；
- KnowledgeBasePage 确认复选框的提交锁改写为与同框取消钮同源的 `store.state.command.phase === 'pending'`（transient 形态，语义等价）；
- DelegateToAgentDialog `!valid` 入豁免清单（与 AgentCreateDialog 等 8 处同类表单校验豁免同性质，理由注明「拆行后首扫」）；
- MemberLifecycleDialog 既有豁免条目表达式随绑定改写更新（`copy(member, action, roleKey).selectable` → `current?.selectable`，语义不变）。

终态：0 unexplained / 34 waived（迁移前 33）。

**e2e 连锁（8 spec）**：

## 8. 偏差登记

1. **净删 −691 行 vs 预估约 2500**：预估口径是「删 28 份外壳+陷阱样板的原始行数」；实际每组件需回写 BaseDialog/BaseDrawer 标签、slot 包装与布局 prop，且 base 层两文件净增（anchor/padding/动效样式集中化）。方向性目标（同构样板清零、base 单源）已达成，行数差额如实入档。
2. **两个迁移暴露的产品缺陷（C2 批次外发现，随包修复）**：MemberActionMenu 焦点归还竞态与 BaseDialog/BaseDrawer landmark 重复（§6）——都不是测试适配而是键盘/读屏用户的真实可达性缺陷，迁移前的旧实现靠「恰好更晚的聚焦」与「非 teleport 的 DOM 位置」掩盖。
3. **disabled-reason 门禁覆盖面扩大**：footer 单行多钮写法让行级扫描漏检第二个绑定（脚本每行只匹配第一个 `:disabled`），拆行后四处业务绑定首次显形——两处真修复（aria-describedby 关联/提交锁改写）、一处新豁免（DelegateToAgentDialog `!valid`，理由注明首扫背景）、一处豁免表达式随绑定改写。门禁比迁移前更严了，不是更松。
4. **快照重生成 18 张全部预期**（§7 漂移源清单逐条对应），无「漂移即缺陷回查」项——交互类失败全部为契约变更（role 更名/焦点合同/选择器外迁）而非产品回归。
