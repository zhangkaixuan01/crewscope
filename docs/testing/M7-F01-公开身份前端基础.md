# M7-F01 公开身份前端基础

## 1. 交付范围

M7-F01 建立公开身份页面可复用的视觉与交互基础，不接入正式路由、AuthStore 或认证 API。真实 `/login`、`/register`、Session 恢复和 Router Guard 分别由 M7-F02 至 M7-F04 继续交付。

本任务新增：

- `AuthLayout`：提供 Skip Link、单一主要内容区、品牌说明区和认证舞台；
- `AuthBrandPanel`：复用 CrewScope Logo，表达“成员 → Personal Agent → 团队”的产品关系；
- `AuthCard`：统一标题、说明、宽度、忙碌状态和初始焦点；
- `AuthField`、`AuthPasswordField`、`AuthCheckbox`：保留原生表单语义、自动填充坐标和至少 44px 的勾选目标；
- `AuthPasswordGuidance`：只说明服务端冻结的 12–128 字符输入预算，不在浏览器伪造密码强度结论；
- `AuthErrorSummary`：使用 `role=alert` 并在失败状态主动接收焦点；
- 命名空间限定的公开身份 Token：支持明暗品牌区、雾面/中性舞台和系统/强制 Reduced Motion。

公开身份 Token 全部限定在 `.cs-auth-theme` 下，不覆盖 AppShell 的全局 Token。密码显隐只存在于组件内存；密码、邀请 Token、Session、Cookie 和 CSRF 均未进入浏览器持久化。

## 2. 状态与 Story 合同

Histoire 新增 25 个 Variant：

- Desktop 1280px：11 个公开认证状态；
- Narrow 390px：同一组 11 个状态；
- Contract：Light Brand、Dark Brand、Reduced Motion 3 个状态。

11 个认证状态为 Session Loading、Session Error、Login、Invalid Credentials、Temporarily Locked、Open Registration、Invite-only Registration、Registration Disabled、First Team Onboarding、Valid Team Invitation 和 Expired Invitation。

Story 使用单 Variant iframe 渲染，任一预览只挂载一个 `main`，避免多个认证状态同时出现在可访问性树中。

## 3. 焦点、键盘与窄屏验证

初始焦点遵循冻结的身份体验规则：

- 普通登录、注册和 Onboarding 表单聚焦首个输入；
- 登录失败与临时锁定聚焦错误摘要；
- 注册关闭、仅邀请和邀请失效等不可继续状态聚焦标题；
- 有效邀请聚焦主要操作；
- DOM 顺序决定键盘顺序，不使用正数 `tabindex`。

在 Codex In-app Browser 的 390×844 真实页面检查结果：

```text
activeName=identifier
innerWidth=390
scrollWidth=390
mainCount=1
positiveTabindex=0
```

Desktop 浏览器检查同时确认 Login 首焦点为 `input[name=identifier]`、Login Error 首焦点为 `role=alert`、Registration Disabled 首焦点为 `h2`。
