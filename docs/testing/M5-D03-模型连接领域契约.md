## 1. 交付范围

M5-D03 在 `crewscope-domain` 与 `crewscope-application` 交付：

- `ModelConnection`：稳定身份、精确 Provider Definition、Endpoint、Region、Owner、Credential Binding、Billing Subject、生命周期、健康、乐观版本和审计；
- USER/TEAM/ORGANIZATION Owner 与 PRINCIPAL/TEAM/ORGANIZATION Credential/Billing Subject 的严格 Scope 矩阵；
- 绑定当前 Credential Version 的 UNKNOWN/HEALTHY/UNHEALTHY 健康快照和平台稳定错误码；
- ModelConnection Repository Port。

CredentialStore 写入、真实 Provider 健康探测、短生命周期 Credential Handle 与审计事件编排由 M5-I02 交付；HTTP API 由 M5-A01 交付。

## 2. 固定领域规则

1. Connection 与 Provider Definition Hash 、Organization 和 Owner 精确绑定，Region 必须在 Provider Region 中。
2. USER Owner 只允许同一 PRINCIPAL Subject；TEAM Owner 只允许同 TEAM 或 Organization Subject；ORGANIZATION Owner 只允许同 Organization Subject。
3. Credential Binding 只保存 Credential ID、Subject 和 Version，不保存 Key、Secret、Header、Provider 原始错误或可恢复凭证的元数据。
4. 轮换保持 Connection ID、Credential ID、Subject、Owner、Provider、Endpoint 和 Region 不变；Credential Version 连续增加，健康重置为 UNKNOWN。
5. 健康快照必须绑定当前 Credential Version；验证同时检查 Expected Connection Version 和 Expected Credential Version。
6. 健康检查时间严格向后推进；成功清零连续失败数，失败保留最后成功时间并只记录稳定错误码。
7. ACTIVE 且当前凭证版本 HEALTHY 的 Connection 才可参与新选择；SUSPENDED 恢复前要求当前健康，REVOKED 不可逆且只保存平台稳定撤销原因枚举。
8. 轮换、验证、停用、恢复和撤销均使用强 Expected Version，任何迟到命令失败关闭。

## 3. 自动化验证

新增 8 个自动化场景：

- `ModelConnectionTest`：7 个场景，覆盖三类 Owner/Subject Scope、区域与 Provider 状态、凭证轮换稳定身份、健康版本与迟到探测、停用/恢复/撤销、强乐观锁和复原校验；
- `ModelConnectionCredentialBoundaryTest`：1 个应用边界场景，证明 Secret 输入只存在于 `CredentialStore.create/rotate`，不会进入 ModelConnection 或 Repository Port。
