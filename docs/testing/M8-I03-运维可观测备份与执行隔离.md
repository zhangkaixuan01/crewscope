# M8-I03 运维可观测、自动备份与执行隔离

## 目标

Team Beta 单机部署具备明确的 Sandbox 控制面边界、可执行告警、自动备份和安全入口。生产默认不
宣称保存 Trace：未配置可查询 Trace Backend 时，API/Worker 显式关闭 OTLP 导出。

## 交付合同

| 领域 | 合同 |
| --- | --- |
| 执行隔离 | Worker 仅使用 `DOCKER_HOST=tcp://docker-socket-proxy:2375`；Worker 无宿主 Socket 挂载和 Socket GID；Proxy 是唯一 Socket 挂载者，关闭 Build/Volume/System/Swarm/Secret 管理接口 |
| Trace | 默认 `CREWSCOPE_OTLP_TRACING_ENABLED=false`；开启时必须通过私有 Overlay 指向可查询 Backend，并单独完成保留、容量和访问控制验证 |
| 告警 | Prometheus 加载 `prometheus-alerts.yaml`，告警发送到内部 Alertmanager；`backup-metrics` 只读采集 Data Root 中的备份新鲜度 textfile；私有 Receiver Overlay 必须显式选择受控通知出站网络；规则只使用低基数标签，不包含租户、任务、Provider 原文或 Secret |
| 备份 | Daily/Weekly systemd timer 调用已有加密备份和 Retention；Health timer 输出最新 Daily Bundle 年龄，26 小时触发 `CrewScopeBackupStale` |
| TLS | Host Nginx 只开放 80/443，保留 HTTPS、Secure Cookie、HSTS、CSP、nosniff、Referrer-Policy 和 SSE 长连接参数 |

同机空目标恢复通过 `CREWSCOPE_BACKEND_SUBNET` 和 `CREWSCOPE_WEB_INTERNAL_IP` 选择独立
内部网段；默认值保持 `172.30.0.0/24` 与 `172.30.0.10`。备份 Environment Fingerprint
不得启动 Maven Wrapper 或临时下载构建工具，宿主 Java/Maven/pnpm 缺失时只记录
`unavailable`。

## 验证命令

```bash
node scripts/check-team-beta-deployment.mjs
node scripts/check-config-contract.mjs
node scripts/check-doc-links.mjs
./mvnw -q -DskipTests compile
git diff --check
```

在 Linux amd64 Release 环境还要执行：

```bash
systemctl list-timers 'crewscope-backup-*'
./deploy/team-beta/operations/backup-health.sh /etc/crewscope/team-beta.env
docker compose --env-file /etc/crewscope/team-beta.env -f deploy/team-beta/compose.yaml config
```

## 残余风险

Socket Proxy 限制了 Worker 可调用的 API，但 Proxy 与 Docker Engine 仍在同一执行主机上。恶意
Sandbox 可能利用允许的 Container/Exec 操作影响其他 CrewScope Sandbox，因此生产主机必须专用，
Sandbox 镜像和运行参数需要继续执行逃逸、特权容器、宿主路径和 Worker 被攻破演练。真正的多租户
强隔离需要独立 rootless Daemon 或专用 Worker 节点，属于后续拓扑演进。
