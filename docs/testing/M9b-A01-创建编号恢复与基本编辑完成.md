## 1. 用户现在怎样使用

1. 项目填名称即可；普通工作项填标题即可，编号由服务端分配；高级字段折叠，默认 TASK/MEDIUM。对话仍填标题、默认私人，不自动发送或启动 Agent。
2. 菜单、空态和快捷动作复用创建流程。创建后按命令的唯一受权坐标打开结果，不找同名项、列表最后一项或差集。
3. 响应丢失/超时后，在页面顶部“创建结果待确认”点击“再次确认并打开”。刷新后仍可查原操作；这里只读，不再次创建。404、过期或失去权限都不表示原操作未提交。
4. 详情“编辑内容”可改标题、描述、优先级、标签、到期时间，编号只读；取消或离开保护未保存输入。冲突时保留本地输入并显示当前内容，明确确认版本后才保存；归档只读，完成/取消状态不会被重开。

无需新增服务、TLS、密钥、生产部署参数或手动数据库步骤。正常部署升级沿用 Flyway V40；本次没有启动此前停掉的产品/Compose 服务，也未连接真实部署数据库或 Provider。

## 3. C02 真实链路（不是 mock 端点，也不是换 adapter 冒充重启）

测试入口为 `A01BrowserIntegrationTest`，测试专属 PG 17 Testcontainer 由 JUnit 创建并销毁。Playwright 启动 `A01TestServer`，加载正式 Controller、应用服务、JPA/JDBC、事务、成员/角色策略、原生 ProviderBinding 与 V40；不加载产品配置文件，不运行 Worker/模型/外部 Provider。

浏览器使用仓库的真实 WorkItemCreateDialog、CreationRecoveryPanel、WorkItemContentEditor、HTTP Gateway 与恢复模块；静态资产在保留 HTTP 测试域名上拦截提供，API 转发至测试进程。唯一替换的认证边界是测试专用 Header→已持久化 Principal，成员/资源授权仍走真实策略。**这不是生产登录/Session、全 App 菜单视觉或外部执行验收**，那些边界分别由已有认证测试与后续 F03/F04/Q02 承担。

固定断言顺序：

1. 浏览器只填标题创建，真实后端返回 202 后只丢弃传输响应；本机已保存原键。
2. 再创建25条工作，按20条分页确认原对象不在首屏；并发同名项目/对话获得不同坐标。
3. SIGKILL 测试服务，使用相同 PG 启动新的 JVM，断言进程 PID 改变。浏览器 reload，点击恢复，详情/URL 均为原 ID，浏览器创建 POST 仍只有一次。
4. 重启后读取项目/对话四条结果，与重启前坐标一致。另一成员不能读取原 actor 的结果。
5. 两账号8条普通创建与真实 TaskIntent 确认同时执行，35个工作编号不重复；原键重放不再创建。显式旧 Key 继续兼容。
6. PATCH 同版本并发返回202/409；取消态内容可编辑但不重开；归档拒绝内容编辑，下一编号不回收；真实编辑组件保存描述不改标题。
7. JUnit 直接核对 PG：丢响应的工作/创建事件各一份，TaskIntent 确认一份；项目/对话每键一条回执和结果，Task 表为0。

## 4. 可复跑命令与结果

需要 JDK17、仓库已安装的 pnpm/Chromium 和 Docker。使用当前 shell 配置 JDK，不读取 `.env`。运行测试只创建隔离短命测试资源。

```bash
  -Da01.browser=true -Dsurefire.failIfNoSpecifiedTests=false test

pnpm check:enum-labels
pnpm check:sensitive
pnpm build
pnpm check:bundle
cd ..

```
