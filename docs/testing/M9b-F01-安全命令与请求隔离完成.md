## 2. 安全命令规则

- `secureId` 优先安全 UUID，不可用时用 `getRandomValues` 生成正确 version/variant 的 UUIDv4；没有安全源就拒绝发送并显示就近原因。没有 Math.random/时间戳兜底。
- `commandIntent` 用于已有创建入口；`commandGateway` 只按具名方法白名单接入，声明的数字是该方法的幂等键参数位置，不拦截所有 POST。
- 请求参数先规范化、快照化；作用域、目标、版本、操作和载荷共同决定意图。重复在途请求合并；修改输入形成新意图，改回原输入仍找到原未知意图。
- 网络错误、408、5xx、Abort/响应解析不确定不能冒充确定失败。未知时保留原键，之后收到 403/409 也不能证明之前未提交；没有后台自动重放。
- 普通意图注册表容量 100，满时拒绝新增，不通过淘汰未知记录生成新键。成功或首次确定拒绝释放；身份/安全版本重置清理。不同 Team 的同名输入不会共用命令。
- 普通注册表不接凭证、密码、open_id、CSRF 或 SSE。凭证指纹/键只在当前表单组件内存，关闭、目标/版本变化和卸载时清理；不放 Store、URL、localStorage/sessionStorage。关闭表单/刷新后不能声称仍可原请求重放。
- 原事实读取不等于成功回执：提供只读核实入口，不用列表新增项或版本变化证明原未知命令成功；可靠的跨刷新结果定位等 A01。

## 3. 作用域与页面隔离

`requestScope` 使用坐标和单调代次，不能只比较 A/B 字符串；取消是优化，即使适配器忽略 Abort，旧结果也不能发布。命令已发送不因页面退出而变成服务端已撤销。

`usePageRequestScope` 分三层：身份所有权、页面 Team/Project、具体 URL 选项。改变查询选项使旧对象操作失效；主动导航只在需要的层级失效，避免把正常导航后的初始化误取消。卸载一次性失效全部层级。

| 页面组 | 所有权与清理 |
|---|---|
| Today、Work、Conversation | await 后报告/导航/草稿回填检查；Work 定时器、行操作、批量续行；详情代次、发送重复及取消结果隔离 |
| Activity、Inbox、Audit、Search、Operations | 过滤/选择后旧 continuation 不恢复旧流或覆盖新对象；Search 清空/同 Team A→B→A；Operations 不重复注册定时器、不在卸载后重启 |
| Agent/Model/Repository/GitHub/Lark 设置 | 原目标、版本和凭证弹窗生命周期；旧命令不关闭新弹窗、不改新 URL；GitHub 定点轮询，飞书证明失效 |
| TeamMembers、Setup、Invite | 旧异步完成不影响新 Scope；Invite 接受后的主动选 Team 使用身份层级，避免正常加入流程自取消 |
| Login、Register、Onboarding、Account | 原认证生命周期/Store generation + 页面身份边界；密码不入普通意图；安全版本变化和换账号重新挂载页面 |
| TeamObserver | 原 Store 的 Scope/Session/Invocation/generation 和 Abort 双重检查，未知首响应不冒充可恢复调用 |
| AccessDenied、NotFound | 无异步写续链；沿用路由守卫/恢复导航，受 App 身份重挂载保护 |

`sessionBoundary` 仅在账号/principal/org/securityVersion 改变或退出时重置业务 Store；同账号普通刷新不清空工作状态。Scope 成员查询额外以请求版本处理同 Team 强制刷新乱序。

## 4. 飞书与凭证目标闭环

验证捕获成员、Binding、Binding 版本、Connection/凭证版本与请求代次；返回 Proof 的回调属于本次验证，不从共享的“最近回执”猜 Proof。切成员、open_id、连接或版本后旧验证结果失效，不能给新成员确认。

确认固定原 member/binding/proof/key，重复点击在途拒绝；响应未知后显式重试仍是原确认。轮换固定原连接版本，不能用晚到 GET 的新 ETag 悄悄替换用户看到的前置条件。模型轮换同样带原资源版本与凭证版本。

飞书错误提供“只读取原连接与映射事实”，凭证弹窗内也可操作；读取不提交秘密、不确认映射、不转换成功回执。重新验证提示其只产生证明，不自动映射成员。模型弹窗亦提供原连接读取。

后端核验结论：verify 的 Proof 绑定外部身份、org/team、Binding/auth/credential 版本、tenant 和有效期，**不是验证时就绑定内部 CrewScope 成员**；confirm 指定内部成员并重新验证其 ACTIVE、范围、证明版本/有效期与唯一性。前端固定内部成员是必要补强，不能把后端能力写错。
