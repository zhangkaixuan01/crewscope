# M7-F02 正式登录页与安全返回目标

## 1. 交付范围

M7-F02 在 M7-F01 的公开身份组件基础上交付正式 `/login` 路由，接入 M7-A02 的 Session 与 JSON Login API。页面完成匿名 Session 准备、标识/密码登录、错误与容量状态、离线/超时恢复、重复提交保护、已登录重定向和原目标恢复。

本任务保持页面级认证边界。全局 AuthStore、应用启动 Session 恢复、401 统一处理、跨标签退出和受保护路由 Guard 由 M7-F04 交付；M7-F02 不提前删除现有 AppShell 的 Bootstrap Principal。

## 2. Session、CSRF 与 Gateway

新增 Identity Gateway 和闭合公开 DTO Mapper：

- 页面先调用 `GET /api/v1/auth/session`，取得匿名 Session、Registration Mode 和 CSRF 坐标；
- CSRF Header/Token 只保存在 LoginPage 组件内存，并随一次 `POST /api/v1/auth/login` 发送；
- 登录请求体只包含 `identifier` 和 `password`，不发送客户端身份、Organization、Team、Remember Me 或其他服务端坐标；
- Session、Account、Principal、Team 和 Login 响应通过显式白名单重建，未知私有字段不进入前端对象；
- 不一致的认证状态、未知 Registration Mode、非批准 CSRF Header 和匿名授权事实全部失败关闭；
- 密码成功后立即清空；`invalid_credentials` 后同样清空，密码、CSRF 和返回目标均不进入 LocalStorage、SessionStorage 或普通 Store。

## 3. 登录体验

正式页面覆盖：

- Session Loading 与 Session Error；
- 用户名或邮箱、当前密码、自动填充语义和 Enter 提交；
- 登录 Pending 与重复提交阻断；
- 未知账号、错误密码、临时/持久锁定和禁用账号统一使用“登录信息无效”文案；
- `too_many_requests` 使用不披露账号状态的容量提示；
- 网络离线、10 秒 Session 超时和 15 秒 Login 超时；
- 已认证 Session 直接离开 `/login`；
- Registration Mode 只展示部署事实，不提前提供尚未交付的 `/register` 交互。

服务端错误 Message、内部限流/Hash 信息和账号状态不直接渲染。登录错误摘要使用 `role=alert` 并获得焦点；普通页面首焦点仍为标识输入框。

## 4. 安全返回目标

登录返回参数固定为单值 `returnTo`。恢复逻辑只接受路由表中已注册的受保护站内路由：Conversation、Today、Work、Activity、Inbox、Team Observer、Operations、Audit、Team Members 和受控 Settings 页面。

以下目标统一回落到 `/conversation`：

- 绝对 URL 和协议相对 URL；
- `/login`、`/register`、`/invite` 等公开身份路由；
- 未注册路由；
- 带 Fragment、反斜杠、控制字符或超过 2,048 字符的值；
- 重复 `returnTo` Query。

返回目标可以保留批准路由的普通 Query，但密码和邀请 Token 不得进入该参数。
