# M0-D06：原子事件事务基线

> 状态：已完成<br>
> 日期：2026-08-06<br>
> 涉及模块：`crewscope-domain`、`crewscope-application`、`crewscope-infrastructure`

## 目标

创建 WorkItem 时，在一个 PostgreSQL 事务中提交聚合快照、DomainEvent 事实和 PENDING Outbox，形成 M0-E02 Publisher 可以直接消费的耐久输入。

## V3 迁移

`V3__domain_event_aggregate_version.sql` 完成：

- `domain_event.aggregate_version BIGINT NOT NULL`；
- V1/V2 存量事件回填 `0`；
- 回填后移除列默认值，所有新写入显式提供聚合版本；
- `aggregate_version >= 0`；
- 非空幂等键禁止空白文本；
- Outbox Topic 和分区键禁止空白文本；
- DomainEvent 索引按 Organization、Aggregate、aggregateVersion、时间和 eventId 支持回放与缺口检测。

V1/V2 文件及校验和保持不变。V2 专项测试固定执行到 V2，通用 Flyway 测试继续执行空库到最新版本和 V1→最新版本。

## 应用与持久化边界

应用层新增：

```text
DomainEventStore
OutboxRepository
PendingOutboxEvent
TransactionExecutor
WorkItemCreated v1 Payload
```

`WorkItemApplicationService.create` 使用一个 UTC 时间点完成：

```text
TransactionExecutor.required
  -> WorkItemRepository.create
  -> DomainEventStore.append
  -> OutboxRepository.enqueue
  -> commit
```

DomainEvent 与 Outbox Adapter 使用 MANDATORY 事务传播，阻止独立写入。`SpringTransactionExecutor` 使用 Spring `TransactionTemplate` 的 REQUIRED 传播语义，JPA WorkItem 与 JDBC 事件写入共享同一连接和事务。

## 持久化映射

`JdbcDomainEventStore` 显式映射 Envelope：

```text
eventType         -> event_type
schemaVersion     -> schema_version
aggregateType     -> subject_type
aggregateId       -> subject_id
aggregateVersion  -> aggregate_version
actor/correlation/causation/scope/idempotency -> 对应列
payload           -> JSONB
```

JDBC 时间参数在 Adapter 边界转换为 UTC `OffsetDateTime`，领域与应用层继续使用 `UtcTimestamp`。

`JdbcOutboxRepository` 创建初始状态：

```text
topic           = crewscope.domain-events.v1
partition_key   = {organizationId}:{aggregateType}:{aggregateId}
delivery_status = PENDING
retry_count     = 0
version         = 0
```

Outbox 通过 `domain_event_id` 关联事件，不复制 Payload。
