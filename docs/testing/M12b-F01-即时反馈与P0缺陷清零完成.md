## 5. hover 盲区清零与按压反馈推广

**终值（对照 §10.2 基线）**：无 hover 文件 **54 → 0**；`:hover` 规则 76 → **151 处**；`:active` 5 → **62 处**；`transition:` 22 → **68 文件**。

分派策略（全部走既有 token，零新色值）：

- 控件类（icon button/菜单项/ghost 文字钮）：`:hover:not(:disabled) { background: var(--cs-surface-accent) }` + `:active:not(:disabled) { transform: scale(.97) }`（BaseButton 既有按压回弹范式推广）；
- 卡片/行类（card/row/item/node/entry）：`:hover` 用 `--cs-surface-subtle` 底 + `--cs-border-accent` 边框，不缩放；
- transition 在稳态规则补 `background-color/border-color/transform var(--cs-motion-fast) var(--cs-ease-out)`（离开悬停同样有过渡）。

脚本批量落地后的**人工修正四件**（自动分派的边界，全部如实保留）：

1. **BaseSwitch 分态 hover**：开关轨道不是按钮——hover 若统一 accent 会把关态「变亮得像开了」。改为关态 hover 加深灰（`--cs-text-muted`）、开态 hover 用 `--cs-action-primary-hover`，且排除 `aria-checked` 互盖（特异性核对过 (0,3,1) vs (0,2,1)）。
2. **view-switcher**（WorkGraphWorkspace/WorkItemsToolbar）：选中项白底+阴影被 hover 规则盖浅，hover 加 `:not(.active)`。
3. **ClarificationCard 选择胶囊**：`.choices input` 是 opacity:0 的全域命中层，hover/active/transition 全部转移到视觉载体 `+ span`（边框强调 + 缩放），不给隐藏 input 上背景。
4. **StatusTransitionMenu**：批量脚本的扁平 regex 把多行块注释吞进 selector 产出坏行（build 期 vue SFC CSS parser 抓获）——修正为纯规则三行；随后对全部 50 个文件的追加块做了逐行合法性扫描，无第二例。

## 8. 偏差与陷阱登记

1. **批量脚本两坑**（§5 修正四件之外的方法论）：扁平 CSS regex 会把多行块注释吞进 selector——必须对产物做逐行合法性扫描 + build 兜底（vue SFC parser 会抓非法 CSS，vitest/lint 不会）；`:hover` 追加规则的特异性 (0,3,1) 会盖过既有的状态变体规则（`.active`/[aria-checked]），批量后必须按「实色底状态规则」清单人工核对（本次核对出 BaseSwitch 与 view-switcher 两处）。
2. **视觉基线盲区再证**：hover/active/transition 不进截图（基线测不出「活」，§10.2 已记）；本包真正会动快照的是 panel-heading 字号（全局）与两 drawer footer 主按钮、ReviewWorkbench 决策选项——最终 20 张快照重生成（首跑 11 张超阈 + 复跑后 `-u` 落地的临界张），清单见 §7；其余 spec 快照零漂移。
3. **useId 必须在 setup 顶层同步调用**（BaseTabs 初版 `computed(() => props.id ?? useId())` 违规）——先 `const autoId = useId()` 再 computed 包裹。
4. **empty-state 豁免只能进不能虚**：新增无动作空态必须登记 `M9-空状态豁免清单.json` 且 reason 写事实型理由；门禁反对装饰性按钮（脚本头注释明示）。
5. **§10.3.1-2 状态双轨合并撤销**（本包唯一未落地项）：第一版实现（TaskControlPanel `showStatus` prop + CodingProgressControl 关闭状态行）被 e2e「Task Retry」用例击穿——该用例的 coding Task 无 CodingTargetSnapshot，Execution Studio 走空态分支无 StatusBadge，控制区状态行是唯一状态源。**状态可见性优先于视觉去重**，撤销并把合并重估挪到 F02。调试此问题时还踩到 **Vue Boolean cast 坑**：`showStatus?: boolean` 未传时运行时值是 `false`（absent Boolean prop 强制转型）而非 undefined，`showStatus !== false` 默认即隐藏——可选 Boolean prop 的缺省判断必须用 `withDefaults` 显式给默认值，或干脆避免「以 false 为非缺省语义」的接口设计。
6. **e2e 本地复用 dev server 的实验污染**：`reuseExistingServer: !CI` 让分步实验（改文件→跑单用例）踩在 HMR 陈旧模块图上，出现过「语义等价的 v-if 改动一过一败」的假象；二分定位前先杀 4173 再验，结论以新 server 为准。
