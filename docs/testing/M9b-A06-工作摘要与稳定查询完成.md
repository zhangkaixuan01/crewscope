## 1. 用户现在怎样使用

## 3. 固定反例（每个都曾真实失败）

- **中途 flush 的交错外键**：规模 fixture 的 batch 满 1000 行即 flush 时，快照表先于其工作项落库——SMALL 档每项目 200 行从不触发中途 flush，缺陷只在 FULL 档暴露。修复：纯累积、依赖序 flush。
- **目录首页断链**：offset 模式首页只回 `nextOffset` 不回 `nextCursor`，cursor 客户端从普通首页启动链时只能拿到一页。修复：截断页恒带 `nextCursor`，offset 响应额外携带 `nextOffset`。
- **seed 返回值错位**：目录测试的 `seedAgentProfile` 返回 profile 行主键而非 Agent principal id，按 id 定点查永远为空——"查询为空"被误判为 SQL 问题。
- **UUID 排序方言差**：Java `UUID.compareTo` 带符号、PostgreSQL 无符号；断言必须比 `toString()`。
- **`IN` 前的授权收敛**：by-id 回显同样走候选集 CTE，外部 Team 的 id 一行都不回。
- **领域 key 格式**：`SCALE-0` 违反 `[1-9][0-9]*`（前导零）；执行等待原因 DB 枚举是 `CONFIRMATION` 等单值而非应用层组合词；RUNNING 状态需要 fencing token（规模 seed 用 READY/WAITING 规避）。
