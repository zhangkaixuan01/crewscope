# M0-A02：可观测性与日志安全基线

> 日期：2026-08-07<br>
> 状态：已完成

## 目标

建立全请求 Correlation ID、W3C Trace、结构化日志、字段级脱敏和低基数指标基线，使 HTTP、命令、事务、事件与错误可以稳定关联，同时控制日志泄露和 Prometheus 时间序列基数。

## Correlation ID

`ApiObservabilityWebFilter` 在所有请求入口处理 `X-Correlation-Id`：

- 接受一个规范小写、非 Nil UUID；
- Header 缺失、重复或非法时生成新 UUID；
- 最终值写入 Exchange 和所有响应的 `X-Correlation-Id`；
- Reactor Context 通过 Micrometer `ThreadLocalAccessor` 恢复到 MDC；
- API Controller 使用 Exchange 中的同一值创建 Command Context；
- Command Receipt、DomainEvent、Outbox、Projection 和 Audit 延续既有 Correlation 契约。

Correlation ID 的来源只以 `accepted/generated` 低基数结果进入指标。具体 UUID 不进入指标标签。

## Trace

Server 引入 Spring Boot 4 的 Micrometer Tracing OpenTelemetry 集成和 OpenTelemetry Bridge：

```text
consume/produce propagation = W3C
sampling probability        = CREWSCOPE_TRACE_SAMPLING_PROBABILITY，默认 1.0
OTLP export                 = CREWSCOPE_OTLP_TRACING_ENABLED，默认 false
```

- 合法 `traceparent` 延续上游 Trace ID，并创建新的 Server Span；
- 缺失或非法 `traceparent` 创建新 Trace；
- Trace ID、Span ID 和 Correlation ID 同时进入请求日志 MDC；
- M0 不要求外部 Collector，后续可通过同一 OpenTelemetry 基线启用导出。

## 结构化日志与脱敏

控制台默认使用 Spring Boot Logstash JSON，Reactor 自动传播日志上下文。请求完成日志事件为 `http_request_completed`，只记录：

```text
correlationId
traceId
spanId
method
route
status
outcome
durationMs
errorCode
failureType
```

- `route` 使用 Spring 路由模板，不记录原始资源 ID；
- 不记录 Query、Header、Cookie、请求体和响应体；
- 未知异常只记录稳定 `internal_error` 和异常类名，不记录异常消息与原始堆栈；
- `StructuredLogSanitizer` 按字段名处理 Authorization、Cookie、Password、Secret、Token、Credential、API Key、Key Material、Ciphertext、Nonce 和认证 Tag；
- 非敏感值移除 CR/LF/Tab，并限制为 256 个字符；
- MDC 与 SLF4J Key Value 不写入同名字段，Logstash JSON 不产生重复成员。

## 指标

除 Spring Boot 的 `http.server.requests`、JVM 和连接池指标外，新增：

```text
crewscope.api.requests
crewscope.api.errors
crewscope.api.correlation.ids
```

自定义标签固定为：

| 指标 | 标签 |
|---|---|
| `crewscope.api.requests` | `method`、路由模板 `route`、`status`、`outcome` |
| `crewscope.api.errors` | 稳定 `code`、`status` |
| `crewscope.api.correlation.ids` | `accepted/generated` 结果 |

Correlation ID、Trace ID、Span ID、Idempotency Key、租户 ID、Principal ID、资源 ID、原始 URI、异常消息和凭证内容禁止作为指标标签。Actuator 继续只暴露 Health、Info 和 Prometheus。

## 验证

`ApiObservabilityWebFilterTest` 的 6 个 WebFlux 测试覆盖：

1. 合法 Correlation ID 复用、响应 Header 和异步 MDC；
2. 缺失、非法和重复 Header 替换；
3. 路由模板代替原始路径与 Query；
4. 未知异常安全信封、错误指标和无消息泄露；
5. 领域错误的稳定 Code/Status；
6. 指标标签不包含请求标识和敏感字段。

`TracePropagationIntegrationTest` 的 2 个真实 Netty/Spring Boot/OpenTelemetry 集成测试覆盖合法 W3C Parent 续接、非法 Parent 替换、Server Span、Trace/MDC/Correlation 一致、Logstash JSON 无重复字段和 Prometheus 指标暴露。

`StructuredLogSanitizerTest` 的 3 个单元测试覆盖大小写与分隔符无关的敏感字段识别、日志注入控制字符处理和值长度上限。

`ApiObservabilityConfigurationTest` 的 1 个配置测试固化 Reactor 自动传播、W3C、采样、默认关闭 OTLP 和 Logstash JSON 配置。

M0-A01 的 API/事务回归继续证明 Controller 解析出的 Correlation ID 进入 Command Receipt、DomainEvent、Outbox 和错误信封。

全仓验证命令：

```bash
./mvnw --batch-mode --no-transfer-progress clean verify
```

结果：7 个 Maven 模块成功，174 个测试全部通过，0 失败、0 错误、0 跳过。
