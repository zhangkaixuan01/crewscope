# M4-D08 V14 执行工作区与制品迁移

> 完成日期：2026-08-18
> 范围：`crewscope-infrastructure`、PostgreSQL 17、Flyway

## 1. 交付结果

M4-D08 新增 `V14__execution_workspace_and_artifacts.sql`，将 M4-D01 至 M4-D07 的 Coding 领域事实落为数据库契约。迁移建立 9 个领域根表和 4 个规范化子表：

- `repository_binding`
- `coding_target_snapshot`
- `execution_workspace`
- `workspace_policy`
- `workspace_policy_overlay`
- `diff_artifact`
- `diff_file_entry`
- `command_evidence`
- `test_evidence`
- `test_evidence_command`
- `test_acceptance_result`
- `test_acceptance_evidence`
- `coding_checkpoint`

V14 同时扩展 `runtime_artifact` 的稳定类型，增加 `DIFF_PATCH`、`COMMAND_LOG` 和 `TEST_REPORT`，并为精确 Artifact ID、类型、大小和 Content Hash 引用建立候选键。

## 2. Scope 与所有权闭合

所有领域根表重复保存 Organization、Team、Workspace、WorkProject、Task 和 TaskExecution 中适用的完整坐标。复合外键关闭以下关系：

- RepositoryBinding 必须属于真实 WorkProject；
- CodingTargetSnapshot 必须属于同一 Task 和 RepositoryBinding；
- ExecutionWorkspace 必须匹配 TaskExecution attempt、CodingTarget、ExecutionLease、Runtime、Worker 和 Fencing Token；
- WorkspacePolicy 必须匹配 TaskExecution attempt、CodingTarget 和 PolicySnapshot；
- CommandEvidence、TestEvidence 必须匹配相同 Workspace Fingerprint、CodingTarget 和 WorkspacePolicy；
- CodingCheckpoint 必须匹配相同 AgentRun/Segment、PlanVersion、StepExecution、TestEvidence、Diff 和 AgentStateSnapshot。

V14 为既有 TaskExecution、ExecutionLease、AgentRun、PlanVersion 和 AgentStateSnapshot 增加只读候选键，使上述精确引用可以由 PostgreSQL 外键验证。

## 3. 冲突裁决

数据库唯一约束与领域稳定冲突码一一对应：

| 数据库唯一事实 | 稳定冲突码 |
|---|---|
| WorkProject + RepositoryKey | `repository_binding_key_conflict` |
| Task + CodingTarget Revision | `coding_target_snapshot_revision_conflict` |
| TaskExecution + attempt 的 ExecutionWorkspace | `execution_workspace_attempt_conflict` |
| ExecutionWorkspace 的唯一 DiffArtifact | `diff_artifact_workspace_conflict` |
| ExecutionWorkspace + Command EvidenceSequence | `command_evidence_sequence_conflict` |
| ExecutionWorkspace + Test EvidenceSequence | `test_evidence_sequence_conflict` |
| ExecutionWorkspace + CheckpointSequence | `coding_checkpoint_sequence_conflict` |

M4-D09 负责将 PostgreSQL 唯一键异常映射为这些领域错误。

## 4. 数据形状

迁移约束覆盖：

- Repository Kind、Binding Status、Workspace Status、Command/Termination、Diff Kind、Acceptance Status 和失败分类枚举；
- UUID 关系、Git SHA-1、SHA-256、RepositoryKey、受管 Workspace Key、分支和归档引用格式；
- JSONB AllowedPaths、AcceptanceCriteria、CommandCatalog、argv 和 Todo 集合形状与数量边界；
- Sandbox/Workspace 正数预算、无网络和只读 Root Filesystem 基线；
- Workspace 恢复、完成、失败和归档字段互斥形状；
- Command exitCode/Termination/FailureClassification 推导形状；
- Test 统计总数等式和可选 TestReport 成组字段；
- Checkpoint Plan/TestEvidence 成对引用与所有执行序号正数约束。

TestEvidence 的 `diff_generation` 和 `diff_manifest_hash` 保持独立事实；CodingCheckpoint 的 TestEvidence 外键同时包含这两个字段，从数据库层拒绝陈旧被测 Diff。

## 5. 审计与删除语义

`repository_binding` 和 `execution_workspace` 是可变业务聚合，保存 Version、创建时间、修改时间、创建 Principal 和修改 Principal。`workspace_policy_overlay` 是追加版本事实，每个版本保存完整创建与最后修改审计。

CodingTargetSnapshot、WorkspacePolicy、DiffArtifact、CommandEvidence、TestEvidence 和 CodingCheckpoint 是不可变事实，只保存创建 Principal 与创建时间。技术子表由父事实级联管理，不伪造业务修改人。

RepositoryBinding 使用 `ACTIVE/DISABLED`，ExecutionWorkspace 使用显式终态和 Retention/Archive；不可变事实保留为审计证据。V14 不增加逻辑删除字段。

## 6. 路径与内容边界

V14 不保存宿主 Repository Path、Worktree Path、Docker Mount Path 或任意绝对路径。数据库只保存：

- `repository_key`
- `workspace_key`
- 平台生成的 `managed_branch`
- 平台生成的 `archive_reference`
- 仓库内 canonical 相对路径

完整 Patch、Command Log 和 Test Report 继续进入 ArtifactStore；业务表只保存 Artifact ID、类型、大小和 Hash。Diff Preview 有 256 KiB 上限，二进制 Diff 不保存 Preview。

M4-D09 的真实对象图往返发现 PostgreSQL `text` 不能构造 NUL，因此在检查约束中调用 `CHR(0)` 会让合法的非空 Preview/Summary 也失败。V14 已移除 Diff Preview、Command/Test/Acceptance Summary 上冗余的 `POSITION(CHR(0) ...)` 表达式；PostgreSQL 与 JDBC 文本类型边界继续直接拒绝 NUL，长度和内容形状约束保持不变。

## 7. 查询索引

V14 建立以下查询入口：

- WorkProject RepositoryBinding 状态列表；
- Task 最新 CodingTarget Revision；
- TaskExecution Workspace 和 Worker 活动 Workspace；
- 到期 Retention 清理；
- TaskExecution WorkspacePolicy 与当前 Overlay；
- TaskExecution DiffArtifact、CommandEvidence 和 TestEvidence；
- TaskExecution 最新 CodingCheckpoint 与 AgentRun Checkpoint 历史。

## 8. 自动化证据

专项测试 `V14ExecutionWorkspaceArtifactsMigrationIntegrationTest` 覆盖 5 个场景：

1. 13 张表、审计字段分层、Diff/Test/Checkpoint 字段和宿主路径禁止；
2. 关键复合外键、唯一约束、查询索引和 Artifact 类型；
3. V9、V10、V13 分别升级到 V14；
4. 非默认 `search_path` 仍只在 `crewscope` Schema 创建对象；
5. 真实 PostgreSQL 拒绝重复 RepositoryKey、非法状态和跨 Scope WorkProject。

既有 `FlywayMigrationIntegrationTest` 继续覆盖空库、V1 升级和非默认 `search_path` 的 latest 迁移。

```bash
./mvnw --batch-mode --no-transfer-progress \
  -pl crewscope-infrastructure -am \
  -Dtest=FlywayMigrationIntegrationTest,V14ExecutionWorkspaceArtifactsMigrationIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```
