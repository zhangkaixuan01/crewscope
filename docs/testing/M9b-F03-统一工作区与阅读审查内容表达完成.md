## 1. 用户现在怎样使用

**Task 详情是一个统一工作区（契约 §4.1）**：抽屉首屏按「标题/编号/工作状态 → 本次产出或等待事实 → 执行选择/责任快照/当前主动作 → 概览/讨论/执行/变更与测试/审查与交付」组织，技术回执与快照明细下沉到所属分区；≥960px 容器查询双列、窄屏单列且 DOM 顺序即阅读顺序（删除旧手写 CSS order 假结构）。执行坐标统一为 `taskExecution`（`attempt` 只作 Coding 兼容读侧别名），两者同现且不相等即坐标冲突——工作区整体禁写并给出「用此执行」单次解冲突动作，不再有静默择一。当前主动作是一条九级决策（无权限→历史视图→命令提交中→版本冲突→多 Task 未选→配置缺失→正在执行→等待审查/要求修改/外部交付确认→未启动/终态），标签全部来自服务端动作词汇。

**成果不合成绿色完成（R11/R13）**：首屏 TaskOutcomeBlock 分别呈现执行结束状态、最新测试结论（失败数独立红标）、待人审/要求修改轮次、外部交付 UNKNOWN/MANUAL_REVIEW 事实；`resultSummary` 的 `coding-attempt:{executionId}@{finalHash}` 与 `runtime-artifact:{artifactId}` 引用被解析成可定位证据锚（跳到变更与测试区并核对 finalHash，不一致显示「证据版本不一致」，找不到目标展示引用原文+复制而不猜跳）。执行侧模型快照只显示该执行自己的 provider/model/catalogRevision，不跟随当前模型切换、不虚构限制数字。

**安全富内容四处一致（R40）**：SafeMarkdown 白名单加入表格（th/td 语义结构，容器横滚、代码块可复制），消息级「复制原文」交出原始 Markdown；WorkItem 评论从纯文本升级为安全渲染，评论框与对话输入都带「预览/编辑」轻量切换（不引入所见即所得）。表格/外链没有为富内容放开任意 HTML、iframe 或远端图片自动请求。

**发送意图分离（R42/R43）**：WorkItem 评论区把「发布评论（记录讨论）」与「让 Agent 处理（以这条评论为委托目标单独确认）」拆成两个动作，旁注说明评论永不触发执行；Conversation 输入删除固定 32,000 假预算，改真实的 `N / 50,000 字符` 计数，限制与价格只在 catalog/模型设置处按 A03 合同呈现（未知写未知）。

## 3. 固定反例与实施偏差（每个都曾真实失败或推翻计划）

**统一坐标系（S6 最深的一组）**
- **buildOffsets 的 gap 属于行上方**：旧 `sums[i] = Σh + (i−1)×gap` 是「spacer 窗口坐标」——虚拟模式内部自洽（e2e 曾全绿掩盖），但 plain 模式（≤80 行无 spacer）与真实布局每行差一个 gap，scrollToAnchor 每行偏 16px。正确数学是「先记顶再加高」（`sums[i]` 为行 i 顶 = Σh[0..i-1] + i×gap，`sums[length]` 为末行底无尾 gap）；spacer 高度 `offsets[start] − rowGap` 恰好使两种模式共享同一套全渲染坐标。
- **anchorFromOffsets 符号必须与 anchorFromViewport 一致**：`offsetWithin` 的语义是「行顶 − 视口顶（负 = 行在上方）」，两条捕获路径（DOM/模型）产出可互换的锚，`currentAnchor()` 的 `??` 回退链才成立。符号反向时 jsdom 模型锚被 scrollToAnchor 反向消费——单测数值差 100px 才暴露。
- **listContentOffset 需要宽度守卫**：jsdom/隐藏宿主 rect 全零而 scroll metrics 可被 mock 成真实数字，`height===0 && top===0` 判定会被 `height:108` 的伪 rect 绕过；改 `width <= 0`（真浏览器列表恒正宽）后模型路径与 DOM 路径一致。

**锚定系统的防误伤链（S6）**
- **捕获锁**：items 变更在 flush 'sync' 从旧 DOM 捕获锚并上锁，防止 re-render 期间的 scroll 事件把锚重推到「新列表 × 旧偏移」的错误推导上；post-flush 恢复后解锁。
- **restore 不重推**：scrollToAnchor 落点建立在估值偏移上，落点后立刻重推锚会把估值误差固化为官方阅读位置；恢复写入后保持锚不变，让行高修正绕锚补偿。
- **follow 区钳制**：未渲染行的估值可能越过真实底部，底部钳制会把锚写进 follow 区并翻转 isFollowing；写入钳到 `maxScroll − 80 − 1`。
- **append-only 跳过**：仅在尾部追加时阅读位置不可能移动，通过估值偏移重写只会引入误差——直接跳过恢复。
- **RO 0×0 守卫**：离开 DOM 的行以 0×0 上报，记录会污染全部偏移并让窗口乒乓；`!isConnected || height<=0` 丢弃。
- **resize 恢复不重推**：锚描述「成员刚才在哪」，resize 后对着新布局恢复，而不是把 resize 自己引入的漂移重推成新位置。
- **moved 判定 0.5px**：程序恢复的 scroll 回显与真实滚动靠「scrollTop 实际位移」区分，回显不重推锚。
- **overflow-anchor: none**：虚拟列表整块换行/换 spacer，浏览器原生 scroll anchoring 会锚到幸存元素上把阅读位置跳到未审视的偏移（一次直接跳进 follow 区翻转 isFollowing）；补偿只能由消息锚独占。
- **内联函数 ref 死循环**：render effect 内联 ref 每次渲染重跑、读布局又触发渲染——挂死 flush 循环；改字符串 ref 只在挂载/卸载触发。
- **MutationObserver 观察行集**：scrollToAnchor 移动窗口后新渲染的行也要进 RO，visibleItems watcher（同 flush 内 computed 已是新窗口而 DOM 还是旧的）与 onUpdated 都不可靠，最终以列表 DOM 的 childList 变化驱动同步。
- **中位数估值**：未测量行用「已测高度的中位数」而非初始估值（一条 500 行代码块会把均值拖离所有正常行），锚上方大段未测量区间仍接近精确。

**jsdom/测试基建**
- **ConversationPage.spec 的 rectSpy 必须按行分布**：统一 `top:0,height:108` 的伪 rect 让 anchorFromViewport 永远命中第一行；改为按行 index×(h+gap) 分布、随 `.message-history` 的 mock scrollTop 平移，非行元素 0×0。
- **crypto.subtle.digest 是线程池宏任务**：CodingDiffExplorer 提交链的 sha256 与一次 setTimeout 的 flushPromises 在全量跑 CPU 竞争下竞态（单跑绿、全量 1/3 概率挂）；断言改 `vi.waitFor` 轮询。

**交互与视觉**
- **跳最新 pill 不能在滚动流内**：sticky pill 在 follow 状态翻转的瞬间把整列下推，这个位移对锚点补偿不可见；改为 message-stage 内 absolute 悬浮层（conversation-tasks 基线用例的注释早已预言 pill 会覆盖该区域，用 scrollIntoView 固定 overlay 偏移）。
- **TaskIntent 折叠改写了意图确认路径**：e2e「预检并确认」现在必须先点「展开提案」——改文案/结构前全局 grep 断言的纪律再次生效（「关键操作进入审计记录」等无其它消费者，header 状态徽标两变体共有不受影响）。

**收尾门禁四连（最终验证阶段逐个暴露并修复）**
- **裸枚举插值**：WorkspaceResponsibilityStrip 的 `{{ line.role }}` 走 `enumLabel(workItemResponsibilityRoleLabels)`，并连带把 TaskDetailDrawer 本地英文 roleLabel（'Owner'/'Executor'）统一到工作台同款词条（负责人/执行人/Reviewer），spec 断言同步。
- **裸 title 属性**：TaskOutcomeBlock 证据锚按钮的 `title=` 改 BaseTooltip 包装。
- **路由 meta 逐行正则**：S2 扩白名单后 work 路由 meta 改多行写法，route-metadata 门禁按行读 title——title 移回 `meta: {` 同行；顺带发现注释里出现 `meta: {` 字样也会被正则命中，注释措辞改写。
- **禁用态解释**：四处新 disabled 落两类修复——真解释（CodingDiffExplorer 行评 gate 的 aria-describedby + sr-only 说明；ConversationComposer 发送按钮挂 guidanceId 描述）与事实豁免（TaskWorkspaceHeader 向 WorkspacePrimaryAction 转发、成因由其 facts 区渲染；WorkItemDetailDrawer「让 Agent 处理」由评论框为空决定），豁免清单 +2 且均为事实性理由。

## 5. 交接与明确非目标

- **runtime-artifact 内容端点**：呈现入口（类型/时间元数据）已交付；内容在线打开不做（后端裁定：无内容端点），归后续工作包。

- **明确非目标（契约禁止）**：不新增工作区聚合端点（现有 6–10 次调用+详情已含 executionSummary）；不合成绿色完成态；不为表格放开 HTML/iframe/远端图片；`@` 不伪装提及；伪预算/未知写 0/字符冒充 token；热注入在途执行；CSS order 假结构；评论失败关草稿；要求修改被普通评论绕过；不重造上游合同（A01 编号/A03 模型/A02 仓库/A05 编排/A06 摘要/F05 存储）。
