## 4. A06 移交规模门实测数字（S6）

预算口径：4vCPU/8GiB 参考环境端到端 p95 ≤ 500ms（A06 证明 SQL 层 ≤200ms，HTTP 面移交 Q01）；A06 原文「paged reads hold the budget **after warm-up**」。实测环境：本机 Docker Desktop 容器（Testcontainers PostgreSQL + Redis，RANDOM_PORT 真实 HTTP）。

| 档 | 测量 | n | p50 | p95 | max |
| --- | --- | --- | --- | --- | --- |
| SMALL（200 行/项目） | work-items 首页（updatedAt 排序） | 20 | 149ms | 159ms | 159ms |
| SMALL | work-desk 段续页 | 1 | 96ms | 96ms | 96ms |
| FULL（10000 行，ACTIVE 集 3334） | work-items 全量 walk（预热后） | 100 | 199ms | 204ms | 219ms |
| FULL | work-desk WORK_ITEM 段续页 walk（3334 行） | 34 | 200ms | 209ms | 210ms |

- 冷启动现象：seed 后未预热前 ~9 页 1.9-2.2s（PG buffer cache 冷），按 after-warm-up 语义以无计时预热 walk 覆盖后全部页面入预算。

## 5. 归属裁定与移交处置（书面结论）

1. **runtime-artifact 内容在线打开（F03 :88 移交）**：维持不做。已交付的证据链是「引用锚定」——`runtime-artifact:{artifactId}` 引用解析为可定位锚，finalHash 不一致显示「证据版本不一致」，找不到目标展示引用原文+复制而不猜跳（docs/testing/M9b-F03-统一工作区与阅读审查内容表达完成.md:9）。内容内联打开需要 artifact 二进制存储与 MIME 处理契约扩展，属于新功能而非回归收口，超出 Q01 边界（边界契约 :36、主计划 :346）。若 M10 需要，应作为独立 API 契约包立项。
2. **TeamObserver 跨进程持久化（M6 设计）**：维持 M6 有意的内存设计。观测摘要定位为可丢弃缓存，真实源是审计事件流与团队活动流；进程重启后「重新生成摘要」即恢复（R38 已交付三态分明的恢复入口）。持久化引入的存储契约、失效与迁移成本没有对应产品诉求。
3. **PinnedProjects 拖拽排序无键盘替代（F04 §8 移交 Q01 裁定）**：裁定不补拖拽的键盘排序等价物。固定项集合本身全键盘可达（菜单矩阵六档键盘遍历覆盖 pin/取消 pin 的操作路径），排序是排序内部的增强；补齐成本涉及拖拽库键盘协议改造，收益不覆盖。若后续固定项超过一屏成为常用场景，再随 F04 域增量交付。
4. **AppShell SSE 空 mock 重连竞态（F04 §7 移交）**：已在 S2 根治——视觉基线用例的 events mock 改挂起不响应（连接保活语义，eventStreamPhase 无 UI 消费者）；功能用例保留事件送达断言。此为 mock 层修复，非生产缺陷。
