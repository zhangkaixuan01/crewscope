# M1-F04：责任链与时间线前端

> 日期：2026-08-08<br>
> 状态：已完成<br>
> 工程：`crewscope-web`

## 目标

把 M1-A06 责任管理与 M1-A07 WorkItem 时间线接入详情抽屉，形成可观察、可协作、具备服务端策略边界的团队责任闭环。前端显示真实 Assignment 和业务事件，所有责任资格、职责分离与并发裁决继续由服务端完成。

## 交付范围

### Gateway 与契约

- 查询 WorkItem 当前 ACTIVE ResponsibilityAssignment；
- 原子替换 Owner，请求同时提交当前 `expectedAssignmentId` 与 `expectedVersion`，保留 ABA 防护；
- 分别接入 Executor、Gate Reviewer 和 Advisory Reviewer 分配路由；
- 非 Owner 责任通过 Assignment `If-Match: "<version>"` 释放，Owner 只允许替换；
- 每个写命令生成独立 `Idempotency-Key`；
- 时间线使用专用 `after` Cursor 与 `limit` 查询，Cursor 不与 WorkItem 集合分页复用；
- 请求体只提交目标 Principal，不提交 Actor、PolicyPack 或客户端资格判断。

### Store 与异步隔离

- WorkItem 详情、责任链和时间线拥有独立 Phase、错误与 Pending 状态；
- 打开详情时并行读取一致性详情、ACTIVE 责任链和第一屏时间线；
- Team、WorkProject、WorkItem 切换或关闭详情后，旧异步响应不能覆盖当前对象；
- 责任命令成功后刷新责任链和时间线；
- 责任命令失败时先刷新服务端责任事实，再展示安全错误；
- `responsibility_conflict` 和 `responsibility_version_conflict` 统一提示责任链已刷新；
- Timeline 使用服务端不透明 Cursor 续传，并按 `eventId` 去重；
- 加载更早事件失败时保留已展示活动和 Cursor 重试入口。

### ResponsibilityChain

- 展示 Owner、Executor、Gate Reviewer 和 Advisory Reviewer；
- `REVIEWER + USER` 显示为 Gate Reviewer，具备 Gate 效力；
- `REVIEWER + SPECIALIST_AGENT` 显示为 Advisory Reviewer，只提供建议；
- 人类与 Agent 使用不同图标和浅色 Token，保持 CrewScope 的协作语义；
- Owner 不显示释放入口；Executor 与 Reviewer 使用各自 Assignment 版本释放；
- 具有 `responsibility:manage` 的用户可以管理责任，其他成员保持只读观察。

### 候选人与资格提示

- 人类候选人来自目标 Team 的 ACTIVE TeamMember；
- 当前登录用户显示会话名称，现有成员 API 未返回显示名时使用缩短 Principal ID；
- M1-F04 交付时 A06 尚未提供 Team Agent/Specialist Agent 目录查询，Agent 分配使用折叠的高级 Principal ID 输入；当前实现已复用 M5 Agent 目录，按 Team、Workspace 与 ACTIVE 状态提供 Executor 候选，并只将 Specialist 列为 Advisory Reviewer 候选；
- 前端不生成模拟 Agent、不推断 Agent 归属；服务端继续校验 Team Scope 和 Principal 类型；
- Gate Reviewer 选择明显命中 Owner/Executor 时展示职责分离提示；客户端不提交 PolicyPack、不阻断服务端显式降级裁决。

### 业务时间线

- 展示已评审的 WorkItem、Comment、ResourceLink 和 Responsibility 业务事件；
- 每项活动显示事件语义、Actor、发生时间、聚合版本和 Outcome；
- 未知事件使用稳定的事件类型回退文案，不直接解释任意 Payload；
- 安全 AuditEvent 和未知关联事件仍由 A07 服务端白名单控制。

### Personal Agent 与执行入口

- “与 Personal Agent 讨论”保留 Team、WorkProject、`workItem` 和 `focus`，进入 Conversation；
- M1-F04 交付时，“交给 Agent 处理”是明确的阶段占位，只展示后续 TaskExecution 接入说明，不创建本地假任务或虚假运行状态；
- 当前实现已由 M3–M5 替代该占位：入口打开真实委托弹窗，按责任链选择 Agent，读取 AgentProfile 与候选模型，完成 CodingTarget 和模型 Preflight 后创建可审计 Task；
- 创建后的 Task、Execution、CodingAttempt、ReviewRequest 与 DeliveryBundle 均来自服务端事实，Work 页面可恢复对应深链接并展示实时运行证据；
- Personal Agent 对话由 M2 交付，TaskExecution 与 Coding 委托闭环由 M3–M5 交付。

### 当前 Agent 责任分配补强

- WorkItem 详情在责任链打开时读取服务端 AgentProfile 目录，不从前端构造 Agent；
- 目录仅展示当前 Team、当前 WorkProject Workspace 下 AgentProfile 与 Principal 均为 ACTIVE 的候选；
- Personal、Team 和 Specialist Agent 均可成为 Executor，只有 Specialist Agent 可成为 Advisory Reviewer；
- 目录读取失败时关闭选择并提供显式重试，分页由“加载更多 Agent”消费服务端 Offset；
- 高级 Principal ID 输入保留为目录分页或运维定位兜底，最终资格仍由责任应用服务裁决。

## 权限与服务端边界

前端 `responsibility:manage` 只用于界面裁剪。服务端继续负责：

- ACTIVE Membership 与完整 Organization/Team/Workspace/WorkProject/WorkItem Scope；
- Team Scope 或目标 WorkProject Scope 的 `RESPONSIBILITY_MANAGE`；
- Owner USER、Gate Reviewer USER、Advisory Reviewer SPECIALIST_AGENT 等主体资格；
- ReviewerEligibilityPolicy、职责分离和 PolicyPack 降级证据；
- 唯一 ACTIVE Owner、重复角色/Actor、责任链锁、ABA 和乐观并发；
- 幂等回执、DomainEvent、Outbox 和 AuditEvent 原子提交。
