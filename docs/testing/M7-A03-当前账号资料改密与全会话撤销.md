# M7-A03 当前账号资料、改密与全会话撤销

## 1. 交付范围

M7-A03 交付当前登录账号专属的四个接口：

```text
GET    /api/v1/account
PATCH  /api/v1/account
POST   /api/v1/account/password
POST   /api/v1/account/sessions/revoke
```

接口不接受目标 Account ID，也不提供用户名或邮箱可用性查询。HTTP 边界从 `BrowserSessionPrincipal` 读取 Account ID 与 SecurityVersion，并通过当前 Organization 的 Account、Local Identity、Binding 和 USER Principal 事实重新解析可信命令上下文。

## 2. 并发与 Step-up 契约

- `GET /api/v1/account` 使用 Account Version 返回强 `ETag: "n"`；
- 三个修改接口都要求单值强 `If-Match`，缺失返回 `428 precondition_required`；
- 多字段资料修改只推进一个 Account Version；
- 展示名修改不执行密码 Hash；
- 用户名或邮箱修改要求当前密码和当前 SecurityVersion；
- 改密与全部设备退出要求当前密码、SecurityVersion 和 Account Version；
- 用户名和邮箱规范唯一键冲突统一为无字段、无冲突值的 `account_identifier_conflict`；
- Credential Version 或 Account Version 并发漂移失败关闭，不覆盖先提交的修改。

## 3. 改密与会话失效

改密先执行一次当前密码 Match。历史 Credential 若在 Match 时完成安全 Rehash，服务重新读取其最新 Credential Version，再编码新密码。新 Hash、Credential Version、Account SecurityVersion、Account Version、`ACCOUNT_PASSWORD_CHANGED` DomainEvent 与 Outbox 在同一个 REQUIRED 事务提交。

全部设备退出在事务内推进 Account SecurityVersion 与 Account Version，并记录 `ACCOUNT_LOGGED_OUT / ALL_SESSIONS`。两条安全命令提交后都使用 Account 主体索引主动删除 Redis 中的全部 Session。数据库 SecurityVersion 是最终撤权事实，因此 Redis 删除失败不会让旧 Session 重新获得权限；旧 Session 在下一次请求身份复验时仍失败关闭。

## 4. 安全与审计

资料事件只记录用户名、邮箱和展示名三个布尔变化坐标；密码事件只记录 Credential Version 与 SecurityVersion；全部设备退出只记录 Scope 与 SecurityVersion。命令 `toString()`、公开响应、错误信封、DomainEvent、Outbox 和审计摘要均不包含当前密码、新密码、Hash、Credential、Session ID、Cookie、冲突用户名/邮箱或内部认证原因。
