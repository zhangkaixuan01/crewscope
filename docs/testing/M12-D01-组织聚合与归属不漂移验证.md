## 2. C1：聚合边界与实现口径

交付六文件，全部遵循仓库既有聚合形态（final class + 私有构造不变量校验 + `reconstitute` 静态工厂）：

| 文件 | 职责 |
| --- | --- |
| `crewscope-domain/.../organization/OrganizationStatus.java` | 单值枚举（`ACTIVE`）+ `from(String)` fail-fast 解析 |
| `crewscope-domain/.../organization/Organization.java` | 聚合：name 边界（trim/非空/≤200=V1 列宽）、version≥0、六列读写面；无创建工厂、无命令方法 |
| `crewscope-application/.../organization/OrganizationRepository.java` | Persistence Port（application 层先例口径），单方法 `findById`，只读 |
| `crewscope-infrastructure/.../persistence/organization/JdbcOrganizationRepositoryAdapter.java` | `NamedParameterJdbcTemplate` 只读适配器（identity 先例形态） |
| `crewscope-domain/src/test/.../OrganizationTest.java` | 6 个单测：六列往返/trim、blank 名、超长名、恰 200 名、负 version、status 词法（含 null 拒） |
| `crewscope-infrastructure/src/test/.../OrganizationPersistenceIntegrationTest.java` | 3 个集成测试（真实 PG + Flyway）：seeder 形态行六字段往返、未知 id 为空、脏状态 fail-fast |

口径决定及其依据（全部继承 ADR-035 §单机合同，无新决策）：

- **零新增列、零迁移**：聚合只映射 V1 既有六列（id/name/status/version/created_at/updated_at），`flyway_schema_history` 无新行——升级演练的快照等值断言同时是这一点的经验证明（见 §3.4）。
- **无创建工厂/命令方法**：单机 profile 下 `TeamBetaBootstrapSeeder`（`INSERT ... ON CONFLICT (id) DO NOTHING`）保持唯一组织写入者；组织生命周期命令属托管增量，须随 ADR-035 显式修订引入，不在 Port 上渐进累加。
- **`OrganizationStatus` 单值词法**：V1 列 `VARCHAR(32)` 无 CHECK，全仓生产代码零读该列，唯一观测值为 `'ACTIVE'`（seeder 与测试 fixture）。新增状态值出现时须同步矩阵与 ADR-035——枚举从值域收窄处 fail-fast，而不是静默映射。
- **Port 落在 application 层**：仓库全部 Repository 接口先例均在 application（domain 零先例），不为 D01 破例。

### 3.3 快照口径：严格等值、零白名单

快照是全库行分布的两段式投影（`\gexec` 按表名定序，输出确定序）：

- 129 张带 `organization_id` 列的表：`表名|组织 id|行数`（按组织分组计数）；
- 其余全部表（组织根 + 全局表 + 库内 flyway 历史表如落在该 schema）：`表名|行数`。

断言为 **B == A 且 C == A 的全量逐行等值**，不设机制表白名单。理由：

- seeder 重启路径幂等（两条 INSERT 均 `ON CONFLICT (id) DO NOTHING`），不产生新行；
- `runtime_worker` 重注册按 `(runtime_id, stable_key)` upsert（`uk_runtime_worker_stable_key`），心跳只改列值不改行数——计数快照对心跳不敏感，机制重启必须不动行数，这正是要验证的不漂移面；
- D01 零迁移，flyway 历史表行数进入等值断言，兼作「升级未夹带 schema 变更」的经验证明。

若演练暴露真实漂移，处理原则是登记缺陷或据实登记机制白名单，不静默放宽断言。
