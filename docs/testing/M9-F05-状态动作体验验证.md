# M9-F05 状态动作体验验证

## 验收范围

- 工作项状态流转是**动作**而不是表单：生产代码里不存在以 `<select>` 选择目标状态的流转控件，按钮集由生成状态机（`api/generated/state-machines.ts`）派生、启用与禁用由服务端 `availableActions` 决定。
- 动作标签是动词短语（「开始执行」「提交评审」），不出现裸枚举名；强弱动作分级并映射到按钮变体。
- 不可逆动作（`REJECTED`/`ARCHIVED` 类）执行前必须二次确认，且不进入拖拽与快捷键通道；可逆动作执行后进入撤销窗口。
- 全部动作走既有命令路径与强 ETag：不改变领域状态边、事件 Schema 与审计记录。

## 交付形状：3 处徽章菜单 + 1 处动作按钮组

动作入口没有做成「升级 `StatusBadge` 一个组件就覆盖四处」。实际形状是：

| 呈现面 | 落点 | 形状 |
|---|---|---|
| 列表行 | `components/domain/WorkItemCard.vue`（`:layout="list"`，由 `WorkItemsWorkspace.vue` 渲染） | `components/action/StatusTransitionMenu.vue`：徽章即按钮，点开是动作菜单 |
| 看板卡片 | 同一个 `WorkItemCard.vue`（`:layout="board"`） | 同上，另加拖拽 |
| 首页卡片 | `components/domain/WorkDeskBoardCard.vue`（`TodayPage.vue` 的「我的工作」看板） | 同上 |
| 详情抽屉 | `components/domain/WorkItemDetailDrawer.vue` 的 `.transition-actions` | 动作按钮组（一次列全所有动作与禁用原因），**不是**菜单 |

`StatusBadge.vue` 里原有的一段交互模式（用 CSS `:focus-within` 打开菜单、没有 `Esc`、没有 `aria-expanded`、没有任何调用点传过 props）已**删除**：保留一个半成品入口点只会让两份实现漂移。徽章视觉现在定义在 `design/base.css`，由 `StatusBadge.vue` 与 `StatusTransitionMenu.vue` 共用，因此既有 `StatusBadge` 调用点零改动（非 Story 的 `.vue` 中实测 **38 个文件、91 处 `<StatusBadge>` 标签**；计划文本与 §10.4.2 里写的「36 处」是立项时的文件数口径，M9 期间新增页面后未再更新），也不必担心两个组件长得不一样。

抽屉之所以没有合并进菜单：抽屉里需要一次列全所有动作及每条禁用原因与 `remedy` 坐标，与徽章上「点开再选」的形状不同。没有合并的是**形状**，不是**裁决**——四处都消费服务端同一份 `availableActions`。

## 唯一的裁决与唯一的漏斗

- 裁决只有一份：服务端可用性投影（`M9-A05`）。前端不从状态机自行推导可用性，`domains/workitem/availability.ts` 只做严格读取；菜单与按钮组渲染的都是服务端给的动作对象。
- 二次确认只有一份：`domains/workitem/useTransitionConfirm.ts`（抽屉、`WorkPage`、`TodayPage` 三处引用）。不可逆动作需要点两次的规则写在里面，不在三个页面各写一遍。
- 撤销窗口只有一份：`domains/workitem/useUndoOffer.ts`（`WorkPage` 与 `TodayPage`）。是否提供撤销由 Store 决定——只有服务端标为可逆、且领域里确实存在反向边的动作才会打开入口；窗口默认 10 秒，过期即消失，撤销本身是一条正常的反向流转命令（产生事件与 Audit，不是删除、不是回滚）。
- 拖拽只有一份：`composables/useBoardDrag.ts`，由工作项看板与首页看板共用（首页此前没有看板，本轮是**抽取复用**工作项看板已有的实现，不是新写一套）。

## 键盘契约

`StatusTransitionMenu.vue` 的菜单用显式状态而不是 CSS 悬停实现，因此键盘可以真正完成一轮操作：

- `Enter`/`Space` 打开并**把焦点放到第一条可执行动作**（服务端禁用的动作会被跳过）；
- 方向键在菜单内移动，`Esc` 关闭并把焦点**归还触发器**（触发器已从 DOM 移除时不归还，避免键盘用户被丢回文档顶部）；
- `Tab` 关闭并继续向后走；命令在途时不可打开；
- 服务端没有给出任何可执行动作时，菜单说明这件事，而不是弹出一个空盒子；
- 禁用项仍然可见、带着服务端的 `reason` 与 `remedy` 入口，点击不执行。

看板拖拽的键盘等价路径是 `Space` 拾起 → 方向键移动 → `Enter` 放下，配 `aria-live` 播报；拖到不允许的列在**拾起阶段**即被拒绝，不是放下后才报错。

## 操作步数：7 → 1 / 2（交互路径对比记录）

旧路径的七步定义取自 [M8 后全面架构与产品体验 Review](../reviews/M8后-全面架构与产品体验Review.md) §3.5：进列表 → 点开卡片 → 等抽屉 → 找到流转区 → 展开 `<select>` → 挑一个枚举 → 点「提交流转」。

| 路径 | 步数 | 说明 |
|---|---|---|
| 旧：详情抽屉 `<select>` + 提交流转 | 7 | 每一步都可能中途放弃，且必须先打开抽屉 |
| 新：看板拖拽 | 1 | 把卡片拖到目标列；键盘等价为 `Space` → 方向键 → `Enter` |
| 新：卡片状态徽章动作 | 2 | 点徽章展开 → 点动作（不可逆动作多一次确认，属安全要求而非额外导航） |
| 新：详情抽屉动作按钮组 | 3 | 打开抽屉 → 点动作（同上，不可逆时 +1 次确认）；抽屉路径没有改用徽章菜单，因此不等于 2 步 |

**这是交互路径的计数，不是用户研究测量**。真实用户完成率与用时属 `M9-Q02` 的可用性验证，本文件不下结论。

最新一次结果（2026-09-17 收口时重新实测，本机）：动作面 7 个 spec 文件 / 84 用例通过（含 `StatusTransitionMenu` 的 12 例：开合状态、首条可执行动作取焦、跳过被禁动作、方向键、`Esc` 归还焦点、禁用项零执行、不可逆动作的第二次点击、可逆动作立即关闭、无动作时的说明、命令在途不可打开）；全量前端 **160 文件 / 924 用例**通过（后一个数字与此前记录的 925 相差 1：`W7` 删除了 `AgentPresence` 的 spec）；`check:quality` 通过；全量 Playwright **5 skipped / 317 passed / 0 failed**（5.5 min，单独执行）。

浏览器档里与本任务直接相关的用例（`e2e/app-shell.spec.ts`）：

| 用例 | 覆盖 |
|---|---|
| `Work board supports the keyboard drag equivalent and the reversible undo window` | 键盘拖拽全流程 + 撤销窗口内的撤销 |
| `Work board expires the undo affordance after the ten-second window` | 窗口到期后入口消失并拒绝再次撤销 |
| `Work board runs an action from the card status badge, keyboard only` | 纯键盘：展开徽章 → 选择 → 执行 |
| `Work list row runs the same action as the board card` | 列表行与看板卡片是同一个动作面 |
| `An irreversible action asks twice and Escape returns focus to the badge` | 二次确认 + `Esc` 归还焦点 |
| `A blocked action shows the server reason instead of vanishing` | 禁用动作给出服务端原因而不是消失 |
