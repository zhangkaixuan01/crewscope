# M1-D01：身份与团队角色领域模型

> 日期：2026-08-07<br>
> 状态：已完成<br>
> 模块：`crewscope-domain`

## 目标

建立人、Agent、Service 和团队成员的稳定身份事实，区分 Team 管理权限与工作对象责任，为 M1-D02 的 Team 创建事务、M1-D03 的默认 Personal Agent 和 M1-D05 的 ResponsibilityAssignment 提供领域边界。

## Principal

`Principal` 统一五类行为主体：

```text
USER
PERSONAL_AGENT
TEAM_AGENT
SPECIALIST_AGENT
SERVICE
```

领域约束：

- USER 和 SERVICE 不包含 Owner；新建三类 Agent 必须包含非自身 Owner Principal；
- V2 迁移生成的无 Owner 停用 Agent 可以先还原，再补齐一次 Owner 后激活；
- Principal 属于一个 Organization，可以具有 Team 归属；
- `TEAM` Visibility 必须具有 Team Scope；
- ExternalIdentity 将 Provider 和 Subject 成对保存并在领域入口归一化；
- DisplayName、Provider 和 Subject 长度与 V2 数据库契约一致；
- `ACTIVE/SUSPENDED/DISABLED/ARCHIVED` 使用显式状态迁移；
- 只有 ACTIVE Principal 可以成为当前行为主体；
- ARCHIVED 是终态，DISABLED 可以在身份对账后重新激活；
- 类型和 Scope 在聚合生命周期中保持稳定，Owner 补齐后不可变。

## TeamMember

`TeamMember` 只接受 ACTIVE USER Principal，Agent 不能伪装成团队成员。成员来源包括：

```text
BOOTSTRAP
INVITATION
OIDC
SCIM
IMPORT
```

Invitation 必须保存 Inviter 并经过邀请激活入口。非邀请来源直接建立 ACTIVE Membership。

成员状态：

```text
INVITED -> ACTIVE / REMOVED
ACTIVE -> SUSPENDED / LEFT / REMOVED
SUSPENDED -> ACTIVE / LEFT / REMOVED
LEFT -> ACTIVE / REMOVED
REMOVED -> INVITED
```

只有 ACTIVE 成员可以参与团队工作和更新 LastActiveAt。创建和激活 Membership 都会校验 USER Principal 当前有效且属于同一 Organization。成员离开后保留稳定 Membership ID、角色授权历史和审计引用；重新加入使用同一 Membership 并开启新的参与时间。REMOVED 不能直接激活，管理员重新邀请时复用稳定 Membership ID，满足 V2 的 Team/User 唯一约束。

## TeamRole 与 MemberRole

TeamRole 管理稳定的团队权限，不表示具体 WorkItem 的 Owner、Executor 或 Reviewer。首批内置角色：

| Role | 主要权限 |
|---|---|
| `TEAM_OWNER` | 全部 Team 管理、工作、观测和治理权限 |
| `TEAM_ADMIN` | 成员、角色、Workspace、Provider、Agent、项目和责任管理 |
| `TEAM_LEAD` | 项目、责任、工作协作和团队观测 |
| `MEMBER` | 创建和参与工作、发起协作 |
| `AUDITOR` | 团队观测、Audit 检索和治理导出 |

内置角色固定为 Team Scope，权限集合由产品定义，内置 RoleKey 不允许被自定义角色占用。自定义角色可以声明 `TEAM` 或 `WORK_PROJECT` Scope，RoleKey 在领域入口归一化为稳定大写机器键。Role Definition 使用 `ACTIVE/DISABLED/ARCHIVED`，只有 ACTIVE Role 可以产生新授权。

`MemberRole` 是 TeamMember 的显式角色授权：

- Member 与 Role 必须属于同一个 Organization/Team；
- Grant Scope 必须与 TeamRole ScopeType 一致；
- Team Scope 不携带 WorkProject，WorkProject Scope 必须携带 WorkProjectId；
- `grantedAt <= validFrom < expiresAt`；
- 有效窗口采用包含 ValidFrom、不包含 ExpiresAt 的区间；
- Revoke 保存 RevokedAt；Expire 只在配置的 ExpiresAt 到达后发生；
- REVOKED 和 EXPIRED 都是终态；
- 终态持久化快照的 UpdatedAt 不得早于 RevokedAt 或 ExpiresAt；
- 历史时点计算同时考虑 ValidFrom、ExpiresAt 和 RevokedAt；
- 当前授权计算仍需组合最新 TeamMember 和 TeamRole 状态，MemberRole 不缓存成员资格。
