# M7-A01 本地账号注册与邀请事务

## 交付范围

`POST /api/v1/auth/register` 接收用户名、邮箱、显示名、密码和可选邀请 Token。Organization、PlatformRole、Principal、Team 与 TeamRole 均由服务端确定，自助注册固定创建 `PlatformRole.USER`。

注册请求先通过 `REGISTRATION` 登录防护。Argon2id 编码在 PostgreSQL 事务外执行，随后在一个事务内写入 UserAccount、local LoginIdentity、LocalCredential、AccountOrganizationBinding、Organization-scoped USER Principal、DomainEvent、Outbox 与 CommandReceipt。邀请注册在同一事务锁定 Digest-only Token，先确认目标 BuiltIn TeamRole 仍为 ACTIVE/可授予，再创建 Membership 和 Role Grant，并把邀请推进到 ACCEPTED。目标 Role 缺失或已停用折叠为 `INVITATION_INVALID`，不依赖事务回滚清理部分 Membership 写入。

PostgreSQL 提交成功后才建立 Redis Browser Session。若 Session 写入失败，数据库事实与完成 Receipt 保留；客户端使用同一 `Idempotency-Key` 和原密码重试时，服务从已提交 Credential 重新验证 Argon2id 密码后恢复 Session。密码不进入 CommandRequestHash，Token 明文不进入数据库、事件、Outbox、Receipt、响应或诊断字符串。

## 公开失败合同

- 注册关闭、邀请缺失或无效统一使用不含命中细节的注册错误；
- 用户名、邮箱和身份冲突不指出具体字段；
- 登录防护与密码 Hash 容量耗尽返回固定限流/不可用响应；
- Redis Session 失败返回 `registration_session_unavailable`，允许安全重试；
- 身份持久化有界执行器满载返回可重试的 `503 registration_unavailable`，不回落到 WebFlux Event Loop；
- 所有响应使用 `Cache-Control: no-store`，不返回邮箱、密码、Token、Hash 或 Session ID。
