## 2. C1（6925111）：通用 tab——组织投影与设置生命周期

**身份收敛**：AuthSession 携带可空组织投影（`organizationId/name/ORG_* role`），
`mapSession` 白名单放行并在「org:\* 词汇与投影不一致」时 fail-closed（一边缺位即后端
契约漂移，不猜测）；`principal.organization` 从 session 组织名单源推导（替换原硬编码
占位串），无 ORG 角色部署渲染空标签。

**organization 域**（`src/domains/organization/`）：枚举/DTO 类型（`confirmationTokenHash`
**有意永不映射**）、中文枚举标签、按 status/code/surface 键控的结构化问题文案、HTTP
gateway（Idempotency-Key + 引号 If-Match + `Idempotency-Replayed` 解析）、按资源分代
generation 的 reactive store（profile 与 settings 加载互不 void）、403→forbidden 相位、
202 回执即重读 settings、409 重读拿下一个 If-Match 版本。

**页面与接线**：`/settings/organization` 路由**有意不做权限门禁**（纯 ORG_\* 持有者无
团队能力），按 org:\* 词汇渐进渲染——全员组织信息卡、审计保留卡（audit-read 可读、
manage-settings 可编辑、≥30 天校验 + 脏表单守卫）、审计中心入口；SettingsShell 菜单
新增组织项；main.ts 装配 + session 边界 reset。

**登记连锁**：commandInventory owners、config-form-token 门禁清单、disabled-reason
豁免（表单自带 reason）、menu-walk MENUS + 显式 GET mock（profile 应答 organizationId、
settings 是对象端点——通用分页 fallback 会毁形状）、e2e session fixture（记忆
m12-f01-e2e-fixture-discipline：裁剪 permissions 必同步 organization=null）。

## 4. C3（b1f19ab）：治理工作流 + 两处连锁修复

**导出工作流**（org:govern）：创建（includeVectors + 幂等键）→ 会话内作业面板逐族进度
→ **单次 process 收敛全部 PENDING**（无轮询、无键、无 If-Match——作业状态机即幂等）→
对账清单 → 产物下载（治理媒体类型再序列化，文件名=作业 ID）。

**删除工作流**（OWNER-only 入口，对 ADMIN **不渲染而非渲染后 403**——避免
ORG_GOVERNANCE_DENIED 审计噪音）：三零预检门 → 创建（20..500 字 reason）→ 用户名令牌
确认（quote 观测到的作业版本 If-Match、无幂等键、autocomplete=off、一次性回显后表单
卸载）→ 13 步协调固定序 → 备份保留声明；**删除 DTO 白名单永不映射
confirmationTokenHash**。

**连锁修复**（真实缺陷，非测试侧）：AppShell scope 规范化不再把「query 白名单带不了
`team`」的路由当团队变更——组织粒度设置 URL 此前每次冷加载被重写、删掉 `tab` 弹掉深链；
e2e auth-session fixture team-only 收窄必须同步摘组织投影（否则复验缓存渗漏）。
