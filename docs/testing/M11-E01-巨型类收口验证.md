### 2.2 GitHubConnectionApplicationService（1228 → ~660 行，21 → 14 参）

主类保持唯一公开 API 编排器；全部组件落同包 `io.crewscope.application.github`，依赖单向 `main → {A,B,C,D}`，唯一组件间边 `D → A`，无组件回调主类（仅编译期引用 `CONNECTOR_KEY`/`DELIVERY_CAPABILITIES` 公开常量，先例已存在）。

| 组件 | 职责（一句话） | 迁入方法 |
|---|---|---|
| `GitHubConnectionAuthorizationService`（A） | 「谁被允许行动」：所有权与可见性裁决 | resolveCreateOwner / resolveListOwner / requireVisibleConnection / requireConnection / requireViewOwner / requireManageOwner / requireTeam / requireTeamManage / requireActiveMember / requireBindingAuthority + static requireOrganizationUser / executionIdentity / authenticationType |
| `GitHubConnectionCommandJournal`（B） | 一条命令日志生命周期：幂等预留、领域事件+outbox、回执完成 | reserve / appendConnectionEvent / appendBindingEvent（CONNECTION_AGGREGATE/BINDING_AGGREGATE 常量随迁，事件 envelope 字节级不变） |
| `GitHubProviderFoundationService`（C） | 内置 Provider definition/implementation 引导与契约重验 | providerFoundation + 构造期 githubRegistration 兼容校验（仍是装配期抛出） |
| `GitHubConnectionAccessService`（D） | 「当前什么为真」：为一次远程调用重验全部授权事实 | requireManagedAccess×2 / currentGrant / requireGrant / requireCurrentProfile / requireCurrentBindingAccess / selectedRepositoryAccess（检查顺序 visibility→manage ownership→version suspension→grant→policy 不变；bindingAccess==null 降级与 suspend→聚合抛 OptimisticLockConflictException 注释逐字保留） |
| `GitHubRepositoryResources`（静态编解码器） | allowlist 编解码（主类与 D 双方使用的无状态纯函数） | repositoryAllowlist（unrestricted 空集与非法资源 DomainValidationException 逐字）/ access + REPOSITORY_RESOURCE_PREFIX |
| 3 个包级 Facts record | 组件间传递的事实束（`OwnerFacts`/`AccessFacts`/`FoundationFacts`） | — |

**留守主类**：12 个公开方法编排、view/bindingView、describeCredential、authorizationStatus、requirePage/requireReason、secretFingerprint、三个幂等 hash 组装（字段顺序属幂等身份合同，逐字未动——同参重放测试锁稳定性）。

**装配（`GitHubProviderApplicationConfiguration`）设计修正**（相对计划的偏差，已按此实施）：组件**不做独立 @Bean**，在 `gitHubConnectionApplicationService` 主 bean 方法体内 new——`@ConditionalOnBean` 13 类型清单与 21 个方法参数字节级不变（部署合同），避免独立条件 bean 把「启动失败」变「静默退场」与 M9b-Q02 defect 27 家族的声明顺序风险；`GitHubConnectionApplicationConfigurationM5A06Test` 零改动（方法体内组合路径由既有 hasNotFailed + hasSingleBean 断言覆盖）。
