## 3. Q2：check-front-boundaries 门禁

## 4. Q3：灵动 DOM 级 e2e 断言

新建 `e2e/m12b-q01/motion.spec.ts`（3 用例 × 双 project）。既有 e2e 全部跑在 `contextOptions.reducedMotion: 'reduce'` 下，动效本身从未被验证——transition 被误删或 token 漂移时无任何用例变红（§5.4 盲区）。

- **button press**：`emulateMedia({ reducedMotion: 'no-preference' })` 逐页覆盖后，断言静息态 transform 为 none、transition-property 含 transform、逐项 duration > 0.05s；`mouse.down()` 保持 :active 并等 200ms 过渡推进后读 `matrix(0.97, 0, 0, 0.97, 0, 0)`，松手 poll 回 none。
- **drawer enter/leave**：rAF 采样循环抓 `.base-drawer` 每帧 transform 与挂载状态（不与过渡时长赛跑）。进场断言存在非 identity 帧且收敛帧归位；出场断言过渡期间元素仍在 DOM（leave-active 生效证据）、帧间 transform 离开 identity、末帧 detached。
- **reduced-motion 反向**：不覆盖 emulateMedia（默认 reduce），断言 transition duration 逐项归零——归零块被删时 reduce 用户会看到全部动效。

### 4.1 过程发现与裁定

- **工作项/Task 详情抽屉无进出场动画（登记不修）**：`WorkPage`/`ConversationPage` 以外层 `v-if` + `:key` 整树挂卸抽屉（M12b-F05 订阅治理的刻意设计），`<BaseDrawer open>` 常真使 Transition 首渲染不经 enter、卸载不经 leave。给 BaseDrawer 加 `appear` 只能修开向（关向仍瞬时）反而体验不一致。e2e 断言锚定 **AppShell 移动端主导航**——BaseDrawer 唯一 `:open` 动态切换的用法，enter/leave 真实运行。
- **Chromium 把 0 时长序列化为 `1e-05s`**：reduce 断言用阈值（<0.001s）而非字面 `'0s'`，不绑引擎序列化格式。
- **:active 的 scale 有 120ms 过渡**：down 后立即读计算样式停在起点 matrix(1)——等过渡推进再读终值。
