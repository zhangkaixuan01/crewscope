# M9b-A07：成员生命周期与撤权交接完成

日期：2026-09-25

## 1. 用户现在怎样使用

成员页从只读名单变成生命周期操作台：行内"⋯"菜单按状态与权限提供停用/恢复/移除/离开/授予与撤销角色/转让 Owner/交接责任，危险动作先过确认对话框；`?tab=members|invitations` 把成员目录与加入邀请分成两个视图，移除后的成员一键跳到邀请流重新拉人。停用即刻收回该 Team 全部通道（HTTP、会话投影、两条 SSE、PersonalAgent、Task 执行、GitHub dispatch、通知投递），他 Team 不受影响；恢复只重建基础访问，旧角色授权不复活。责任交接是显式 job：确认页先预览"该角色当前有 N 项在途责任"，处理后逐项给出 DONE/CONFLICT/DENIED 明细（版本冲突项保持原状、提示人工处理），取消不影响已 DONE 项。邀请接受不再靠"差集→同名→第一个"三级猜测——accept 响应携带受权坐标直达目标 Team，会话滞后时进入"接受已提交、会话待同步"，重新同步永不重复 accept；普通成员在账号页即可读写自己的通知偏好，不需要任何管理权限。

## 3. 固定反例与实施偏差（每个都曾真实失败或推翻计划）

- **网关透传线格式（P6 真缺陷）**：`HttpScopeGateway` 的 process/get/cancel 三个 handover 方法直接透传后端 `jobId`/`itemId` 线格式，类型却标注视图形状——单测的 FixtureScopeGateway 返回视图格式所以从未暴露，e2e 里 `item.id` undefined 触发 Vue :key 警告才发现。修复：三方法包 `mapHandoverJob`，gateway.spec 新增契约测试锁定线形状。
- **markAuthorizationChanged 双递增（计划决策修正）**：计划说"仅 authorizationVersion+1、version 不变"；实施发现每个提交都要过 version 谓词才能落库，version 必须随行——方向上的分离保持为 recordActivity 永不递增 authorizationVersion。
- **item 事务三段式**：caught exception 会把 joined transaction 标记 rollback-only——CONFLICT/DENIED 的 stopped outcome 若在同一事务里落库，外层提交必失败。每项 = replay+DONE 一个事务 + stopped outcome 之后的新事务；job 状态翻转（PENDING→RUNNING→COMPLETED）再一个事务。
- **生命周期 202 回执不带成员现状**：与 Team 命令协议一致，客户端重读成员列表；e2e 断言的是 world fixture 状态而非响应体。
- **P3 集成测试拆两处**：计划的单一 `MemberRevocationRuntimeIntegrationTest` 落地为 application `PersonalAgentRevocationGuardTest`（三边界）+ infrastructure `TaskTokenCurrentAuthorizationM3Q01Test`（快照维度/边界拒绝）。
- **快照维度只落 `TaskTokenGrantScope` 顶层**：`ExecutionPrincipalSnapshot` 未动——维度属于授权事实而非执行者身份；V44 两列 NULLable 且不入签名指纹，旧 token 升级后仍可验签。
- **V45 无外键**：job/item 是钉住的历史事实，源 assignment 可被并发命令 release——item 走版本期待落 CONFLICT 而非阻塞 job。
- **菜单 z-index token 回退**：`--cs-z-dropdown` 不存在，回退值 30 被移动底栏（sticky=400）拦截 pointer events——narrow e2e 超时才暴露。改用 `--cs-z-popover`（800）。
- **members-tabs 命中区**：tab 链接实测高 35.5 < 44px——接入 `min-height: var(--cs-density-control-height)`（窄屏 token 自动抬到 44+4，密度 token 是控件高度唯一来源）。
- **e2e URL 锚点**：`?team=X$` 因 AppShell 回填 `project` 参数不匹配；heading 匹配需 `exact`（"团队邀请"同时命中空态 h3）。
- **CSRF 从 cookie 取值**：apiClient 读 `XSRF-TOKEN` cookie 设请求头（Spring CookieServerCsrfTokenRepository 模式），e2e 夹具必须 `context.addCookies`，断言里 `csrf` 字段才能落实。
- **m7-invitation 适配**：P6 默认 tab 改 members 后邀请管理在 `?tab=invitations`，两个 goto 补参数。
- **生成物与操作基线漏更新（收尾 review 发现）**：A06/A07 新增服务端端点后未重新生成前端契约物——`openapi.ts` 缺整个 A07 端点面（生命周期/交接/本人偏好）与 A06 的 WorkDesk 分段等，`state-machines.ts` 域 SHA 过期，`check-openapi-drift.mjs` 与 I01 契约文档的基线停在 223（实际 238），推送即被 CI quality 门禁拦截。已重新生成三份生成物并同步基线至 238。
- **suspend/remove 缺自我目标防线（提交前 review 发现）**：契约规定"操作自己 → 403 policy_denied"，但骨架只挡了权限与最后 Owner——双 Owner 场景其一可把自己 suspend 成 SUSPENDED 而绕过 last_owner_protection，产生 SUSPENDED 而非 LEFT 事件。修复：`lifecycleInTransaction` 加 `forbidSelfTarget`（先于最后 Owner 判定，单 Owner 自我操作也得到"走 leave"指引而非 409）+ application 测试（单 Owner 自我 suspend/remove 均拒绝且无事件）。
- **e2e 夹具把停用/恢复的授权语义教反（提交前 review 发现）**：夹具 suspend 保留 grants、activate 清空——真实服务器相反（suspend `revokeActiveGrants`、activate `ensureDefaultMemberRole` 重建 MEMBER；wire 对非 ACTIVE 成员恒返回空角色）。修正夹具与终态断言（`roles=['MEMBER']`），另修正重放 accept 夹具回填全量坐标的问题（真实重放只回填 teamId/memberId）。
- **本人偏好卡片切换 Team 竞态（提交前 review 发现）**：`TeamNotificationPreferenceCard` 的 load/save 无 stale 守卫，慢 GET 返回时把上一个 Team 的偏好写进当前选中——加捕获比对（同库内 `isCurrent` 惯用法）。另修 `useScopedUserState` 丢弃 epoch 订阅退订函数导致的逐挂载监听器泄漏（`onScopeDispose`）。

## 5. 交接与明确非目标

- **F04 账号入口扩展**：账号页当前只读当前 Team 的本人偏好；多 Team 切换、R21 的已选回显与呈现语义归 F04。
- **A05 委托编排**：交接处理的是"已钉住的 assignment 转移"，不涉及委托关系的建立与撤销。
- **Saga/跨组织转移**：不做跨 Team/组织的成员迁移——移除+重新邀请是唯一路径（`membershipDisposition=ACTIVATED/CREATED` 已支持）。
- **交接调度**：process 是显式触发 + 可重入，没有自动定时器；UI 引导管理员在移除前或移除后主动处理 CONFLICT 项。
- **WebSocket**：七通道撤权只覆盖既有通道；M11-D02 若引入新通道需自带检查点。
- **F05 遗留**：Task Retry 2 例 e2e 为 F05 收口顺序缺陷（服务端未创建 successor attempt 投影），F05 完成文档已交接跟踪，非本包责任。
