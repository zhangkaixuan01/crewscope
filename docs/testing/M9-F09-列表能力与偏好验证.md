# M9-F09：列表能力与偏好验证

## 交付范围

本任务建立所有列表页共用的四项基础能力：

- `useListSort` 统一排序键、方向切换与服务端查询参数，带允许键白名单；
- `useSelection` 支持跨游标页保留选择、当页全选、上限与部分页面回显；
- `formatRelativeTime` / `formatAbsoluteTime` 统一相对时间和完整时间提示，未来时间不会出现负数；
- `usePreference` 作为唯一的 `localStorage` 入口，使用版本化载荷、损坏值回退和跨标签页同步。

`AppBreadcrumb` 从路由 `meta` 派生并接入 `AppShell`，所有页面均有稳定的上下文位置。

## 验证结果

- `useListSort.spec.ts`：允许键、升降序切换、重置与非法键拒绝；
- `useSelection.spec.ts`：跨页选择、上限和当前页回显；
- `usePreference.spec.ts`：版本不匹配回退、持久化、跨标签页同步与重置；
- `formatRelativeTime.spec.ts`：刚刚、分钟、小时、未来时间和非法输入边界；
- Activity 与 Inbox 列表使用相对时间，并以完整绝对时间作为悬浮信息；
- AppShell 全页面接入面包屑。
- `m6-activity` 与 `m6-inbox` 的 Desktop/Narrow Darwin 视觉基线已按预期变化重拍，10 条对应 E2E 全部通过。

排序、批量命令与服务端游标查询的业务动作由后续工作台任务接入；本任务不改变既有领域 API、事件或权限语义。

## 工作项列表接入（2026-09-17 收口）

工作项列表此前没有消费者，本轮接入：

- **排序**：`components/domain/WorkItemsToolbar.vue` 接 `useListSort`，排序键写进 URL；可排序字段是 `updatedAt` / `priority` / `dueAt` / `title`（`domains/workitem/list.ts` 是唯一声明处）。**负责人不可排序，并且界面明说原因**——`WorkItemSummary` 行上没有责任事实，所以这个字段不在行上，写了也没得排；把它显式命名而不是悄悄省略，是因为成员会合理地期待能按负责人排序。
- **批量**：`components/domain/WorkItemsBulkBar.vue` 接 `useSelection`（多选列、全选当页、跨页选择上界、选中数小条）。首批批量动作是**改状态**与**指派**：逐项执行、**每项独立幂等键**，逐项给出结果汇总，没执行的行**逐条说明为什么**（权限不足或不满足前置条件的行会被自动排除并标注），因此不存在"一半成功、界面上却像全成功"的静默状态。
- **相对时间**：列表里的时间统一走 `formatRelativeTime()`，不再自造格式；排序与批量都复用本任务（`M9-F09`）的组合式函数，没有第二份实现。
- **权限**：一批里能不能选、哪些行能选，全部读服务端随行下发的可用性裁决（`domains/workitem/bulk.ts`），前端不自行判断动作是否存在。

浏览器档（`e2e/m9-list-capabilities.spec.ts`）：

| 用例 | 覆盖 |
|---|---|
| `orders the loaded rows and keeps the sort in the URL` | 排序生效 + 排序键进 URL |
| `runs one batch command per selected row through the single command endpoint` | 批量逐项走同一条命令端点、各带自己的幂等键 |
| `names every row a batch did not execute and why` | 部分失败：逐行说明未执行原因 |
| `selects the visible page and keeps rows selected across pages` | 全选当页 + 跨页保持选择 |
| `says a batch cannot be submitted while offline instead of offering dead buttons` | 离线态：不给死按钮，明说不能提交 |
| `offers no selection at all to a member who may not act on the list` | 无权限：整列不提供选择 |

**如实记录的偏差**：排序作用在**已加载页**内（`WorkItemSummary` 自带排序列，`useListSort` 是纯函数比较），**不是服务端排序**。服务端排序需要把排序键装进游标（否则翻页会重复或漏行），那是游标信封的变更，本轮未做。因此本页的排序期望是"眼前这页可读可整理"，不是"全量有序"；计划里"服务端可排序字段由生成契约约束"这一句尚未落地。
