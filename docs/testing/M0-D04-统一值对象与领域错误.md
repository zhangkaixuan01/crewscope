# M0-D04 统一值对象与领域错误

> 模块：`crewscope-domain`、`crewscope-application`  
> Java：17  
> 验证日期：2026-08-06

## 1. 目标

CrewScope 使用统一的强类型聚合 ID、UTC 时间和值对象错误契约。领域失败以稳定错误码表达，应用层
只向 API、Agent Tool 和事件适配器传递安全错误信息。

## 2. ID 契约

`AggregateId` 是聚合 ID 的公共契约，当前实现：

- `OrganizationId`；
- `TeamId`；
- `WorkspaceId`；
- `PrincipalId`；
- `WorkItemId`。

ID 使用 UUID 作为数据库和外部契约表示。每种 ID 保持独立 Java 类型，拒绝 `null`、nil UUID 和
非标准 UUID 文本，`toString()` 输出标准 UUID。生成方法使用 JDK UUID 随机源。

## 3. 时间契约

`UtcTimestamp` 保存 UTC `Instant`，统一截断为微秒精度，与 PostgreSQL `TIMESTAMPTZ` 往返精度
一致。它支持 `Instant`、`OffsetDateTime` 和 ISO-8601 文本输入，并统一输出 UTC。

`TimeProvider` 是领域与应用层的可注入时钟。生产代码可以适配系统 `Clock`，测试代码可以使用固定
`Clock`，避免业务测试依赖真实时间。

`DomainEvent.occurredAt()` 已改为返回 `UtcTimestamp`。M0-E01 将在此基础上定义完整事件信封。

## 4. 错误契约

`DomainError` 是不可变、安全的错误载荷，包含：

| 字段 | 作用 |
|---|---|
| `code` | 稳定机器错误码 |
| `category` | Validation、Not Found、Conflict 或 Policy 分类 |
| `message` | 可安全返回的业务描述 |
| `details` | 不可变字符串详情，不保存请求正文、凭证和非法原始值 |

当前错误码：

| Java 枚举 | 协议值 | 分类 |
|---|---|---|
| `INVALID_VALUE` | `invalid_value` | `VALIDATION` |
| `RULE_VIOLATION` | `rule_violation` | `VALIDATION` |
| `INVALID_STATE_TRANSITION` | `invalid_state_transition` | `CONFLICT` |
| `AGGREGATE_NOT_FOUND` | `aggregate_not_found` | `NOT_FOUND` |
| `OPTIMISTIC_LOCK_CONFLICT` | `optimistic_lock_conflict` | `CONFLICT` |
| `IDEMPOTENCY_CONFLICT` | `idempotency_conflict` | `CONFLICT` |

对应异常统一继承 `DomainException`。乐观锁错误携带期望版本和已提交版本；幂等冲突携带幂等键和两次
规范请求的 Hash，不携带请求正文。

WorkItem 标题、Key 和状态迁移已使用该契约，后续领域模型直接复用。

## 5. 应用边界

`ApplicationErrorMapper` 可以从直接异常或基础设施包装异常的 Cause Chain 中提取 `DomainError`。
遍历使用对象身份集合阻止异常因果环。未知异常返回空结果，由 Server 适配器生成通用内部错误，避免
暴露异常消息、数据库信息和实现细节。

M0-A01 将把错误分类映射为 `/api/v1` HTTP 错误信封。
