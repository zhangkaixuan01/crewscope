# M7-D07 本地账号与身份迁移

## 1. 目标

M7-D07 将 M7-D01 至 M7-D04 的账号、登录身份、本地 Credential 和 Organization Binding 领域契约落到 PostgreSQL V31，并保持 Account 与 Organization 内 Principal 的边界清晰。

## 2. 实现

新增 `V31__local_user_account_and_identity.sql`，建立：

- `user_account`：保存用户名/邮箱显示值和规范唯一键、展示名、闭合账号状态、`USER / OPERATOR` 平台角色、SecurityVersion、业务版本和生命周期；
- `login_identity`：保存稳定 Account、Provider、精确 Subject、状态和最后成功认证时间，并以 `(provider, subject)` 和 `(account_id, provider)` 双唯一约束裁决冲突；
- `local_credential`：在唯一受限列保存有界 `{argon2id}` 或历史 `{bcrypt}` 编码 Hash，保存算法、Credential Version、密码修改时间、业务版本和生命周期；
- `local_credential_metadata`：排除 `password_hash` 的稳定非敏感视图，供通用账号与审计 Reader 使用；
- `account_organization_binding`：通过 Account/Organization 与 Organization/Principal 双唯一键，以及 Organization/Principal 复合外键，建立部署账号到 Organization Scope USER Principal 的单向授权桥。

`username_normalized / email_normalized` 必须由 `Username / NormalizedEmail` 和 Repository Adapter 从显示值派生并与显示值原子写入。该规则包含 Java Unicode NFKC、Locale ROOT 大小写折叠和邮箱 IDNA；PostgreSQL `LOWER` 受数据库 Locale 影响且不等价于该规则，因此 V31 只审核规范键形状与唯一性，不在 SQL 内重算。后续 M7-I01 的写入 Adapter 不接受外部传入的规范键。

四类事实使用显式 Check Constraint 和触发器保护枚举闭集、版本起点与单步推进、时间单调、不可变坐标、状态转移和禁止物理删除。Binding 写入时验证 Principal 为同 Organization 的 Organization Scope USER；存在 Binding 后，Principal 的 Organization、ID、类型和 Team Scope 不可改变。

账号注册发生在 Principal 创建之前，因此 V31 使用 `created_at / updated_at / version` 作为账号审计边界，不虚构 `created_by_principal_id`。账号归档、Identity 撤销和 Binding 停用表达逻辑终态。

## 3. 敏感列边界

`password_hash` 只存在于 `local_credential` 底表。V31 显式撤销底表和元数据视图的 PUBLIC 权限；通用数据库 Reader 只授予 `local_credential_metadata` 的 SELECT，无法读取底表 Hash。认证 Adapter 使用独立受信权限读取和原子轮换底表，Repository、审计和公开 DTO 不映射 Hash。

## 4. 自动验证

专项 Testcontainers 测试：

```bash
./mvnw -pl crewscope-infrastructure -Dtest=V31LocalUserAccountIdentityMigrationIntegrationTest test
```

结果：`6 / 6` 通过，覆盖：

1. 空库 V1→V31、非默认 `search_path`、Flyway Validate 和重复迁移收敛；
2. V30→V31 单版本升级以及既有 Organization/Principal 数据不变；
3. 用户名/邮箱规范唯一、Provider/Subject、Account/Provider、每 Account Local Credential、Binding 双唯一冲突；
4. 本地 Subject、Hash 形状、版本、闭合状态、Organization Scope USER Principal 与跨 Organization 复合外键；
5. 仅获元数据视图权限的 Reader 可读元数据且读取 `password_hash` 返回 PostgreSQL `42501`，PUBLIC 不具备 Hash 列 SELECT；
6. V30 上保留关系名冲突导致 V31 失败时，PostgreSQL/Flyway 整笔回滚且版本保持 V30。

通用 Flyway 回归继续通过 `FlywayMigrationIntegrationTest` 自动覆盖空库到 latest、V1 到 latest 和非默认 `search_path`。

## 5. 结论

M7-D07 完成。V31 已成为账号持久化与后续 Repository、Session、密码认证和 Bootstrap Operator 实现的数据库基线；V32 TeamInvitation 迁移已由 M7-D08 完成。
