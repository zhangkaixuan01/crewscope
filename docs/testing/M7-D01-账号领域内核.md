# M7-D01 账号领域内核

> 任务：`M7-D01`<br>
> 日期：2026-08-28<br>
> 状态：完成<br>
> 关联决策：[ADR-024](../adr/ADR-024-Account与Principal身份边界.md)

## 1. 交付目标

M7-D01 建立 CrewScope 部署级登录账号的正式领域内核：

- `UserAccountId` 作为稳定账号聚合标识；
- `Username` 和 `NormalizedEmail` 表达可修改展示值与稳定规范唯一键；
- `UserAccount` 闭合资料、状态、平台角色、Security Version、业务版本和生命周期；
- `UserAccountRepository` 定义 D07/I01 需要实现的类型化查询、创建和乐观更新端口；
- 用户名或邮箱唯一冲突统一为无字段、无输入值的 `account_identifier_conflict`。

## 2. 标识规范化

### 2.1 用户名

`Username` 保存两份不可变事实：

```text
displayValue    = trim + NFC
normalizedValue = displayValue + NFKC + Locale.ROOT lowercase
```

展示值保留用户提交的大小写和全角形式，规范值用于唯一索引与登录定位。长度按 Unicode code point 计算，固定为 3–64；允许 Unicode 字母、数字、合法组合符及单个 `.`、`-`、`_` 分隔符。首尾分隔符、连续分隔符、空白、控制字符、双向覆盖、私用字符和补充代理项失败关闭。

### 2.2 邮箱

`UserAccount.email` 保留 trim + NFC 展示值，`NormalizedEmail` 对完整地址应用 NFKC 和 Locale-independent 小写，再用 STD3 IDN 规则将域名转换为 ASCII。本地部分最多 64 code point，完整规范值最多 254 code point；非法点位、多个 `@`、非法 IDN Label、控制/格式字符和未允许符号被拒绝。`NormalizedEmail.toString()` 固定返回 `[REDACTED]`，持久化和精确比较必须显式读取 `value`。

用户名或邮箱修改会在同一新聚合版本中同时替换展示值和规范值。持久化恢复会重新派生并比对规范邮箱，阻断不一致投影进入聚合。

## 3. 状态、角色与版本

账号状态转移图：

```text
ACTIVE   -> LOCKED | DISABLED | ARCHIVED
LOCKED   -> ACTIVE | DISABLED | ARCHIVED
DISABLED -> ACTIVE | ARCHIVED
ARCHIVED -> terminal
```

只有 ACTIVE 账号可认证。每次状态变更同时推进聚合业务版本和 `SecurityVersion`，保证既有 Session 在持续授权时失效。资料修改只推进业务版本；后续改密和全会话撤销使用 `advanceSecurityVersion`。`SecurityVersion` 从 1 开始并阻断溢出，聚合业务版本从 0 开始。

`register` 不接受角色参数并始终创建 USER。`bootstrapOperator` 是独立受信工厂，创建 OPERATOR。`allowsPlatformOperations` 同时要求 ACTIVE 和 OPERATOR；PlatformRole 不创建 Organization Binding、TeamMember 或 TeamRole 权限。

## 4. 应用与冲突边界

`UserAccountRepository` 使用 `UserAccountId`、`Username` 和 `NormalizedEmail` 作为查询坐标，不接受 Credential、Principal 或 Session 类型。D07/I01 的两个规范唯一索引失败必须映射为同一 `AccountIdentifierConflictException`。该异常仅含：

```text
code    = account_identifier_conflict
message = Account identifier conflicts with an existing account
details = {}
```

它不包含冲突字段、输入值、已有 Account ID 或数据库约束名。后续注册和资料修改 API 可以对用户名/邮箱冲突返回完全一致的公开形状。
