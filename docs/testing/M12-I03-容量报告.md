## 2. 六指标实测基线（GET /api/v1/organizations/{org}/sli）

| 指标 | 实测（process_lifetime / 窗口） | 对阈值 | 判读 |
| --- | --- | --- | --- |
| api.latency.p95 | 1216.9 ms，12 样本（冷启动含登录链） | 超 800 ms | 样本仅 12 且含冷启动首批；稳态复测归后续运营，不据此改阈值。5xx 预算 consumedRatio=0.0（ok） |
| agent.first.token（model_side / app_overhead） | no_data | 不适用 | 无模型调用即无样本——诚实呈现，等真实流量积累 |
| queueing.latency | outbox_delivery 25.2 ms / 50 样本 ok；projection_replay no_data；snapshot：backlog 0 | 远低于 30 s | snapshot 的 checkpoint lag 在**空组织上随墙钟增长**（实测 50 s→113 s）：活跃代 checkpoint 无新事件不推进，lag=now−checkpoint 的定义使然。降级评审时先对时间线（Runbook 清单第 5 条）；阈值判读以 backlog 与 outbox_delivery 为准 |
| execution.success.rate | 双窗口 no_data（空库分母 0） | 不适用 | no_data ≠ 0，诚实分层生效 |
| notification.delivery.rate | 双窗口 no_data | 不适用 | 同上 |
| knowledge.retrieval.latency.p95 | no_data | 不适用 | 检索未调用（未启用时也计时 outcome=degraded，无样本仍 no_data） |

端点本身：5×200，经 nginx 端到端 69–258 ms（空库）；注入 10 万行后 88–239 ms（表类四条窗口 SQL 在真实数据量下仍由端到端噪声主导）。

## 3. 28 天窗扫描代价（EXPLAIN ANALYZE，真实 PG 17）

- 空表基线：`Index Scan using uk_task_execution_scope_attempt`（organization 前缀），execution 2.9 ms。
- 单 org 100 000 行（窗口内）：`Bitmap Heap Scan on uk_task_execution_scope_id`，Heap Blocks 2858，**execution 62 ms**（FILTER COUNT 双状态聚合一条 SQL）。
- 结论：organization 前缀唯一索引使窗口查询的代价与 **org 内行数**（而非全表行数）线性；10 万行/org 量级约 60 ms，单机 SLI 查询面无容量风险。通知/agent_run 查询同构（同前缀索引族），不重复测量。

## 4. 档位形态（50/200/500 并发，推算不是压测结论）

| 档位 | 假设 | 推算 |
| --- | --- | --- |
| 50 并发 | 单机四服务、PG/Redis 本机 | API Timer 直方图 series 数=路由模板×方法×状态（数百级），内存 <5 MB；表类查询按 §3 线性外推，无压力点 |
| 200 并发 | 同上 | `crewscope.api.requests` 样本量增大只影响 registry 计数，不增 series；瓶颈首先出现在业务写路径（outbox/执行），不是 SLI 查询面（只读+no-store） |
| 500 并发 | 超出 Team-Beta 单机目标形态 | 不外推动结论；需独立压测（Q01 范围）。本报告档位为 ADR-037 §5 要求的形态样本，非强制规格 |

## 5. Prometheus 折叠验证

`/actuator/prometheus`（Basic 认证 `crewscope-prometheus`，`crewscope.security.monitoring.password`，默认仅开发兜底）实测暴露 **414 个 `_bucket` 系列**；`crewscope_api_requests_seconds_bucket` 与 `crewscope_m6_outbox_duration_seconds_bucket` 两族直方图确认生效。其余族（首 Token/projection/检索）在 meter 出现首个样本后自动出现。28 天窗折叠公式见 Runbook「SLI 与错误预算」。

## 6. 运营注记

- Timer 类 28 天条目恒 degraded 是合同行为（进程内 registry 无法跨重启），部署外部 Prometheus 后即可回答——不构成告警。
- 空组织 checkpoint lag 增长（§2）建议后续切片评估「lag 仅对存在待投递事件的投影计算」；当前按诚实原始值报告。
- 本报告数值为 2026-10-15 单次取数；ADR-037 §5 初值不变更，运营积累后由下一份报告校准。
