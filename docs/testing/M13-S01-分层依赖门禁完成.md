# M13-S01：分层依赖门禁自动化 — 完成记录

> 来源：[M13-后端结构收敛执行计划](../plans/M13-后端结构收敛.md) S01 工作包（Review §2.2/§8 P0）。
> 性质：纯门禁脚本扩展，零 Java 改动、零行为变化。

## 1. 勘察校准

开工即发现 Review §2.2 「后端目前无等价自动门禁」表述不准确：`scripts/check-module-boundaries.mjs` 已存在且已挂 CI（quality job 与 release workflow 各一处）——但只有 **import 级**规则（四模块禁包前缀），且 infrastructure 无规则、无 pom 依赖声明级断言。pom 洋葱单向此前确实靠人工。本包实际范围据此从「新建门禁」校准为「扩展既有脚本补 pom 层 + 补 infrastructure 规则对齐」。

## 2. 交付：两层门禁

`scripts/check-module-boundaries.mjs` 现断言两层（脚本内 `internalDependencyMatrix` 即矩阵基线，漂移即红）：

| 层 | 断言 | 覆盖 |
| --- | --- | --- |
| import 级（既有+补齐） | 各模块源码 import 禁越层包前缀 | domain/application/agentscope/integration/**+infrastructure（本包补）** |
| pom 级（本包新增） | 六模块内部依赖双向断言：多余依赖红、期望依赖缺失红、新模块未登记红 | 全部六模块 |

**依赖矩阵基线**（洋葱单向，pom 实测与 Review §2.2 一致）：

```
domain → （无内部依赖）
application → domain
agentscope → domain, application
integration → domain, application
infrastructure → domain, application
server → domain, application, agentscope, integration, infrastructure
```

实现注记：pom 解析取全部 `<dependency>` 块中 groupId=`io.crewscope` 且 artifactId 以 `crewscope-` 开头者（build 段零 plugin dependency 已实测，全文匹配安全）；未登记模块检查以 pom.xml 存在为前提（crewscope-web 前端目录不误伤——首跑即抓到并修正）。

## 3. 自测证据（构造违规样例必红）

| 用例 | 操作 | 结果 |
| --- | --- | --- |
| 正常路径 | 当前 main 六模块 | PASS（exit 0） |
| 多余依赖 | agentscope pom 注入 `crewscope-infrastructure` 依赖 | 红：`unexpected internal dependency crewscope-infrastructure (allowed: crewscope-domain, crewscope-application)` |
| 缺失依赖 | application pom 删 `crewscope-domain` 依赖 | 红：`expected internal dependency crewscope-domain is not declared` |
| 未登记模块 | 临时 `crewscope-foo/pom.xml` | 红：`module pom exists but is not registered in internalDependencyMatrix` |
| 还原复核 | 全部样例还原后 | PASS，工作树仅脚本改动 |

过程注记：首个「多余依赖」自测一度未红，定位为注入手法把 XML 弄成错位嵌套（非贪婪解析并块取首个 artifactId 吞掉注入项）——非脚本缺陷（坏 XML 由 Maven 构建层拒绝兜底），换整块匹配注入后按预期红。
