## 3. 归属裁定与书面结论

1. **OIDC 攻击集不另建浏览器级 gate**：`OidcProtocolAttackM12I01IntegrationTest` 已是 team-beta 全栈 IT 形态（真实 PG/Redis + EmbeddedOidcIdp RSA-256，九行攻击矩阵逐协议断言）——M11 沉淀的「独立 Compose 栈+分相位脚本」默认形态适用于需要部署形态差异的面；OIDC 协议攻击在应用层可穷举且浏览器不新增攻击面，Q01 归属引用不重跑（终跑零回归 S12 全量覆盖其用例）。
2. **配额挂点窄缝裁定（A02 偏差 2 收口）**：完整任务创建链 HTTP e2e 未做——`AgentTaskCreationService` 24+ 参数构造器的 conversationService/bindingResolver/codingTargetRepository 深水区，全仓只有 mock 层测试无真实存储创建链先例。Q01 裁定：装配缝 IT（q01/S10：服务+真实 PG 在挂点事务形态下组合）承证超占/崩溃对账的组合语义；完整创建链 HTTP（含 replay×quota 组合）如实记为已知边界，不虚报为已验。
3. **重复占用的证据链**：replay 短路（:395）先于配额挂点（:439）是代码顺序事实；A05 `replayDoesNotAssignOrDelegateTwice` 在 mock 层钉死 replay 不重走后段管线（assign/delegate 不重复）——配额不双占是同一短路的直接推论，不另造 HTTP 级重复请求测试冒充已验完整链。
4. **auditor 读面分界（首跑修正记录）**：C2 首跑把 role-grants GET 断言为 403 而挂——`listGrants` 的能力是 AUDIT_READ_ORG（OrganizationRoleApplicationService.java :85，javadoc「the role-management audit face」），ORG_AUDITOR 读 200 是设计正解。修正后矩阵如实钉死：审计事实面（SLI、角色授予清单）对 auditor 开放，配置面（settings/quota）与全部治理写面拒绝——这是「审计事实 vs 配置」的正交，不是门禁漏洞。
5. **团队端点存在性差分（已知边界登记）**：团队点读（getTeam/listMembers/invitations 列表）先 `requireTeam`（不存在→404）后成员检查（非成员→403）——同 org 已认证的非成员对存在/不存在的 team 有响应差分。缓解事实：目录面 `listTeams` 按成员资格过滤返回空列表，团队存在性不可经目录枚举；攻击者须已是同 org 已认证成员。改序=行为变更，超出 Q01 测试工作包红线，登记不改判。
6. **升级恢复证据形态**：D01 三相位演练（盘点/升级/恢复对账）即 §8-1/2 的「存量归属不漂移+完整恢复」证据源；Q01 复跑（q01/S14）证明攻击/故障收口时点漂移 gate 仍绿，Q02 Release Gate 再做终跑。
