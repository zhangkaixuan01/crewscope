# M2-A02：用户消息追加

> 日期：2026-08-10<br>
> 状态：已完成<br>
> 模块：`crewscope-domain`、`crewscope-application`、`crewscope-infrastructure`、`crewscope-server`

## 目标

交付受 Team Scope 和 Conversation Participant 保护的用户消息追加命令，让前端以幂等方式提交 Markdown，并由服务端原子生成消息顺序、事件和命令回执。

## 命令契约

- 请求体只包含 Markdown `content`，作者、Participant、MessageType、MessageId 和 Sequence 均来自服务端事实；
- 当前 Principal 必须是 ACTIVE USER、ACTIVE TeamMember 和目标 Conversation 的 ACTIVE USER Participant；
- 归档 Conversation、LEFT Participant、跨 Team Conversation 和仅可发现但未参与的 TEAM Conversation 拒绝写入；
- `Idempotency-Key` 同时作为命令预留键和 `clientMessageKey`，相同请求重放、不同请求冲突；
- Conversation 行锁串行分配从 1 开始的 Message Sequence；
- Conversation、Message、`CONVERSATION_MESSAGE_POSTED`、Outbox 和 CommandReceipt 同事务提交；
- DomainEvent 聚合引用为 Conversation，AggregateVersion 等于追加后的 Conversation Version。

## Markdown 安全契约

- 内容 `strip` 后非空且不超过 50,000 个字符；
- 允许换行、回车和水平制表符，拒绝其他 ISO 控制字符和 Unicode 双向覆盖/隔离控制字符；
- 服务端把 Markdown 作为不可执行文本通过 JSON 保存和返回，不在日志与错误详情中输出正文；
- 持久化保留规范化原文，不以字符串替换模拟 HTML Sanitizer；
- M2-F02 使用禁用原始 HTML、链接协议白名单和节点清理的 Markdown Renderer。

## HTTP 契约

```text
POST /api/v1/organizations/{organizationId}/teams/{teamId}/conversations/{conversationId}/messages
Idempotency-Key: <client-generated-key>
Content-Type: application/json

{"content":"请整理本周发布风险。"}
```

首次成功和幂等重放均返回 `202 CommandReceiptResponse` 与 `Cache-Control: no-store`；重放额外返回 `Idempotency-Replayed: true`。

## 实施结果

- `ConversationApplicationService` 新增用户消息命令，服务端解析作者 Participant、分配 MessageId 与 Sequence，并复用统一 CommandReceipt 事务边界；
- `ConversationMessagePosted` 以 Conversation 为聚合生成不可变事件，Message、Conversation Version、DomainEvent、Outbox 和 CommandReceipt 原子提交；
- JPA 适配通过 Conversation 悲观行锁串行化并发追加，事件 AggregateVersion 与消息 Sequence 保持单调一致；
- HTTP 边界只接受 `content` 与 `Idempotency-Key`，首次提交和重放返回统一 `202 CommandReceiptResponse`；
- `MessageContent` 拒绝危险控制字符、Unicode 双向控制字符和不配对 Surrogate，同时保留合法 Markdown、多行文本、TAB、LF 与 CR。
