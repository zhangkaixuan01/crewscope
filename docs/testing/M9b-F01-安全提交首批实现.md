## 2. 已实现

### 2.1 HTTP 兼容安全 ID

[secureId.ts](../../crewscope-web/src/api/secureId.ts) 优先原生 randomUUID，缺失时用 getRandomValues 生成带正确 version/variant 位的 UUIDv4；无安全随机源/源失败则拒绝，不使用 Math.random 或时间戳补位。S01 记录的 23 个生产调用文件已迁移，包括页面、Store、配置对话框与本地 Diff 评论。测试/Story 的服务器 fixture 不冒充生产接线；纯 DOM 标识不属于命令身份。

注册页就近展示 `secure_random_unavailable`；其他既有捕获链收到相同受控错误，未捕获的入口通过全局错误边界显示安全提示而不是内部异常。每个菜单的按钮复位/就近提示仍须在剩余 F01 调用点测试中逐项验证，不能以静态替换关闭所有交互验收。

### 2.2 意图级内存重放

[commandIntent.ts](../../crewscope-web/src/api/commandIntent.ts) 只对明确具有幂等合同的入口按需接入，没有给所有 POST 设置通用自动重试。

- 规范 JSON 比较对象键顺序，省略未定义对象属性，保留数组顺序；在发请求前复制请求快照，适配器修改参数也不改变下一次重放输入。该规范串只是内存身份比较，**不是落盘 hash**。
- 同坐标/命令/规范输入的重复点击共用在途 Promise；网络异常、Abort、408、5xx、响应解析异常均为 unknown，不声称写入失败。用户明确重试才按原键发送，无后台自动重发。
- 修改输入产生另一意图，旧未知记录仍保留；改回原内容恢复原键。先 unknown、后 403/409 不能证明原操作未提交，仍保留原键。确定成功后才移除记录；首次确定拒绝/冲突允许修正后新意图。
- 每个实例最多 100 个未决意图，满后拒绝新操作而不淘汰旧未知项。仅页面/当前会话内存保存，不读写 localStorage/sessionStorage，不支持跨刷新恢复；注册秘密不进入全局 Store、日志或持久化。
- 身份清理后，尚未派发的命令停止；已派发写入不能撤销，晚到结果不重新写回新会话。身份切换清理遵循 S01，不跨账号恢复。

接入：RegisterPage、WorkItemStore.create、ConversationStore.create。其他入口本轮只统一安全随机源，**尚未全部获得意图级重放**。注册收到成功结果即清空密码与旧意图、锁定已提交字段；会话刷新失败时按钮变为“继续登录”，仅继续刷新会话，不再次注册；注册不调用 Organization 结果查询。

### 2.3 创建请求与身份边界

工作项/对话创建捕获 Store 命令代次；切 Scope、reset 后的旧 catch/finally 不修改新界面的错误/忙态，同 Scope 的 A→B→A 或退出后重新进入也不能只凭字符串相等误接旧响应。

[sessionBoundary.ts](../../crewscope-web/src/app/sessionBoundary.ts) 在 account/principal/org/securityVersion 变化、会话恢复发现匿名、显式/跨标签退出时复用原域 Store 清理；同身份普通 session refresh 不清掉当前意图。这里只是内存域边界，不声称已完成 F05 的持久草稿、缓存迁移或所有页面自身异步回调隔离。
