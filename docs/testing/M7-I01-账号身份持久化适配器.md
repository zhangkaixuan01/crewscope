# M7-I01 账号身份持久化适配器

> 任务：`M7-I01`<br>
> 日期：2026-08-28<br>
> 状态：完成<br>
> 数据库基线：PostgreSQL 17、Flyway V32

## 1. 交付目标

M7-I01 将 V31 的账号与身份关系表接入正式 Application Port：

- `JdbcUserAccountRepositoryAdapter` 支持 ID、规范用户名、规范邮箱、创建、更新和行锁；
- `JdbcLoginIdentityRepositoryAdapter` 支持两类唯一坐标、Account 列表、创建、更新和行锁；
- `JdbcLocalCredentialMetadataRepositoryAdapter` 只读取或锁定不含 Hash 的元数据视图；
- `JdbcAccountOrganizationBindingRepositoryAdapter` 支持两类唯一坐标、Account 列表、创建、更新和行锁；
- `JdbcCurrentAccountSnapshotReader` 使用一条 SQL 读取当前账号的完整非秘密持久化图；
- Adapter 使用 `@Repository`、构造器注入和 Spring REQUIRED/read-only 事务，外层 `TransactionExecutor.required` 可以跨多个 Repository 整笔提交或回滚。

## 2. 规范键与冲突

Repository 的写方法只接收领域聚合，不接收 `username_normalized` 或 `email_normalized` 参数。SQL 参数从 `Username.normalizedValue()` 和 `NormalizedEmail.value()` 派生。读取 Account 时重新从展示用户名和邮箱派生规范键，并与持久化列精确比较；数据库中形状合法但不等于领域派生值的数据失败关闭。

Account 的用户名/邮箱唯一冲突、LoginIdentity 的两类唯一冲突、Binding 的两类唯一或跨 Scope 冲突分别映射为稳定领域错误。错误不包含约束名、用户名、邮箱、Provider Subject、Account、Organization 或 Principal 坐标。

## 3. 并发与事务

Account、Identity 和 Binding 更新要求传入聚合版本精确等于 `expectedVersion + 1`，SQL 同时使用 `WHERE id = ? AND version = ?`。未命中时区分不存在与实际版本，返回 Aggregate Not Found 或 Optimistic Lock Conflict。

以下锁定查询要求调用方保持外层事务：

```text
UserAccount by AccountId              FOR UPDATE
LoginIdentity by Provider/Subject     FOR UPDATE
CredentialMetadata by AccountId       FOR UPDATE
Binding by Account/Organization       FOR UPDATE
```

并发注册由 PostgreSQL 规范唯一索引裁决。两个兼容形用户名同时创建时只提交一个 Account，另一个获得无枚举信息的冲突。跨 Repository REQUIRED 事务内后续写入冲突时，之前创建的 Account 一并回滚。

## 4. 当前账号读取

`CurrentAccountSnapshotReader` 一次读取：

```text
UserAccount
  + 0..N LoginIdentity
  + 0..1 LocalCredentialMetadata
  + 0..N AccountOrganizationBinding
```

查询只连接 `local_credential_metadata` 视图，不选择 `password_hash`。连接产生的组合行按强类型 LoginIdentityId 与 BindingId 去重。Identity 受 Account/Provider 唯一约束限定，当前规模接受 Identity × Binding 的连接行，避免引入额外序列化路径。专项测试通过计数 DataSource 证明读取只准备一条 SQL，不产生 N+1。`CurrentAccountSnapshot` 还会校验所有子对象都属于同一 Account，防止错误组装跨账号事实。

## 5. 验证

专项命令：

```bash
./mvnw --batch-mode --no-transfer-progress \
  -pl crewscope-infrastructure -am \
  -Dtest=M7I01IdentityPersistenceIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

9 个 PostgreSQL Testcontainers 场景全部通过：

1. 规范用户名、IDN 邮箱、Identity、Credential Metadata 与 Binding 完整往返；
2. 当前账号两 Identity、两 Binding、一 Credential 的单 SQL 读取与去重；
3. CurrentAccountSnapshot 拒绝组装其他 Account 的子对象；
4. Account、Identity 与 Binding 乐观锁更新及陈旧版本拒绝；
5. 兼容形用户名并发注册唯一收敛；
6. Account 行锁阻断并发修改直至外层事务结束；
7. 跨 Organization Principal Binding 以安全冲突失败；
8. REQUIRED 跨 Repository 事务发生冲突时整笔回滚；
9. 非领域派生的持久化规范键在读取时失败关闭。

结果：`9 / 9`，0 Failure、0 Error、0 Skip。
