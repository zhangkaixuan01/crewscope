# M9-F10：配置体验重构验证记录

## 目标

验证九类配置面共享同一套可读、可恢复、可审计的交互基线，同时保持配置语义、权限、校验和不可变 Revision 模型不变。

## 已落地能力

- `useDirtyForm()` 统一跟踪脏态，支持路由离开、浏览器刷新和对话框关闭确认；Team Scope 切换自动保存本地草稿。
- `FormField`、`SettingsShell`、`ModelOptionPicker`、`RevisionDiffView` 提供统一表单、导航、模型选择和版本差异呈现。
- Agent 配置数值输入显示 `min`、`max`、`step` 与字段级错误文案，输入框使用至少 14px 正文，标签和辅助文案使用至少 12px。**边界来自服务端**（`AgentGenerateOptionsLimits` → `generate-agent-limits.mjs` → `src/api/generated/agent-limits.ts`，进入 `check-openapi-drift.mjs`），越界在**输入时**即有可见字段级错误，不等待提交，详见下文「③ 约束可见（2026-09-17 收口）」与 [M9 配置参数边界契约](../api/M9-配置参数边界契约.md)。
- Revision Hash 完整展示并可复制；版本差异只读、逐字段展开嵌套对象，不提供覆盖历史版本的写入口。
- 模型选择按 Provider 分组并支持键盘搜索，选项同时展示区域、归属、能力和价格。
- API Key 复用 `AuthPasswordField`，明文切换默认关闭，提交边界 `trim()`；过期时间限制为当前时刻之后。
- 模型治理页展示服务端生效事实，不再显示“API 待交付”占位卡片。
- **⑤ 配置搜索**：`SettingsShell` 的二级导航内接入 `M9-A06` 的 `GET …/configuration-search`。复用外壳已有的过滤输入框（250ms 防抖，1–100 字之外不发请求），命中项以 `RouterLink` 落到对应设置页，并把当前 Scope 的 `team` 并入服务端给出的路由；无 Team、加载中、离线、权限不足、空结果、投影不可用六种状态各有明文的 `role="status"` 行与重试入口，不使用 `StatePanel`（因此不新增空状态棘轮条目）。
- **⑨ 配置健康**：`SetupPage` 在就绪摘要之后、能力清单之前增加「配置健康 · 四项组件」一节，渲染 `M9-A06` 的 `GET …/configuration-health`：四类组件（Agent 配置 / 模型连接 / 凭证可用性 / 集成连接）各自的稳定状态、成员语言的原因说明、责任方与 `actionKey` 对应的跳转按钮。投影缺失、离线、加载中与失败四种情形给出明文说明而不是空的组件列表。
- **深链落点**：配置搜索给出的 `member=`（团队成员）、`binding=`（受管仓库）与 `taskExecution=`（工作项执行）三个参数各自被对应页面消费：命中当前已加载的列表行时滚动到该行并高亮，参数存在但列表里没有时如实说明（不假装定位成功），参数不存在时不渲染任何新增节点（既有全页快照因此不变）。

以上 ⑤⑨ 两项在 `M9-F10` 首次收口时被标记为已完成，但当时前端只有 `api/generated/openapi.ts` 的生成类型、没有任何消费代码；本轮补齐接线，并同时修正 `M9-A06` 复核发现的三处接线缺陷（`agentId→agent`、工作台深链补 `task=`、参数错误回落 `invalid_request`）。详见 [M9-A06 配置查询与配置健康验证](./M9-A06-配置查询与配置健康验证.md)。

## ③ 约束可见（2026-09-17 收口）

**对上一版文档的更正**：本文件此前写「Agent 配置数值输入显示 `min`、`max`、`step` 与字段级错误文案，输入框使用至少 14px 正文」，这句话当时**只有一部分是真的**——输入框仍继承 `13px` 正文（`--cs-text-sm`），字段级错误只在 `submitted` 之后才渲染（因此"输入时提示"并不存在），而且没有任何东西从服务端取过区间：`min`/`max`/`step` 是硬编码字面量，区间文案是散文（如「Maximum output tokens 1–10,000,000」），没有任何机制保证它与校验区间一致，`FormField.vue` 当时也零消费者。本轮把三件事都做实了。

**服务端是唯一声明。** 边界集中在领域表 `crewscope-domain/…/agent/AgentGenerateOptionsLimits.java`：每个 `Limit(field, shape, minimum, maximum, includeMinimum, step, required)` 把边界保存为**十进制文本**（`0.01` 而不是 `0.010`/`1E-2`——拼写即契约，生成器按纯文本解析）。`SafeModelGenerateOptions` 改为读这张表做归一化与拒绝（判定值未变；形如 `MAXIMUM_OUTPUT_TOKEN_CEILING`、`MAXIMUM_ATTEMPTS_CEILING` 的重复常量已删除，拒绝对话统一由表派生，删除前确认过仓库内零外部引用），因此表单属性、屏幕上印的区间、服务端接受的值是同一份记录的三种视图。`scripts/generate-agent-limits.mjs` 生成 `src/api/generated/agent-limits.ts` 并接入 `scripts/check-openapi-drift.mjs`（与状态机、OpenAPI 两个生成器并列，`--check` 不一致即 CI 失败）。

**表单侧。** `AgentConfigurationPreferencesSection.vue` 用 `v-for="field in generateOptionFields()"` 渲染四个有界字段（顺序即表的声明顺序），每个字段的 `min`/`max`/`step` 来自生成表、区间文案来自 `limitRangeText()`；`FormField.vue` 统一产出 `:id`、`aria-describedby`、`aria-invalid` 与提示/错误的可见文案，`preferenceError()` 在**每次输入**时求值，没有提交闸门。两个刻意的细节：`topP` 的下界在表里是**开区间**（0 不接受），输入的 `min` 由 `limitFloor()` 抬高一档到 `0.01`，使浏览器原生约束与字段级错误拒绝同一批值；`maximumAttempts` 标为 `required`（它的参数是基本类型 `int`，其余三个是 `Optional<...>`），清空它必须报错而不是被读成 `0` 发出去。

**同批修掉的三个真实缺陷**（都不是本轮新引入的）：

| 缺陷 | 症状 | 修法 |
|---|---|---|
| `<input type="number">` 经 `v-model` 给出的是**数字**而不是字符串（Vue 在 `el.type === 'number'` 时应用 `looseToNumber`） | 旧的 `numberOrNull(preferences.temperature)` 对数字调用 `value.trim()`，成员一旦在数值框里输入就会在保存时抛 `TypeError`；旧的 `aria-invalid` 之所以没暴露它，是因为 `submitted &&` 短路了整段校验 | 显式引入 `PreferenceNumber = string \| number`（`domains/agent/configurationTypes.ts` 的 `PreferenceForm` 字段与 `limits.ts` 的 `PreferenceValue`），读取统一走 `asText()`，面板侧 `numberOrNull`/`integerOrNull` 改为空值安全 |
| 清空 `maximumAttempts` 会被读成 `Number('') = 0` 并作为 0 发送 | 服务端以 1..10 拒绝，而前端 `validPreferences` 认为它有效 | 表里新增 `required` 标志（理由是该参数自身类型是 `int` 而不是 `Optional<...>`），并沿生成器 → `limits.ts` → 组件传播 |
| `aria-describedby` 指向一个从未渲染的 `${id}-hint` | 提示存在但辅助技术读不到（描述符悬空） | `FormField.vue` 补 `:id="`${id}-hint`"`，描述符真正可解析 |

**证据。**

- Java：`AgentGenerateOptionsLimitsTest`（6 例，全部通过）——表良构性、表驱动边界（与 `SafeModelGenerateOptions` 的接受结果逐值对账）、形状决定取值、拒绝消息同时给出字段与两个边界、空值不是越界，以及一个**反射**测试 `theTableDescribesTheParameterTheAggregateActuallyDeclares`：逐字段读 `SafeModelGenerateOptions` 的 record component 泛型类型，断言 `required` 与该参数是基本类型还是 `Optional<...>` 一致——表的字段名写错、或必需性与参数类型脱节都会失败。
- 前端：`src/domains/agent/limits.ts` 覆盖率 100%（语句/分支/函数/行）；`AgentConfigurationPreferencesSection.spec.ts` 断言的每一个 `min`/`max`/`step` 都从生成表读出（一致性测试，不是手抄常量），并覆盖「输入 3 立即出现 `aria-invalid` + 指向 `#preference-temperature-error` 的 `role="alert"`」「清空必需字段被拒」「清空可选字段回落模型默认值」「分数被整数字段拒绝」「topP 的 0 被拒」。
- 浏览器：`e2e/app-shell.spec.ts` 的 M5 配置用例断言温度 `0/2/0.01`、topP `min=0.01`、token 上界 `10000000`、attempts 上界 `10`、输入框计算字号 ≥ 14px，以及填入 `3` 后实时出现可见错误、改回 `1.2` 后错误消失。
- 门禁：`scripts/check-config-form-tokens.mjs` 的扫描面从 7 个扩到 **8 个**——此前它从未读过 `AgentConfigurationPreferencesSection.vue`，也就是成员真正输入数字的那几个字段。
- 基线：本次改动使生成选项区域变高（桌面 4169 → 4247px，窄屏 5863 → 5922px），差异从该区域顶端开始、其上方无变化；逐张人工确认后用 `--update-snapshots` 只重拍了 `agent-configuration-{desktop,narrow}-chromium-darwin.png` 两张（`shasum` 前后比对确认无第三个文件被改写），随后复跑两次均为字节稳定。

**未做/不适用**：seed 不在生成表内——服务端以 `Optional<Long>` 接收且**没有范围**，因此前端只用 JSON 数字能无损承载的安全整数界（±2^53-1）并给出对应文案，这是"诚实的边界"而不是服务端约束；WorkItem 面的可用性投影与本项无关。

## 安全边界

本任务未新增配置字段、写接口或权限；历史版本只读。草稿仅保存在当前浏览器 Scope，API Key 不写入草稿、URL、日志、Toast 或遥测。
