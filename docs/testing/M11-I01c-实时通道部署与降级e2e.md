## 1. 环境

- **栈形态**：`scripts/m11-i01c-real-stack-gate.sh` 起两套独立 Compose 栈（`CREWSCOPE_QUICKSTART_PROJECT_NAME` + `CREWSCOPE_QUICKSTART_RUNTIME_ROOT` 隔离，不触碰开发栈）：
  - 主栈 `m11-i01c`（18087）：`CREWSCOPE_COLLABORATION_REALTIME_ENABLED=true` + `HEARTBEAT_INTERVAL=1s`（1s 对 e2e/基线无害，1013 演练必需）；
  - 降级栈 `m11-i01c-degraded`（18088）：开关保持默认关闭。
- **硬件诚实声明**：team-beta 的 Alpine 基础镜像（maven/temurin alpine、redis/postgres alpine）只发布 amd64 manifest，本机为 Apple Silicon（arm64），整栈经 `DOCKER_DEFAULT_PLATFORM=linux/amd64` 以 qemu 模拟运行。**所有数字 run-to-run 内部可比，但不是原生硬件形态**，绝对值含模拟税（见 §4 第 3 条）。
- **网络形态**：单机 Docker bridge，压测客户端、Nginx、API 同宿主机。不是跨网 WAN 形态，RTT 不含真实网络抖动；连接数全部过 Nginx 的 Upgrade 路由（`map $http_upgrade $connection_upgrade`）。
- **账号**：经公开注册（OPEN）+ onboarding API 建立的 13 个真实 principal（每 principal 16 连接上限 → 13×16=208 ≥ 200）；凭证与 session cookie 存 `var/release/m11-i01c/load-principals.json`（git-ignored）。登录串行 + 2s 间隔 + 429 指数退避，避免触发登录防护的按网络限流。

## 2. 复跑指引

```bash
# 全量 gate（build → 主栈 up → 两 spec → 四压测 → slow1013 → 降级栈 spec → 双栈 reset）
sh scripts/m11-i01c-real-stack-gate.sh

# 分段（保留栈迭代时必须 KEEP_STACKS，否则 trap 在脚本退出时拆栈）
CREWSCOPE_M11I01C_KEEP_STACKS=1 CREWSCOPE_M11I01C_PHASES=up   sh scripts/m11-i01c-real-stack-gate.sh
CREWSCOPE_M11I01C_KEEP_STACKS=1 CREWSCOPE_M11I01C_PHASES=specs sh scripts/m11-i01c-real-stack-gate.sh

# 单场景压测（对已运行的主栈）
node scripts/m11-i01c/load-product-ws.mjs --scenario storm   --base-url http://127.0.0.1:18087
node scripts/m11-i01c/load-product-ws.mjs --scenario steady  --duration 120 --base-url http://127.0.0.1:18087
node scripts/m11-i01c/load-product-ws.mjs --scenario leak    --base-url http://127.0.0.1:18087
```

约束：`build` 相位在 api 镜像内跑 Maven，勿与其他 Maven 会话并发；`slow1013` 场景需要 1s 心跳（主栈默认形态即带）；`degraded` 相位自带 reset。压测脚本依赖 `--redis-container`/`--api-container`（默认对准 `m11-i01c-*`）。

## 4. 解释与诚实声明

1. **1013 在真实链路同样不触发**。S01b 结论是 Reactor Netty 的 WebSocket send 路径不把 channel writability 传导为 sink 消费停滞（`CollaborationOutboundChannel` 类注释即该结论）；本轮在真实形态（过 Nginx + 客户端真停读 socket + 3s 盲 pong 防 idle 断开 + 1s 心跳压缩周期）复现同一结论：420s 观察窗内出站预算未触发，被 inbound-idle 之外唯一的真实防线兜住的是「客户端假活」而非「慢读」。出站预算（256 帧）的实际触发面是握手期 FAIL_ZERO_SUBSCRIBER 积压与未来 A01 fanout 突发，这两条路径已有各自断言覆盖。慢客户端的现实防线组合=inbound-idle（30s）+ 未来频率限制，与 ADR-032 的边界设计一致。
2. **leak 的「最终归零」窗口由 lossy-presence 契约决定**，不是 teardown 即时性：断连清理与在途心跳刷新存在竞态——迟到的 refresh 可把 ZSET member 以新 45s score 写回，清扫器（60s 周期）在 score 过期后才清除，所以裸键最长合法残留 ≈ TTL + 清扫周期。读路径不受影响（`listPresent` 惰性清理过期 score）。观察窗因此取 180s（首轮 90s 实测偶见 2 个残留键，手动查询确认最终归零后放宽并注释）。
3. **绝对值含 qemu 模拟税与反代税**，与 S01b 对照的量级差异来自三层：①过 Nginx 反代 + 四服务 Docker bridge（非 loopback 直连）；②amd64-on-arm64 模拟；③稳态探针不同——产品协议无客户端 ping，稳态延迟用幂等 re-subscribe 往返（每往返真实重跑订阅授权），天然重于纯 ping/pong。验收点是零失败、无积压、隔离成立与资源有界，不是与 loopback 比绝对延迟。
4. **单节点软预算 200 下的数字**。硬上限 500、每 principal 16、每连接 32 订阅的合同见运维手册「实时协作通道」小节；本文档不外推多实例形态（跨节点归 I03 边界外）。
5. 压测账号为一次性 gate 栈账号，与 e2e spec 走同一公开注册面；无任何真实凭据参与。

## 5. 降级栈验证（18088）

开关保持默认关闭的同一套镜像，两 test 全绿（2 passed，2026-10-10）：

- **WS 显式失败**（74ms）：开关关闭时 `/api/v1/collaboration/ws` 无 handler，浏览器 WebSocket 握手收到非 101 应答——`opened=false`、零协议帧、`onclose(1006)`，连接不进入半开挂起。
- **SSE 降级可用**（615ms）：同一会话 `EventSource` 打开 Team Activity SSE 流（`proxy_buffering off` / `read_timeout 3600s` 未动），经 REST 创建 WorkProject + WorkItem 后，流上收到 `WORK_ITEM_CREATED` 帧（命名事件），`subject.id` 与 REST 返回的 workItemId 一致——权威更新与恢复继续走 SSE，这是 ADR-032 定义的降级形态而非故障。
- **实现注意**（首跑失败的根因）：该 SSE 流的每一帧都以活动事件类型命名（`event: WORK_ITEM_CREATED`、心跳帧 `event: heartbeat`），原生 EventSource 只把**无名帧**交给 `onmessage`——消费方必须按事件名 `addEventListener`。spec 首版用 `onmessage` 等不到任何帧，改为命名监听后通过；产品前端自有的 text/event-stream 解析器不受影响（自逐帧解析）。
