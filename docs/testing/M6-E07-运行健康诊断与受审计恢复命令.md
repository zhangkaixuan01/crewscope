# M6-E07 运行健康诊断与受审计恢复命令

> 任务：`M6-E07`<br>
> 日期：2026-08-26<br>
> 状态：完成<br>
> 前置契约：M6-E01 至 M6-E06、ADR-020、ADR-023

## 1. 交付目标

M6-E07 为 Projection、Outbox、Dead Letter、Cursor 和 Notification 建立统一应用边界：

- 活跃 Team 成员可读取不含资源身份的五组件健康摘要；
- Organization 管理员可读取 Projection、Generation、Rebuild 和可恢复目标的安全诊断；
- Outbox Dead Letter、Projection Dead Letter 和 Notification 最终失败使用闭集恢复目标；
- 恢复命令携带精确目标版本、强确认、Command ID 和语义 SHA-256 指纹；
- Adapter 必须原子提交恢复调度、Command Receipt、安全 DomainEvent 和 Audit；
- Prometheus 输入只使用固定 Component/Health 枚举，不接受租户或业务 ID 标签。

本任务交付 application 契约、派生服务、Spring 装配和配置。PostgreSQL Query Adapter 由 M6-I01 实现，Projection Supervisor 与原子恢复 Adapter 由 M6-I02 实现，HTTP API 由 M6-A06 实现。

## 2. 成员健康摘要

成员摘要固定包含以下五项且每项只出现一次：

```text
PROJECTION
OUTBOX
DEAD_LETTER
CURSOR
NOTIFICATION
```

每个组件只公开 `HEALTHY/DEGRADED/ATTENTION_REQUIRED/UNAVAILABLE`、Backlog、InFlight、Failure、Affected、最老积压秒数和 Stale。成员 DTO 不包含 Organization、Team、Projection、Generation、Event、Delivery、Connection、Worker、Lease、Cursor Token、错误文本或外部引用。

`OperationsHealthQueryPort` 返回同一事务的一致安全快照。应用服务先复验当前 Team 可见性，再查询当前 Organization；Scope 不一致、快照时间或积压时间来自未来、组件缺失或重复时失败关闭。部署配置为每个组件提供退化/需处理时间和积压阈值，配置不完整、非正数或阈值倒退时启动失败。

`OperationsMemberHealthSummary.metrics()` 只生成 `OperationsHealthComponent + OperationsHealthLevel` 两个有界标签和值。Organization、Team、Projection Name、Correlation、Event 和错误消息不能进入该指标形状；M6-I08 在 ADR-023 的 Series 预算内注册真实 Micrometer 指标。

## 3. 管理员诊断

管理员入口把 Server 从当前认证解析的完整 `TeamAccessContext` 传入应用层。`DefaultProjectionAdministration` 同时复验 ACTIVE USER、Organization Scope 与可信 `platformAdministrator` 事实，授权通过后读取同一快照。应用服务的 Command Fingerprint、DomainEvent 和 Audit 只使用 `access.actor()`，不持久化角色布尔值。额外诊断只包含：

- Projection Name、Definition Version、ACTIVE Generation 和 Pointer/Generation 强版本；
- 可选 BUILDING/VALIDATING Generation、RebuildJob 和对应强版本；
- Lag、Gap、Dead Letter Count 与 `ProjectionFailureCode`；
- 三类闭集 `OperationsRecoveryTarget` 的精确安全坐标。

诊断不返回 DomainEvent Payload、Partition Key、异常文本、通知正文、成员映射、Provider Body、Credential、Secret 或 Cursor Token。Projection Failure 继续使用最大 80 字符的 Upper Snake Case 有界码。

## 4. 恢复命令

恢复目标固定为：

| Action | 精确坐标 | 强版本 |
|---|---|---|
| `REPLAY_OUTBOX_DEAD_LETTER` | Outbox Event ID + DomainEvent ID | Outbox Version |
| `REPLAY_PROJECTION_DEAD_LETTER` | Projection + Generation + DeadLetter ID + DomainEvent ID | Generation Version |
| `RETRY_NOTIFICATION_DELIVERY` | Notification Delivery ID | Delivery Version |

每条命令要求：

1. 当前认证解析出的 ACTIVE USER、Organization Scope 和平台管理员授权；
2. 与 Action、目标身份和 Expected Version 完全绑定的强确认短语；
3. Organization 内 Command ID；
4. Organization、Actor、Action 和完整目标坐标的长度前缀 SHA-256 指纹；
5. 相同 Command ID/相同指纹返回原 Receipt，不同指纹返回幂等冲突；
6. Adapter 在锁定当前目标后比较 Expected Version，并发变化失败关闭；
7. 既有 DeadLetter、Delivery 和失败历史保持不可变，恢复产生新调度事实；
8. 恢复、Receipt、DomainEvent 和 Audit 在同一事务提交；
9. 并发使用同一 Organization + Command ID 时，Repository 通过唯一约束和事务内 Receipt 回读保证仅产生一次恢复调度；同指纹返回已提交结果，异指纹失败关闭。

传给 Repository 的 `OperationsRecoveryRequest` 不包含用户输入的确认短语、Payload、Secret、Credential、异常或外部 Body。安全结果只公开 Action、目标引用 SHA-256、`SCHEDULED` 和接受时间。

## 5. Audit Registry

M6-E06 初始 Registry 的 96 个坐标保持不变；M6-E07 新增：

```text
OUTBOX_DEAD_LETTER_REPLAY_REQUESTED@1
PROJECTION_DEAD_LETTER_REPLAY_REQUESTED@1
```

M6-E07 交付时已评审 Registry 共 98 个精确坐标。M6-A03 后续增加查询与导出自身 Audit，当前总数为 100。两类恢复 Audit 只保存 `recoveryAction/status`，Projection 恢复额外保存 `projectionName/generation`；Command、Event 和 DeadLetter 身份可以作为原始事件的受控字段参与事务闭合，但不进入低基数摘要。Notification 复用既有 `NOTIFICATION_REDELIVERY_REQUESTED@1`。

## 6. Spring 装配

`OperationsApplicationConfiguration` 始终创建已校验的 `OperationsHealthThresholds`，并强制构造器装配三个生产服务：

```text
OperationsHealthQueryPort + Authorization + Transaction + Time
  -> OperationsHealthService

OperationsRecoveryRepository + Authorization + Transaction + Time
  -> OperationsRecoveryService

ProjectionAdministrationRepository + SnapshotVerifier + Authorization + Transaction + Time
  -> ProjectionAdministrationService
```

`OperationsApplicationConfiguration` 默认装配 `DefaultProjectionAdministration`；显式测试或扩展 Bean 可以通过 `@ConditionalOnMissingBean` 覆盖它。三个生产服务继续强依赖 I01/I02 的 Repository/Query Port；缺少任一 Port 或阈值非法都使 Spring Context 启动失败。必需服务不使用依赖 Bean 注册顺序的 `@ConditionalOnBean`。
