# M11-D02 成员撤权接入新增实时通道验证

> 定位：主计划 `docs/plans/M11-协作规模化与开放生态.md` §6 D02——「已有成员撤权接入新增实时通道」：消费 M9b 成员生命周期事件，使 WebSocket 连接、订阅、在场信号立即失效。**不重建基础命令、成员表、责任转移或管理 UI**（M9b-A07 交付，全部回归不动）。通道合同冻结于 [ADR-038 §3.1](../adr/ADR-038-团队成员生命周期与责任转移.md)（三层协议）与 [M9b 契约](../api/M9b-团队成员生命周期API契约.md)「M11 实时通道撤权」小节（HTTP 边界）。
>
> 本切片只交付**事件层**（快路径）；复验层（A01 已交付：≤5s 缓存 + 心跳强制刷新 + fail-closed）与 TTL 层（在场键 45s、连接 30s 无入站断开）已在线，三层共同满足验收「停用/移除/降权后旧 WebSocket 断开、在场清理，旧游标与重连不能恢复权限」。

## 1. 实现链（事件层）

```text
Outbox 事件（TEAM_MEMBER_SUSPENDED/REMOVED/LEFT/MEMBER_ROLE_REVOKED）
  → CollaborationMemberRevocationConsumer（crewscope-infrastructure，
     "collaboration-member-revocation-v1"，@Order(LOWEST_PRECEDENCE-100)，
     @Transactional(MANDATORY)，malformed 与 sink 抛错均 warn 不抛——receipt 事务内永不连坐）
  → CollaborationMemberRevocationSink（application 端口；CollaborationSignalFanout 实现）
  → CollaborationRevocationIndex（subscribe ALLOWED 时以鉴权链解析的成员 Principal 记录
     (userPrincipalId, 组织, Team) → connectionId 纯内存反查表，双向 map）
  → 逐连接：revalidator.invalidate(principalKey) + revoke(4403)（A01 幂等链复用：
     revoked CAS → metrics.recordClosedRevoked → close(4403) → removeAll 订阅
     → leave delta → index.forget → presence.removeConnection）
```

开关同 `crewscope.collaboration-realtime.enabled`：关闭时无 consumer 无 sink，零 receipt 足迹。单实例注册表与消费者同进程直连（ADR-038 §3.1 末段，多实例演进按 §6 重新评估）。

## 3. 集成场景断言（验收条目对照）

四条连接：alice 双标签 + alice 另一 Team 观察位 + bob 观察席（fixture 临时授权），全部订阅 Team scope 后以**真实形状信封**（`TEAM_MEMBER_SUSPENDED`，root 含 eventType/organizationId/teamId/aggregate*/payload{memberId, userPrincipalId, authorizationVersionAfter}）驱动真实 consumer 实例：

| 验收条目 | 断言 |
| --- | --- |
| 旧 WebSocket 断开 | 被扫成员该 Team 两个标签连接均收 close 4403（10s 内） |
| 在场数据清理 | 被扫 scope 的 zset 两条 score 归 null、两连接键消失；幸存者（bob、另一 Team）条目仍在 |
| 同 Team 幸存者走同一清理路径 | bob 依序读到两条 leave delta（principalId=被扫成员），`connections` 恰为 {1, 0}（多标签合并计数递减） |
| 其他 Team 不误伤 | alice 另一 Team 连接静默（500ms 无非 ping 帧）且重订阅成功——索引键含组织+Team，扫断只命中该 Team 订阅 |
| 旧游标/重连不能恢复权限 | 断开即订阅全拆；重连语义由前端用例锁定（完整重新握手 + 逐订阅重授权，旧句柄不复活）；被撤成员重订阅收到 `forbidden_scope` 为 A01 既有行为 |
| at-least-once 重投 | 同一事件重复消费：零新帧、幸存者不受扰（幂等） |
| 无旁路授权 | 通道关闭时零 consumer/sink/receipt（既有 Disabled 模式覆盖） |

真实命令全链（suspendMember → Outbox 轮询 → 断开）归 Q01/Q02 真实栈演练，本文档不虚报覆盖。

## 4. 设计裁决记录

1. **principalId 索引 vs principalKey 映射**：连接注册表按 `principalKey`（`account:<id>`）索引，事件载荷给 `userPrincipalId`（domain Principal UUID），两者无推导关系（account→principal 是运行期解析）。选择**subscribe 入场时记录**（鉴权链已解析的 `TeamAccessContext.actor`，authorizer 接口以 `admit` 携带 Principal 带出），而非撤权时反查成员表——后者把通道耦合进库读与表结构。代价：无订阅的连接不进索引，见下条。
2. **空订阅连接的语义**：「断开该成员在该 Team 的全部连接」实现为**断开持有该 Team 任意 scope 订阅的连接**（三种粒度都带 org+team 坐标）。无订阅连接无 Team 归属、收不到任何数据帧，由 subscribe 时真实鉴权拒绝兜底；30s 无入站心跳的自然回收兜底剩余窗口。
3. **四类断开事件集**：`SUSPENDED/REMOVED/LEFT/MEMBER_ROLE_REVOKED`（降权=角色撤销路径）；`ACTIVATED/GRANTED` 只增权限不断开；**`TEAM_OWNERSHIP_TRANSFERRED` 不触发**——让出方仍是 ACTIVE 成员，订阅授权按资源可见性裁决、与 OWNER 角色无关，断开无安全增益只添闪断（且该事件载荷无 `userPrincipalId`，纳入需反查成员表）。
4. **复验缓存失效口**：事件到达时按被断连接的 principalKey 逐个 `invalidate`（防御在途帧交付）。in-flight probe 的 stale-positive 回写竞态无害：连接已断、缓存条目无主，新订阅走真实鉴权不经缓存。
5. **无持久化投递坐标**：不为通道撤卷新增任何持久化状态——权威事实已耐久（`team_member.authorization_version` + Outbox 事件），通道状态可丢弃可重建，复验层漏事件在下一帧自愈（最坏 5s + 一个心跳）。论证全文见 ADR-038 §3.1 裁定段。

## 5. 测试坑记录（复跑者必读）

- **复验缓存 DENIED 跨场景渗漏**：复验层缓存是 Spring 单例、跨测试场景存活（TTL=类属性 `revalidation-interval`）。前一撤权场景写入的 DENIED 判定渗进下一场景时，新订阅者的 enter delta 触发 `deliver()` 查到「新鲜 DENIED」→ 链式 4403 团灭，ack 被 close 抢跑、表现为「订阅后零帧（连 ping 都没有）」。**单独跑用例永远绿、类内必挂**——修法：场景内先等两个心跳 ping（> TTL）让陈旧 DENIED 过期，再继续多订阅者编排。
- **集成用例顺序**：JUnit 方法顺序默认确定性（MethodOrderer 缺省），但场景间通过**单例缓存/静态 fixture 表**交互时仍按「前场景残留」写防御等待，不依赖顺序巧合。
- **帧时间线取证优于推理**：疑似「零帧」时先换 `awaitCloseCode` 打印关闭码——本轮一次取证即定位 4403 团灭根因，快于任何静态分析。
