# M9-E01 前端工程化与组件拆分验证

## 交付范围

- 接入 ESLint 9、`eslint-plugin-vue`、`@typescript-eslint` 与 Stylelint 16。
- `crewscope-web/package.json` 增加 `lint:eslint`、`lint:style` 与统一 `check:quality` 门禁。
- 将 `WorkPage.vue` 的新建 WorkItem 表单提取为 `WorkItemCreateDialog.vue`，容器页面只负责生成项目内 Key、调用 Store 和处理路由/业务结果。
- 对话框负责表单状态、字段校验、输入清洗、键盘焦点陷阱、Esc 关闭与提交事件，保持原有服务端接口和错误边界。
- 将 `ConversationPage.vue` 的新建对话弹层提取为 `ConversationCreateDialog.vue`，组件自持有表单状态、可见范围、焦点陷阱和键盘关闭行为；页面继续负责 Conversation Store、错误边界和成功后的路由跳转。
- 将 `AgentConfigurationPanel.vue` 的 Revision 历史拆为 `AgentConfigurationHistoryPanel.vue`（历史列表与分页）和 `AgentConfigurationRevisionView.vue`（只读详情、Hash 复制、Revision 对比）；容器继续负责历史加载、版本选择、Clipboard 与脏态/保存协调。
- 将 Agent Configuration 的模型绑定区提取为 `AgentConfigurationModelBindingSection.vue`，组件通过本地副本和显式 `updateBindings` 事件回传，避免子组件直接修改父级响应式状态。
- 将 Agent Configuration 的 Template 偏好槽位提取为 `AgentConfigurationPreferencesSection.vue`，数值校验、Skill 切换和策略引用展示由展示组件承载，容器只同步偏好状态并组装提交载荷。
- 将 `TaskDetailDrawer.vue` 的 Attempt 历史和执行事实选择拆为 `TaskAttemptHistoryPanel.vue`，并将 `ConversationPage.vue` 的参与者列表拆为 `ConversationParticipantsPanel.vue`；两个组件只接收公开投影和回调，不直接持有领域 Store。
- 将 `TaskDetailDrawer.vue` 的 Plan、Step、Agent Run、Lease 与恢复事实展示拆为 `TaskRuntimeFactsPanel.vue`，组件内部只管理当前 Plan Revision 选择，重试与事实加载仍由抽屉容器协调。
- 将 `WorkPage.vue` 的工作项列表/看板展示拆为 `WorkItemsWorkspace.vue`，页面继续负责筛选路由、拖拽状态、权限校验与 Store 调用。
- 将 `WorkPage.vue` 的筛选工具栏拆为 `WorkItemsToolbar.vue`，组件只负责筛选/视图切换和新建入口，路由更新仍由页面编排。
- 将 `AgentConfigurationPanel.vue` 的生命周期操作拆为 `AgentConfigurationLifecycleSection.vue`，组件只负责展示生命周期边界与确认动作，状态转换仍由容器调用 Store。
- 将 Task/Coding Store 的键生成、分页合并、缓存存储、Abort/错误归一化与 SHA-256 完整性校验抽到 `domains/task/storeUtils.ts` 和 `domains/coding/storeUtils.ts`，保留原 Store 的公开导出兼容性。

## 附：本次会话中发现并处理的前端质量问题

- **`e2e/m6-activity.spec.ts` 定位符冲突**：活动证据链接断言原先用英文正则 `/WorkItem/` 匹配，与实际渲染的中文文案「工作项」不符，改为 `/工作项/` 后在桌面视口仍会误中全局侧边导航里同样标注「工作项」的常驻链接（窄视口因导航栏收起而侥幸通过）。修复为把定位符限定在 `团队活动列表` 列表容器内。这类「标签命中多个候选、仅部分视口暴露」的定位符冲突在其余 E2E 用例中未系统性排查，建议后续新增用例时默认按语义容器限定范围，而不是依赖 `.first()`。
- **`TaskRuntimeFactsPanel.vue` 拆分后窄屏卡片重排失效**：`TaskDetailDrawer.vue` 的 767px 断点靠 `.task-detail-column { display: contents }` 把卡片"提升"成 `.task-detail-columns` 的直接网格子项，再用 `order` 重排；但 Vue scoped CSS 只会给子组件的**根节点**打父组件的 scope 属性，`.plan-card`/`.steps-card`/`.runs-card`/`.lease-card` 拆到 `TaskRuntimeFactsPanel.vue` 后已经不是它的根节点（根节点是 `.task-runtime-panel`），父组件里写的 `order` 规则从拆分那一刻起就选不中任何元素——`TaskAttemptHistoryPanel.vue` 没有这个问题，因为它整个组件的根节点恰好就是 `.attempt-card`。这类问题在拆分评审时容易被漏掉，因为它不报错、不报警告，只在窄屏视觉/顺序上出偏差；`e2e/app-shell.spec.ts` 的"Task detail switches attempts..."用例在窄屏项目下的失败就是这个根因暴露出来的。修复：把 `display: contents` 和对应 `order` 规则移到 `TaskRuntimeFactsPanel.vue` 自己的 scoped 样式里，父组件里已失效的四条 `order` 规则同步删除。**结论：拆出去的组件如果有多个非根节点需要参与祖先组件的 `display:contents` 重排，排序规则必须写在子组件自己的样式里，不能留在父组件。**
- **`e2e/m9-theme-density.spec.ts` 测试范围 bug**："restores the sidebar collapse preference after a reload" 在窄屏项目下超时——它等待的"折叠侧栏"按钮位于 `.app-shell__rail` 内，而 `AppShell.vue` 767px 以下把整个 rail `display: none`（移动端由抽屉导航替代），窄屏项目跑在 390px，按钮根本不存在。修复为 `test.skip((viewport?.width ?? 0) <= 767, ...)`，与 `e2e/m9-mobile-reach.spec.ts` 里"仅约束 ≤767px"的反向写法保持同一套约定。
- **3 张过期视觉快照**："AppShell visual baseline"（窄屏）与"M5 Agent Center visual baseline"（桌面+窄屏）在 `AgentConfigurationPanel.vue` 拆成 5 个子组件后没有跟着重拍（Agent Center 窄屏截图高度从 5435px 变为 5863px）。确认实际渲染截图本身正常、无视觉缺陷后，用 `--update-snapshots` 重新录制。
