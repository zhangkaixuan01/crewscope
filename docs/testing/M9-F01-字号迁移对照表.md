# M9-F01：字号迁移对照表

> 状态：已完成（全站排版已挂 Token，`scripts/check-design-tokens.mjs` 已按全站口径守住）

这份文档记录 M9-F01 把全站硬编码排版值迁到 Design System v2 七档阶梯的**完整对照关系**，以便任何一处视觉争议都能回溯到「原来是几 px、为什么落到这一档」。迁移脚本是一次性的，对照表是长期事实。

## 1. 为什么不能用「就近取整」

第一版迁移按最近档取整（并列时向上取），结果是对的又是错的：

- **对**：885 处 `font-size` 里有 733 处在 7–11px，阶梯下限是 12px，这些必须抬上来，可读性债务必须偿还；
- **错**：7/8/9/10/11/12px 这**六**档全部落到同一个 12px 下限。对迁移前的源码实测：用到小字号的 71 个文件里有 60 个用了两档以上、36 个用了四档以上；就近取整丢掉了 179 处文件内的字号区分，并让 60 个文件的小字号层级彻底压平。

用压平层级的方式修可读性，只是把一个体验缺陷换成另一个。所以 12px 以下的区间按**三层**映射，层界由穷举全部**单调**映射（旧值的相对顺序必须存活）并在「任何字号都不得被抬过下一个可读档位」的硬上限内取最优得到：

| 方案 | 丢失的文件内字号区分 | 小字号被完全压平的文件 | 累计字号放大 |
| --- | --- | --- | --- |
| 就近取整（第一版） | 179 | 60 | 2238px |
| 二层 7-9 / 10-12 | 136 | 4 | 2532px |
| **三层 7-9 / 10-11 / 12-14（采用）** | **110** | **1** | **2587px** |
| 三层 7-8 / 9-10 / 11-13 | 117 | 5 | 2876px |

采用方案比就近取整多付 16% 的字号放大，换回 69 处层级区分和 59 个文件的小字号层级。

## 3. 字重：四档塌成三档

| 原始值 | 目标 Token | 出现次数 |
| --- | --- | --- |
| 450 | `--cs-weight-regular`（400） | 1 |
| 500 / 560 / 580 | `--cs-weight-medium`（500） | 19 / 1 / 1 |
| 600 / 650 / 680 | `--cs-weight-semibold`（600） | 5 / 2 / 4 |
| 700 / 720 / 740 / 750 / 760 / 780 | `--cs-weight-semibold` | 50 / 8 / 3 / 97 / 2 / 1 |
| 800 / 850 | `--cs-weight-semibold` | 39 / 3 |

合计 236 处：`regular` 1、`medium` 21、`semibold` 214。**700 及以上一律降到 600**。原实现里 750 出现 97 次、800 出现 39 次——那是在用「更粗」补偿「太小」，下限抬到 12px 之后这个补偿不再需要，而且 Inter 在 750/800 档并没有真正的字面，浏览器是合成加粗，边缘发毛。

## 4. 行高：按字号对应改成按阅读距离分档

| 原始值 | 目标 Token | 出现次数 |
| --- | --- | --- |
| 1.18 / 1.2 / 1.3 / 1.32 / 1.35 | `--cs-leading-tight`（1.3） | 2 / 2 / 1 / 1 / 2 |
| 1.4 / 1.45 / 1.5 / 1.55 / 1.6 | `--cs-leading-normal`（1.5） | 3 / 20 / 21 / 14 / 6 |
| 1.65 / 1.7 / 1.75 | `--cs-leading-relaxed`（1.7） | 2 / 1 / 1 |

合计 76 处：`tight` 8、`normal` 64、`relaxed` 4。`line-height: 1` 与 `0` 不在迁移范围——它们是给图标撑盒子用的，不是阅读节奏。

## 5. 可输入控件的下限

七档映射之后再跑一遍控件下限：选择器命中 `input` / `textarea` / `select` / `__input` / `-input` / `[type=…]` 的规则，字号一律抬到至少 `--cs-text-base`（14px），共 **28 处**。

理由是 §10.3.1 里唯一「机械映射结果不够好」的位置：成员要往里打字的控件不能跟着周围密度缩小，而 iOS Safari 在输入框字号小于 16px 时会自动缩放整页。窄屏 Composer 另有 `--cs-text-md`（16px）的要求，见规范 §7.1。

## 6. 声明口径与例外

| 类别 | 数量 |
| --- | --- |
| `font-size` 声明 | 817 |
| `font` 简写（含字重/行高的复合声明） | 68 |
| `font-weight` 声明 | 230 |
| `line-height` 声明 | 66 |
| 可输入控件下限抬升 | 28 |
| 保留原样 | 6 |
| **合计** | **1215** |

保留原样的 6 处是 5 处 `font: inherit`（把排版交还给容器，本身不含取值）与 1 处 `.9em`。后者是 `SafeMarkdown` 的行内代码，`.9em` 在 12px 下解析成 10.8px——正好跌破本次要建立的下限，因此改为只换字族（`font-family: var(--cs-font-mono)`）、字号继承正文。等宽字在同等 px 下本来就比无衬线看起来小，不需要再缩。

两处流体标题登记在 [`docs/quality/M9-字号白名单.json`](../quality/M9-字号白名单.json)：未登录态的 `AuthBrandPanel` 品牌标题与 `AuthCard` 登录卡标题用 `clamp()` 随视口连续放大，离散阶梯表达不了，下界锚定在阶梯顶部两档。门禁按**登记的声明原文**比对，改了取值就会失败；登记项对应的声明如果已不存在，门禁同样失败——白名单只能变短。

`src/spikes/` 不在迁移与门禁范围内：那是 M4/M7 的实验夹具，是「当时试过什么」的记录，不是交付面。

## 7. 门禁

`scripts/check-design-tokens.mjs` 迁移后分两个口径：

- **全站口径（113 个文件）**：`src/**/*.{vue,css}`（排除 `generated/`、`spikes/`、`*.story.vue`）禁止裸 `font-size`、禁止 `font` 简写里的裸长度、禁止数值字重、禁止数值行高。**没有计数基线**——存量已清零，任何新增直接失败。
  - 第一版门禁只查 `font-size:`，漏掉 `font:` 简写里的字号；这次补上，实测当场抓出 1 处。
- **基础件口径（24 个文件）**：`components/base/**` 与三个反馈单例、`design/base.css` 额外校验动效 Token 与四档断点。

间距与层级的全站化在同一批次里由 M9-F01b 完成，逐值对照见 [`M9-F01b-间距与层级迁移对照表.md`](M9-F01b-间距与层级迁移对照表.md)；断点仍留在基础件口径，因为 23 种 `max-width` 取值收敛到四档是**行为变更**（把 480px 的规则搬到 640px，意味着它在更宽的屏上就开始生效），需要显式映射表而不是机械改写。

```bash
node scripts/check-design-tokens.mjs
cd crewscope-web && pnpm lint:style && pnpm vue-tsc --noEmit && pnpm vitest run
```

迁移后验证：stylelint 无告警、`vue-tsc --noEmit` 无错误、136 个测试文件 / 737 个用例全绿、Design Token 门禁 PASS。
