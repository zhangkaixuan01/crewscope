# M0-F01：前端工程基线

> 日期：2026-08-07<br>
> 状态：已完成<br>
> 工程：`crewscope-web`

## 目标

建立 CrewScope 可持续演进的 Vue 前端基线，使对话式执行与传统管理从同一个 AppShell 进入，共享 Team、Focus 和对象上下文，并为后续 Team、WorkItem、Conversation、Task 和 Review 纵向能力提供稳定的设计、路由、请求、错误与测试边界。

## 产品边界

M0 页面是产品骨架，页面内显式标记演示数据。真实 Team/WorkItem 闭环在 M1 接入，真实 Conversation/Personal Agent 闭环在 M2 接入。

当前交付两个入口：

- Conversation：成员消息、Personal Agent 协作、任务意图、执行计划、Agent Presence、Responsibility Chain 和 Review Gate 骨架；
- Control：Team Pulse、工作列表、状态、Owner/Executor、责任链与团队动态骨架。

两个入口使用相同 `focus`、`team` Query，切换模式不会丢失当前对象。页面不把 AG-UI 增量状态当成最终业务事实。

## 设计系统

`src/design` 固化颜色、字体、间距、圆角、阴影、Focus 和 Reduced Motion Token。视觉语言采用暖灰 Canvas、浅薄荷导航与摘要面、深绿小面积品牌强调、紫色 Agent、橙色 Review 和红色风险。

基础组件包括：

- `BaseButton`：主、次、弱、危险、Loading 和 Disabled；
- `StatusBadge`：文字、色彩和状态点共同表达语义；
- `StatePanel`：Loading、Empty、Error、Forbidden 和 Conflict；
- `ResponsibilityChain`：Owner、Executor 和 Reviewer 完整责任链；
- `AgentPresence`：Agent 类型、运行状态、当前步骤、Runtime 和接管入口；
- `GlobalErrorBanner`：不暴露内部异常信息的全局错误边界。

Histoire 提供 3 组 Story、9 个 Variant，覆盖 Token、基础组件、CrewScope 领域组件、基础页面状态和长内容。

## 工程边界

### Router

```text
/             -> /conversation
/conversation -> Conversation Mode
/control      -> Control Mode
/*            -> Not Found
```

页面级组件使用懒加载。AppShell 的桌面模式切换与移动端底部模式切换都保留当前 Query。

### API Client

`CrewScopeApiClient` 统一处理：

- `Accept: application/json` 与 JSON 请求体；
- `Idempotency-Key`；
- 强 ETag 对应的 `If-Match: "<version>"`；
- 204 空响应；
- 服务端错误信封；
- 非 JSON 服务错误与网络错误的安全降级；
- Abort 请求继续交给调用方处理。

`idempotencyKey` 和 `expectedVersion` 是 Client 内部命令选项，只用于生成标准 HTTP Header，调用 `fetch` 前会从 `RequestInit` 中剥离。

错误信息不展示代理响应体、异常消息、凭证或内部堆栈。

### 认证占位

`installAuthPlaceholder` 提供显式 M0 Principal 注入边界。页面只把它用于身份展示与权限占位，后续由 OIDC 替换。服务端授权继续作为安全边界。

## 响应式与独立性

- 1440px 展示导航、工作区和责任上下文；
- 桌面侧栏将品牌与 Scope 固定在顶部、账号入口固定在底部，中间导航在较矮视口独立滚动；
- 中等宽度折叠主导航，Conversation 上下文降到下一行；
- 390px 使用单列内容和固定模式切换，工作表格降级为工作卡片；
- 页面不设置阻断访问的全局最小工作区宽度；
- Focus Ring、语义区域、ARIA 状态、Live Region 和 Reduced Motion 已进入组件基线。

交互关系吸收研发工作台的对话/执行联动和管理控制面的多视图思路。信息架构、路由、Token、组件、品牌资产、布局与文案均在 CrewScope 内独立实现，页面主轴是责任、执行、决策和证据。

## 自动化验证

验证环境：Node.js 24、pnpm 11、Chrome Stable。

```bash
pnpm test
pnpm build
pnpm story:build
pnpm test:e2e:update
pnpm test:e2e
```

结果：

- Vitest：4 个测试文件，11 个测试通过；
- Coverage Gate：Statements 80%、Branches 70%、Functions 75%、Lines 80%；
- TypeScript 与 Vite：生产构建通过，路由页面形成独立 Chunk；
- Histoire：3 个 Story、9 个 Variant 构建通过；
- Playwright：桌面 1440×960 与窄屏 390×844 共 4 个测试通过；
- 视觉基线：Conversation/Control 各保存桌面和窄屏截图；
- Query 场景：`focus=CRW-18&team=platform` 在双入口切换后保持不变。

本机复用已安装 Chrome。CI 使用 `pnpm exec playwright install chromium` 安装固定 Playwright Chromium 后执行相同测试。
