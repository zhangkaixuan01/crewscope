# M8-I01：依赖与配置治理

> 任务：`M8-I01`
>
> 状态：已完成（本地实现，待主分支 CI 复核）
>
> 范围：Maven 直接依赖、AgentScope 运行时、Spring 配置元数据、Compose 与环境/Secret 合同

## 1. 交付结论

CrewScope 现在对依赖和部署配置使用可审计的合同：

- 默认 `crewscope-agentscope` 不携带 Kubernetes Sandbox/Fabric8 扩展。需要 Kubernetes 时通过独立适配模块或显式 Profile 引入，默认 Backend Jar 保持最小运行时边界；
- AgentScope、Integration、Infrastructure 和 Server 对直接使用的 Domain 类型已显式声明 `crewscope-domain`，避免通过 Application 的传递依赖隐藏模块边界；
- Infrastructure 和 Server 声明可选 `spring-boot-configuration-processor`。编译后分别生成 `META-INF/spring-configuration-metadata.json`，IDE 可以补全 `crewscope.*` 属性；
- Maven `dependency:analyze` 作为 Backend 门禁执行。当前框架 Starter、AgentScope BOM 和测试夹具产生的既有诊断写入 `config/maven-dependency-analyze.allowlist`，脚本会阻断任何未审阅的新坐标；
- `.env.example`、生产 Compose、Secret README 和 Compose 引用由 `scripts/check-config-contract.mjs` 交叉校验；
- 本地 `compose.yaml` 的 PostgreSQL/Redis 只绑定 `127.0.0.1`。生产 Compose 不发布 PostgreSQL/Redis，Web 也只绑定宿主机环回地址；
- Team Beta 生产镜像继续要求 `@sha256:<digest>`，Secret 继续通过 configtree/file-backed Compose Secret 注入，不进入普通环境变量。

## 2. 依赖治理规则

运行：

```bash
./mvnw --batch-mode --no-transfer-progress \
  -DskipTests dependency:analyze -DfailOnWarning=false 2>&1 | tee dependency-analyze.log
node scripts/check-maven-dependency-report.mjs dependency-analyze.log
```

`dependency:analyze` 的三类结果按 `used`、`unused`、`non` 和 `groupId:artifactId` 记录。白名单只接受已经检查过的坐标，不忽略版本、类型或范围之外的新依赖。新增生产代码依赖时优先在对应模块 POM 中声明直接依赖；确认属于 Starter 提供的实现类、配置处理器、运行时驱动或测试夹具时，才在同一变更中补充白名单并写明原因。

AgentScope Kubernetes 扩展是显式排除项。`scripts/check-dependency-contract.mjs` 和本合同共同保证默认 POM 不重新引入它。

## 3. 配置合同规则

```bash
node scripts/check-config-contract.mjs
```

脚本以临时占位 Secret 渲染生产 Compose，不启动容器、不读取真实凭证，检查：

1. 生产 Compose 中无默认值的 `CREWSCOPE_*` 变量都出现在 `deploy/team-beta/.env.example`；Demo 专用变量必须有安全默认值或出现在根模板；
2. Compose Secret 名称与 `deploy/team-beta/secrets.example/README.md` 双向一致；备份口令保持 Operator-only，不挂载给应用；
3. 本地 PostgreSQL/Redis 的发布地址是 Loopback；生产 PostgreSQL/Redis 无宿主端口，Web 仅发布 Loopback；
4. 生产服务镜像全部是不可变 Digest；
5. Infrastructure/Server POM 保留 Configuration Processor，已生成元数据时 JSON 结构和 `crewscope.*` 分组有效。

生产恢复 Schema 坐标由 `common.sh`、恢复脚本和 Recovery Contract 共同冻结为 V26–V36；变更迁移版本时必须同步更新恢复边界、Runbook、固定夹具和对应 Release Contract，不能只修改环境模板。

## 4. CI 接入

- `quality` Job 执行 `check-config-contract.mjs`，因此环境/Secret/端口漂移会在 PR 反馈；
- `backend` Job 在编译和元数据检查后执行 Maven 依赖分析，并上传 `dependency-analyze.log`；
- 依赖分析仍使用 `failOnWarning=false`，由白名单脚本负责失败关闭。这样既保留 Maven 原始诊断，又不会把 Starter 传递实现误判为工程缺陷。
