# M7-A06 认证路由与浏览器安全边界

> 日期：2026-08-29<br>
> 结论：通过<br>
> 下一任务：`M7-A07`

## 1. 交付范围

M7-A06 将认证 Controller 之前的浏览器安全行为收敛到应用 `SecurityWebFilterChain`：

- 公开 SPA 入口和认证 Bootstrap API 可匿名访问；
- 业务 API 的 401、403、CSRF、跨源和请求体超限使用统一安全错误信封；
- 业务入口不返回 `WWW-Authenticate: Basic`，Prometheus 机器入口继续使用独立 Basic Chain；
- Local 与 OIDC Session 模式使用同一 Cookie/Header CSRF 协议；
- 浏览器 API 只允许同源 Origin，不提供 Credentialed CORS；
- 认证请求按路由在 DTO 聚合前执行字节预算；
- 应用响应带固定 CSP、Frame、Content-Type、Referrer、Permissions、COOP、CORP 和 HTTPS HSTS 头。

本任务只冻结服务端路由与协议。`/login`、`/register` 和 `/invite` 的实际页面由 M7-F01 至 M7-F03 实现，生产静态文件仍由 Web/Nginx 入口提供。

## 2. 路由矩阵

| 路由 | 匿名 | 已认证 | 浏览器协议 |
|---|---|---|---|
| `GET /`、`/index.html`、`/login`、`/register`、`/invite`、`/assets/**` | 允许 | 允许 | HTML/静态入口不进入认证挑战 |
| `GET /api/v1/auth/session` | 允许 | 允许 | `no-store`，返回 CSRF 坐标 |
| `POST /api/v1/auth/register`、`/login`、`/invitations/preview` | 允许进入 Controller | 允许 | Local/OIDC 模式仍要求 CSRF |
| 其他业务 API | `401 authentication_required` | 按资源权限执行 | JSON 与 HTML Accept 都返回 JSON，不重定向、不发 Basic Challenge |
| 已登录但权限不足 | 不适用 | `403 access_denied` | 统一 JSON 与 `no-store` |
| `/actuator/prometheus` | 独立 Basic Challenge | 仅 `ROLE_MONITORING` | 无业务 Session、无 Operator 凭证复用 |

未知账号、持久 `LOCKED`、`DISABLED`、临时锁定和错误密码继续由登录应用服务执行一次真实或 Dummy Match，并统一映射为 `401 invalid_credentials`。M7-A06 增加 `LOCKED/DISABLED` 专项回归，证明两种状态都不产生状态识别响应。

## 3. 安全错误信封

`ApiSecurityResponseWriter` 负责 Spring Security 在 Controller 之前产生的响应：

```json
{
  "code": "authentication_required",
  "message": "Authentication is required",
  "correlationId": "8a5dff65-5377-4a27-bb63-3cf892819f8d",
  "retryable": false,
  "currentVersion": null,
  "details": {}
}
```

固定映射：

| 状态 | Code | 触发边界 |
|---|---|---|
| 401 | `authentication_required` | 匿名业务 API、错误 Bootstrap Basic |
| 403 | `access_denied` | 已认证但缺少 Security Authority |
| 403 | `csrf_rejected` | Local/OIDC 写请求缺失或提交错误 CSRF |
| 403 | `cross_origin_rejected` | API Origin 非同源、重复或非法 |
| 413 | `request_too_large` | 认证请求体超过路由预算或全局聚合预算 |

上述响应固定为 `application/json`、`Cache-Control: no-store`，携带规范 `X-Correlation-Id`，并删除 `WWW-Authenticate`。异常对象、认证原因、账号状态、输入值和内部路径不进入 Body。

## 4. Origin、CSRF 与代理边界

CrewScope 浏览器只通过一个 Web Origin 使用业务 API。应用禁用 Credentialed CORS；存在 `Origin` 的 `/api/**` 请求必须精确匹配当前请求 URI 的 Scheme、Host 与规范 Port。`SameOriginWebFilter` 不直接解析或信任原始 `X-Forwarded-Proto / X-Forwarded-Host`；Team Beta 由 `server.forward-headers-strategy=framework` 在进入 Security Chain 前将代理坐标规范化到请求 URI，Filter 只比较这一个权威结果。`null` Origin、用户信息、Path、Query、Fragment 和非 HTTP(S) Scheme 全部拒绝。

部署入口必须覆盖而不是透传客户端提供的 Forwarded Host/Proto，API 端口只在内部 Backend Network 可达。Team Beta Nginx 已固定覆盖这两个 Header；单元合同进一步证明伪造原始 Forwarded Header 不能改变 Filter 看到的 Origin。同源请求不返回 `Access-Control-Allow-Credentials`，跨源请求不返回 `Access-Control-Allow-Origin`。

Local 与 OIDC 都使用 `CookieServerCsrfTokenRepository.withHttpOnlyFalse()`、Cookie Path `/` 和 `ServerCsrfTokenRequestAttributeHandler`。Vue 读取 `XSRF-TOKEN`，按原值发送 `X-XSRF-TOKEN`；登录、注册、退出、邀请 Preview/Accept 和其他写请求遵守同一协议。

## 5. 请求体预算

`AuthenticationRequestBodyLimitWebFilter` 在 CSRF 校验后、Controller DTO 聚合前同时检查声明的 Content-Length 和实际 DataBuffer 字节数：

| 路由 | 上限 |
|---|---:|
| `POST /api/v1/auth/login` | 8 KiB |
| `POST /api/v1/auth/register` | 16 KiB |
| 邀请创建、Preview、Accept、撤销 POST | 8 KiB |

DTO 继续执行更小的字段级长度和强类型约束。全局 `spring.codec.max-in-memory-size=256KB` 只作为其他 API 的最后聚合上限；其 `DataBufferLimitException` 同样映射为安全的 413 信封。

## 6. 浏览器安全响应头

应用 Chain 固定：

```text
Content-Security-Policy:
  default-src 'self'; base-uri 'self'; frame-ancestors 'none';
  form-action 'self'; object-src 'none'
X-Content-Type-Options: nosniff
X-Frame-Options: DENY
Referrer-Policy: same-origin
Permissions-Policy: camera=(), microphone=(), geolocation=()
Cross-Origin-Opener-Policy: same-origin
Cross-Origin-Resource-Policy: same-origin
Strict-Transport-Security: max-age=31536000; includeSubDomains
```

HSTS 只由 Spring Security 在 HTTPS 响应写入；外部 TLS 入口继续负责 HTTP→HTTPS 跳转和 Web 静态页面的同等 Header。
