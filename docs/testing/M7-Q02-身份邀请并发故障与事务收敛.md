## 1. 交付结果

M7-Q02 将开放用户体系的并发、故障与迁移边界固化为真实 PostgreSQL 17、Redis 7.4 和版本化固定矩阵共同执行的一键门禁。完整注册事务必须原子提交 UserAccount、LoginIdentity、LocalCredential、Organization USER Principal、AccountOrganizationBinding、DomainEvent、Outbox 和 CommandReceipt；邀请注册还必须在同一事务提交 TeamMember、MemberRole 与 TeamInvitation 终态。

统一入口：

```bash
./scripts/m7-q02-convergence-gate.sh
```

Docker 是强制前置条件。门禁不允许以 H2、内存 Session、内存锁或跳过 Testcontainers 替代 PostgreSQL 行锁、唯一约束、Flyway 事务和 Redis 故障语义。

## 3. 新增跨层事务证明

`M7IdentityInvitationTransactionConvergenceM7Q02IntegrationTest` 使用生产 Repository Adapter、`SpringTransactionExecutor`、Flyway V32 和真实 PostgreSQL 执行四个纵向场景：

1. 八路规范化用户名并发注册只有一个胜者，并且只提交一套 Account、Identity、Credential、Principal、Binding、Event、Outbox 和 Receipt；
2. 八路竞争同一邀请只有一个注册成功，并且只新增一个 Membership、一个 MemberRole、一个 ACCEPTED Invitation 以及注册/接受两个事件；
3. 在 LoginIdentity、Binding、DomainEvent 和 CommandReceipt 已写入后注入进程异常，当前事务中的所有身份、授权、事件与回执全部回滚；
4. 模拟提交成功但响应丢失后重新构造应用服务，以相同 Idempotency Key 和密码证明恢复相同 Account、Binding 和 Receipt，行数保持不变。

邀请注册跨层测试发现并修复了一个真实缺陷：账号注册主事件与邀请接受派生事件原本复用同一个 DomainEvent Idempotency Key，会命中 `ux_domain_event_idempotency` 并使整个邀请注册回滚。修复后只有主事件占用命令幂等键；派生邀请事件使用主事件 ID 作为 Causation ID，两个事件继续共享 Correlation ID，保持清晰因果链且不放宽数据库唯一约束。

## 4. Redis、迁移与 Operator 收敛

- 注册前 Redis LoginDefense 不可用或超时继续失败关闭，Controller 不进入身份持久化；
- 身份事务提交后 Redis Session 建立失败返回 `503 registration_session_unavailable`，客户端可使用同一 Idempotency Key 恢复已提交账号；
- Session 重启共享、续期、过期、账号级撤销和 Redis 不可用均不回退客户端或内存身份；
- 空库、非默认 Search Path、V30→V31、V31→V32、V30 Fixture→V32 和失败迁移回滚均使用真实 PostgreSQL；
- Bootstrap Operator 八路并发启动只产生一套 Account、Identity、Credential 和 Binding，Secret 轮换、旧 Hash Rehash 与错误历史形状按既有合同收敛。
