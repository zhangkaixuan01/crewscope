## 1. 交付范围

M5-D02 在 `crewscope-domain` 与 `crewscope-application` 交付：

- `ModelProviderDefinition`：厂商 Key、显示名、受信 Adapter Key、默认 Endpoint、Region、DataPolicy、内容 Hash 和生命周期；
- `ModelCatalogEntry`：稳定 Entry ID、Provider/Model 坐标、连续 Catalog Revision、精确厂商 Model Revision、Token 上限、Capability、Region、内容 Hash 和生命周期；
- `ModelPriceSchedule`：绑定精确 Catalog Revision，以只追加的生效时间点保存输入/输出/缓存 Token 单价、币种、来源、Revision、创建审计和 Hash；
- Provider、Catalog 与 Price Schedule Repository Port。

ModelConnection、Credential/Billing Subject、连接健康与轮换由 M5-D03 交付；AgentConfigurationVersion 与主/Fallback Binding 由 M5-D04 交付；模型可选交集、默认和 Preflight 由 M5-D05 交付。

## 2. 固定领域规则

1. `providerKey` 表达产品厂商，`adapterKey` 表达 AgentScope 运行适配，两者分别存储和审计。
2. Provider 内容不随 ACTIVE/DISABLED/ARCHIVED 生命周期变化，复原时重算 Hash 并拒绝不一致事实。
3. ModelCatalogEntry ID、Provider Key 和 Model ID 在追加链中保持稳定；Catalog Revision 从 1 连续增长并引用直接前一 Revision。
4. Catalog Region 必须是 Provider Region 的非空子集；Context Window 和最大输出 Token 必须为正，且输出上限不超过 Context Window。
5. Catalog 停用阻止新选择和新价格追加；已固定的 Catalog/Price Revision 仍可复原和定价。
6. Price Revision 按 `revision` 和 `effectiveFrom` 同时严格递增。下一生效时间为上一价格的排他上界，时间片无缝、无重叠。
7. 价格修改追加新 Price Revision，不修改旧单价、生效时间、来源或 Hash。
8. 新配置只选择 ACTIVE Provider 与 ACTIVE Catalog Revision；历史运行事实按精确坐标读取，不回退到当前默认值。
9. 每个 Price Revision 记录可信创建 Principal 和创建时间；审计字段不进入不可变价格内容 Hash。

## 3. Hash 闭合

```text
ProviderContentHash
  = SHA-256(providerKey + displayName + adapterKey + endpoint
             + orderedRegions + dataPolicy)

CatalogContentHash
  = SHA-256(entryId + providerKey + providerHash + modelId
             + catalogRevision + previousRevision + providerModelRevision
             + displayName + tokenLimits + orderedCapabilities + orderedRegions)

PriceContentHash
  = SHA-256(catalogCoordinate + priceRevision + effectiveFrom
             + normalizedPrices + currency + source)
```

集合按稳定字符串键排序，字符串使用长度前缀编码，金额使用规范十进制字符串。生命周期状态、乐观版本和审计不进入不可变内容 Hash。
