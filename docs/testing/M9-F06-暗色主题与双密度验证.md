# M9-F06 暗色主题与双密度验证

## 交付范围

M9-F06 为 CrewScope 提供设备级主题与密度偏好：主题支持跟随系统、浅色、深色，密度支持舒适、紧凑。偏好使用带版本号的 `usePreference` 存储在浏览器 `localStorage`，不进入服务端领域状态。

首帧由 `crewscope-web/index.html` 在 Vue 挂载前读取并校验偏好，提前写入 `data-theme` 与 `data-density`，避免刷新时先显示浅色再切换。运行时由 `App.vue` 统一应用，系统主题变化通过 `matchMedia` 同步；顶栏按钮和账号设置页共享同一组键与校验规则。

## 实现要点

- `usePreference` 支持可选运行时校验器，版本匹配但值非法时回退默认值；跨标签页同步同样经过校验。
- 语义 Token 在 `[data-theme="dark"]` 下覆盖画布、表面、边框、文字、反馈、导航选中态、Diff 增删/上下文色和代码语法色。
- 认证页通过 `.cs-auth-theme` 的暗色覆盖层适配未登录入口；不会把认证卡片恢复成浅色硬编码。
- 密度只调整控件高度和面板间距，不改变字号阶梯；移动端隐藏顶栏密度按钮，账号设置仍可调整。
- Diff 增删同时保留 `+`/`-` 前缀与色彩编码，暗色下使用独立对比度校准的 Token，满足色觉差异用户的辨识需求。

## 暗色对比度缺陷与修复

最初的 `m9-theme-density.spec.ts` 只断言了 `data-theme="dark"` 属性被正确设置，**没有任何针对暗色下实际画面的断言**——主题切换本身工作正常，但暗色下的颜色是否可读从未被验证过。逐菜单人工核查（14 个菜单 × 两种主题）后按 axe `color-contrast` 规则实测，发现并修复了以下真实缺陷（均记录在 `tokens.css` 的行内注释中）：

| 缺陷 | 根因 | 修复前对比度 | 修复后对比度 |
|---|---|---|---|
| 暗色主按钮文字几乎不可读 | `--cs-action-primary-text` 固定借用 `--cs-text-on-dark`；暗色下按钮背景变成浅绿 `brand-300`，浅色文字叠加浅色背景 | 1.59:1（hover 1.20:1） | 9.48:1 |
| 危险按钮 / 未读徽标 / Agent 图标白字发灰 | 语义色按钮统一用白字，未按各语义色自身亮度回算 | 1.71–2.14:1 | 通过新增 `--cs-text-on-semantic` 修复 |
| 品牌色当正文文字用 | `brand-600/700/800` 被直接当前景字色使用，在暗色下亮度不足 | 2.03–2.89:1（184 处，axe 报出 86 处违规） | 新增 `--cs-text-brand`/`--cs-text-brand-strong` 后 ≥ 9.43:1 |
| 语义反馈色（`danger`/`success`/`warning`/`info`）本身对比不足 | 未针对 canvas/surface/surface-subtle 逐一重新计算 | 4.11–4.54:1（低于 AA 的 4.5） | 全部 ≥ 5.0:1 |
| `.advanced-toggle` 等控件顶着浏览器默认按钮底色 | `design/base.css` 的按钮 reset 只清了 `border: 0`，没清 `background` | 3.1:1（UA 默认 `buttonface`） | 归零 `background` 后随主题正确取色 |

`--cs-scrim`（单一遮罩变量取代 9 种不同透明度/底色组合）与 `--cs-surface-glass`/`-strong`（取代 8 处硬编码白色透明度）同批收敛，避免暗色下玻璃态/遮罩效果失真。

## 自动化结果

新增 `e2e/m9-dark-theme.spec.ts`，复用 `menu-walk.ts` 共享夹具（`MENUS`：14 个菜单路径，逐个走查而非抽样，因为上述缺陷是组件级分散存在的，抽样会漏检）：

1. **暗色下每个菜单都没有不跟主题的白底**：扫描所有菜单的背景色与渐变端点，用「通道下限 232 + 容差 12」而非亮度判定（因为 `brand-300` 的相对亮度 0.57 高于很多合法的白色场景）；
2. **暗色下每个菜单都满足 AA 对比度**：只跑 axe 的 `color-contrast` 规则（其余规则与主题无关，已由各菜单自己的用例覆盖，重复跑没有增量信号）；
3. **没有任何元素顶着浏览器默认按钮底色**：在 Shadow DOM 里放一个未样式化的原生 `<button>`取真实 UA 默认背景值（不同 Chromium 版本/平台的默认值不同，不能硬编码 `#efefef`），逐一比对页面按钮背景是否与之相同。
