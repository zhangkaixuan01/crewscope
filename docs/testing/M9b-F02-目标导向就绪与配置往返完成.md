# M9b-F02：目标导向就绪与配置往返完成

日期：2026-09-26

## 1. 用户现在怎样使用

**Setup 先问目标**：配置中心不再以清单开场——成员先在「先开始对话 / 先开始 Coding」两张目标卡之间即时选择（不持久化），卡内只给该目标聚合出的第一个可执行下一步；全局保留一张单一下一步卡作为主动作，「刷新事实」降为次动作，已就绪能力折叠成一行摘要，配置健康四组件默认收起；手机端不再铺大进度 Hero。`OPEN_WORKPROJECT_SETTINGS` 的落点从裸 Today 改为带一次性 `intent=create-project` 的创建表单，`OPEN_EXECUTION_DEFAULTS` 直达 repository-settings 的默认执行配置面板。

**配置后回原任务**：任何「A → 配置 → 回 A」往返都以登记路由名（`from=`）白名单校验——只接受站内已登记路由及受权对象坐标（team/project 等按来源路由裁剪），未登记来源、超长值、数组值一律降级「返回配置中心」；凭据、邀请 token、草稿文本不进 URL。设置壳显示「返回 &lt;来源&gt;」次按钮；委托表单预检缺模型/仓库/构建时给出「去配置并返回」，返回后凭既有 `?delegate=coding` 深链与 delegationDraft 恢复草稿——重开对话框不等于自动执行。

**readiness 不只看实体存在**：`CODING_REVIEW` 现在消费 A04 执行默认值——取第一个 ACTIVE WorkProject，缺仓库绑定、绑定指向非 ACTIVE/版本漂移、构建方案缺失或目录失效都判 `EXECUTION_DEFAULTS_REQUIRED`（branch 与 agentProfileId 按合同是回退语义，不算缺项）；READY 需 defaultsComplete。词表已同步契约 §4（`OPEN_EXECUTION_DEFAULTS`）。

**邀请落点不乱跳（R29/L12）**：accept 成功先写 session 级存活记录（org/team/memberId/principalId，TTL 10 分钟，仅对象 ID 非 token）再刷新；重登/刷新后 `/invite` 按 principalId 恢复坐标并以 teamId+memberId 双匹配定位——session 未同步时保持「接受已提交，会话待同步」而非乱跳或重复接受。已登录打开邀请看到「当前账号：displayName（identifier）」与「换账号接受」：换账号原地退出不导航（邀请 proof 留内存、不扩散到 URL），失败则保持原会话不半切换。

**空团队不再有死胡同**：五处空态删除「或加入」承诺（加入只走邀请链接）；Conversation 空团队面板补「创建 Team」、空对话面板给「创建第一个对话 / 需要 Coding？先完成配置」双引导；Today 空项目面板给「创建 WorkProject / 或先从对话开始」；Onboarding 完成卡给「进入团队对话 / 先完成 Coding 配置」分流，Personal Agent 模型未配置只提示不阻断（L10：进度只列真实完成步骤）。

**单项目迁移试用有正式指南**：`docs/guides/M9b-单项目迁移试用指南.md` 固化五步（挑非敏感小任务 → 手工带入标题/说明/原链接、原编号作来源文本不强填 Key → 只连接确实支持的模型与仓库 → 执行并审查 → 结果交回原系统）与边界节（不伪造历史、不做双向同步、没有批量导入、不复制凭据、本机 CLI 与附件批量迁移未在当前范围）；Setup 尾部入口卡同步摘要与边界，组件测试锁定措辞。

## 3. 固定反例与实施偏差（每个都曾真实失败或推翻计划）

- **pageRequestScope capture 覆盖**：InvitePage initialize 的外层 `capture()` 被 preview() 内部 capture 覆盖，generation 递增后外层 `isCurrent()` 恒 false，恢复分支静默失效（acceptance 为 null、显示 unavailable 卡）。修复是外层 capture 移到 preview 之后。教训：**外层 capture 后不得再调用内部含 capture 的函数**。
- **e2e 身份链路 mock 三要素**：换账号后常驻「会话恢复失败」边界卡，根因有二——logout mock `json({}, 204)` 带 body（204 必须无 body）；匿名 session 仍带 account/principal/teams 被 identity gateway 严格校验拒绝（匿名必须干净形状）。另 access-denied 需 route 级 permissions 全集（fixture 只给 scope:read 不够）。
- **R29 场景设计错误**：最初 e2e 用「接受 → 恢复 → 再次 goto」验证，但第一次成功进入时记录已被正确清除，第二次理应不恢复——测试场景本身违背设计。重写为 acceptBreaksSession 模式（accept 后第一次 session 返回匿名 → 刷新丢内存 → sessionStorage 恢复到正确 Team），这才是 R29 要保的真实故事。
- **门禁扫注释**：acceptanceRecovery.ts 与 store.ts 的 doc 注释里出现 `sessionStorage` 字样，被 check-web-sensitive-fields 的正则命中（实现本身已走 browserStorage 间接层）。改措辞为「session-scoped browser storage」。门禁是对源码全文的契约，注释也不例外。
- **TTL 测试时钟竞态（两次）**：断言里二次调用 `entry()`/`Date.now()` 与持久化时刻差 1ms，偶发失败。修复是固定断言对象 + 窗口内近过期取样（`-10min+1s`）。
- **次链接也要 44px 命中区**：空态双引导的次链接（下划线文字链）实测命中区 19.5px，被 m9-mobile-reach 两个密度档全数拦下——文本链接不是触控豁免理由，`inline-flex + min-height:44px` 修复。
- **文案即契约**：五处空态文案改动前先全局 grep e2e/spec 断言（TodayPage.spec、app-shell.spec 均有旧文案断言），标题与主按钮文案保持不变故零回归；A05 的教训（文案改动必须全量跑）这次以「先 grep 后改」前置化。
