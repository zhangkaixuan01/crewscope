# M9b-F05：输入与本地内容可信完成记录

## 1. 关闭对象与非目标

本包关闭"浏览器本地的用户内容必须可信"：草稿不丢、不串、不越权存活，最近访问与阅读状态按账号隔离，失败提交永不谎报成功。全部工作在 crewscope-web，后端零改动，无新依赖。

非目标（沿计划 §5.1）：

- 阅读标记与固定视图（reading/view/pin）只交付存储合同，UI 接线留给 F03/F04；
- 敏感表单（ModelCredentialDialog、GitHub token、Lark secret）继续**不接**草稿——凭据不入本地层是硬边界，`stripSensitiveFields` 仅作纵深防御；
- 设备级偏好（主题、密度、栏宽、diff 视图模式）不迁入用户命名空间。

## 2. 存储合同（S01 D06 冻结实现）

`src/app/f05Storage.ts` 顶部有完整合同注释。要点：

- **九段 key**：`cs.user.v1:<accountId>:<principalId>:<orgId>:<teamId|personal>:<projectId|none>:<kind>:<objectOrIntentId>:<revision>`，每段 `encodeURIComponent` 后以 `:` 连接；kind 枚举 `draft|recent|reading|view|pin`。记录体含 `schemaVersion/kind/epoch/scope 七维/createdAt/updatedAt/expiresAt/value`；读取逐维 + epoch + 过期校验，任一不符即删（自愈）。
- **预算**：草稿 20 份 / 2 MiB / 7 天，满额返回 `{ok:false, reason:'quota'}` **不驱逐**（宁可不写也不挤掉他人草稿），且写后读校验成功才报 ok；recent 100 / 30 天；reading 200 / 30 天；view/pin 各 50 / 180 天（F04 接线）。
- **epoch**：设备级 `cs.user.epoch.v1` 记 `{epoch, accountId}`；切账号 epoch+1；模块态 epoch 为 null 时一切读写拒绝——旧标签页不复活已清数据。跨页封口走 storage 事件 + `subscribeF05Epoch`。
- **清理时序**：`clearSession` 在 **notify 之前**调 `clearF05UserData()`（先清再渲染）；403 走 `clearF05TeamScope(activeTeamId)` 只清当前 Team；全程禁止 `localStorage.clear()`（逐前缀枚举删）。
- **迁移**：`purgeF05LegacyKeys` 在启动（applyPrincipal）与登出各跑一次，一次性删除 `cs.f05.*`、`cs.pref.device.command-recent.v1`、`crewscope:agent-configuration:*`、`crewscope:coding-target:v1:*`、`crewscope:task-delegation:v1:*`、`crewscope:stream:v1:*`、`crewscope:task-cursor:*`、`crewscope:conversation:{invocation,events,clarification,task-intent}:*` 及 `cs.pref.conversation.{scroll,read-sequences}.v1`、`cs.pref.diff.viewed-files.v1` 等旧坐标——不盲迁移，读取端自愈。

## 3. 调用处分类

**手工模式**（对话框/抽屉：onMounted 空态恢复 + watch 持久化 + 成功后 `removeF05DraftIfRevision`）：

| 调用处 | 域适配器 | objectId / revision 语义 |
| --- | --- | --- |
| WorkItemCreateDialog | `workitem/createDraft.ts` | `create:<projectKey>`，提交成功整删 |
| WorkItemDetailDrawer 评论 | `workitem/commentDraft.ts` | 工作项 id；**草稿按对象单 key、评论跨条目版本存活**，item version 记在 `draftRevision`，仅提交成功且 revision 匹配时删 |
| ReviewWorkbench 决策 | `review/decisionDraft.ts` | 按评审对象 |
| ReviewWorkbench 行评论 | `review/lineCommentDraft.ts` | 含 execution/file/blob/side/line/baseVersion |
| ConversationCreateDialog | `conversation/createDraft.ts` | `create:conversation` |
| ConversationPage composer 草稿 | 内存 Map 写通 F05 | 懒读 + 发送成功删 + epoch 订阅清空 |
| CodingDiffExplorer 行评论 | 坐标 watch 清空**前**持久化到旧坐标 | objectId=executionId，回访且 diffGeneration 匹配才恢复 |

**useDirtyForm draftScope 模式**（页面/常驻面板，带路由离开/切 Team 语义）：RepositorySettingsPage 创建表单、ProjectExecutionDefaultsPanel、WorkItemContentEditor。

**reading 模式**（`composables/useScopedUserState.ts`）：ConversationPage 滚动/已读序列、CodingDiffExplorer viewed-files 迁入（objectId=executionId 维度，修复跨账号/跨版本串标记）。

**recent**：CommandPalette 写真实 label/objectType/subtitle，同对象去重，quota 静默降级，epoch 清空时同步清内存。**本包 e2e 发现并修复一个真实缺陷**：recent 读写原先都带 `selectedProjectId`，但 reload 后的读取发生在 project 选择恢复之前，key 的 project 段不一致导致最近访问丢失——recent 本质是 **Team 级概念**，现已收敛为 `projectId: null`。

**假入口清理**：ConversationComposer 删除附件假按钮与 Slash 伪按钮，"发送"是唯一控件。

## 4. e2e 架构与六场景

`playwright.m9b-f05.config.ts` + `e2e/m9b-f05/{fixtures.ts,local-trust.spec.ts}` + `pnpm test:e2e:m9b-f05` 脚本。

**架构**（与计划的偏差，仿 m9b-f01 的精神但非字面 harness）：生产构建 `dist` 由 `page.route('**/*')` 全拦截伺服——非 `/api` 走静态文件 + SPA fallback，`/api/v1/*` 走 mock；origin 用保留域 `http://crewscope-f05.test`（避免 localhost 的 secure-context 特权）；无 webServer、workers 1、serviceWorkers block。这能测到**真实的 main.ts 接线**（`onForbidden → clearF05TeamScope`、`clearSession → clearF05UserData`）而非测试专用 harness。

六场景（`local-trust.spec.ts`）：

1. **recents 隔离**：palette 执行动作写入 recent → reload 后"最近访问"仍在 → 登出（真点菜单，POST logout 后 mock 返回匿名 session）→ URL 到 /login 且 `cs.user.v1:` 全清 → B 账号无"最近访问"分组。
2. **创建草稿往返**：关闭重开恢复；**422 明确拒绝**显示 envelope 消息且草稿保留；成功提交导航到新对象且草稿永删。
3. **评论草稿**：跨 reload 恢复；提交成功只删本次修订；503（unknown，写可能已落地）显示"提交结果尚未确认"走 A04 恢复文案、草稿保留；他人评论推高版本后**未提交草稿仍恢复**（评论 outlive 条目编辑是设计语义，只有成功提交的那一修订能删它）。
4. **403 按 Team 清**：teamA/teamB 各留草稿 → teamB 失去成员资格 → 只清 teamB 的，teamA 的照常恢复。
5. **composer 无假入口**：对话页（URL 必须带 project 段，否则 Scope 规范化会丢弃 conversation 对象参数——这是既定设计）composer 渲染且"发送"是唯一按钮。
6. **quota 不说谎**：预置 20 份草稿占满预算 → 第 21 份写被拒 → 不恢复、无"已保存"字样、无残留 key。

调试中确认的三个合同事实（写进断言，防回归）：命令面优先显示 API envelope 消息而非 store 兜底文案；`Idempotency-Key` 是 header（POST 与 command-results 读取都一样）；503 属"unknown"结果走 A04 恢复链、4xx 明确拒绝不进恢复轮询。

## 6. 与计划的偏差

1. **RepositorySettingsPage / ProjectExecutionDefaultsPanel / WorkItemContentEditor 用手工模式**替代原定的 useDirtyForm draftScope——三处的"离开即弃"语义更适合显式恢复横条，避免为路由守卫引入额外复杂度。
2. **e2e 用 dist + 全拦截**而非 m9b-a01 式 Vue harness：六场景需要双账号、真实 main.ts 接线与真实构建产物，harness 无法覆盖 `onForbidden`/`clearSession` 的全局接线。
3. **CommandPalette recent 收敛为 Team 维度**（projectId: null）——e2e 发现的真实产品缺陷修复，见 §3。
4. 评论草稿的版本语义在实现时定为"**跨条目版本存活**"（S2.4），比计划文档里"跟随 item version"的直觉更符合评论场景：他人评论不应丢弃你的半成品评论；防串靠账号/团队/项目/对象四维 key，防误删靠"仅成功提交的修订可删"。
