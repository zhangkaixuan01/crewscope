# M9-Q01：质量门禁与基线

M9 的体验回归由两个互补的门禁守住：一个是**计数式基线**，用于存量债务的偿还；一个是**清单式棘轮**，用于「一旦做对就不许再退回去」的规则。

## 1. `scripts/check-m9-q01.mjs`（计数式基线）

扫描生产前端代码中最容易造成体验回退的三类问题：原生弹窗、要求用户粘贴 UUID/Principal ID 的输入，以及裸 `title` 属性。

门禁采用可审计基线：当前基数写入 `docs/quality/M9-门禁基线.json`，新增违规会让 CI 失败；每次偿还存量问题时同步下调基线。

| 指标 | 含义 | 当前基线 |
| --- | --- | --- |
| `nativeDialogs` | `window.alert/confirm/prompt` 与裸 `alert/prompt` 调用。所有确认都必须走 `useConfirm()` 的应用内对话框，才能承载原因、影响面与撤销窗口 | 0 |
| `uuidInputs` | `placeholder`/`aria-label` 里要求成员键入 UUID 或 Principal ID 的输入框。身份一律由选择器给出 | 0 |
| `bareTitleAttributes` | 仅靠 `title` 承载信息的元素。`title` 在触屏上不可达、对读屏不可靠，应改用 `BaseTooltip` + `aria-describedby` | 0 |

三项已全部归零，因此整个计数式基线事实上已经是棘轮：任何新增都会失败。`bareTitleAttributes` 此前的 313 处是**扫描口径的误报**（原正则把 Vue 组件的 `title` prop 当成 HTML 属性），修正后仓库内真实违规为 0，机制说明与样例证据见第 7 节。

## 2. `scripts/check-web-enum-labels.mjs`（清单式棘轮）

服务端把每个枚举按 `{Enum}.name()` 序列化，因此模板一旦直接插值这类字段，成员看到的就是 `RESPONSIBILITY_ASSIGNMENT` 这种 Java 常量。M9 的收口做法是：

1. 每个领域在 `domains/{name}/types.ts` 里用 `as const` 数组声明该枚举的**全部**常量，并派生联合类型；
2. `domains/{name}/labels.ts` 用 `Record<Enum, string>` 给出成员语言的文案——漏一个常量是编译错误，而不是屏幕上的一个 Java 常量；
3. 调用点统一走 `domains/shared/labels.ts` 的 `enumLabel(value, map)` / `enumLabelOr(value, map, fallback)`；引用多个领域枚举的组件再包一层本地 `label()` 辅助函数。

门禁在此之上做静态检查：遍历 `crewscope-web/src/**/*.vue` 的每个 `{{ }}` 插值，取 `??` 兜底之前的最后一个标识符，若其小写形态以枚举后缀词表（`status`/`type`/`kind`/`reason`/`code`/`phase`/`mode`/… 共 28 个）结尾且表达式未经过 `labels`、`enumLabel`、三元本地化或 `*Text()`/`*Tone()` 辅助函数，即判为裸枚举。

与 `check-m9-q01.mjs` 不同，这个门禁**不用计数**：

- 任何未登记的裸枚举插值直接失败；
- 已评审的例外写在 `docs/quality/M9-裸枚举豁免清单.json`，每条都必须给出「这个表达式不是服务端枚举」的事实性理由（开放词表的领域事件名、有界自由文本证据码、Agent 手写的 todo 优先级、数字优先级、ISO 4217 货币码、已本地化的本地 computed、Histoire 演示夹具）；
- 豁免一旦失效（对应插值已被改掉）同样失败，逼着清单只能变短，不会烂在仓库里。

后缀词表按**小写**比较。第一版实现区分大小写，`\bcode` 匹配不到 `failureCode` 这类小驼峰字段，于是漏掉了绝大多数真实站点（15 → 42 处）；这条经验就是门禁必须自带回归清单的原因。

`.story.vue` 不在扫描范围内：Histoire 故事的事实来自 `domains/demo/fixtures.ts`，本来就是人话而不是序列化枚举。

## 7. 三项计数式基线的清零：度量修正、豁免清单与验证证据

三项计数式基线此前都挂着"待偿还"的数字。本轮逐条复核后发现，**其中两项数字的主要来源是门禁自身的度量错误**，而不是仓库里的真实违规；因此第一步是修正度量口径，再把剩余的真实存量按原因迁移，最后才谈归零。

| 基线文件 | 指标 | 原值 | 现值 | 剩余条目的去处 |
| --- | --- | --- | --- | --- |
| `docs/quality/M9-门禁基线.json` | `bareTitleAttributes` | 313 | 0 | 无（313 处全为误报） |
| `docs/quality/M9-disabled-baseline.json` | `unexplained` | 88 | 0 | `docs/quality/M9-禁用态豁免清单.json`（14 条） |
| `docs/quality/M9-empty-state-baseline.json` | `emptyWithoutAction` / `forbiddenWithoutAction` | 31 / 10 | 0 / 0 | `docs/quality/M9-空状态豁免清单.json`（19 条） |

### 7.1 `bareTitleAttributes` 的 313 处是可复现的误报

原实现（`scripts/check-m9-q01.mjs`）用 `/\stitle=["'][^"']*["']/g` 匹配，**没有锚定 HTML 元素**，于是把所有 Vue 组件的 `title` prop 一并计入。逐条回溯到所属开始标签后：`StatePanel` 142 处（渲染成 `<h3>{{ title }}</h3>`）、Histoire 的 `Variant`/`Story` 134 处（Histoire 自己的 API）、`AuthCard` 14 处（`<h2>` + `aria-labelledby`）、`AppShell` 7 处（`<h1>`）、`SettingsShell` 4 处（透传 `AppShell`）、`AuthErrorSummary` 1 处（`role="alert"` 内的可见标题）。全部是**可见标题与文案**，不存在 `title` 属性"触屏不可达、对读屏不可靠"的问题——门禁想抓的东西在仓库里本来就不存在。

修正为**逐文件**统计（原实现把所有文件拼成一个大字符串，`lastIndexOf` 会跨文件回溯），并对每个 ` title=` 命中回溯所属开始标签，仅当标签名匹配 `/^[a-z][a-z0-9]*$/`（小写 = HTML 元素）时计数；命中不落在任何开始标签内时同样计数，可疑写法不放行。

### 7.2 `unexplained` 的 88 处被两个 bug 抬高

- `scripts/check-disabled-reasons.mjs` 的 `.replace(/^\(|\)$/g, "")` 本意是剥掉 `(a || b)` 的分组括号，但 `g` 标志下 `\)$` 会连函数调用的右括号一起剥：`Boolean(pending)` → `Boolean(pending`，于是永远匹配不上原子表里明确列出的 `Boolean\((?:pending|commandPending)\)`。修正为只剥成对包裹的一层：`part.trim().replace(/^\((.*)\)$/, '$1').trim()`。
- 原子表只登记了**裸写法**的瞬时锁，`store.state.phase === 'loading'`、`command.phase === 'pending'`、`agents.loadingMore` 这类带限定路径的写法全部落空。补上 `(?:\w+(?:\.\w+)*\.)?phase === '(?:loading|pending|accepting|cancelling)'` 与 `(?:\w+(?:\.\w+)*\.)?loadingMore`（只补实测确认为同一类提交锁的形态，不做泛化放宽）。

修正后实测 88 → 77，其余按真实原因迁移（见 7.4）。

### 7.3 归零不等于放宽：边界一律按真实语义处理

- `TaskIntentCard.vue` 的 `Boolean(pending) && pending !== 'confirm'` 是 `&&` 组合的提交锁，原子表按 `||` 切分覆盖不到。**没有为了让数字下降去放宽正则**，而是把它提成具名 computed（`otherCommandPending`）并补真实原因元素。
- `ModelSettingsPage` 的 `canOpenCreate` 合并了「未选 Team」与「Provider 目录未就绪」两个成因（计划 ⑥ 行点名的真违规）。这里同样没有为了让数字下降而简化：拆成 `teamMissingReason` / `providerCatalogReason` 两条可区分原因并各自接线 `aria-describedby`，同时**保持 `canOpenCreate` 本身的判定不变**——若改为从原因派生，会在 Provider 目录仍在加载时提前放开按钮，那是行为变更而不是解释补齐。
- 权限类空状态的动作一律指向 `/access-denied?requiredPermission=<permission>`（无权限守卫的公共路由，页面会报出所需权限并提示联系 Team Owner/管理员）。**不能指向 `/team/members`**：该路由自身要求 `teamMembersRead`，恰好缺这条权限的成员会被守卫弹回，形成循环。

### 7.4 豁免清单：与裸枚举清单同构，且只许变短

禁用态清单登记的 14 条全部是**纯表单完整性**导致的禁用（`!valid`、`!text.trim()`、`!openId.trim()`、各类 `!xxxPrincipalId`）：原因由同一表单的 `aria-invalid` 与校验文案承载，再补一段说明只会重复播报。空状态清单登记的 19 条全部是**确无成员可执行下一步**的面板：平台侧事实（无可用 Provider、暂无 Projection 定义、没有符合条件的模型交集），或出口已在同一视口内（Team 切换器在页面外壳侧栏、搜索框在上面、连接列表在同屏左列）。

两个清单都沿用 `docs/quality/M9-裸枚举豁免清单.json` 的约定：`{file, expression|state+title, reason}`，理由必须是「这不是门禁针对的对象」的事实性陈述，且**失效条目判失败**。

顺带修正了裸枚举门禁的一处**假阳性来源**：本轮新增的禁用态原因元素大量形如 `<p class="sr-only">{{ providerCatalogReason }}</p>`，其中 `*Reason` 正好落在后缀词表里，于是 18 处「本地 computed 返回中文说明句」被当成裸枚举插值。这些站点按仓库既有约定登记进 `docs/quality/M9-裸枚举豁免清单.json`（13 → 31 条），理由写成事实性陈述（本地 computed 返回的已经是成员可读的中文说明，不是服务端枚举）。注意这与"绕过门禁"不同：门禁真正要抓的 `{{ item.eventType }}`、`{{ task.status }}` 一类服务端枚举插值仍然会失败——本轮清点过一遍，未新增任何此类站点。

### 7.5 检测能力证据（修正后仓库内违约为 0，必须证明门禁没被削弱）

- `bareTitleAttributes`：构造样例验证 `<button title="x">` 判违规、`<StatePanel title="x">` 放行。
- 空状态清单：把清单临时清空 → 门禁失败并如实报出 17 处 offender；把某条 `title` 改成不存在的值 → 门禁同时报出 `emptyWithoutAction: 1 > baseline 0` 与 `waiver list has stale entries`。
- 禁用态清单：一次意外的路径笔误（写成 `components/domain/SearchPage.vue`，真实站点在 `pages/SearchPage.vue`）被失效检测抓出，修正路径后 PASS——这是失效检测真实工作的正向证据。

### 7.6 顺带修掉的一处真实体验缺陷

为 `ReviewWorkbench` 的 Gate 按钮补原因时，sr-only 文案与页面上已有的可见说明是同一句话的两种措辞，`e2e/app-shell.spec.ts` 的 `getByText` 因此命中两个元素（strict mode violation）。修复方式是**复用页面上已有的可见说明**作为 `aria-describedby` 目标（给那段 `<p>` 加 `id`），而不是再写一段近似文案——读屏也不再重复播报。
