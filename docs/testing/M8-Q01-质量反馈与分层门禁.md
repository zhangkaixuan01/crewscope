# M8-Q01 质量反馈与分层门禁

> 任务：`M8-Q01`
>
> 状态：进行中（本地实现已完成，待 CI 主分支验证）

M8-Q01 收口质量反馈面，让本地检查、Pull Request、Main 和 Release 使用同一套可解释的合同。门禁优先报告可修复的事实，不把历史证据数字伪装成当前运行结果。

## Coverage 基线

前端 Vitest Coverage 的分母覆盖 `crewscope-web/src/**/*.{ts,vue}`，只排除测试、Histoire Story、测试夹具和 spikes。核心 Conversation、Task、Coding、Review、Delivery、TeamOps、TeamObserver 页面因此会进入分母。

扩大分母后的当前本地基线（2026-09-02）为：

| 指标 | 基线 | Q01 门槛 |
|---|---:|---:|
| Statements | 68.36% | 65% |
| Branches | 61.96% | 60% |
| Functions | 69.84% | 65% |
| Lines | 72.56% | 70% |

门槛是单向 ratchet：新增页面测试后可以提高门槛，不能为了让流水线通过而降低门槛。后续逐步为未覆盖的业务页面补齐测试，目标恢复到 M7 的 80/70/75/80 基线。

## 分层门禁

- 本地快速反馈：`git diff --check`、`pnpm check:quality`、`pnpm build`、`./mvnw -DskipTests compile`。
- Pull Request：按变更面执行后端回归、前端单元与浏览器测试、文档/敏感字段/架构/依赖合同；同一 PR 的新提交会取消旧运行。
- Main：保留完整 Maven、Coverage、Story、Playwright、依赖和镜像安全检查。
- Release：在 Q02 追加不可变镜像、签名、升级恢复和真实 Linux amd64 证据。

路径感知只缩小与变更无关的构建面，不缩小质量面：文档与脚本变更仍执行质量合同；Java、Vue、迁移、Dockerfile 和依赖清单变更会触发对应构建或扫描。Release Gate 对被路径过滤的任务接受 `skipped`，对被判定为必需的任务仍要求 `success`。

## 自动检查

- `scripts/check-module-boundaries.mjs`：阻止 Domain 引入 Spring/JPA/AgentScope 或适配层；阻止 Application 反向依赖运行时和基础设施；阻止 Integration 反向依赖。
- `scripts/check-dependency-contract.mjs`：保证默认 AgentScope 运行时不带 Kubernetes Sandbox 扩展，并检查 Web 质量脚本存在。
- `scripts/check-config-contract.mjs`：交叉校验环境变量、Compose Secret、Loopback 端口、不可变镜像和配置元数据。
- `scripts/check-maven-dependency-report.mjs`：将 Maven `dependency:analyze` 结果与审阅白名单比较，阻断未解释的新坐标；原始报告由 Backend Job 保存。
- `scripts/check-web-quality.mjs`：检查生产 TS/Vue 文件的尾随空白和非 UTF-8 行尾，保持输出低噪音。
- Spring Configuration Processor 在 Infrastructure/Server 生成 `spring-configuration-metadata.json`，IDE 与部署模板可据此发现配置。

Maven `dependency:analyze` 在 Backend Job 中作为诊断报告运行；多模块测试夹具和传递依赖产生的既有警告由 I01 白名单治理，未审阅的新坐标会使门禁失败。详见 [M8-I01 依赖与配置治理](M8-I01-依赖与配置治理.md)。

## 历史证据

README 中的 M7 数字是历史发布证据，不代表当前工作区结果。M6/M7 证据分别绑定其 Release Gate 文档中的 Git Revision、Artifact 和 GitHub Actions Run；Q01 的本地基线只以本文件记录的日期和命令为准。新的数字必须同时写入报告、Revision 和 CI Run 后才可进入 README。
