# M9b-A05：委托编排完成

日期：2026-09-25

## 1. 用户现在怎样使用

工作项抽屉的「交给 Agent 处理」升级为统一委托表单：打开时一次读取责任链、候选 Agent（含已分配/冲突/停用标注）、项目默认值与在途执行事实（`GET .../delegation-context`），不再由前端拼四个端点。未分配执行者且有责任管理权时，成员在「分配并启动」（默认）与「仅分配」两个发送意图里显式选择——前者是同一条可恢复命令内先落 EXECUTOR 责任再启动执行（失败不留下半提交），后者复用既有责任命令、不创建任何 Task；已有执行者时表单自动进入「启动」模式，其他 Agent 标注「责任冲突——需先显式释放再分配」，本命令从不静默替换责任。项目默认的仓库绑定、分支与受控构建方案在表单内预选并标注来源，已解析默认值不要求重复选择；选定 Agent 后仍走服务端预检（模型/构建/PolicySnapshot）。在途执行不被热注入：表单提示「当前执行仍按原说明继续；补充要求请发布评论，或等本轮完成后开启新一轮」。评论区按钮与文案明示只记录讨论、`@` 不触发执行；崩溃/超时后凭原幂等键可恢复到确切 Task（TASK 恢复坐标），不会重复委托。TaskIntent 确认后的「配置 Coding Task」深链原样进入升级表单的启动模式。

## 3. 固定反例与实施偏差（每个都曾真实失败或推翻计划）

- **既有 e2e 数据源迁移（P5）**：dialog 改读 delegation-context 后，app-shell 四个既有委托用例因缺端点 mock 而挂。修复按「夹具语义必须源码核实」：先读 `DelegationContextController` 定 wire 形状，mock 的候选五态从 responsibilities+agent 目录推导、activeExecution 从 Task 投影推导、defaults 与既有 repository/build mock 的 hash/branch 严格一致——否则 CodingTarget 默认预选静默失败。
- **评论文案改名漏 e2e 断言（P4→P5 全量才发现）**：「发送评论」→「发布评论」后 app-shell 与 m9b-f05/local-trust 两处既有断言（共三处点击）未跟上，单跑委托用例全绿掩盖了它——全量 `pnpm test:e2e` 才暴露。教训同 A07「生成物基线漏更新」：**文案即契约**，UI 文案改动必须全局搜 e2e 断言并全量跑。
- **e2e 夹具评论行缺字段（P5 真缺陷）**：world.comments 只落 `{id, content}`，刷新后 `humanName(undefined)` 抛错触发全局错误横幅、抽屉消失。夹具行必须是完整 wire 形状——少一个字段不是"少断言"，是换一个产品在测。
- **createTask 不查 command-results 定位新 Task**：202 回执不含客户端可信的 Task 身份；store 靠关联查询差集定位（`createAndLocate` 合同）。e2e world 必须让 `GET .../work-items/{id}/tasks` 立即可见新 Task，否则深链不刷新。V47 的 TASK 坐标服务的是崩溃后按幂等键恢复，正常路径不走。
- **双击幂等的测法**：第二次点击必须是真实落在同一坐标的物理点击（`page.mouse.click(boundingBox)`）——用 role 选择器二次 click 会被 Playwright 的 actionability 等待"帮忙"跳过，验不出前端待态守卫。
- **requestHash 收紧方向**：assignment 字段进 requestHash 只影响同键异载荷判定（更严，正确方向）；双击/重试同键同载荷仍是重放。
- **模式状态机单真源**：模式只由服务端事实（责任链 + 权限布尔）推导；前端不维护第二份真相。深链 `?delegate=coding` 行为保持（TaskIntent 原入口零改动，回归覆盖）。

## 5. 交接与明确非目标

- **F02/Q02 空环境配置**：A05 用符合既有授权合同的测试仓库验证委托；空环境配置下的全链引导不在本包（不预置绕过导入）。
- **F03 呈现层**：非 coding `resultSummary` 恒 null（模型结果不解析进列表）；`runtime-artifact:`/`coding-attempt:` 引用的完整呈现、工作区按钮归 F03。
- **F04 视图接线**：执行摘要区扩展与列表/视图接线归 F04。
- **明确非目标（契约禁止）**：不做热注入执行引擎、不做通用 Saga、不自动释放旧责任、不改评论/TaskIntent 语义、不重做执行引擎。
- **失败恢复**：TASK 坐标 + 幂等键覆盖「提交结果未知」场景；跨步骤编排（通用 Saga）仍是契约级非目标。
