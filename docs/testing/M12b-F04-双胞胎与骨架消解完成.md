## 2. 骨架基础件（`components/shared/` 新层，13 文件 + 2 composables + 1 util）

Review §3.2 的修法是「抽 BaseXxx 泛型骨架」。落地时发现这些骨架消费的不是 base 控件级合同，而是**两域 store 的结构化资源形状**——放在 base 层会让 base 反向依赖域形状。故新建 `components/shared/`（base 之上、domain 之下的组合骨架层），形状契约放 `shared/types.ts`：

- **`shared/types.ts`**——`ResourcePhase` / `Resource<T>` / `ListPageResource<T>`（keyset 字符串游标 + loadingMore）/ `VersionPageResource<T>`（revision 数字游标）/ `Etagged<T>` / `EntryLike`（详情壳 facts/audit 区渲染的头字段）/ `VersionLike`（title 可选：knowledge 版本有发布标题，skill 修订渲染「修订 rN」）。注释钉死：与 `domains/skill/store.ts`、`domains/knowledge/store.ts` 的 `XxxResource<T>` 逐字段兼容，两域资源无需适配层直接满足。
- **BaseListShell\<I\>**——三胞胎的状态梯（loading / forbidden(403) / offline / error / empty 五级 + 有内容时的紧凑条）、`<ol>` 行容器、load-more footer 及其离线 describedby 模式。`online`/`errorMessage` 经 `OnlineProps & ErrorMessageProps` 切片进入（§6）；筛选头/行/空态动作是域领土走 slot。spec 8 条（状态梯逐级、紧凑条、游标 footer、离线禁用原因关联）。
- **BaseDetailPage\<T extends EntryLike\>**——详情页对共有的 facts 网格、audit 元信息区（创建/更新/origin）、状态徽章行。spec 7 条。
- **BaseVersionHistory\<T extends VersionLike\>**——版本列表、游标分页、选中态、**回滚按钮按 prop 出现**（迁移前 Skill 侧有 Knowledge 侧无——分叉功能差保留为显式注入而不是隐式继承）。spec 5 条。
- **BaseDraftEditor\<T\>**——草稿编辑器对的 useDirtyForm 配置（四条中文文案单源）、编辑/只读切换、表单外壳。spec 5 条。
- **BaseReceiptPanel**——蒸馏回执框：幂等重放 banner、facts 列表容器（行内容走 #facts slot）、后续提示行、打开/再蒸馏动作。spec 5 条。
- **ActionConfirmDialog**——三模式确认框（§4.3）。spec 5 条。
- **`useIdempotentCommand(fingerprint, onEdit?)`**——六个表单命令对话框逐字相同的幂等键协议单源：编辑任何命令输入 = 新逻辑请求（清 attemptKey + onEdit 副作用）、未变重试复用 key、key 生成失败以可朗读错误拦截且**不发送**。返回 `{ submissionError, keyFor, clearAttempt }`。
- **`utils/displayDate.ts`**——`Intl.DateTimeFormat('zh-CN', { dateStyle: 'medium', timeStyle: 'short' })` 一份。自带 null/短横兜底的调用点保留本地包装（注释钉死边界）。

## 4. useEntryLibraryPage：整页双胞胎合并（Review §3.4-2）

### 4.1 composable 合同

`useEntryLibraryPage<Id extends string>(options)` 收编 SkillsPage/KnowledgeBasePage 除域文案外的全部页面逻辑——三只 watch（catalog / selection / query 收敛）+ 命令族 + query 协调族：

- **catalog watch（注册在最前，§8 教训）**：源 `[catalogSources(), phase]`（页面注入 `[phase, orgId, teamId, ...filters]`）——ready 且 scopePresent 才 activateScope + 清命令 + 重载目录；`onCatalogReset` 回调让域做自己的重置（Skills 清 deep link 状态）。
- **selection watch**：源含 teamId 位（team 切换即重载）；先清 commandAttempt/clearCommand 再 gate；`effectiveOnDraftTab` 决定 draft tab 是否预载 effective（编辑器 diff baseline）；versions tab 预载版本列表（+ 有 revision 时 loadVersion）。
- **query 收敛 watch**：normalizeQuery 循环 + tab 归一 + 孤儿 selected/revision 删除；源含 extraQueryKeys（Skills 的 `skillKey` deep link 参数不参与收敛）。
- **runCommand 语义逐字保留**：captureSelection → 离线 gate（**不 mint key**）→ run(attemptKeyFor) → isCurrent 才动页面状态；成功清 key + refreshFacts 四路；conflict 清 key + 目录/详情双 reload；非 retryable 清 key（清发生在 run 之后——本次已用旧 key 发出，丢 key 体现在下一次 mint）；retryable 保留 key 复用。

### 4.2 两域差异点全部注入化（验收契约核心）

## 5. useInlineSettingEditor 与设置页（Review §3.4-3）

`useInlineSettingEditor<T>({ payload, serverValue, applyServerValue, valid, ready, phase, clearCommand, save, fingerprint? })` 收编 Quota/Organization 两设置页逐行对应的编辑生命周期（createFormCommandKeys + attemptKey + startEditing/cancelEditing/save + 三只 watch），返回 `{ editing, submitted, dirtyForm, startEditing, cancelEditing, submit }`。语义钉死：

- success watch 只 markClean + 退出编辑；**字段重置交给 serverValue watch**（退出编辑后回填服务端权威值——与原页面对齐，spec 承证）；
- submit 失败保留 attemptKey（未变重试复用）、成功/换 fingerprint 清；Org 页 `fingerprint: () => [retentionChoice, retentionPayload]`（radio 切换也算新逻辑请求：forever→limited→forever 同日数是新请求，payload 同为 null 也要重新 mint）；
- 非编辑期 server 值变化回写字段、编辑期不动（spec 双向断言）。

两页净删约 150 行编辑样板；`useDirtyForm.markClean` 签名放宽 `nextValue?: T | null`（原页面一直传 null，运行时本就合法，是声明瑕疵）。spec 5 用例。

## 8. 教训（本批新增，全部门禁链上实证）

1. **immediate watch 注册顺序即执行顺序（最大单点）**：composable 初版自带 selection watch、页面保留 catalog watch——setup 内 immediate watch 按注册顺序同步执行，selection watch 先跑导致 loadDetail 跑在 activateScope 之前，10 个页面 spec 全挂 + 14 个 Unhandled Rejection。修法：catalog watch **收编进 composable 并注册在最前**（函数体顺序：catalog → selection → query 收敛，注释钉死保序约束），域重置经 `onCatalogReset` 注入。
2. **清 attempt key 的时点断言**：非 retryable 失败清 key 发生在 `run()` 之后——本次请求已用旧 key 发出，「丢 key」体现在下一次 mint。用最小调试 spec 证明 composable 正确后断言改为「第四次调用拿新 key」，不靠臆断写测试。
3. **vue-router replace 是异步 promise 链**：nextTick 不够，测试 helper 需 nextTick + setTimeout 0 + nextTick 三段排干（settleRoute）。
4. **vitest `toHaveBeenCalledWith` 参数个数严格**：单参断言与 `(id, undefined, undefined)` 调用不匹配——undefined 占位也要写全，否则恒假。
5. **jsdom 不实现 form 属性按钮点击提交**：`type="submit" form="id"` 在 jsdom 无效——换 `type="button" @click` 直调（浏览器语义等价，textarea Enter 本就不提交）。
