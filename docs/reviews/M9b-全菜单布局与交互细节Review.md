# M9b：全菜单布局与交互细节 Review

日期：2026-09-20。源码基线：`4385d9a`。状态：待实施的产品审查增量，不是功能修复或全站浏览器验收报告。

关联：[主计划](../plans/M9b-核心流程与使用体验收口.md)、[实现契约](../plans/M9b-实现边界与验收契约.md)、[原菜单逐操作清单](M9b-菜单逐操作产品Review.md)、[迁移体验 Review](M9b-Multica用户迁移体验Review.md)。

## 1. 结论、范围与证据边界

当前主要问题不是缺少更多菜单，而是**内容和动作虽存在，用户仍要绕过多层导航、说明、筛选和技术事实，才能找到自己要做的事**。应保留 M9 的设计 Token、主题、权限和确认机制，调整位置、顺序与状态表达，不再增加一层仪表盘或整套设计系统。

本轮按“进入菜单 → 找到对象 → 阅读详情 → 执行动作 → 获得反馈 → 返回继续”走查了 15 个一级菜单、9 个二级入口，覆盖 23 个 Page 的模板及关联关键组件/处理函数；重点复核桌面、窄屏、折叠导航和长内容下的布局规则。原菜单 Review 的逐按钮成功/失败/未知结果清单仍有效，本文件不替代它，也不声称所有处理函数已经穷尽验证。

- **源码确认**：组件顺序、控件样式、条件显示、路由/事件接线；引用以组件/选择器定位，避免行号随实施失效。
- **受控复现**：只把当前 AppShell CSS 与最小控件结构放进无服务的 Chromium 页面，验证网格换行；不是挂载完整 Vue 应用，不据此宣布所有页面的具体像素坐标。
- **历史视觉证据**：查看仓库现有 8 张截图，辅助判断信息层级。历史截图不是当前实例；例如账号截图仍使用旧独立外壳，不能用来证明当前三层导航的实际宽度。
- **产品决定**：下文目标位置与顺序是 M9b 待实现约束，不是已存在功能或竞品实测结论。
- 未启动之前停掉的应用/Compose 栈，未连接真实模型、发送通知或写远端仓库；没有真人测评要求。

新增 `L01–L12` 是已有 R 项的**布局/接线子要求**，不是 12 个新 R、独立里程碑或可选美化。R01–R43、15 个父包和依赖图不变；对应 R 关闭时必须包含本轮适用子要求，不能因不扩号而漏做。S01 重估接线与测试工作量。

## 2. 具体发现与需要冻结的改进

### L01：全局工具栏换行越界，手机搜索和折叠菜单辨识不足

证据：[AppShell](../../crewscope-web/src/components/layout/AppShell.vue) 的 `.topbar` 桌面只有 4 列，但模式、搜索、主题、密度、通知共 5 个可见直属项；手机只有 3 列，却有导航、范围、主题、通知、账号共 5 项。容器固定高度为 58/52px，隐式第二行不会为下一块页头让位。当前最小布局复现中，1440/1024px 的通知底边 91px 超过工具栏 58px；390px 为 108px 超过 52px。历史截图也能看到铃铛落在页头附近。

同组件手机隐藏 `.command-search`，移动菜单和底栏都没有搜索项；不能要求触屏用户使用 Cmd+K 或手写 `/search`。折叠及 1100px 以下侧栏把链接文字 `display:none`，图标又 `aria-hidden=true`，链接没有独立名称；仓库/GitHub 还共用近似图标。范围与账号的手动折叠样式也未完全复用中宽屏规则。

**决定**：桌面把全局导航/搜索与右侧工具组明确分组，不用固定列数碰运气自动排项；主题/密度移入账号外观设置，日常工具优先。手机顶栏仅保留导航、可收缩的当前范围、搜索、通知，账号进入导航菜单；底栏直接对应今日/工作/对话，不再和顶部“模式”形成两套认知。折叠菜单必须保留独立 accessible name，hover/focus 可见名称；触屏可展开文字导航。长团队/项目名省略但能展开看全名，弹层不越视口。

归并：R12/R27/R28/R30；F04 主责，C15/C13。优先于各页换样式。

### L02：设置搜索、分类与对象详情挤在一起，账号还叠第三层导航

证据：[SettingsShell](../../crewscope-web/src/components/settings/SettingsShell.vue) 的搜索框、[SettingsFieldSearch](../../crewscope-web/src/components/settings/SettingsFieldSearch.vue) 和 9 个菜单是同一 nav 的子元素；手机 nav 为不换行 flex，结果块虽有 `flex:1 0 100%`，仍在同一横向滚动线上，不会自动独占下一行。字段结果命中时还可能同时出现“没有匹配配置”的菜单空态。当前 [AccountPage](../../crewscope-web/src/pages/AccountPage.vue) 使用 SettingsShell，而 [AccountWorkspace](../../crewscope-web/src/components/account/AccountWorkspace.vue) 再加 190px 纵向导航。

**决定**：配置分类只由一层二级导航表达，搜索框/结果独立于菜单滚动区域；分别命名“配置分类”“配置字段结果”，不能用分类无匹配暗示整个搜索无结果。窄屏采用当前分类选择器，展开后显示受权分类；字段结果纵向排列。账号从账号菜单进入，使用账号自己的分区导航，不再套团队配置目录；外观/本人通知/资料/安全的适用范围分清。九个旧入口均保留受权跳转，不丢 Scope 和返回坐标。

归并：R12/R20/R27/R30/R31；F04 主责，C08/C13/C15。

### L03：对话高度靠固定减数，输入与底栏争空间

证据：[ConversationPage](../../crewscope-web/src/pages/ConversationPage.vue) 桌面 `calc(100vh - 176px)` 加 640px 最小高度，手机 `calc(100dvh - 208px)`；但页头动作可换行，还有离线条。消息前默认展开任务提案及关联卡；手机仍显示“折叠参与者”，参与者区却被 CSS 隐藏。[ConversationComposer](../../crewscope-web/src/components/domain/ConversationComposer.vue) 的 sticky `bottom:0` 与 AppShell 固定底栏分属不同容器；历史窄屏截图中发送区落到固定底栏附近。不能仅凭截图断言所有设备都无法发送。

**决定**：聊天工作区使用实际可用高度分配，消息区伸缩，输入区与导航避让统一管理，不继续追加固定减数。会话标题/可见范围一行优先，参与者与普通关联项按需展开；待我确认仅保留摘要和明确入口，不反复把历史卡放在最新消息前。手机详情显示返回列表，不显示不可生效的侧栏开关；键盘弹出/收起、离线条出现、输入增长后，最后消息、输入及发送均可达。

归并：R12/R16/R19/R27/R28；F03 主责聊天内容/高度，F04 提供壳与底栏避让，F05 保留输入；C10/C11/C15。

### L04：对象列表和详情之间缺乏稳定位置关系

证据：[AgentSettingsPage](../../crewscope-web/src/pages/AgentSettingsPage.vue) 把选中配置放在所有分组目录前；[ModelSettingsPage](../../crewscope-web/src/pages/ModelSettingsPage.vue) 是目录 → 连接详情 → 连接列表；[GitHubSettingsPage](../../crewscope-web/src/pages/GitHubSettingsPage.vue) 是连接列表 → 详情 → 仓库列表 → 导入表单，目录变长后详情/导入随之远离点击处。Agent 配置有首次 mount 焦点处理，应保留；但不能用首次聚焦保证换对象、浏览器返回和长目录路径均正确。

**决定**：桌面在可用宽度足够时使用稳定的列表—详情关系；不足时进入独立详情视图，顶端保留对象名、状态、返回入口。不在长列表上/下方动态插入巨型表单改变原滚动位置。手机列表与详情单层切换；从列表第 20 项打开、切第二对象、返回后保持筛选/位置和明确选中。配置页历史版本默认收起，当前有效配置先于历史/Hash；保存栏固定在本编辑区域，不能漂浮到另一个对象上。

归并：R12/R24/R28/R30；Agent/通用呈现 F04，模型 A03，GitHub A02，草稿 F05；C11/C13/C15。

### L05：工作内容、执行选择和下一步不在同一个观察位置

证据：[WorkPage](../../crewscope-web/src/pages/WorkPage.vue) 把工作列表与独立 TaskListPanel 纵向堆叠；[TaskDetailDrawer](../../crewscope-web/src/components/domain/TaskDetailDrawer.vue) 先放执行/Diff/测试/审查/交付，再放目标、验收标准和执行历史选择；用户可能要滚过旧执行的长结果才能切换执行。[WorkItemDetailDrawer](../../crewscope-web/src/components/domain/WorkItemDetailDrawer.vue) 底部突出“与 Personal Agent 讨论”，而“交给 Agent 处理”为 ghost，和用户推进任务的目标不一定匹配。

**决定**：工作标题/状态、当前或历史执行选择器、成果/待办摘要与当前主动作位于同一工作区顶部。详情采用契约 §4.1 的概览/讨论/执行/变更与测试/审查与交付结构，不把全部面板一路堆到底。未执行时以“交给 Agent”作为有权限者的主动作，待审查时以审查为主；普通讨论为次动作，工作状态与运行状态分开。审查页保留文件/版本/行评目标；危险确认在阅读影响之后，不因主动作靠前而跳过审核。

归并：R11/R12/R13/R16/R22/R23/R39/R42；F03 主责，A01/A05/A06 供事实；C06/C07/C10/C15。

### L06：筛选与说明吃掉首屏，手机看到的是控制面板而非工作

证据：[WorkItemsToolbar](../../crewscope-web/src/components/domain/WorkItemsToolbar.vue) 同时常驻三类筛选、两种视图、多个排序按钮及不可排序提示；[InboxWorkspace](../../crewscope-web/src/components/domain/InboxWorkspace.vue) 同时放大概览、分类说明卡、筛选和排序；[TodayPage](../../crewscope-web/src/pages/TodayPage.vue) 手机将筛选逐项铺开，且说明始终写“全部 WorkProject”，未体现当前项目过滤。历史 Work/Inbox 手机首屏主要被这些控件占据。

**决定**：列表工具条按“当前范围/已应用条件 → 搜索或筛选入口 → 视图/排序 → 创建”组织；手机显示筛选数量和条件摘要，详细筛选在展开区域，排序使用单一选择器而非一排等权按钮。Today 首先展示需要我行动，Inbox 首先展示待处理对象与业务动作；计数为辅助，不再重复大 Hero。空数据、无匹配、无权限、读取失败各自有不同下一步。隐藏筛选不等于清空，清除必须一次清所有可选条件。

归并：R12/R16/R20/R26/R30/R33/R41；F04 主责，A06 供查询/计数；C08/C09/C14/C15。

### L07：设置页以内部目录为先，静态绿色标签可能被当成当前健康

证据：ModelSettingsPage 把 Provider 目录放在日常连接管理前；底部治理卡的“服务端生效”标签为静态成功态，并未绑定逐项实际配置读取结果。[SetupPage](../../crewscope-web/src/pages/SetupPage.vue) 同时铺总进度、下一步、配置健康和能力清单，且刷新是主按钮；手机 Hero 仍有 220px 最小高度。Agent 页总览、类型入口卡与分组目录重复表达分类。飞书 Hero 仅依据 `online` 显示“安全管理可用”，不能代表连接/权限/健康已验证。

**决定**：模型默认先展示我能使用/管理的连接及故障补救，Provider/能力目录为次级入口；不能隐藏 A03 要实现的服务地址与模型管理。Setup 先显示用户目标与一个可执行下一步，已就绪项收起，完整健康诊断按需展开。Agent 默认目录按用途/可用性供选择，减少重复统计卡。只有有事实来源的状态才能用成功语义；产品能力说明使用中性说明，不伪装健康结果。未知、未检查和不可用分别显示，不以联网代替可用。

归并：R08/R10/R12/R17/R25/R37/R43；F02 负责目标就绪，A03 负责模型事实/页面，F04 负责 Agent/飞书呈现；C04/C14/C15。

### L08：成员页主入口是重新加入旧成员，新同事邀请藏在名单后

证据：[TeamMembersPage](../../crewscope-web/src/pages/TeamMembersPage.vue) 顶部和目录的“添加成员”只打开 `rejoinCandidates`，没有候选时再让用户找下方 TeamInvitationManager；新邀请区放在整份成员名单后。说明仍写“输入 Principal ID”，但实际控件已是选择器；窄屏直接隐藏加入方式/时间，没有本页展开入口。

**决定**：管理员默认主动作“邀请成员”，新成员/已有成员恢复分开命名；目录采用成员/邀请两个视图，邀请刚创建后就地显示复制结果和一次性提示。重新加入/恢复按服务端生命周期语义显示，不将历史 ID 复制作为普通操作。成员行先名字、角色、状态，再提供就地角色/交接/停用等 A07 动作；加入信息在详情可查。普通成员不看到不可用管理主动作，角色/状态不能只靠颜色。

归并：R12/R15/R21/R25/R29；A07 主责纵向操作，F04 接统一布局；C12/C13/C15。

### L09：反馈或危险动作离目标太远，换对象后易认错结果

证据：GitHub 把 success/error 放在页面顶部，导入操作在详情底部；[OperationsWorkspace](../../crewscope-web/src/components/domain/OperationsWorkspace.vue) 命令结果在整份诊断列表后；飞书命令反馈在页签之上，轮换/映射/重投发生在不同对象区域。GitHub 的验证/重新检查/撤销紧邻，飞书映射行直接发撤销；既有 R35 已指出目标固定问题，本轮补动作位置要求，不重复登记后端缺陷。

**决定**：读取/保存/导入/恢复反馈靠近原对象和发起动作，持续显示对象名及“已受理/正在同步/完成/未知”的实际阶段；全局 toast 仅作补充。切对象后旧反馈不能漂到新对象上。验证、同步、保存等常规动作在主区域；停用/撤销/移除/取消执行进独立危险区或更多菜单，并在最终确认里显示目标、影响和不能撤回的事实。现有强确认不削弱，临时收纳则按 R26 提供恢复而非一律加确认。

归并：R06/R13/R15/R25/R26/R35/R36/R37/R38；F01 保证目标/命令，各 A 包负责本页写动作，F04 接通用反馈；C03/C05/C09/C12/C15。

### L10：业务文案与技术诊断混层，说明还包含未经当前事实支持的承诺

证据：动态首屏解释 DTO/权威 API；运行页在恢复管理前放“一键演示证据入口”；飞书凭证弹窗写“本次 HTTPS 命令”，与支持 HTTP 部署不一致；OnboardingWorkspace 提示“创建后可在团队设置中调整”团队名，但本轮菜单走查未见对应编辑入口。NotFoundPage 在 AppShell 的 main/h1 内再套 main/h1，并用 `min-height:100vh`，加上壳后容易额外拉长错误页。

**决定**：普通界面统一使用工作项、执行、本次执行、审查、连接、仓库、团队等业务词；内部 DTO/ETag/Proof/Receipt 放诊断。技术缩写在确有必要时保留解释，不能为中文化改变协议值。“运行与发布”在普通导航归管理中的运行健康，不暗示这里能部署用户产物；演示入口移到帮助/文档。HTTP 页面不得承诺 TLS 加密传输，凭据提交旁提供事实一致的简短安全说明，但不重新强制 SSL。没有团队名修改能力就删除修改承诺，不顺带新增团队管理功能。404 保留一个页面标题和主要地标，返回/搜索集中显示。

归并：R10/R12/R17/R25/R27/R30；F02/F04，各配置包同步文案；C13/C15/C16。

### L11：窄屏详情视觉上移，却仍在列表后面的键盘顺序中

证据：[ActivityPage](../../crewscope-web/src/pages/ActivityPage.vue)、InboxWorkspace、[AuditExplorer](../../crewscope-web/src/components/domain/AuditExplorer.vue) 都是 DOM 列表先、详情后，窄屏用 `grid-row:1` 把详情视觉移到列表前。Inbox/Audit 有标题焦点处理，但后续 Tab/关闭返回仍需与视觉顺序一致。全站多处只读标签、胶囊、可点击状态和低对比辅助字并排，不能仅靠换肤辨别是否可操作。

**决定**：窄屏打开详情采用独立层级，返回恢复原列表；不以 CSS order/grid-row 伪造与键盘相反的流程。桌面详情若与列表同屏，应明确选中行与详情对应关系；长详情可读，关闭不清空筛选。保留现有 AA 色彩 Token，正文使用正文级字号，密度仅改变间距/行高，不隐藏字段能力；主要触屏按钮使用既有触控最小尺寸。状态、选择、hover、错误各用不同语义；状态是否可点有一致样式和名称。

归并：R12/R16/R27/R28/R30；F04 主责，F03 消费共享细节；C13/C15。

### L12：认证/账号页应保持简单，确认身份要比系统初始化细节更醒目

证据：[Login](../../crewscope-web/src/pages/LoginPage.vue)/[Register](../../crewscope-web/src/pages/RegisterPage.vue) 已有明确标签、密码自动填充与错误摘要，优先保留；[InvitationWorkspace](../../crewscope-web/src/components/auth/InvitationWorkspace.vue) 接受区显示团队/角色/有效期，但 `authenticated` 仅为布尔值，没有当前账号身份展示；[OnboardingWorkspace](../../crewscope-web/src/components/auth/OnboardingWorkspace.vue) “已就绪”主要依据初始化投影，不代表模型已经能回复。AccountWorkspace 修改密码/退出全部设备的影响说明已有，不重复说它缺失。

**决定**：邀请接受区增加当前账号的受权名称/邮箱提示和明确换账号路径；换账号走现有安全退出/登录流程，保留安全邀请上下文，不自动接受、不把邀请明文扩散到返回 URL。初始化只说明实际完成的步骤，下一步按只对话/Coding 目标继续。账号资料、外观/本人通知、安全分区清晰；不新增找回密码、设备管理平台或不存在的“保持登录”控件。窄屏表单先字段/错误/提交，再辅助说明，200% 缩放与错误展开后按钮仍可达。

归并：R10/R24/R25/R27/R29/R30/R31；A07 提供受权邀请结果，F02 负责认证返回，F04 负责账号；C11/C12/C13/C15。
