> 审查范围：`M0-D06`、`M0-E01`–`M0-E03`、`M0-I01`–`M0-I04`、`M0-A01`–`M0-A02`<br>
> 审查日期：2026-08-07<br>
> 目标：形成 M0 事件、存储、凭证、API 和可观测性的稳定提交基线

## 1. 结论

业务状态、DomainEvent、Outbox 和 Command Receipt 的本地事务边界成立。Outbox 的 Claim Token、Lease、退避、Dead Letter、分区顺序和消费回执能够提供至少一次投递。ArtifactStore 和 CredentialStore 的租户、完整性、并发与脱敏边界与 ADR 一致。API 命令协议、Correlation ID、Trace、MDC、结构化日志和低基数指标可以作为 M0 基线。

提交前需要完成三项边界收紧。

## 2. 提交前修正

| ID | 级别 | 问题 | 修正规则 | 验证 |
|---|---|---|---|---|
| `R01` | 必须 | Projection Mapper 校验 Event ID、Partition 和时间，但会接受非 DomainEvent Topic | Audit Projection 只接受 `crewscope.domain-events.v1`，Topic 不匹配时在写入回执、Checkpoint 和 AuditEvent 前拒绝 | Mapper 单元测试证明正确 Topic 可映射，错误 Topic 被拒绝 |
| `R02` | 必须 | Worker ID 的 200 字符数据库边界只在首次 Claim 时校验 | Publisher 构造时即校验非空、去除外围空白和最大长度，与 JDBC Adapter 共用单一常量 | 构造契约测试证明 200 字符可用，201 字符立即失败 |
| `R03` | 必须 | 租约和退避只校验严格为正，但小于 1ms 的值会在数据库时间精度和 `Duration.toMillis()` 处理中退化 | Claim Lease、Initial Backoff 和 Maximum Backoff 统一不小于 1ms | 单元测试覆盖亚毫秒拒绝、1ms 边界和退避大小关系 |

## 3. 审查后保持不变

- 同一 Topic/Partition 只领取最早未完成事件，不同分区使用有界线程池并发；
- Projection 使用 Aggregate Version、Occurred At 和 Event ID 处理同版本多事件和 Gap；
- FilesystemArtifactStore 使用内容寻址、原子移动、逻辑引用和跨进程文件锁；
- CredentialStore 使用 AES-256-GCM、确定性 AAD、显式允许集、乐观锁、轮换与 Rewrap；
- 未知 API 异常只返回安全错误信封，日志和指标不使用请求路径 ID、Correlation ID、凭证或异常消息作为标签。
