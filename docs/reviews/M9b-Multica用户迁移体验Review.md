# M9b：从 Multica 用户迁移意愿出发的产品 Review

日期：2026-09-19。承接 [全流程 Review](M9后-全流程使用体验与竞品对照Review.md)、[菜单逐操作 Review](M9b-菜单逐操作产品Review.md) 与 [M9b 计划](../plans/M9b-核心流程与使用体验收口.md)。这是审查与待实施要求，不是修复报告。

验收方式已按用户要求调整：保留迁移用户视角的产品判断，取消真人招募、访谈、理解度和迁移意愿测评。全部验收改为固定场景、浏览器操作和可核对的行为/视觉证据；不以真人参与作为关闭条件。

## 1. 如果我是 Multica 用户，现在会不会迁移

**不会仅因为 CrewScope 换了样式就迁移。当前主流程还有阻断，日常工作还需要在工作项、对话、执行和配置之间自行拼上下文。** 对已用顺手的用户，换工具意味着重新配置、重新理解概念、重新建立信任；“功能也有”不足以抵消这笔成本。

我愿意先试一个项目的条件是：

1. **上手不退步**：不用填 Key，不用读架构说明，只配置实际需要的能力；明确原有 CLI/runtime、订阅、技能、历史记录哪些不能直接带过来。
2. **高频操作不退步**：创建、改说明、补充要求、选 Agent、找回工作、阅读结果和处理通知顺手；不把一次任务变成重复配置。
3. **结果更容易放心交给团队**：一眼看清本次产出、测试依据、待我决定、谁负责和是否已对外提交；出错后不重复执行、不丢上下文。

第三点是 CrewScope 可以争取的差异化方向，**不是已经证实优于 Multica**。Multica 也有执行历史、权限与确认；不能把“竞品没有治理”当论据。CrewScope 的责任快照、人工审查和外部结果对账，必须转化成更省心的可见操作，不能转化成更多必填字段。这里的人工审查是业务权限流程，测试由自动化操作对应账号验证，不要求真人参加测评。

## 3. 四项新增问题

### R40（P2）：同一份工作内容在不同入口读起来不一样，表格还会丢信息

证据：[SafeMarkdown.vue](../../crewscope-web/src/components/domain/SafeMarkdown.vue) 的允许标签不含 table/thead/tbody/tr/th/td；它由 [ConversationPage](../../crewscope-web/src/pages/ConversationPage.vue) 与 [CodingDiffExplorer](../../crewscope-web/src/components/domain/CodingDiffExplorer.vue) 使用。[WorkItemDetailDrawer](../../crewscope-web/src/components/domain/WorkItemDetailDrawer.vue) 的描述与评论分别用 `{{ item.description }}`、`{{ entry.content }}` 输出纯文本。不能说全站完全没有 Markdown，但阅读能力不一致。

条件模拟：输入两列表格“用例/结果、登录/通过、注册/失败”，MarkdownIt 生成完整表格；调用实际清洗函数后只剩登录/通过/注册/失败文本，表头和行列结构消失。即使修好了 R19 的长消息高度，测试对照仍可能被读错。

最小交付：

- 复用并完善安全渲染组件，先支持标题、段落、列表、引用、代码、链接、表格；需求描述、普通评论、聊天、行评按适用能力一致呈现，保留原文与复制。
- 表格在内容区内横滚、表头不丢；代码显示语言/换行策略、复制原文与失败提示；复制不能把高亮标记当代码。
- 轻量编辑提供 Markdown 提示/预览及少量常用插入，不要求引入完整所见即所得编辑器；已有纯文本不自动改写存储格式。
- 保留禁止原始 HTML、危险链接等边界；不为显示表格放开任意 HTML/脚本、iframe 或远端图片自动请求。

责任：F03 主责共享内容与主路径，F04 接剩余展示；F05 保护编辑草稿。验收包括表头/单元格关联、长中文/代码/链接、流式和最终内容、复制失败、恶意 Markdown、390px/200% 缩放。**表格回归要断言语义结构，不仅断言文字存在。**

### R41（P2）：有临时筛选和最近访问，但缺少用户主动固定的日常工作环境

证据：[WorkPage](../../crewscope-web/src/pages/WorkPage.vue) 通过 URL 管理列表/看板、类型/状态/优先级/排序，[TodayPage](../../crewscope-web/src/pages/TodayPage.vue) 已有个人工作与责任角色筛选；[AppShell](../../crewscope-web/src/components/layout/AppShell.vue) 是固定导航，[CommandPalette](../../crewscope-web/src/components/action/CommandPalette.vue) 是最近访问。当前入口未见命名保存视图、固定工作/项目与取消固定闭环。**不是没有个人工作，也不是没有可分享筛选。**

对每天回访三个项目、同一待审筛选的用户，自动最近访问不能替代主动固定；每次从通用导航出发会损失迁移后的效率。

最小交付：保存当前受支持筛选为个人视图，重命名/更新/删除；固定/取消固定受权工作或项目，支持调整顺序；视图显示作用范围，打开时重新授权、处理失效对象。先做本浏览器个人能力并标注“不跨设备同步”，不新造共享视图平台或 Gantt。

责任：F04 主责入口/视图，F05 提供账号、Team、版本化缓存与清理。保存定义而非复制业务数据；显式 URL 优先于默认偏好，不能让旧偏好覆盖别人分享的筛选。只允许当前 A06 支持的全量筛选，不制造仅过滤首屏的视图。

验收：新窗口/刷新、分享视图、切账号/Team、删项目/撤权、存储禁用、老版本偏好、清除全部固定项；不可显示另一账号的固定标题。需要跨设备时另立需求，不暗中存服务端却无权限模型。

### R42（P2）：评论、对话、指派、要求修改的“发给谁/会不会执行”缺少统一产品合同

证据：[WorkItemDetailDrawer](../../crewscope-web/src/components/domain/WorkItemDetailDrawer.vue) 是普通“发送评论”；[WorkItemQueryController](../../crewscope-server/src/main/java/io/crewscope/server/api/WorkItemQueryController.java) 的评论请求仅带 content，[WorkItemCollaborationService](../../crewscope-application/src/main/java/io/crewscope/application/workitem/WorkItemCollaborationService.java) 落评论及事件；[ConversationPage](../../crewscope-web/src/pages/ConversationPage.vue) 的 submitMessage 则在有调用权时走 Agent invoke，其他路径发普通消息。审查“要求修改”又是独立流程。当前普通评论表单没有明确目标 Agent、所引用版本或本次调用回执。

这不是要求照搬 Multica 的 @ 自动触发，也不据此断言所有后台消费者都不可能处理评论。确认的产品缺口是：习惯在工作下回复“再改一下”的用户，不能仅从当前操作判断是否只是留了记录、是否启动了 AI、是否影响正在执行的版本。

最小交付：

- 工作区提供明确的“发布评论（记录讨论）”与“让 Agent 处理”意图；选后者时预览 Agent、关联工作、引用内容及将继续哪条对话/新建哪次执行，使用已有委托/对话合同。
- 原文引用带来源坐标和版本；只传授权、用户确认的内容，不能把私聊全部自动复制到团队工作。
- 不支持向当前 Coding 执行追加要求时，明示“当前执行仍按原说明”；可保存讨论并走受支持的新一轮/要求修改流程，不能假称已实时注入。
- 普通文本 `@名字` 不伪装成真实提及；若无提及能力，给显式 Agent 选择。评论发布与启动部分成功时分别记录，重试不能重复评论或执行。

责任：A05 冻结意图/上下文引用和必要编排，F03 接工作区，F01/F05 复用结果恢复和草稿。验收覆盖普通评论无意外费用、双击/丢响应、不同运行阶段、切 Agent/版本、撤权和私有对话边界；人审不能被普通回复绕过。

### R43（P2）：输入框固定显示“预算 32,000”，看似精确却不是当前模型事实

证据：[ConversationComposer](../../crewscope-web/src/components/domain/ConversationComposer.vue) 给 `modelBudget` 默认值 32000，同时展示 `modelValue.length / 50,000 · 预算 …`；[ConversationPage](../../crewscope-web/src/pages/ConversationPage.vue) 使用时未传真实预算。字符长度、模型上下文窗口、剩余 token 与费用不是同一单位。

对接入不同模型的迁移用户，这会误导“还能发多少/会花多少”。不能把它包装成成本控制优势，也不能仅把 32,000 换成另一个常量。

最小交付：保留真实输入长度限制并明确计数口径；未有模型事实时去掉伪预算。已知时分别展示有效模型/来源、服务端生效限制、已报告 token/成本的单位、时间与估算性质；历史执行显示自己的快照，不跟随当前模型切换。未知费用写未知，不能写 0 或剩余额度充足。

责任：A03 定义能力/限制来源与未知语义，F03 接显示；已有公开用量可复用，无数据则诚实省略，不新增计费/配额系统。验收覆盖模型切换、缺失目录字段、中文/emoji 计数、旧执行和部分用量，确保输入限制与后端约束一致。

| R25/R32 等待与异常 | 先说发生了什么、影响什么、下一步，诊断 ID 可复制；短暂刷新不整页遮挡；显示最后成功观测与状态未知 | 把所有失败引到运维；伪进度、无限转圈或永远“刚刚” |
| R26 通知收纳 | 升级为查看已归档、恢复归档、重新标未读的真实闭环，计数与批处理同步，来源审批/任务不回滚 | 仅增加“不可恢复”提示作为最终交付；只在前端撤销样式 |
| R29/R31 团队协作 | 邀请说明身份/权限/通知方式；本人偏好在账号或 Inbox；跨成员交接有可读摘要 | 邀请邮箱输入让人误以为已发邮件；普通成员还须进入集成管理 |
| R17 验收 | 固定首用/创建/补充要求/回访等脚本，验证步骤、目标、反馈、恢复；公开仍不支持的能力，不要求运行竞品或真人参与 | 截图更漂亮、组件测试通过就宣称用户愿意迁移 |

### 4.1 Inbox 的升级涉及后端，不只加按钮

[InboxDisposition](../../crewscope-domain/src/main/java/io/crewscope/domain/inbox/InboxDisposition.java) 的 transitionTo 拒绝逆向状态，UNREAD 以无记录表示；[InboxPage](../../crewscope-web/src/pages/InboxPage.vue) 的写动作也排除 UNREAD。上一轮“缺恢复则先明确不可撤回”仍可作为过渡提示，**不再作为 M9b 最终关闭标准**。

F04 主责最小领域/API/投影和 UI 增量：为本人收纳定义合法恢复与未读语义，强版本、幂等、权限及审计，保留源业务状态。后续 [实现契约 §5.1](../plans/M9b-实现边界与验收契约.md) 已选定恢复到 READ 并说明，重新标未读为持久 UNREAD/正版本，不通过删除历史行伪造未读，也不假称恢复了未记录的归档前状态。旧客户端兼容、计数/分页/深链、两窗口冲突和批量部分失败均要回归。不新增提醒调度/订阅平台。

### 4.2 附件、迁移和兼容性的明确取舍

本期不为竞品对齐强上完整附件/富文本/Slash 平台，也不静默扩大 M10/M11。M9b 至少把文字、Markdown、受权站内引用和显式外链做可靠；外链可点击不等于 Agent 已读取。图片/文件输入依赖的存储、访问授权、扫描/大小限制、模型视觉支持未完成时，明确列为迁移缺口。

如果目标用户的核心工作依赖截图标注、任意附件、本机 CLI 订阅、Squad/自动化或自定义工作流，**即使本期通过，也不能宣传为完整替代 Multica**。S01 根据支持矩阵记录适用范围和缺口，不要求访谈；新的平台能力另立经确认的范围，不把本期缺口换成假按钮。

## 5. 前端视觉与微交互验收规范

以下是要落实到现有设计规范的产品约束，不新建另一套 token，不照抄 Multica 商标/配色。基于现有截图提出的判断需在新实现上重新截图验收。

| 细节 | 建议结果 | 验证方式 |
| --- | --- | --- |
| 默认导航 | 工作优先、团队/设置折叠、当前项目可辨；常用固定入口不盖过待处理 | 普通成员/管理员、零/多项目、390px、键盘展开 |
| 首屏层级 | 保留一个页面标题、一个主任务入口；多余 Scope/工作标题不层层重述 | 1440×900 与 390×844 首屏能看到真实内容与主动作，不以压字实现 |
| 列表节奏 | 标题占主要宽度；状态、负责人、日期有固定对齐；不为每个字段套胶囊 | 长短标题、中文/英文、20+ 行、选中与 hover 同时可辨 |
| 颜色语义 | 绿色品牌不代表任务成功；运行、待我处理、阻塞、未知有文字/图标；危险色留给当前有后果的动作 | 两主题、灰度识别、现有 AA 对比度回归；不重引入旧颜色问题 |
| 字号与密度 | 使用现有语义字号和两种密度；正文可连续阅读，辅助文本不占注意力 | 200% 缩放、中文字体、320px 降级；密度变化不藏操作 |
| 表单默认值 | 合理默认、真实字段标签、可选项可识别；说明只讲约束/影响，不复述标题 | 仅标题创建、复杂创建、冲突、回设置后继续 |
| 保存与草稿 | 清楚区分“仅本机草稿/保存中/已保存/失败”；取消含义与实际一致 | 刷新、断网、禁用存储、切对象/身份，无秘密落盘 |
| 行内编辑 | 选中字段就地改，Enter/保存与 Escape/取消清楚，错误贴近字段 | IME、Tab、冲突、切行；失败不能看似已生效 |
| 对话阅读 | 阅读区优先；参与者/关联工作默认摘要或折叠，待确认卡例外；新增消息不强拉历史阅读者 | 长回复、流式、滚回底部、移动软键盘 |
| 内容呈现 | 相同 Markdown 跨面一致，表格/代码可读和复制；宽内容只滚自己 | R40 语义/安全测试，加窄屏真实截图 |
| 详情与返回 | 快速预览和深入工作有明确区分；关闭不丢筛选、选中、滚动 | 列表→详情→审查→返回，浏览器前进/后退，新窗口链接 |
| 动作风险 | 常见低风险操作可快速做且可恢复；外部写入/撤权/取消显示目标和影响 | 鼠标/键盘/触屏同等确认，不用统一“确定吗” |
| 异步反馈 | 提交立即显示真实 pending；旧内容可读；成功后定位结果而非仅 toast | 丢响应、超时、后台恢复、部分成功；不假乐观完成 |
| 空态与筛选 | 无工作/无匹配/无权限/数据失败分别解释；清筛选与创建不混用 | 四态加续页失败；空态不反复推已完成设置 |
| 键盘与链接 | 搜索/创建快捷键可发现；所有菜单与弹层可退出；标准链接支持复制/新页 | 中文输入法、读屏标签、焦点还原；快捷键不劫持输入 |
| 成果与通知 | 待我操作靠近工作；批处理有逐项结果；消息不靠只闪一下提醒 | 错误不消失、恢复归档/未读、后台回来发现变化 |
| 文案与身份 | 默认中文一致：工作项/执行/本次执行/待审查；人/Agent 显示可读名字与必要角色 | 不出现孤立 Hash/Proof/Grant 或重复英文眉题；诊断可访问 |

重点不是“所有页面变成白底小字”。例如原 Work 截图的筛选卡、工作列表、Agent Tasks、页尾权限说明都抢占空间；Conversation 的关联卡先于消息。优化应减少重复和技术解释、让正文靠前，而不是删除关键权限说明或把重要结果折叠得更深。

## 7. 迁移路径验证：固定场景，不设真人验收

### 7.1 一个项目的低风险试用

F02/Q02 增加简短试用指南：挑一个非敏感小任务 → 手工带入标题/说明/原链接 → 连接确实支持的模型与仓库 → 执行并审查 → 将结果交回。原编号作为来源文本/链接保留，不强填 CrewScope Key；不伪造历史作者/审批、复制旧凭据或把 Multica 私有 URL 当作已授权导入。

不要求先搬全量历史，不新增批量导入/双向同步平台；已有任务仍留原系统，避免迁移中误认为两边实时同步。能试一个项目不等于已有完整迁移工具。

### 7.2 场景脚本与关闭条件

Q02 使用隔离测试账号与固定数据，由浏览器自动化执行，必要时由编码代理操作浏览器补证。删除原有参与人数、30 秒理解度、2/3 完成率/迁移意愿及竞品真人效率对照要求；无需招募用户或安装运行 Multica。竞品源码只作为路径设计参考，验收对象是 CrewScope 的行为与呈现。

| 场景任务 | 记录/关闭要求 |
| --- | --- |
| 环境配置与首次回复 | 空账号/团队走正式入口，不预置绕过待测配置；真实 Provider 行按授权验证，其余场景明确测试层次 |
| 已配置项目创建并启动 | 按冻结步骤完成，不跳设置、不重复填写项目默认值、不填内部 Key；断言资源定位及执行次数，留 trace |
| 补充要求、修改说明 | 断言调用对象、是否执行、影响当前还是下一轮的说明与请求一致；发送记录与执行定位正确，无意外外部写入 |
| 阅读结果与审查 | 在固定桌面/窄屏视口检查产出、测试事实、待办责任和主动作可见/可达；证据打开正确版本，完成意见/要求修改 |
| 次日回来与清理通知 | 重开页面找回固定工作/视图，处理后恢复误归档、标未读；断言筛选/滚动/草稿保留 |
| 失败恢复与边界 | 网络未知、冲突、撤权、取消/返回均有确定断言；记录不支持能力，不能用假按钮通过 |

S01 冻结输入、权限、视口、预期步骤与行为断言；执行时记录实际路径、失败位置、API 结果、trace 和关键截图。脚本可读写两个隔离身份以测试权限与业务审批，但不能绕过服务端规则。沿用工程性能预算，不把浏览器脚本速度当真人效率，也不再设竞品 1.2 倍时间门槛。

场景通过只证明这些路径、展示与恢复符合合同，不证明真人满意度或迁移意愿。若核心依赖附件/本机 CLI 等未支持能力，则按 §4.2 说明适用范围，不宣称完整替代。
