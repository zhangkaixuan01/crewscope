# M1-A01–A07 提交前审查

> 审查范围：`M1-A01`–`M1-A07`<br>
> 审查日期：2026-08-08<br>
> 目标：形成 Team、身份映射、WorkProject、WorkItem、责任链与时间线应用层纵向闭环的稳定提交基线

## 1. 结论

M1 应用层采用纯 Java Application Service，`crewscope-server` 组合根负责 Spring Bean 装配，Controller 使用 `@RestController` 与构造器注入，基础设施 Adapter 使用 `@Repository`。认证主体、Organization、Team、Workspace、WorkProject 与 WorkItem Scope 均由服务端解析和校验；写命令使用 REQUIRED 事务原子提交业务事实、DomainEvent、Outbox 与 CommandReceipt。

提交前发现并修正三项会影响产品不变式或公开协议的问题。修正后 M1-A01–A07 可以作为前端 M1-F01–F04 的稳定后端基线。

## 2. 提交前修正

| ID | 级别 | 问题 | 修正规则 | 验证 |
|---|---|---|---|---|
| `R01` | 必须 | Native WorkItem 创建与首次 Owner 分配原为两个公开命令，两个事务之间存在可见的无 Owner 窗口 | 创建者自动成为初始 Owner；WorkItem、ResponsibilityAssignment、`WORK_ITEM_CREATED`、Outbox 与 CommandReceipt 在同一事务提交；创建事件携带初始 Owner Assignment 与 Principal 坐标 | Application 测试校验创建即存在 Owner 和事件坐标；PostgreSQL 并发同 Key 场景校验只提交一份 WorkItem 与一份 ACTIVE Owner |
| `R02` | 必须 | 旧 M0 `WorkItemApplicationService` 仍注册为生产 Bean，可绕过 M1 Membership、Role Scope、WorkProject 锁与初始 Owner 规则 | 生产组合根只注册 `WorkItemCommandService`；旧类暂留给 M0 原子事件兼容测试，不进入运行时依赖注入图 | Spring Context 测试证明 M1 WorkItem 服务及其责任 Repository 依赖可以唯一装配，旧服务不再成为 Bean |
| `R03` | 必须 | Team 与 WorkProject Command Request Hash 未包含 Causation，与 ADR-007 的可信因果链规则不一致 | Team 创建、成员加入、遗留 Team 补全和 WorkProject 创建统一把规范化 Causation ID 纳入 Request Hash；Correlation ID 继续不改变命令语义 | 单元测试证明同一 Idempotency-Key、同一业务字段但不同 Causation 返回 `idempotency_conflict` |

同时移除了 Team 创建入口的一次重复 ACTIVE USER 校验，保留统一 `requireCommandContext` 信任边界。

## 3. 审查后保持不变

- Bootstrap 与 OIDC Subject 通过数据库唯一边界原子映射到 Organization Scope USER Principal；认证不会自动产生 Team Membership；
- OIDC 部署绑定单一 Organization，请求路径不能跨租户创建或解析 Principal；
- Team 创建、成员加入与遗留 Team 补全原子闭合 Membership、内置角色、Grant、默认 Workspace 和默认 Personal Agent；
- WorkProject Key 与 WorkItem Key 分别使用 Team 行锁和 WorkProject 行锁串行化并发创建，数据库唯一约束负责最终裁决；
- WorkItem 状态迁移、Owner 替换和 Assignment 释放保留强 ETag、乐观锁与 Assignment ID + Version 的 ABA 防护；
- 查询先完成 ACTIVE Membership 与完整 Scope 授权，再读取详情、责任链或时间线；查询响应继续使用 `Cache-Control: no-store`；
- 时间线只公开 M1 业务事件白名单，以 DomainEvent ID 合并 Audit 投影副本，并使用专用 Keyset Cursor 续传；
- Application/Domain 不依赖 Spring 注解，组合根按业务边界显式装配，不恢复跨业务集中配置类。
