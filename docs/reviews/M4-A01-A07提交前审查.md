## 1. 结论

M4 应用层已将受管仓库目标接入耐久 Task Runtime，闭合了 Workspace、Sandbox、受控 Tool、Diff、TestEvidence、Artifact 和 Runtime Fleet。公开 API 均从服务端身份与完整 Scope 出发，写命令使用 CommandReceipt、DomainEvent 和 Outbox，成员投影使用显式白名单。

## 2. 提交前修正

| ID | 级别 | 问题 | 修正规则 | 验证 |
|---|---|---|---|---|
| `R01` | 必须 | Coding Artifact 对起点有效、结束位置超过对象末尾的标准单 Range 返回 `416`，与 HTTP Range 和尾页字节分页语义不符 | 开始位置小于对象大小时，将结束位置截断到 `totalSize`；开始越界或空对象 Range 继续返回 `416` | Application 测试覆盖超长闭区间与尾页截断，HTTP 测试校验 `206` 和精确 `Content-Range` |

## 3. 审查后保持不变

- RepositoryBinding 只保存稳定 Repository Key，宿主路径仅存在于 Worker 基础设施对象；
- CodingTargetSnapshot 在首个 attempt 前原子固化完整 Scope、Commit、AllowedPaths 和精确 BuildProfile；
- Durable Worker 使用 Lease/Fencing 串联 Workspace Provision、Recover、Finalize 和跨 Worker 写预算；
- Coding attempt 查询使用专用读模型，查询次数不随 DiffFile 和 Evidence 数量增长；
- Workspace、Diff、TestEvidence 和最终 DiffArtifact 进入统一耐久 Task Timeline，SSE 每轮重新校验当前成员权限；
- Artifact 读取先闭合 Task/attempt/Evidence 归属并验证完整 Blob Hash，再返回有界流；
- Runtime Fleet 成员摘要不包含宿主路径、容器、Lease、Token 或存储 URI，运维命令保持有界、幂等、可审计；
- Application/Domain 保持纯 Java，Spring 组合根使用明确 `@Bean` 和构造器注入。
