# M0-F01–M1-D04 提交前审查

> 目标：形成前端工程、Release Gate、Team 与 WorkItem 领域模型的稳定提交基线

## 1. 结论

Conversation/Control 双入口、前端设计系统、API Client、浏览器测试和 CI Release Gate 已形成可演进的 Web 基线。Principal、TeamMember、TeamRole、MemberRole、Team 初始化、默认 Personal Agent、WorkProject、WorkItem、Comment 和 ResourceLink 的职责边界清晰，领域层没有依赖 Spring、JPA 或外部 SDK，也没有提前破坏 M0 Repository 契约。

提交前需要完成四项边界收紧。

## 2. 提交前修正

| ID | 级别 | 问题 | 修正规则 | 验证 |
|---|---|---|---|---|
| `R01` | 必须 | `MemberRole.reconstitute` 会接受 `REVOKED/EXPIRED` 事实时间晚于 Lifecycle UpdatedAt 的非法快照 | 终态快照必须保证 UpdatedAt 不早于 RevokedAt 或 ExpiresAt | 领域测试覆盖两类非法终态快照 |
| `R02` | 必须 | API Client 将 `idempotencyKey`、`expectedVersion` 等内部选项随 `RequestInit` 传给 `fetch` | 内部命令选项只用于生成标准请求头，调用 `fetch` 前显式剥离 | Client 测试断言非标准属性不进入 Fetch RequestInit |
| `R03` | 必须 | Vitest Coverage 只生成报告，不阻止覆盖率持续退化 | Release Gate 固定全局最低门槛：Statements 80%、Branches 70%、Functions 75%、Lines 80% | `pnpm test:coverage` 达标并在低于门槛时失败 |
| `R04` | 清理 | Playwright 视觉目录同时存在当前稳定命名和旧 OS/Project 重复命名 | 只保留 Snapshot Template 生成的 Conversation/Control 桌面与窄屏 4 张基线 | Playwright 4 个测试通过且无孤立截图 |

## 3. 审查后保持不变

- M0 WorkItem 简化创建与重建入口继续兼容现有 Repository、事件和 API；
- M1 完整 Team、WorkProject、WorkItem、Comment 和 ResourceLink 字段由 D07/D08 落库；
- TeamRole 表示团队权限，ResponsibilityAssignment 表示工作对象责任；
- 默认 Personal Agent 以 TeamMember 为稳定边界，Principal 与 AgentProfile 原子初始化；

- TeamMember、TeamRole 和责任授权由应用层解析，领域对象继续校验 Principal 状态和 Scope。

## 4. 提交门槛

1. 四项修正均完成并有自动化验证；
2. `./mvnw --batch-mode --no-transfer-progress clean verify` 通过；
3. `pnpm test:coverage`、`pnpm build`、`pnpm story:build` 和 `pnpm test:e2e` 通过；
4. Markdown 链接检查与 `git diff --check` 通过；
5. 变更按前端/质量基线与 M1 领域模型拆分提交。
