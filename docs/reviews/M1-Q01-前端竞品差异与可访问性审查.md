## 审查基线

本次审查使用本地源码固定版本：

| 项目 | 提交 | 主要审查入口 |
|---|---|---|
| `vibe-kanban` | `4deb7eca8` | README、`ProjectKanban`、`KanbanContainer`、`WorkspacesLayout`、`RightSidebar`、`TerminalPanelContainer`、Diff Renderer |
| `multica` | `a8d5daac5` | README、`app-sidebar`、Issues Surface、Issue Detail、Chat、Inbox、Agent Detail 与 Agent Presence |
| `crewscope-java` | `61197b8` 加 M1 工作区改动 | AppShell、ScopeSwitcher、Work、WorkItem Detail、ResponsibilityChain 与 Timeline |

`vibe-kanban` 的产品重心是从 Kanban Issue 创建 Coding Workspace，并在一个执行工作区联动 Agent 会话、Terminal、Preview 和 Diff。`multica` 的产品重心是把外部 Coding Agent 作为 Workspace 队友，提供 Issue、Chat、Inbox、Agent、Squad、Skill、Runtime 和 Autopilot 管理面。

## 能力吸收

M1 已吸收以下成熟交互原则：

- 工作集合同时提供 List 与 Board，并把视图、筛选和 Scope 固化到 URL；
- Scope 切换、详情深链接、刷新恢复和浏览器前进后退保持一致；
- 详情使用检查器式抽屉，集合上下文继续可见；
- Loading、Empty、Error、Forbidden、Conflict 采用稳定状态组件；
- 桌面和窄屏共享业务语义，窄屏采用单列布局与底部主要操作；
- 执行进度、Diff、Terminal、Preview、Inbox 和 Agent Presence 作为后续里程碑的交互研究输入。

这些原则通过 CrewScope 自己的 Vue 组件、API 契约、Design Token 和测试实现。

## 差异矩阵

| 维度 | `vibe-kanban` | `multica` | CrewScope M1 |
|---|---|---|---|
| 导航 | Project、Issue 与 Coding Workspace 路径 | Workspace 下 Issues、Inbox、Chat、Agents 等产品对象 | Conversation/Control 双模式；Control 以 Today、Work、团队成员组织，Operate 与 Observe 能力按里程碑开放 |
| 页面布局 | Kanban 到执行 Workspace，Terminal、Preview、Diff 占主要空间 | Issue 多视图、右侧详情、Agent 与 Inbox 管理面 | Scope 头部 + List/Board + WorkItem 责任详情抽屉；责任和事实链先于执行面板 |
| 视觉 Token | 高密度 Coding 工具界面 | 中性协作 SaaS 体系 | 浅绿色品牌面、暖灰画布、深绿操作色、紫色 Agent 语义色；人类和 Agent 具有独立视觉语义 |
| 核心组件 | Workspace、Terminal、Preview、Diff Review | Issue Surface、Agent Presence、Chat、Inbox、Squad | ScopeSwitcher、WorkItemCard、ResponsibilityChain、Reviewer Policy 提示、业务 Timeline |
| 任务流 | 选择外部 Coding Agent 并创建执行 Workspace | 将 Issue 分派给外部 Agent 或 Squad，由 Runtime 执行 | USER 始终承担 Owner 与 Gate Review；Executor 可为人或 Agent；服务端裁决 Membership、Scope、职责分离与 PolicyPack |

| 审计语义 | 侧重执行会话、Diff 与 PR 结果 | 侧重 Agent 活动、Issue 和 Runtime 状态 | Command Receipt、DomainEvent、AuditEvent、责任历史和 Timeline 形成统一事实链 |

## CrewScope 产品边界

M1 继续固定以下边界：

- 人类 Owner 对交付结果负责，人类 Gate Reviewer 做最终 Gate Decision；
- Agent 使用独立 Principal 类型进入责任链，Advisory Reviewer 的建议不获得 Gate 效力；
- 前端权限只用于界面裁剪，服务端是 Membership、Scope、授权、资格与并发裁决边界；
- WorkItem 与责任命令使用幂等键、强 ETag、Assignment Version 和 Owner ABA 期望；
- Timeline 只解释服务端白名单事件，并通过事件 ID 和不透明 Cursor 去重；
- M1 不创建模拟 Agent、TaskExecution 或运行状态。

提交前页面复核发现 Conversation 骨架仍使用了容易被理解为真实事实的执行中状态、运行编号、进度、耗时和 Diff 数量。该页面已按前端规范收敛为 M2 原型预览：保留对话、计划、证据和 Review Gate 的信息结构，仅展示交互蓝图与预期边界，不暗示已经创建 Conversation、TaskIntent、TaskExecution 或 AgentRun。

同一轮复核修正了 Work 筛选清除的路由竞态、Work 空状态 Action Slot、ScopeSwitcher 的非模态展开语义，以及 Team Member 目录中无行为的复制图标；Playwright 固定业务时钟，防止 Today 日期使视觉基线跨日漂移。WorkItem Key 的本地自动值保留为可编辑建议，项目范围唯一性继续由服务端裁决。

## 可访问性与响应式证据

Playwright 在 1440×960 和 390×844 两个视口执行：

- Today、Work、Team Members 和 WorkItem Detail 的 Axe 自动扫描；
- WCAG 2 A/AA、WCAG 2.1 AA 与 WCAG 2.2 AA 规则无违规；
- WorkItem Detail 打开后焦点进入关闭按钮，Tab 在抽屉内循环，Escape 关闭后焦点回到原 WorkItemCard；
- List、Board、详情抽屉与 ResponsibilityChain 在两种视口下可读、可滚动、可操作；
- Team Members 使用完整 ARIA Table、ColumnHeader 和 Cell 语义；
- 导航分组和次级文本颜色满足自动对比度检查。

## 审查结论

CrewScope 的页面结构、Token、组件语义和任务流与两个参考项目形成明确差异。M1 吸收了成熟的集合管理、详情检查器、URL 状态和响应式模式，同时把团队责任、服务端治理、对话/管理双入口和原生 AgentScope Runtime 保持为产品主线。
