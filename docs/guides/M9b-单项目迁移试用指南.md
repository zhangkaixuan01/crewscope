# M9b 单项目迁移试用指南

适用成员：正在考虑从现有任务系统（如 Multica）迁到 CrewScope 的团队。本指南描述**一个项目的低风险试用**路径——它验证「CrewScope 能否承接一件真实工作」，不构成全量迁移方案。来源与取舍见《[M9b-Multica 用户迁移体验 Review](../reviews/M9b-Multica用户迁移体验Review.md)》§7.1。

## 五步试用

1. **挑一个非敏感小任务。** 选择一件边界清晰、一两天内能闭环、不涉及私有凭证与合规红线的工作（例如一次小型重构或一份文档评审）。不要用核心生产任务做第一次试用。
2. **手工带入上下文。** 在 CrewScope 创建 WorkProject 与工作项时，把原标题、说明与原系统链接（Multica URL 等）作为文本填入。**原编号保留为来源文本，不要强填进 CrewScope 的 Key 字段**——Key 由 CrewScope 自己的语义生成，塞入外来编号会污染后续检索。
3. **只连接确实支持的模型与仓库。** 在配置中心连接团队真实可用的模型 Provider 与受管仓库；没有的能力不要伪造（例如不存在的 Provider 行、借来的凭证）。配置健康面板会按 Agent 配置、模型连接、凭证与集成四类给出当前事实。
4. **执行并审查。** 让 Agent 执行任务，成员按正常流程审查产出：读证据、看测试事实、给出完成意见或要求修改。这一步验证的是「执行与责任链路」，不是速度。
5. **把结果交回原系统。** 用一条链接或摘要把 CrewScope 的结果贴回原任务，原任务标记为「由 CrewScope 执行」。两边各自保留完整记录，不需要复制内容。

## 边界：本试用不承诺什么

- **不伪造历史。** 原系统的作者、审批、时间线不会被搬进来；CrewScope 的记录从你创建的那一刻开始。
- **不做双向同步。** 已有任务仍留在原系统，两边不会实时同步；删除或修改不会自动互通。
- **没有批量导入。** 不存在整库迁移工具；能试一个项目不等于已有完整迁移工具。
- **不复制凭据。** 旧系统的 API Key、私有 Token 不应粘贴到 CrewScope；模型与仓库连接使用各自平台的正式授权流程。
- **CLI 与附件按 §4.2 取舍。** 本机 CLI 深度集成与附件批量迁移未在当前范围，相关场景按能力边界说明处理，不宣称完整替代。

## 从哪里开始

- 空团队首次进入：Onboarding 完成卡选择「先完成 Coding 配置」进入配置中心。
- 已有团队：Today 页空项目面板「创建 WorkProject」，或配置中心（Setup）目标卡「先开始 Coding」。
- 配置各组件的权限与责任边界见《[M8 SetupReadiness API 契约](../api/M8-SetupReadinessAPI契约.md)》。
