# M9：配置参数边界契约

这份契约写的是 `M9-F10` ③ 的一条保证：**成员在配置表单里能输入的值，就是服务端会接受的值**。

与 `docs/api/` 下其它契约不同，这里**没有任何 HTTP 端点**。这条契约是**构建期**的：服务端的一张领域表被生成成前端的一份 TypeScript 常量，两边由漂移门禁绑在一起。之所以仍然写进 `docs/api/`，是因为它约束的正是两侧之间的公开形状——生成物有稳定字段名、稳定拼写与稳定顺序，前端把它当接口读。

## 一、唯一声明：`AgentGenerateOptionsLimits`

`crewscope-domain/src/main/java/io/crewscope/domain/agent/AgentGenerateOptionsLimits.java`

一张静态表，一个字段一条 `Limit`：

| 组件 | 含义 |
|---|---|
| `field` | 成员载荷里的字段名，也是表单 key 的字段名 |
| `shape` | `DECIMAL` 或 `INTEGER` |
| `minimum` / `maximum` | 边界，**十进制文本** |
| `includeMinimum` | 下界本身是否在区间内 |
| `step` | 表单提供的增量 |
| `required` | 该字段必须给出数字，还是可以整体缺省 |

边界保存为**文本而不是 `BigDecimal`**：拼写本身就是要发布的东西（temperature 的步长是 `0.01`，不是 `0.010`，也不是 `1E-2`），而文本是生成器在不求值 Java 的前提下唯一能逐字读走的东西。`Limit` 只在进入判定时才解析一次。

| `field` | `shape` | `minimum` | `maximum` | `includeMinimum` | `step` | `required` |
|---|---|---|---|---|---|---|
| `temperature` | DECIMAL | `0` | `2` | 是 | `0.01` | 否 |
| `topP` | DECIMAL | `0` | `1` | **否** | `0.01` | 否 |
| `maximumOutputTokens` | INTEGER | `1` | `10000000` | 是 | `1` | 否 |
| `maximumAttempts` | INTEGER | `1` | `10` | 是 | `1` | **是** |

`ALL` 的声明顺序**就是**表单的渲染顺序，生成物保持它。

两个不显然但必要的事实写在表旁边并由此测试钉住：

- `required` 复述的是参数自身的类型。`temperature`/`topP`/`maximumOutputTokens` 是 `Optional<...>`，缺省即"用模型默认值"；`maximumAttempts` 是基本类型 `int`，**必须**给数字——否则空表单会被读成 `0` 并当成 `0` 发出去。
- `topP` 的下界是**开区间**：表里的最小值 `0` 不是它接受的值。

## 二、发布：生成物与漂移门禁

`scripts/generate-agent-limits.mjs` 读上面那个 `.java` 文件，产出
`crewscope-web/src/api/generated/agent-limits.ts`。

生成物头部含三行：`GENERATED FILE`、重新生成的命令、以及**领域源文件的 SHA-256**。因此领域表的任何编辑都会让生成物变陈旧，`--check` 立刻失败——重新生成时只有第 4 行的哈希会变。

生成器只接受一种写法（一条 `new Limit(...)`，可以跨行），并且**拒绝三种半成品**，全部以非零退出码失败而不是产出可疑的生成物：

- 声明了但没有出现在 `ALL` 里 —— 那个字段会存在于领域、永远到不了表单，而生成器存在的意义正是防这个；
- `ALL` 引用了没有声明的名字；
- `ALL` 的条目数与声明数不符。

生成物形状：

```ts
export interface AgentGenerateOptionLimit {
  readonly field: string
  readonly shape: 'DECIMAL' | 'INTEGER'
  readonly minimum: string
  readonly maximum: string
  readonly includeMinimum: boolean
  readonly step: string
  readonly required: boolean
}

export const agentGenerateOptionLimits: {
  temperature: {...}; topP: {...}; maximumOutputTokens: {...}; maximumAttempts: {...}
}
```

边界在线上形状里是 **string**，理由是注释里写明的那句：`"0.01"` 与 `0.010` 不是一回事，而表单印的就是它、成员重打的也是它。要数字时由消费侧 `Number()` 转换。

`scripts/check-openapi-drift.mjs` 以 `--check` 运行**三个**生成器——`generate-state-machine.mjs`、`generate-openapi-types.mjs`、`generate-agent-limits.mjs`——任何一个与源码不一致即 CI 失败。

## 三、消费：前端只有一个读取器

`crewscope-web/src/domains/agent/limits.ts` 是生成表的唯一读取处，业务组件不直接 import 生成文件：

| 函数 | 职责 |
|---|---|
| `generateOptionLimit(field)` | 取一条记录 |
| `generateOptionFields()` | 声明顺序的字段名列表（`Object.keys` 保序） |
| `limitBound(field, 'minimum'\|'maximum'\|'step')` | 边界转数字，供输入的属性用 |
| `limitShape(field)` | `DECIMAL` / `INTEGER`，决定键盘与校验 |
| `limitFloor(field)` | 输入的 `min`。**开区间下界上抬一档**：`topP` 抬到 `0.01`，使浏览器原生约束与可见错误拒绝同一批值 |
| `limitRangeText(field)` | 屏幕上印的区间：`0–2`，或 `大于 0 且不超过 1` |
| `limitErrorMessage(field)` | 字段级错误文案，重新措辞同一条区间 |
| `withinGenerateOptionLimit(field, value)` | 单个值的判定 |

上界无需同类抬升：领域发布的每一个上界都是闭的。

`withinGenerateOptionLimit` 的两条细则值得写下来：

- **空值对可选字段是模型默认值，对必需字段是错误**。这正是 `required` 的用途。
- **整数字段拒绝分数**：服务端的 `long`/`int` 承载不了，表单不能放它过去。

### 表单侧

`components/domain/AgentConfigurationPreferencesSection.vue` 用 `v-for="field in generateOptionFields()"` 渲染四个有界字段，`components/form/FormField.vue` 统一产出「标签 / 说明 / 参数边界 / 字段级错误」四件套，并负责 `:id`、`aria-describedby`、`aria-invalid` 与提示、错误的可见文案。`preferenceError()` 在**每次输入**时求值，没有提交闸门——越界在成员还在打字时就已经可见。

## 四、拒绝：服务端的同一张表

`crewscope-domain/.../agent/SafeModelGenerateOptions.java` 也用这张表归一化与拒绝：`normalizeDecimal`/`normalizeInteger` 读 `accepts(...)`，越界的拒绝消息里同时给出**字段的 i18n key**（如 `agentConfiguration.generateOptions.temperature`）与**两个边界**（取自同一张表，不另写常量）。

形如 `MAXIMUM_OUTPUT_TOKEN_CEILING`、`MAXIMUM_ATTEMPTS_CEILING` 的重复常量已删除（删除前确认过仓库内零外部引用），避免第二份边界定义。

## 五、两端一致由谁证明

| 要证明的事 | 由谁证明 |
|---|---|
| 表本身良构（步长为正、下界小于上界、一步不越界、整数字段的边界与步长无小数部分、形状决定增量） | `AgentGenerateOptionsLimitsTest.everyLimitIsAWellFormedRangeThatItsOwnShapeCanReach` |
| **表与校验器是两条代码路径却被钉在一起**：接受结果逐值对账（下界、下界上一档、上界、上界上一档、上界下两倍、下界下一档） | `…theAggregateAcceptsExactlyTheValuesThePublishedRangeAccepts`（边界断言由表**算出**，不是抄写） |
| `required` 与参数自身的类型一致（`Optional<...>` vs 基本类型），用**反射**读 `record` 组件泛型 | `…theTableDescribesTheParameterTheAggregateActuallyDeclares` |
| 形状决定取值路径（DECIMAL 不被整数通道接受，反之亦然） | `…theShapeOfALimitDecidesWhatKindOfValueItTakes` |
| 拒绝消息给出字段与两个边界 | `rejectionNamesTheFieldAndBothBoundsItPublishes` |
| 缺省不是越界 | `anUnsetFieldIsNotARangeViolation` |
| 前端渲染的 `min`/`max`/`step` 就是生成表里的值 | `components/domain/AgentConfigurationPreferencesSection.spec.ts`（逐个从生成表读出比对，不是手抄常量） |
| 前端判定与表的开闭区间一致 | `domains/agent/limits.spec.ts`（含 `topP` 的 `0` 被拒、`maximumAttempts` 的 `11` 被拒、分数与 `1e999` 被拒、空值语义按 `required` 分流） |
| 浏览器里真实属性与实时错误 | `e2e/app-shell.spec.ts` 的 `M5 Agent creation and configuration preserve server-owned boundaries` |
| 生成物不陈旧 | `scripts/check-openapi-drift.mjs`（`--check` 三个生成器） |

全量后端与前端回归的结果记在 [M9-F10 配置体验重构](../testing/M9-F10-配置体验重构.md) 与 [M9-Q01 质量门禁与基线](../testing/M9-Q01-质量门禁与基线.md)。

## 六、边界（如实记录）

- **不在表内的字段**：`seed` 的服务端类型是 `Optional<Long>` 且**没有范围**，因此它不进这张表。前端只用 JSON 数字能无损承载的安全整数界（±2^53−1）并给出对应文案——那是"诚实的边界"，不是服务端约束，所以它写在 `limits.ts` 里而不是生成物里。
- **表的覆盖面是"有界数值参数"**，不是 GenerateOptions 的全部：`reasoningMode`、`streaming`、`toolChoice` 一类非数值参数不在此表，表单也不对它们宣称区间。
- **这条契约不构成服务端校验的全部**：`SafeModelGenerateOptions` 之外仍有模型能力、Provider、权限等校验，它们与此表无关。
