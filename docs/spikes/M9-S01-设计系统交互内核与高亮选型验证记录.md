## 1. 验证目标

本 Spike 冻结 M9 后续实现不可自行解释的产品和工程契约：

1. Design System v2 的 Token、主题、密度、动效、断点和基础组件边界；
2. ActionRegistry、状态流转动作、不可用原因和撤销窗口；
3. 个人工作台优先级、跨项目聚合、统一搜索对象与查询预算；
4. OpenAPI/状态机生成和漂移门禁的单向来源；
5. Diff 高亮、行级评论锚点和配置体验合同。

本记录只冻结决策，不提前实现 M9-F01/F08/F10 的业务代码，也不改变 M0–M8 的 API、事件、迁移、权限或恢复语义。

## 3. 语法高亮候选实测

### 3.1 体积

使用 npm Registry 发布包和 esbuild 0.25.9，在临时目录构建“核心运行时 + Java 语言包”的浏览器 bundle。包体积为压缩 tarball、解包大小；bundle 为 minify 后 gzip 大小。

| 候选 | 版本 | tarball | 解包 | 核心 + Java bundle gzip | 结论 |
|---|---|---:|---:|---:|---|
| Prism | 1.30.0 | 528KB | 2.05MB | **4.7KB** | Token 流安全渲染，语言组件可动态加载 |
| highlight.js | 11.11.1 | 818KB | 5.43MB | 9.5KB | 体积可控，但默认 API 产出 HTML，需额外安全边界 |
| Shiki | 1.29.2 | 193KB | 624KB | 1.64MB（默认入口含语言/主题） | 主题质量高，但默认入口超出主包预算，初始化成本高 |

Shiki 的默认入口测量用于记录风险；若未来要重新评估，必须使用 `shiki/core` 的显式语言/主题入口重新测量，不能用默认入口数据声称已满足 30KB 预算。

### 3.2 3000 行基线

输入为 3000 行、177,779 bytes 的合成 Java 代码；每个候选在 Node 24 单进程冷启动运行一次，时间包含首次加载和 tokenization，不包含 DOM 挂载。

| 候选 | 结果 | 冷启动 + 3000 行耗时 |
|---|---:|---:|
| Prism Core + Java grammar | 1,185,779 bytes HTML 等价输出 | **58.54ms** |
| highlight.js Core + Java grammar | 684,779 bytes HTML 输出 | **34.48ms** |
| Shiki 默认入口 + GitHub Dark | 3000 行 token 结果 | **610.35ms** |

该基线用于比较候选，不代表生产 DOM 性能。Chromium 中“Token 流生成 + 3000 行 Diff 首屏渲染”的生产预算已由 `e2e/m9-performance.spec.ts` 落地并纳入 M9-Q01；超过预算时先启用虚拟滚动和语言懒加载，不扩大主包。

### 3.3 选型

选用 **Prism Core + 动态语言组件**：

- 主包最小，核心 + Java 仅 4.7KB gzip，满足 30KB 预算并保留多语言扩展余量；
- `Prism.tokenize()` 返回 Token 流，Vue 可逐行安全渲染，无需把不可信代码交给 `v-html`；
- 主题不绑定第三方颜色，直接由 CSS Token 映射明暗主题；
- 任意语言组件加载失败都回退纯文本，不阻塞 Diff；
- 语言包按文件类型动态 import，首屏只加载当前文件语言。

放弃 highlight.js 的原因是默认 HTML 输出会扩大清洗和 Trusted Types 的审计面；放弃 Shiki 默认入口的原因是初始化和包体积明显超出首屏预算。两者都保留为未来在明确性能或主题需求变化时的重新评估候选。

## 7. 结论

三个 ADR 已冻结 M9 的设计、工作台/搜索/契约、Diff/配置边界；Prism 是当前满足主包预算、安全渲染和语言懒加载要求的首选。后续实现可以直接进入 `M9-I01` 与 `M9-F01`，无需再次讨论 Token、动作命名、搜索预算或评论锚点模型。
