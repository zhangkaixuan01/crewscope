## 1. D02：配置、构建和状态合同

### 1.1 模型管理的唯一实现路径

复用现有 ProviderDefinition/Catalog/PriceRevision、ModelConnection 与 Agent 配置 resolver；V20 已有定义/目录表，不另建平行目录。静态内置项作为种子与安全默认，动态管理以数据库版本为权威。平台写入产生新 revision/hash，旧执行引用保持可解析，不能原地改历史配置。

**A03 的版本迁移固定如下**：V20 的 `model_provider_definition` 以 provider_key 单列为主键，catalog 与 connection 的 `(provider_key, provider_definition_hash)` 外键指向该表；因此不能直接覆盖 content_hash 来实现多版本。新增同一目录下的不可变子表 `model_provider_definition_revision`，主键 `(provider_key, content_hash)`，保存完整定义内容及创建审计；旧行按原 hash 原样回填，不重新计算旧 hash。原表继续作为身份/生命周期根，content_hash 指向当前 revision，现有展示/内容字段仅为该 revision 的一致投影，不是第二份权威配置。根的复合外键指向 revision，revision 的 provider_key 外键指回根；两者延迟至事务提交检查，首次创建在同一事务插入根与 revision。revision 的 UPDATE/DELETE 均禁止，根身份不变；更新锁根并校验 lifecycle_version，插入新 revision、切换当前指针/投影、递增版本及写事件/结果必须同事务。

迁移以新的 Flyway 版本完成：先建/回填 revision，再将 `model_catalog_entry` 与 `model_connection` 的上述两个直接外键重定向到 revision，最后加根当前指针及一致性约束。Agent configuration/binding 等经 catalog/connection 的间接复合外键保持原值；迁移测试须验证完整引用链，不改已发布 V20。历史执行/连接按指定 key/hash 读取 revision，目录展示读根当前版本；旧连接不会因平台编辑自动切 Endpoint，新配置需明确选择新 revision/连接并重新验证。Provider 根停用对所有 revision 的下一次调用生效，不能借旧 revision 绕过；新连接/新目录条目只接受当前 ACTIVE 根的当前 revision，旧合法连接的复用仍按既有快照与当前授权规则。数据库读写 Adapter、resolver 和种子导入统一使用该目录 port，种子不得覆盖数据库已管理版本；禁止删 FK、级联改历史 hash 或另建平行注册中心。隔离 SQL fixture 已覆盖双外键迁移与旧引用保留；完整 V20 升级、应用映射与并发测试归 A03。

新增平台管理集合 `/api/v1/platform/model-providers` 及其 `/{providerKey}/catalog`：有效 platformAdministrator 才能创建/更新/停用；列表写字段固定为 providerKey（服务端生成或高级显式值）、displayName、API 协议、endpoint、启用状态、网络策略；catalog 固定 modelId、显示名、明确的能力值及来源/校验时间、上下文上限与输出上限、可选价格 revision/币种/单位。版本变更必须 If-Match + Idempotency-Key；普通 Team 管理员只能选择已有定义并管理受权连接，不能写平台 Endpoint。

实际源码 `ModelEndpoint` 目前只校验 HTTP(S)/host/长度以及无 userinfo/query/fragment，**并没有已经实现的私网 allowlist**。A03 必须在 Provider 验证与每次实际客户端连接处加同一网络判定：默认公开地址；管理员可为单个定义明确放行固定 host/port 和私有 CIDR（包含明确的本机代理用途）；始终拒绝 metadata/link-local/组播/未指定地址、凭据 URL 与重定向绕过。DNS 所有候选解析地址均检查，连接固定到已验证地址，不能检查完再由另一个客户端重新 DNS；无安全固定能力的客户端拒绝该配置，不做前端-only 校验。默认部署仍为 HTTP，不需要额外证书或代理服务。

能力检测结果必须区别 SUPPORTED / UNSUPPORTED / UNKNOWN，附 provider/model/revision/来源/checkedAt；保存成功不意味着验证成功。验证凭据健康不代表所有模型、tool calling、structured output 都已探测成功。未知价格显示“未知”，不显示 ¥0；现有费用策略需要价格才能授权时拒绝并说明，不能为简化 UI 绕过费用策略。token、字符、货币分别显示，有 tokenizer/usage 事实才显示精确 token。

新增 `POST /api/v1/organizations/{org}/model-connections/{connection}/activate` 复用领域 activate，需当前凭据版本 HEALTHY + 当前 Provider active + If-Match。SUSPENDED→ACTIVE 可以，REVOKED 不可恢复；rotate 会令健康 UNKNOWN，必须重新 verify，不继承旧凭据健康。停用拒绝下一次模型调用/新执行，正在远端处理的一次请求不能保证取消；已返回的结果可按原快照记账，但下一调用必须复验。运行快照不静默换连接，需用户修正后新执行/受控重试。用户撤权与响应披露另按 ADR-038。

### 1.2 构建类型与版本化默认值

现有 BuildTool 有 MAVEN/MAVEN_WRAPPER/GRADLE_WRAPPER/PROJECT_SCRIPT；BuildProfile 强制 Java release。不能把 PROJECT_SCRIPT 当作正式 Node 支持，伪填 javaRelease 17 也不接受。

唯一选择为新增 schemaVersion=2 的判别式运行时配置：JAVA 分支保留 Java facts；NODE 分支保存 nodeVersion/packageManager/packageManagerVersion，不带 javaRelease。旧 v1 序列化、hash 和 reconstitute 不变，缺 schemaVersion 的旧快照明确按 v1 读取；未知 schemaVersion 拒绝。新增 Node 版本化 profile 使用 [可执行原型](../../scripts/spikes/m9b-s01/contract-prototype.mjs) 的字段校验/固定 tuple 编码，hash 为 SHA-256(`build-profile-v2\n` + UTF-8 JSON tuple)，属性插入顺序不能影响 hash。本期 Node 只 NPM，不默认支持 pnpm/yarn 或任意 shell。

| 支持层 | 明确范围 | S01 证据 / 后续责任 |
| --- | --- | --- |
| 现有 Java | 领域允许 release 17–25；现有受控 Maven/wrapper/Gradle/script 不改变 | 已跑现有 BuildProfile/runner 测试；17 样本真实编译运行。17–25 是可配置范围，不声称每个 JDK 都实测 |
| 本期新增 Node | 24.19.0、npm 11.17.0，package-lock.json，单 package、规范仓库相对目录 | 离线 npm ci/test/build 已执行，目录/argv/版本/hash 原型已测；A04 才接生产 BuildProfile、CommandSpec、runner 与 UI |
| 多 package、其他管理器 | 不自动推断 workspace/filter/test selector | 预检“不支持此构建方案”，不以只运行根目录测试冒充全仓支持 |
| 未知栈 | 不猜 Java/Node、不运行任意命令 | 可只创建/讨论，Coding 启动给选受支持方案或配置入口 |

Node 准备步骤 `npm ci --ignore-scripts --no-audit --no-fund` 每次干净执行环境只运行一次，成功才开放后续 COMPILE=`npm run build`、TEST=`npm run test`；准备失败不把它当业务测试失败。默认 timeout 60s，最大 900s，每步保留独立 CommandSpec/hash/结果；准备步骤同样进入 profile hash、权限与沙箱预算。缺 lockfile、缺声明 script、lockfile/package.json 不一致时显式拒绝，不自动 npm install 改依赖。VERIFY/FORMAT_CHECK/ACCEPTANCE 未声明就不暴露，不添加 `--runInBand` 等猜测参数，不开放额外 selectors。

fixture digest 见主记录 §4.4；Java 容器样本为 `maven@sha256:59a6335c47fc184e1755864431de23c4fb67e704d49474c624f1be194a9b980c`（linux/amd64、Java 17.0.17）；Node 样本为 linux/arm64。它们是本机已缓存的实验版本，不承诺两个架构都经过集成/安全扫描。A04 发布版本必须在其支持矩阵列每架构实际 digest/测试，不能直接用此单架构 digest 充作多架构标签。

项目默认配置选择 `GET/PUT /api/v1/organizations/{org}/teams/{team}/work-projects/{project}/execution-defaults`（新增），返回 version、repositoryBindingId/version、branch、buildProfileRef(key/version/hash)、可选 agentProfileId/revision，以及逐字段 source/availability/reason。PUT 为完整版本化替换，null 清除可选默认；GET 无配置时返回 version=0 与缺项，不阻止 API-only 启动。项目默认的管理权限使用现有仓库 Owner/Admin 边界（下表），不因通用 WORK_PROJECT_MANAGE 自动扩权。

平台 BuildProfile 目录新增 `/api/v1/platform/build-profiles`（platformAdministrator 管理受控模板/镜像/命令），团队配置只选择受权版本，不开放用户任意宿主命令。迁移复用/追加目录与项目默认表，现有内存 ImmutableBuildProfileCatalog 改为同一 catalog port 的持久版本实现；禁止两份权威目录。旧任务保持原 profile 引用，新项目无默认不强制填写部署配置。

## 3. D01/D02/D03：分配并启动与结果衔接

采用工作项范围的具体编排命令，不建设通用 Saga。新增 `POST /api/v1/organizations/{org}/teams/{team}/work-projects/{project}/work-items/{workItem}/delegations`，请求为 intent=ASSIGN_ONLY 或 ASSIGN_AND_START、agentProfileId、明确的配置引用/版本、可选受权 sourceMessage 引用与必要的冲突确认。Idempotency-Key/If-Match 固定意图，不收原始 shell、平台权限或完整私聊历史。

ASSIGN_ONLY 只调用责任服务、提交责任事实/事件/回执，不创建 Task。ASSIGN_AND_START 先解析当前身份/已有责任、预检有效配置，再在一个本地事务内锁 WorkItem、复验版本/授权、保存需要的责任变更与 Task/初始 execution/耐久调度意图、D01 结果。数据库内任一步失败全部回滚；不能把本可原子的步骤人为拆成两个 HTTP 命令，先分配成功后无从追踪启动。

Worker claim/模型/仓库准备发生在提交之后：若运行准备失败，返回原 Task/execution 的失败/等待事实，不重建责任/工作项。响应丢失按原命令结果恢复。旧独立“分配”已经提交后再选择启动属于两个明确意图，页面显示已分配和待启动；同 Agent Executor 可复用，不同 Agent 需明确确认且有改责任权。既有人审、policy、fencing 与 ActionBundle 机制不弱化。

当前 AgentTaskCreationService 已要求有效 OWNER/EXECUTOR，TaskAgentSelectionService 要求合法 Agent 与恰好一个匹配的 EXECUTOR；新编排只能在该事务准备合法责任后复用这些服务，不能删掉它们来减少步骤。消息“让 Agent 处理”选择对话 invocation 或 Coding Task 的明确目标；普通评论只落讨论，不双写评论+执行、不热注入在途 Coding。PRIVATE 来源只传有权引用与用户明确选择的必要内容，不能整段私聊默认为团队共享。

邀请接受用现 TeamInvitationAcceptanceResult 的 invitation/membership 坐标形成 D01 持久结果（teamId/memberId/invitationId），不能继续用新旧团队列表差集/同名/第一项猜团队。登录成功但 session 刷新失败时保留“接受已提交、会话待同步”，再读本人的结果与 session，不重新接受另一条邀请。

### 4.1 工作摘要 DTO（新增在现 Work/WorkDesk 读模型）

```text
workItemId / workItemVersion / workStatus
taskCount / activeTaskCount / pendingReviewCount
currentTaskId? / currentExecutionId? / executionStatus?
selectionRequired / availableActions[] / blockedReasons[]
resultSummary? / resultSourceReference? / projectionVersion / observedAt
```

0 Task：current 均 null，显示“尚未启动”；恰好 1 Task：读取该 Task 的 currentExecutionId；多 Task：current 均 null、selectionRequired=true，展示每项可选择状态，不按更新最晚挑“主任务”。Task 详情的 attempt 历史由显式 URL 定位，不改变服务端 current。显式错关联/已删除/无权返回安全错误，不能 fallback。多个在途执行写动作必须选定合法目标；工作状态、执行、测试、Review、PR 五个事实分开，摘要必须带可追溯来源，不用 LLM 临时编造“已完成”。

数量来自相同受权全量集合，不用当前分页长度充当 count。摘要与列表带 observedAt/projectionVersion，暂未追到 committedVersion 显示“已提交，等待同步”；客户端只刷新对象/相应查询，不重复命令。A06 不新建永久“当前 Task”写字段以掩盖多任务语义。

## 5. D07：剩余路由与认证定案

`scripts/spikes/m9b-s01/contract-prototype.mjs` 的 routeQueries 是本 Spike 的表驱动样例，生产需接入现路由/helper，不能直接复制成第二套权限实现。

- github-settings 新增 `connection`、`importJob`（UUID），有 job 时按当前 team/project 点查并核对 connection；不一致拒绝，不创建另一个 job。repository-settings 保留已有服务端搜索链接的 binding。
- team-members 新增 `invitation`、`tab=members|invitations`，保留 member；邀请点查需管理权，无权用户不获取邀请管理详情。接受邀请的公共 route 仍为 invite，不能用管理 query 替代 proof。
- setup 新增 `goal=conversation|coding`，默认 conversation；配置页/Setup 新增主记录的 returnContext。跨配置跳转保留同一个合法 token，不能复制来自其他账号的 sessionStorage 内容。
- login 只允许 `returnTo`，长度 1–2048，站内已登记 route，拒绝 `//`、反斜杠、控制字符、hash；解析后继续按目标 route 白名单与当前权限过滤。补入现 safeLoginDestination 遗漏的 setup/search/github-settings；无返回来源落 today，与 `/` 一致，不再固定 conversation。invite 仅允许 proof-free `/invite` 返回。
- register/invite 不接受 query token；唯一例外为当前 fragment `#token=<43字符base64url>`，拒绝重复/其他 fragment 键，读取后立即 replace 去除地址栏/hash，只留交互内存。register 也可沿用当前 invite 内存 proof；不持久化到 returnContext/草稿/日志。刷新后无 proof 明确要求重新打开原邀请，不伪称秘密已恢复。
- onboarding 无外部业务 query 输入；创建结果使用准确 Team 坐标，完成去合法目标（无来源默认 today）。account 不带团队 query，本人偏好选择当前合法团队在账号页内部处理；无团队仍可进入账号基本设置。
- F01 请求代次包含身份 epoch；F02 登录/配置返回不自动提交原命令。主体/对象不合法属于错误，不用 display filter 的“回默认”规则处理。
