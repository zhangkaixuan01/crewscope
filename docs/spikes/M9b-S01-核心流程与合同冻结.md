## 3. D01：命令身份、结果查询与编号

### 3.1 唯一结果恢复路径（待实现）

选择**独立受权查询**，不扩展旧 `CommandReceiptResponse` 的四字段响应。拟定接口为 `GET /api/v1/organizations/{organizationId}/command-results`，用现有单值 `Idempotency-Key` 请求头定位原命令，避免将键放入 URL、访问日志和分享链接。A01 将其写入正式 API/OpenAPI；其他写侧复用同一协议，不另建同义结果接口。

- 持久化最小结果：org、原操作者 principal、commandId、commandType、受权 Scope、结果类型/坐标、已提交版本、阶段/未完成步骤、createdAt。关联既有回执，业务事实、事件、回执和首次结果坐标在**同一事务**提交。
- 读接口先验证登录身份与 Organization，再校验原 actor 相同、当前成员及结果对象权限；“管理员”不自动拥有他人的命令恢复入口。结果中每个引用重新授权，不返回标题/正文/凭据等不必要内容。
- `200`：原命令已经提交；返回原四字段回执和 `result`（类型、定位、版本、阶段）。命令已提交不等于整个外部流程已完成。导入/执行另按原 job/execution 定点读当前事实，不用回执副本冒充实时状态。
- `404`：无可披露结果，统一覆盖不存在/他人结果/当前无权读取；前端显示“暂未找到可访问的结果”，**不解释为原命令没发生**。身份失效仍走 `401`；保留现有错误信封，不建立第二套错误格式。
- 全部结果响应使用 `Cache-Control: no-store`；跨域部署按既有 CORS 明确允许该请求头，不把结果缓存到共享代理。日志只记安全关联信息，不记录恢复键或结果正文。
- 旧回执没有可靠 actor/坐标时不从同名对象、列表最新项或不完整 event 猜测回填。只有认证后的旧命令处理器能按原 type/hash 安全重放，才能恢复；否则显示“旧命令暂无自动定位结果”，提供安全支持信息，不生成新键重试。
- 结果记录与幂等回执一同保留，M9b **不增加自动 TTL 删除**；后续保留策略不得留下可再次执行的旧键。前端恢复坐标过期只意味着本机丢失恢复入口，不代表服务端未提交。备份恢复边界按原数据库事实处理。
- 不设计可被读取的“预留中就已持久”假状态；本地事务未提交时读不到记录是正常情况。多步骤外部动作只有在已提交耐久意图后才返回其真实阶段。

### 3.2 前端意图与等待常量

- 意图创建时捕获 `{account, principal, org, team, project, target, expectedVersion, commandType, normalizedInput, key}`；规范请求只在内存，秘密永不持久化；改载荷/目标/版本形成新意图，但旧未知记录保留。
- ID：优先 `crypto.randomUUID()`；不存在时使用 `crypto.getRandomValues()` 生成 RFC 4122 UUIDv4（正确 version/variant 位）。无安全随机源时就近说明并拒绝发送；禁用 Math.random、时间戳拼接和静默降级。
- 未知结果查询：首次立即，然后 1、2、4、8 秒退避，单轮总预算 30 秒、最多 8 次，任一条件达到即停止；离页/卸载停止自动轮询。到期显示“结果仍待确认”和“再次确认”，沿用原键，不创建新意图。429 尊重 Retry-After，不在本轮超预算后继续后台轮询。
- 已提交但投影未可见：按**唯一坐标**点查，采用同一等待预算；保留成功事实和再次读取入口，不再次执行命令、不扫描全部列表。
- 内存保有完全相同规范请求且接口有幂等合同才允许原键重放；刷新后只有恢复坐标、或请求含已清理的秘密时只能先查事实，不自动重建请求。
- API/注册等不同身份阶段复用安全 ID，但未登录注册不接 Organization 结果查询。注册保留自身防枚举/重试合同，不声称已获得通用跨刷新恢复。
- 状态为 idle / submitting / unknown / committed / rejected / conflict；网络中断、Abort、5xx 不被自动归类为确定 rejected。切 Scope 的晚到回包不能改变新页面，但原未知意图可保留。

### 3.3 编号与基本编辑

- 工作项缺省 Key 走现有项目行锁 + `nextKey`；把普通创建和 TaskIntent 纳入同一锁序与事务。仍保留唯一约束，先匹配原命令再分配编号。生成值不进入重放前需要重新计算的请求 hash；hash 区分“缺省”与“显式 Key”。
- 旧显式 Key 请求继续按项目前缀、格式/32 字符上限、唯一性校验；占用返回明确冲突，不悄悄换号。旧记录、归档记录均不重写，号码不回收，允许间隙。
- 项目缺省代号：名称 ASCII 字母数字清洗为大写，首位非字母则加 P；空结果用 PRJ；最短右补 P 至 2 字符，基础部分最多 6 字符。占用时追加从 2 开始的递增数字（截断基础以满足 10 字符上限），在 `TeamRepository.lockById` 的 Team 行锁内分配，对应现 `UNIQUE(team_id,project_key)`。显式旧代号也参与同锁/校验；名称变化不改代号，不得只靠前端预查。数字尾缀耗尽/长度超界明确拒绝，不无限重试。
- 普通创建只标题必填，TASK/MEDIUM；对话 PRIVATE 默认；创建不启动执行。结果页显示编号，不让用户填写 UUID 或生成规则。
- 基本编辑仅标题/描述/优先级/标签/到期；请求字段缺省=不改，显式 null=清除可空字段，标题不能 null/空。采用既有强版本头、命令回执和字段校验；ARCHIVED 只读，DONE/CANCELLED 编辑不重开，历史执行/审查快照不可变。

### 4.3 GitHub 与模型接入调查结论

当前 GitHub 服务接收 `GITHUB_TOKEN`；APP_INSTALLATION 对应 Team 所有权，OAUTH_USER 对应 USER/PRINCIPAL。**枚举名不是浏览器安装/OAuth 流程已实现的证据**。普通入口应明确叫“连接已有 GitHub 凭据”，验证实际身份、仓库与用途。短期安装 token 必须显示到期/需更新，不承诺自动续期。仅在配置真实 App、回调校验、token 获取/刷新链路均可用时才开放“安装应用”入口；本期不以搭 OAuth 平台阻塞已有凭据路径。

当前导入授权要求同 Team 连接、当前 Connection/Grant 版本、ACTIVE ProviderBinding、有效 DELIVERABLE 目录项与精确仓库资源；能力集合包含 catalog/read/push/create PR。A02 **不得**跳过这些检查来修复空绑定。需展示当前导入为 Coding 交付用途，不能把可读仓库承诺为可交付；进一步细分只读导入不是本批授权。

模型目录写权限仍属于平台管理，不让团队普通成员通过自定义 Endpoint 探测任意私网。当前 ModelEndpoint 仅检查 URL 形状；A03 新增单 Provider 显式网络 allowlist，禁止 link-local/metadata 地址、凭据 URL、重定向绕过和 DNS 地址漂移。持久字段、管理 API、能力/价格、停用与在途影响均已在细表 §1 定案；不把新增保护写成当前已实现。

### 4.4 构建支持样本，不是已交付能力

已有 Java/Maven 路径保持既有 v1 hash 和历史快照。新增 Node 类型必须使用新的版本化编码，不重算旧任务 hash；项目默认更新只影响新执行。未支持的语言/包管理器在预检明确拒绝，不能偷偷用 shell 任意执行。

选定 Node `24.19.0` + npm `11.17.0`；样本镜像 `node@sha256:71d7f07420e0acab162781f0bae22c18a1d04d4704594a6cd7d1f5cbb87cb0d7`，两版本均由隔离短命容器实际读取并执行 profile 原型。它是本期 Coding 样本方案，不是修改 Web 构建镜像的指令，也不代表安全扫描或生产 runner 集成已通过。Web 项目自身仍按 package.json 的 pnpm `11.9.0` 构建。

候选命令固定为 `npm ci --ignore-scripts --no-audit --no-fund`、`npm run test` 与 `npm run build`，不追加特定测试器才支持的参数。参数为受控 argv，工作目录仅允许当前仓库内规范化相对目录，拒绝绝对路径、`..` 逃逸和符号链接越界；不开放宿主目录/Socket/环境秘密。项目脚本是待执行的不可信代码，仍在原沙箱、网络策略、输出/时间/资源限制内，不能因为命令叫 npm 就信任。依赖安装需走已授权网络，样本可无依赖离线验证。

Java 旧 BuildProfile/runner、固定 v1 hash 与 Node v2 原型的解析/命令执行/路径反例已验证。首批将“生产 runner 必须支持 Node”列入 S01 出口过宽：主计划明确该实现归 A04；本轮以真实原型证明可行性、精确冻结增量，再由 A04 做生产闭环，不提前在支持说明写“已支持 Node Coding”。

## 5. D04：Inbox 可逆状态、迁移与批次

采用配套契约 §5.1 的唯一状态表：无行 UNREAD/v0，READ/ACTED → 显式 UNREAD/正版本，ARCHIVED → READ；ARCHIVED 不能直接标未读/已处理，须先恢复。重复目标状态可无新事件返回当前幂等结果，但不同旧 expectedVersion 不能绕过冲突校验。

迁移须追加实际下一个 Flyway 版本，不预占固定号码、不修改 V27：

1. 放宽 status CHECK 接受 UNREAD；替换 `guard_inbox_disposition_v27` 的单调 rank 条件为明确允许转移；保留禁止 DELETE、Scope/createdAt 不变、version=old+1、updatedAt 不倒退。
2. Java transition 不再依赖 enum.ordinal；repository 更新继续以 expectedVersion 为条件。首次 v0 插入与并发插入唯一冲突映射成版本冲突，不吞错成功。
3. Inbox 列表/count 与 WorkDesk 未读统一为 `COALESCE(disposition.status, 'UNREAD') = 'UNREAD'`，在原受权集合和源业务过滤上执行；不可只改 count 不改工作台。source closed 与成员 disposition 分开，不重新打开源任务。
4. disposition 为权威事实，不因 Inbox 投影重建删除；旧事件和重复新事件不覆盖较新版本。恢复/标未读不重新生成外部通知，通知来源版本/授权/去重键不改变。
5. 旧 READ/ACTED/ARCHIVED 行保持原版本及历史；旧客户端提交强版本仍可使用原操作。观察旧版本后再写应冲突，不允许较大 ordinal 覆盖新版未读。
6. 发布顺序为后端/迁移先、支持新状态的前端后；新状态落库后不支持启动旧二进制无损回退。前滚修复优先；备份恢复会丢失备份后业务写入，必须单独说明，不默认为安全撤销。

批量沿用“当前加载可见项”，上限不超过现有工作列表 100，按领域现有更低上限收紧；每项固定 id/version/原命令键。结果逐项为成功/拒绝/冲突/未知，未知先确认，成功不重发；切条件清选择但不修改已提交批次快照。不新增全匹配服务端批处理平台。

固定迁移数据：无行、READ/v1、ACTED/v2、ARCHIVED/v3 各一项，同源不同成员、已关闭源业务、另一 Team 各一项；执行恢复→未读→重复命令→旧版本写→投影重建，断言版本、未读计数、authority 行和通知数量。空库建表与从旧数据升级分别测试。

## 6. D05：规模、排序和证据预算

下列数字是**待验证预算**，不是本轮实测性能或生产容量承诺。不增加数据库/服务/监控部署前提。

| 集合 | 已核实/保留的默认顺序 | 页/规模合同 |
| --- | --- | --- |
| 工作/项目 | updatedAt DESC，id DESC；工作可选业务排序须服务端实现 | 工作默认 20、目标最大 100；现有其他 API 更低上限不扩大 |

所有 cursor 绑定 org/team/actor 的当前授权集合、已应用筛选、排序方向和投影代际；失效提示重新读取，不混入旧页。时间按 UTC 比较，本地时区只负责输入/展示，空值顺序必须同时进入 cursor 比较。变动集合不承诺跨并发写的静态快照；稳定 fixture 必须无重复/漏项，实时变化提示刷新。

测试数据：2 org、每 org 2 Team、每 Team 3 项目；目标 Team 10,000 工作项、30,000 Task/执行、50,000 Inbox 项、100,000 audit、200 个混合候选（含重名/失效/他 Team）。每个排序值至少 3 条相同；选定目标放在第三页以后；每个列表另有 20 行布局集。权限集至少含只读、对应写权、管理权、个人连接 owner、他 Team、已停用/移除与未登录。

性能测量目标：隔离 4 vCPU/8 GiB、单机 PostgreSQL 与现四服务拓扑，记录宿主/容器实际限额、版本、索引、冷/热缓存；若本机达不到则报告实际配置，不能冒称同机对比。热读预热 10 次后采样 100 次、并发 5：列表/点查数据库 SQL p95 ≤200ms、API p95 ≤500ms、局域网浏览器首批可操作 ≤1.5s；批量 100 项本地收纳 ≤5s。失败时给查询计划与请求数，不以 mock、首批内存排序或隐藏数据达标。外部模型/仓库耗时独立记录，不纳入本地读预算。

D05 的目录字段、空值、末级键、多 Task 摘要 DTO、section cursor 和索引方案已在细表 §4 冻结。A06 不能自行改成所有页面更新时间倒序。本轮 SQL 原型规模/环境与上述完整性能预算分别记证。

## 7. D06：本地内容白名单与安全清理

选择 localStorage 存有限非敏感草稿/个人视图，sessionStorage 只放同标签页的配置返回上下文；不引入 IndexedDB/服务端同步。命名空间为 `cs.user.v1:<accountId>:<principalId>:<orgId>:<teamId-or-personal>:<projectId-or-none>:<kind>:<object-or-intentId>:<revision>`，记录内仍含 schemaVersion、updatedAt、expiresAt，恢复必须验证每一维。不得用 displayName 代替身份；新建对象使用创建 intentId，不借用上个对象 ID。

| 类型 | 允许字段 | 容量/期限 |
| --- | --- | --- |
| 工作创建/编辑 | title、description、type（仅创建）、priority、labels、dueAt、baseVersion、draftRevision；对象/Scope 在命名空间 | 所有草稿合计 20 份、UTF-8 JSON 字节 2 MiB、最后修改后 7 天 |
| 对话/评论/行评 | 用户未提交 text、visibility（创建）、明确来源引用；行评含 execution/review/file/blob/side/line/baseVersion | 同一草稿预算；不得保存远端完整历史/私聊全文副本 |
| 委托/非敏感设置 | intent、agentId、受权 repository/branch/profile/model 选择及版本、用户补充说明；名称和非敏感开关 | 同一草稿预算；每类显式 schema，新增字段默认不持久化 |
| 命令恢复 | commandType、原 key、actor/Scope、target（如已知）、createdAt、状态 | 独立最多 100 项、7 天；满额不静默驱逐未知结果，提示仅内存与清理。已过期不解释为失败 |
| 固定 / 命名视图 | 对象坐标；用户自定义视图名与本页允许筛选/排序 | 各 50 项；固定/视图最长 180 天未使用失效，读取时校验权限 |
| 最近访问 / 阅读进度 | 对象坐标、访问时间；阅读为执行+文件 blob+锚点，不能只用路径 | 最近 100 项/30 天；阅读 200 项/30 天，可淘汰最早项，不影响草稿 |
| 设备偏好 | theme、density、非业务布局宽度/折叠 | 保留现设备命名空间，损坏回默认；不含团队/对象名称 |

禁止项：密码、API key、token、Secret、Authorization、完整凭据请求体、成员验证 Proof、远端对象标题/正文缓存、可执行 returnTo。用户自写草稿可能含私人内容，界面明确仅本浏览器保存；不能承诺自动识别并去除用户粘贴的一切秘密。凭据表单不保存任何秘密字段，关闭就清内存。

写入前清过期项、检查容量，写后读取校验成功才显示“已保存在此浏览器”；异常/禁用/满额保留内存并明确提示，无秘密场景普通关闭保存草稿，无法保存或含未提交秘密主动离开才提示继续/丢弃。提交成功只删已提交 draftRevision，不能清除等待期间的新输入。

切 Team 隐藏但可保留旧 Scope 合规草稿；切账号/登出先清旧业务内存、所有旧身份持久项和游标，再渲染新账号。撤权/403 先隐藏目标，清该权限 Scope；不能全局误删另一 Team。通过 storage 事件广播身份 epoch/撤权清理，BroadcastChannel 可用时辅助；每次恢复/写入检查 epoch，旧标签页不能复活被清数据。离线恢复先验身份和当前对象访问权，不展示缓存后再异步检查。

旧版无法证明身份归属的业务 key 一次性删除（含命令面板最近对象、委托草稿、coding target、业务游标），不盲迁移；清理前列确切 key/prefix 并逐类测试，禁用 `localStorage.clear()` 破坏同源其他数据。纯主题/密度可保留。此清理属于 F05 上线迁移，**本轮未删除用户浏览器数据**。
