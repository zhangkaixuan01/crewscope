## 4. 组织根与聚合建模口径（D01 输入）

`organization`（V1，id/name/status/version/created_at/updated_at）：**表已在而聚合未建**——domain 仅有 `OrganizationId` 值对象与 AccountOrganizationBinding 等绑定值对象，无 Organization 聚合、无 Repository、无管理 API；组织创建唯一入口 = TeamBetaBootstrapSeeder 裸 SQL；开放注册钉死 `crewscope.registration.organization-id`（application.yml，env `CREWSCOPE_REGISTRATION_ORGANIZATION_ID`）。

S01 冻结的建模口径（ADR-035 详述）：D01 实体化聚合**零新增列起步**（六列即聚合状态面）；组织创建 API 属托管增量，单机主线维持 seeder+静态注册不变。

## 5. 归属不漂移基线（D01 演练对照）

D01「升级/恢复演练前后对照」以本节断言为基线，演练后重跑 `python3 scripts/m12-s01-table-inventory.py` 须逐项一致：

1. 主链存活 161；组织作用域 132（131 带列 + organization 本体）；全局 29。
2. 131 张带列表**全部 create 自带**（org 来源列全为 create；任何 ALTER 后补即漂移）。
3. 零 DROP、零 RENAME（脚本 RENAME 段为空）。
4. 向量链 2 张均带 organization_id。
5. §2/§3 族归属逐表不变（新增表进入 V68+ 属正常演进，须在 D01 矩阵增补裁定，不算漂移）。

## 6. 托管扩展预勾选（不裁定方案）

选入托管后 ADR-035 须按本清单逐面决策（此处只列盘点面，候选比较不预写结论）：

- 131 带列表 + 向量 2 张：数据层隔离的**直接覆盖面**（组织列已就位）。
- §3.3 的 17 张派生明细：join 联结 vs 增列/复合键的成本与漏判风险面。
- §3.1 账号身份 3 张：跨组织共享数据的隔离例外清单。
- §3.2 目录 6 张 + §3.4 机制 3 张：平台级共享面（目录按租户复制/共享、机制表按租户拆列或保持全局单扫描）。
- Redis（session/presence/LoginDefense 三键域）与对象存储/工件（ArtifactStore）：非 SQL 隔离面，§4.1 合同要求纳入而非只测 SQL。
