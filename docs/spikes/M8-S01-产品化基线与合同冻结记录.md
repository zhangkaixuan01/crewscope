## 5. 冻结的状态与动作矩阵

Setup Readiness 使用 `READY`、`ACTION_REQUIRED`、`BLOCKED`、`UNAVAILABLE` 四态；每项带 `required`、稳定 `reasonCode`、`canConfigure`、责任人摘要和受信 `actionKey`。基础对话、普通任务、Coding/Review、GitHub Draft PR、飞书通知和 Team Observer 按 ADR-026 的能力级前置事实计算。可选 GitHub/飞书缺失不阻断基础对话；无权限成员不获得写动作。

受信动作只允许固定枚举和同源预注册路由。浏览器不提交 Remote URL、Token、Provider Endpoint 或宿主路径；Provider 原始错误、Secret、Credential、Session、内部路径和数据库坐标不进入公开字段或 Telemetry。

## 6. 验证夹具

后续任务必须复用并标识以下五类 Fixture：

1. 新 Team；
2. 已配置 Team；
3. 无权限成员；
4. Provider 故障或撤权；
5. 只完成部分能力配置的 Team。

每类 Fixture 至少验证状态闭合、权限边界、稳定原因码、敏感字段脱敏、并发配置变化和刷新后的版本一致性。

## 7. 三层门禁与发行坐标

PR、Main、Release 三层门禁及 `v0.1.0-beta.1` 首个发行坐标已冻结，详细规则见 ADR-026。Release 必须使用受保护 Tag、干净源码、Backend/Web 同 Revision 的固定 Digest，并附 SBOM、Provenance、签名、安装、升级和恢复证据。
