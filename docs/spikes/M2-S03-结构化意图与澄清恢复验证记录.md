## 1. 验证目标

M2-S03 使用正式 `TaskIntentV1` 与 `ClarificationRequestV1` 验证 AgentScope Structured Output、CrewScope 校验边界和澄清中断恢复语义。

验收场景包括：

- 合法 TaskIntent 与嵌套 Clarification Structured Output；
- JSON Schema 错误由 AgentScope ToolValidator 拒绝并允许模型修正；
- Schema/Bean 合法但领域业务冲突由 CrewScope Domain 拒绝；
- 澄清请求产生 Permission ASK 中断和稳定 Pending Tool；
- 回答绑定 Pending Tool 后恢复，并生成 TaskIntent；
- 重复 Resume 返回首次结果，不再次进入 AgentScope；
- 过期与错配 Resume 在 AgentScope 前失败关闭。

## 2. AgentScope 2.0.0 源码结论

### 2.1 Structured Output

`HarnessAgent.call(messages, outputClass, runtimeContext)` 通过 `JsonSchemaUtils.generateSchemaFromClass` 生成 Schema。当前 Fixture Model 不声明 Native Structured Output，AgentScope 注入临时 `generate_response` Tool，其外层参数为：

```json
{
  "type": "object",
  "properties": {
    "response": { "type": "object" }
  },
  "required": ["response"]
}
```

`ToolValidator.validateInput` 在 Tool 执行前校验 Schema 实际声明的 required、type、enum、长度、Pattern 及嵌套 Object/Array。Schema 错误生成 Tool Error Result，Agent 回到下一轮 Model；合法 `response` 写入 `MessageMetadataKeys.STRUCTURED_OUTPUT`，调用方通过 `Msg.getStructuredData` 转为 M2 DTO。

`JsonSchemaUtils` 的 2.0.0 生成配置没有把 M2 DTO 的 Jakarta Validation 注解完整映射为 Schema 关键字。Fixture 证明空白 Objective 和空 Acceptance Criteria 可以通过生成的 Schema，再被 Bean Validation 拒绝。CrewScope 必须显式调用 `Validator`，之后再以当前 Project、Principal、Membership、Conversation Scope 和聚合版本执行 Application/Domain Validation。

### 2.2 Interrupt 与 Resume

Permission 为 `ASKING` 的 Tool 使调用以 `GenerateReason.PERMISSION_ASKING` 返回，并依次发出：

```text
RequireUserConfirmEvent
RequestStopEvent(PERMISSION_ASKING)
```

Pending `ToolUseBlock.state` 为 `ASKING`。Resume 消息必须在 `Msg.METADATA_CONFIRM_RESULTS` 中携带 `List<ConfirmResult>`。AgentScope 应用确认后直接进入 Acting，执行 Pending Tool，再回到 Model。

确认消息的普通文本不会被加入上下文。CrewScope Bridge 必须将用户回答写入从服务端 Pending Tool 重建的受约束 Tool 输入；`request_clarification` Tool 再把规范化回答作为 Tool Result 交给模型。Web 客户端不接触 AgentScope ConfirmResult 或 ToolUseBlock。

### 2.3 重复与过期边界

第一次 Resume 完成后，AgentScope 已没有 Pending Tool。同一个 ConfirmResult 再次提交不会重复执行 Tool，但会作为新输入再次进入 Model。AgentScope 原生状态也不表达 CrewScope 的 Clarification 过期时间、Conversation Scope 或 Invocation 幂等。

正式 Adapter 在调用 AgentScope 前按以下顺序裁决：

```text
Scope / Invocation / Session
  -> Pending replyId + toolCallId + schemaVersion
  -> expiresAt
  -> Idempotency-Key + Request Hash
  -> AgentScope Resume
```

测试内 Guard 只证明顺序和计数边界；生产持久化、并发唯一约束和结果重放由 M2-A03/M2-A05 实现。

专项验证命令：

```bash
/Users/zhangkaixuan/Downloads/apache-maven-3.9.6/bin/mvn \
  -pl crewscope-agentscope -am \
  -Dtest=HarnessAgentM2S03StructuredConversationIntegrationTest \
  -Dsurefire.failIfNoSpecifiedTests=false test
```

结果：7 个专项测试通过。测试使用确定性 Fixture Model 和测试内 Resume Guard，不依赖网络、真实模型或时间等待。

全仓回归：`mvn clean verify` 通过，共 529 个 Java 测试；`node scripts/check-doc-links.mjs` 通过，共检查 75 个 Markdown 文件；`git diff --check` 通过。

结论：AgentScope 2.0.0 可以直接承担 M2 Structured Output、Permission ASK 中断和 Pending Tool 恢复。CrewScope 必须显式执行 Bean/Domain Validation，把澄清回答绑定到服务端 Pending Tool，并在进入 AgentScope 前完成 Scope、Invocation、Session、幂等、过期和错配裁决。
