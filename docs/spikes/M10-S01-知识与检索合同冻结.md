## 3. §10.11 十项冻结

### 3.1 来源 Scope、披露、生效失效与 Generation（必答 1）

**Team Knowledge（A02 权威）**

- Scope：知识条目属于 Team（organization+team 租户前缀），无跨 Team 共享；检索侧授权与代码执行边界同源（§3.4）。
- 生效：发布动作创建不可变版本（版本号单调、内容哈希），提交即对**新的**检索请求生效；草稿不入索引、不可被检索命中。
- 失效：废弃/删除/Scope 收窄先在权威查询失效（下一版本或删除墓碑），索引侧由变更事件异步清理；旧事件重放不得复活旧版本——索引消费以「权威当前有效版本」为闸，不以事件序号为准。
- 披露：提炼草稿（从执行结果/仓库内容产生）发布前必须通过目标受众披露检查——草稿来源若含其他 Team、成员私有内容或凭据，禁止发布到更大受众；这是 A02 的命令级校验，不是事后审计。
- 「保存成功」与「已可检索」是两个状态：A02 返回保存回执，索引状态由 I01 的索引投影单独呈现（PENDING/INDEXED/FAILED 与 Generation 信息）。

**Repository Index（I01 派生）**

- 索引键至少含 Organization/Team/RepositoryBinding/commit/分片策略哈希/embedding 模型修订；物理 Mirror 可复用，索引授权不以全局 RepositoryKey 划分（同一仓库不同 Binding 的索引互不可见）。
- Generation：一次索引构建=一个 Generation，键=（索引键, 构建序号）；构建完成原子激活（单事务切换 active 指针），失败保留旧代；只查询匹配任务目标 commit 的**可用** Generation，无匹配时显式缺失并降级（§3.4），不得静默拿默认分支最新内容充当。
- 保留：保留最近 N 代（默认 2，可配置）供回退；索引是派生视图可随时整体重建，权威知识/配置/迁移历史不可丢失（对齐主计划 §10.2 第 4 条）。

### 3.2 embedding Provider 能力、数据策略与验证方法（必答 2；维度留 S01b）

**选型范围（已冻结，2026-09-30）**：智谱 `embedding-3` 或阿里 `text-embedding-v4`；均 OpenAI 兼容端点、国内直连。**S01b 实测选定（2026-10-01）：阿里 `text-embedding-v4`，维度 1024**（有真实 key 可实测；智谱 `embedding-3` 未实测，若后续接入须按下表同样实测并核对价格/数据政策后再入目录——I01a 的 embeddings 客户端按 OpenAI 兼容形状实现，不锁定单一 Provider）。

**目录与凭据复用**：为选定 Provider 新增目录行（endpoint 指向其 OpenAI 兼容 embeddings 基址、能力标记含 embedding、带生效价格行与数据策略声明）；连接/凭据/AES-GCM/旋转/吊销/handle 链**原样复用** `ModelConnection` 治理，不新造通道。同维度不同模型不混用向量（§3.1 Generation 键已含模型修订）。

### 3.3 文本范围、分片、持久作业与资源上限（必答 3）

**语言与文本范围**：主线=Java 源码+Markdown/文本文档+中英文知识条目（本仓库即双语真实样本）；代码按「有界文本分片」处理（路径/语言/行号锚点），符号级解析、Doc 注释抽取、提交摘要**不在主线**（确认支持范围后按主计划 §4.7 另行评审）。

**分片规则（I01b 实现，A01 验收锚点）**：

- 代码文件：按行窗口分块（默认窗口 ~80 行、重叠 ~10 行），在括号/空行边界就近切分；每片携带（仓库、commit、路径、语言、起止行、内容哈希）。
- 文档：按标题层级分块；单块超上限再按行窗口二次切分。
- 排除清单（路径 glob，I01 配置）：密钥形态文件（`.env*`、`*.pem`、`id_rsa*`、`*.key`、`credentials*`）、二进制/超阈值单文件、`.git/`、`node_modules/`、构建产物目录。排除是辅助手段不是「零秘密」保证（主计划 §4.8 原文语义保持）。
- 单条知识条目整条为一片（超长明确拒绝，不静默截断——A02 命令级校验）。

**持久作业合同**（沿用 `GitHubRepositoryImportWorker` 形状 + 两处冻结差异）：

- 形状沿用：单表状态机（QUEUED→CHUNKING→EMBEDDING→ACTIVATING→READY/FAILED/CANCELLED）+ progress（里程碑+已处理分片计数双层）+ attempt + 唯一目标键（索引键）+ CTE `FOR UPDATE SKIP LOCKED` claim 按 created_at + 状态推进即续租、终态清空 + claim 后重放授权与坐标校验 + `@Scheduled fixedDelay` 防重入单 worker。
- **差异一（Fencing 可观测）**：索引作业分批写多，WHERE 三重条件静默 0 行失效会表现为进度停滞等待 lease 过期；I01b 增加单调 `claim_token` 代际列（对照 task_execution 体系 `fencing_token` 范式），旧 claim 的写入返回显式 fencing 拒绝并计数（OperationalTelemetry `FENCED`），不静默。
- **差异二（分批 checkpoint）**：进度不止单行 percent——已成功提交的分片批次可跳过（作业重启后按（索引键, Generation, 分片序号）续传），embedding 调用幂等（同批次同输入重发由 Provider 幂等或客户端去重保证，重试消耗计入真实用量）。
- 资源上限（默认值 I01b 可配）：单作业 embedding 并发 1、单批 ≤实测批量上限（§3.2 回填）、作业 lease 上限 1h（对齐 ImportWorker 合法域）、单 Generation 分片总量上限（超限显式 FAILED 带原因码，不静默截断仓库）。

### 3.4 检索、预算与优先级（必答 4）

**授权（A01）**：检索发生在服务端，范围=`ExecutionScope ∩ Ownership`（沿用 `JdbcWorkDeskRepositoryAdapter` 范式：租户前缀+责任/归属交集内联进 SQL）；向量候选生成必须先经 SQL Scope 收敛（候选集=授权+有效版本+可用 Generation 过滤后的行集），不做「全局 Top-K 返回后应用层过滤」；缓存键含 Scope/授权版本/来源版本。

**Top-K/排序/去重（默认值，Q01 前可实测微调）**：

- 候选 Top-K 默认 8、硬上限 20（超出显式拒绝配置）。
- 排序：向量相似度为主；同分（容差内）时知识条目优先于仓库片段、版本新优先；排序输入输出可解释（记录每候选的分数与来源，供 A01 离线质量门禁复盘）。
- 去重：同知识条目只取当前生效版本最高分；同文件相邻分片合并呈现为一个候选（保留片段明细）。

**Prompt 组装优先级与裁剪（I02b）**：四层优先级自高到低=Skill 指令（结构化操作指南，硬保留）→ 知识条目 → 仓库片段 → 辅助记忆偏好。超预算裁剪从最低层尾部开始（先辅助记忆、再仓库片段、再知识条目），Skill 指令与安全边界不裁；每次裁剪记录进注入清单（§3.7）。

**失败关闭与显式降级的分界**（对齐主计划 §4.6/§8 第 9 条）：

- 失败关闭（不降级继续）：授权失败（越权/成员失效/Scope 不符）、业务预算超限（任务级 token 预算耗尽）。
- 显式降级（无知识继续执行，标注 degraded 原因码）：检索开关关、无可用 Generation（目标 commit 无匹配）、embedding Provider 暂时不可用/超时。降级原因写入执行证据，不伪装成「检索了但没结果」。
- Prompt Token 总预算：配置项；硬上限 32K token（超出配置拒绝启动）。**S01b 首轮基线与默认值（2026-10-01，实测依据见 §4 基线小节）**：默认总预算 **8K token**（占 32K 硬上限 25%）；分层默认=知识条目 ≤3K（整条注入，实测条目均值远低于此）+ 仓库片段 ≤4K（实测 80 行窗口分片均值 336 token/片，Top-K=8 全注入 ≈2.7K，余量覆盖相邻分片合并与锚点元数据）+ 辅助记忆 ≤1K（单条 ≤1KB 文本）。默认值进配置基线，Q01 前允许 I02b 按真实执行微调，不得高于硬上限。

### 3.5 用量事实缺口、价格与软预算（必答 9，提前并入本文；原第 5 项见 §4）

**缺口清单（现状核实，F03 不得假设已有）**：

1. 无每次调用模型身份归因（providerKey/modelId/catalog 坐标）；
2. 无连接/凭据归因（connectionId/connectionVersion）；
3. 无模型调用 id（`toolCallId` 只覆盖工具调用，Coding 路径模型调用 id 缺失）；
4. 无角色区分（PRIMARY/FALLBACK/COMPACTION/EMBEDDING/提炼 各混在 plain UsageReported）；
5. 实时路径只发累计值，单次调用用量不可分；
6. embedding 无任何用量发射点（token 用量只从 chat middleware `ChatUsage` 产生）；
7. 无「已消耗」台账（`policy_snapshot` 只有上限）。

**冻结的补齐合同**：产生环节（A02 提炼、I01 embedding/索引、I02 注入执行、A03 Skill 提炼）各自补发**统一形状的用量事实事件**：稳定调用 id（去重键）、providerKey/modelId、connectionId+version、角色枚举（CHAT_PRIMARY/CHAT_FALLBACK/COMPACTION/EMBEDDING/DISTILLATION）、attempt、token 四元组、时间戳；事件入既有 outbox，F03b 做可重建聚合投影（重放幂等），不从 Prometheus 反推。真实重试发生的用量计入（按 attempt 分列）；缺失用量/价格标 UNKNOWN 不按零处理。

**价格与分母**：目录价格行版本化（生效时间窗+币种；S01b 已回填 `text-embedding-v4`=0.0005 元/千 Token 人民币，见 §3.2 实测表——智谱 `embedding-3` 接入前按表补核）；成功率分母=执行尝试（成功/失败分列，缺陷 24 修复后命令超时不再混入）；Review 一次通过率只统计进入 Review 的样本。

**软预算提醒**：复用 ADR-022 Inbox/飞书固定模板通道；team×月 幂等去重；提醒失败不影响执行；不建硬配额（M12 范围）。

### 3.6 辅助记忆边界（必答 6）

- **所有者键**：organization+team+成员 principal+Agent profile+策略版本；策略版本即现有 `AgentMemoryPolicyReference`（policyId@version）——该引用现状悬空（无策略聚合/表），I02a 交付策略实体（TTL/容量/允许内容结构定义）承接它，Agent 配置链（槽位门禁/配置哈希/幂等哈希）零改动。
- **允许内容**：冻结的偏好结构（命名键值，如回复语言、代码风格、常用技术栈、评审关注点），单条 ≤1KB 文本；**不保留任意原始会话副本**；自动写入仅限该结构。
- **TTL/容量默认合同**：默认 TTL 90 天滑动（被使用即续期）；每（成员×Agent）≤100 条；超限显式拒绝最新写入并提示清理，不静默淘汰。
- **清除防复活**：每（成员×Agent）单调 `clearance_generation`；清除=代际+1；一切写入必须带当前代际，旧代际写入拒绝（挡住清除瞬间在途写入）；成员停用/移除后立即不可读（对齐 ADR-038 authorizationVersion 语义），物理清理异步。
- **复用判定**：Session/AgentState/Checkpoint 原样承载短期上下文与恢复；辅助记忆只是可选上下文来源，删除它不破坏执行状态（不保证模型答案不变）。

### 3.7 注入清单、恢复、反馈与检索预览（必答 7）

- **清单持久化**：每次模型调用前持久化注入清单（执行 id/attempt/片段或条目 id+版本+内容哈希/裁剪记录/Prompt 预算快照/降级原因码）；「已注入」≠「模型实际采用」——模型返回的引用只能关联本次清单集合，自由生成的引用不能冒充系统证据（呈现层区分）。
- **恢复/重试**：新 attempt 新清单；旧清单保留不重计（F03 重放去重按清单 id）；恢复后调用↔清单关联可查。
- **反馈**：按（执行/片段/成员）幂等记录「不适用」；不改写已发送 Prompt 与既有结果；用于质量统计，后续重试/新执行可显式排除对应来源版本；不隐式全局废弃、不自动改排序。
- **历史展示**：展示历史证据时重新授权；未授权内容/已删除来源不经 Prompt 日志泄漏；不能只展示条目 ID 丢失实际注入版本。
- **检索预览 HTTP**：**交付一个只读预览入口**（`POST .../knowledge-retrieval:preview`，授权同执行面、`Cache-Control: no-store`），输入查询与 Scope 约束、返回候选与分数——供 A01 离线评测与调试复用真实检索路径；仅此一个入口，不进 Prompt 链路。

### 3.8 Team Skill 合同（必答 8；详细决策见 ADR-031）

- 主线流：成员显式选择已完成执行 → 提炼草稿（结构化 SKILL.md 草稿+来源披露）→ 目标 Team 审批发布（发布授权：发布权限+受众披露+工具声明+版本）→ 后续执行按配置求交使用（执行授权：Task Tool Policy/Scope 求交，版本+内容哈希入执行快照）。发布授权与执行授权**分开**；不做自动后台提炼。
- Factory 扩展四点（现状取证）：①bundle 清单/pin 常量与「恰好 1 个」校验放宽为「内置恰好 1 + 动态 N」；②`SkillFilter.only(内置)` 扩展为 allow-list（内置+本次执行已授权的 Team Skill 发布版本）；③单一 repository 接线扩展为内置 classpath repository+受控动态 repository（内容取自发布版本快照，每 HarnessAgent 独占实例约束保持）；④`TaskWorkerConfiguration` 装配点接动态供给。
- 内置兼容：`java-spring-v1` 为保留名，Team Skill 同名发布拒绝；关闭 `crewscope.skill.enabled` 只停 Team Skill 链路，内置只读 Skill 照常；`SKILL_LOAD_TOOL` 驱逐排除表保持。
- 运行时：命中 Skill 不增加工具权限；工具调用继续鉴权与 Human Gate；撤权在安全点阻止后续使用；回滚=激活历史内容的新修订，不改历史事实。

首轮两条结构性发现（进 I01/A01 实现约束）：

1. **生效版本闸必须进候选 SQL，不是可选优化**：对照组（同一批查询、不带 `effective` 过滤）8/11 多版本对被 RETIRED v1 抢占排名（v1/v2 内容语义相近时旧版分数更高）——若做「全局 Top-K 后应用层过滤」，过滤后剩余候选不足 K 且旧版污染排序。§3.4「先 SQL 收敛再向量 Top-K」由数据实证。
2. **授权谓词承重验证（id 级）**：带租户谓词检索只返回本 Team 行（回查 id 集合的 team_id 单一）；去掉谓词的对照检索立即混入 Team B 行——隔离由 SQL 保证而非数据巧合，越权样本集 Q01 冻结时沿用此证法。
