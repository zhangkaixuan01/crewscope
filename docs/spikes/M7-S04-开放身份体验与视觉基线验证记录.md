# M7-S04 开放身份体验与视觉基线验证记录

> 任务：`M7-S04`<br>
> 结论：`PASS`<br>
> 验证日期：2026-08-28<br>
> 范围：登录、注册、首次 Team Onboarding、团队邀请与账号设置的信息架构、响应式、焦点顺序、可访问性与 CrewScope 品牌基线

## 1. 验证目标

M7-S04 在生产认证 API 和路由实现前冻结开放身份体验，使 `M7-F01` 至 `M7-F07` 共享同一产品边界。本 Spike 回答以下问题：

1. 未登录用户如何理解 CrewScope 的“成员 → Personal Agent → 团队”价值链；
2. 登录、注册、Onboarding 和邀请如何保持一致，同时清晰表达当前任务；
3. 已登录账号设置与公开认证页如何分界；
4. 1440×960 桌面端与 390×844 窄屏是否具备稳定的阅读、键盘和辅助技术路径；
5. 密码、邀请 Token 和 Session 状态是否在前端原型中保持零持久化。

## 2. 原型边界

验证入口为 `crewscope-web/m7-s04-fixture.html`，通过 `state` Query 切换静态状态。页面明确标记“M7 交互原型 · 不提交数据”，表单不调用 API，不进入生产 Router，不替代真实 AuthStore、Session 恢复和服务端授权。

正式实现归属：

| 范围 | 后续任务 |
|---|---|
| AuthLayout、品牌区、表单和错误摘要 | `M7-F01` |
| 登录 | `M7-F02` |
| 注册与 Registration Mode | `M7-F03` |
| AuthStore、Session 恢复和 Router Guard | `M7-F04` |
| 首次 Team Onboarding | `M7-F05` |
| 账号与会话管理 | `M7-F06` |
| 邀请 Preview/Accept 与管理 | `M7-F07` |

## 3. 冻结的状态矩阵

原型共固定 12 个状态：

| 状态 | 产品含义 | 初始焦点 |
|---|---|---|
| `loading` | 检查 Session、Organization Binding 和 Team 入口 | 状态标题 |
| `service-error` | 会话检查未完成 | 错误摘要 |
| `login` | 用户名或邮箱与密码登录 | 标识输入 |
| `login-error` | 统一的无效登录信息 | 错误摘要 |
| `locked` | 限流或临时锁定，禁止提交 | 错误摘要 |
| `register` | 开放注册 | 用户名输入 |
| `registration-invite-only` | 仅允许通过邀请加入 | 状态标题 |
| `registration-closed` | 部署关闭新账号 | 状态标题 |
| `onboarding` | 创建第一个 Team 及其工作入口 | Team 名称输入 |
| `invite` | 预览 Team、角色、邀请人与有效期 | 主接受动作 |
| `invite-expired` | 过期、撤销或已使用的统一失效态 | 状态标题 |
| `account` | 个人资料、密码与登录会话管理 | 页面标题 |

登录失败文案不区分账号不存在、密码错误、账号锁定或 Credential 异常，与 M7-S03 枚举防护保持一致。

## 4. 信息架构与视觉决策

### 4.1 公开身份页

`/login`、`/register`、`/onboarding` 和 `/invite#token=...` 使用独立 AuthLayout：

- 桌面端左侧是 CrewScope 品牌与团队协作说明，右侧只承载当前身份任务；
- 品牌区用“成员 → Personal Agent → 团队”表达人是最终责任人、Agent 负责理解与执行、Team 负责协作与 Review；
- 390px 窄屏先展示简化品牌说明，再按单列阅读当前表单或状态；
- 使用现有浅绿 CrewScope Token、Logo、克制的衬线标题和低饱和背景，不复制通用后台登录模板；
- 主标语为“把 AI 执行带回团队”，登录任务与平台协作价值同时可见。

### 4.2 账号页

`/account` 是已登录 AppShell 内的设置页，不沿用公开登录卡。页面使用账号标题、设置导航和内容分区，依次承载个人资料、密码安全与登录会话。窄屏将导航改为横向三项，设置内容保持单列顺序。

## 5. 键盘、语义与敏感状态

- 页面保留“跳到主要内容”链接，每个状态只有一个 `main#identity-primary`；
- 普通表单进入后聚焦首个可编辑字段；错误、锁定和会话故障聚焦 `role=alert` 摘要；注册关闭和邀请失效聚焦状态标题；
- 登录 Tab 路径从标识、密码、显隐按钮到“保持登录”，不依赖正 `tabindex` 强制排序；
- 登录使用 `autocomplete=username/current-password`；注册使用 `username/email/name/new-password`；
- 密码提示与 M7-S03 一致：至少 12 个字符，最多 128 个字符；
- 密码显隐只是 Vue 组件内存状态，不写入 `localStorage`、`sessionStorage` 或 URL；
- 原型不读取或保存邀请 Token、Session ID、Cookie 或 CSRF Token。正式邀请页仍必须按 M7 设计在内存中读取 Fragment 并立即清理地址栏。

## 6. 自动化与双平台视觉结果

| 门禁 | 结果 | 覆盖 |
|---|---:|---|
| Vitest | 4 / 4 | 12 状态单 Main、登录语义/焦点/通用错误、密码预算/零持久化、五类页面分界 |

五个双视口截图页为 `login`、`register`、`onboarding`、`invite` 和 `account`。每个页面同时校验无横向溢出与 Axe 零违规。Linux 基线由真实 Linux Chromium 生成，对应专项 Playwright 结果为 6 / 6。

## 7. 结论

M7-S04 完成了开放身份体验的产品和前端基线：公开页表达 CrewScope 的团队协作定位，账号页保持已登录设置语义，桌面/窄屏、键盘、Axe 和 Darwin/Linux 视觉基线均通过。该 Spike 不改变运行时架构，无需新增 ADR。
