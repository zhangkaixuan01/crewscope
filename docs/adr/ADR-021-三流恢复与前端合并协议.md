# ADR-021：三流恢复与前端合并协议

> 状态：ACCEPTED<br>
> 日期：2026-08-25<br>
> 关联决策：[ADR-005](ADR-005-事件与投影协议.md)、[ADR-007](ADR-007-API命令与并发协议.md)、[ADR-009](ADR-009-会话执行所有权与恢复协议.md)、[ADR-020](ADR-020-投影代际重建与游标协议.md)<br>
> 影响里程碑：M6

## 背景

CrewScope 的团队工作台同时使用 Team Event、Conversation Event 和 AG-UI 三条实时流。Team Event 提供团队共享事实，Conversation Event 提供会话耐久业务事实，AG-UI 提供当次 Agent Invocation 的瞬时文本和受控运行状态。

三条流的持久性、位置身份和过期条件不同。断线、投影代际切换、浏览器重载和 Team Scope 切换需要稳定恢复，前端需要合并重复业务事实并保留各流的一致性边界。

## 决策

### 三条独立一致性边界

| 流 | 用途 | 恢复坐标 | 耐久性 |
|---|---|---|---|
| Team Event | Activity、Inbox 摘要和团队共享状态 | Team Cursor | Generation 可重建投影 |
| Conversation Event | Message、TaskIntent、Task/Review/Action 会话关联事实 | Conversation Cursor | 追加写耐久流索引 |
| AG-UI | 当次 Invocation Segment 文本增量、中断和终态 | Invocation + Segment + Idempotency Key + Event ID | 可重放的调用 Segment |

三条流各自连接、重试、推进位置和暴露错误。一条流的网络失败、Cursor 过期或权限终止不清理其他流的有效状态。服务端和客户端不生成跨流 Global Cursor、Global Sequence 或 Global Acknowledgement。

### Team Cursor 与快照

Team Cursor 是版本化、签名、Base64URL 编码的不透明值，绑定：

```text
organizationId
teamId
projectionName
projectionGeneration
projectionSchemaVersion
filterFingerprint
teamSequence
eventId
```

`teamSequence` 在 Team、Projection 和 Generation 内单调递增。过滤后的页可以存在 Sequence 空洞，空洞不表示事件丢失。Cursor 的 Filter Fingerprint 覆盖规范化的 WorkItem、Inbox Category、Actor、Event Type 和其他公开过滤条件，过滤条件变化后使用新 Cursor。

Team 快照返回同一个 Generation 的有界数据、`snapshotCursor` 和 `hasMore`。快照行与 `snapshotCursor` 在同一读取快照中生成。客户端先安装快照，再从 `snapshotCursor` 建立 SSE；快照后提交的事件通过缺口补发到达。

Generation 切换、保留期清理或 Projection Schema 不兼容时返回 `410 cursor_expired`。过期恢复只替换 Team 投影快照和 Team Cursor，保留 Conversation 与当前 AG-UI 的有效状态。编码非规范、签名失败、跨 Scope、跨 Projection 和 Filter Fingerprint 不一致返回 `400 invalid_cursor`。

### Conversation Cursor 与耐久补发

Conversation Cursor 继续绑定：

```text
organizationId + teamId + conversationId + position + eventId
```

Conversation Event 的 JSON 历史与 SSE 使用同一个 Cursor 编码器和升序查询。服务端在提交 SSE `200` 前完成当前成员、Participant 和首页可见性校验，再串行补发历史和轮询新事件。`Last-Event-ID` 与 `after` 同时提供时必须完全相同。

浏览器断线后使用最后已应用 Conversation Cursor 重连。保留期使位置失效时返回 `410 cursor_expired`，客户端重读当前 Message、TaskIntent 和会话关联业务状态，清空该 Conversation Cursor，再从当前可用耐久历史恢复。Conversation 恢复不替换 Team 快照。

Conversation Event 索引重建保留规范 `conversationId + position + eventId`。需要重新编号时先发布新 Cursor Version，并让旧版 Cursor 明确过期。

### AG-UI Segment 恢复

AG-UI 事件属于当次 Conversation-scoped Invocation Segment。SSE `id` 使用稳定 AG-UI Event ID，只负责该 Segment 重放去重和诊断，不作为 Team/Conversation 历史位置，不提供通用 `GET after` 恢复入口。

调用断线后，客户端使用原 Conversation Scope、原 POST/Resume Input 和原 Idempotency Key 重放请求。服务端返回同一 Invocation ID、Segment ID 和稳定 Event ID 的 Segment。客户端在 AG-UI 流内按 Event ID 去重，不用 Team/Conversation Event ID 集合过滤 AG-UI 文本。

浏览器持久化的恢复坐标只包含安全公开的 Conversation Scope、Invocation ID、调用种类、规范 Input、Idempotency Key 和 Segment 身份。Interrupt Token、Tool Input、Runtime Session、Provider Binding、Credential 和内部 AgentState 不进入浏览器恢复数据。

AG-UI 终态触发 Conversation Message、TaskIntent 和相关耐久事实的权威回读。AG-UI 公开文本是瞬时呈现，Conversation Event/Message 是刷新后的耐久状态。

### 应用、Cursor 推进与断线重连

耐久 SSE 帧按以下顺序处理：

```text
解析 JSON 和公开 Event Schema
  -> 校验 Stream Type 与当前 Scope
  -> 按本流 Event ID 判定新事件或重放
  -> 应用新事件或安全忽略已验证重复
  -> 保存该流 Cursor
```

解析失败、未知公开 Schema、Stream Type 错配和 Scope 错配不推进 Cursor。浏览器在保存 Cursor 后断线时，从已应用位置继续；服务端至少一次重放时，Event ID 去重保持幂等。

网络错误、`429` 和 `5xx` 使用有上限退避并保留最后位置。`400 invalid_cursor` 作为客户端或篡改错误失败关闭。`401/403` 终止该流并触发当前身份与 Scope 回读。`410 cursor_expired` 使用对应流的快照恢复。

### 跨流去重与展示

- 每条流在独立 Event ID 命名空间内去重；
- Team 与 Conversation 中来自同一 DomainEvent 的事件保持同一 `domainEventId`；
- 合并的 Conversation 工作面按 `domainEventId` 去重耐久业务事实，并优先保留 Conversation 的更具体表示；
- Team Activity 和 Conversation Timeline 各自的原生视图保留完整流内历史；
- AG-UI 瞬时事件的 `domainEventId` 为空，不按 Correlation ID、文本或时间与耐久事实去重；
- 合并视图使用 `occurredAt + eventId` 形成稳定的展示顺序，该顺序不声明跨流因果、事务或提交顺序；
- 卡片保留流类型、发生时间和权威资源链接，允许用户返回原生视图核对。

### Scope Epoch 与迟到事件

前端实时协调器为每次 Organization、Team 或 Conversation Scope 变更提升本地 Scope Epoch，中止旧 Fetch/SSE 与 Invocation 客户端流消费，并清理当前视图的流内去重集合。断开 Invocation SSE 只停止当前浏览器消费，不作为业务取消；只有显式 Cancel 命令或服务端策略可以取消运行。每个异步响应、SSE 帧、重试回调、快照和错误在写入 Store 前同时校验：

```text
capturedScope == activeScope
capturedEpoch == activeEpoch
request is not aborted
```

旧 Team 迟到帧、旧快照、旧错误和旧 AG-UI 终态均不得写入新 Scope。本地 Cursor 按完整 Scope 命名空间保存：Team Cursor 使用 Organization + Team + Filter，Conversation Cursor 使用 Organization + Team + Conversation，AG-UI Recovery 使用 Organization + Team + Conversation + Invocation Segment。

## 实现约束

- 耐久流使用 JSON 历史与 SSE 共享的 Cursor 编码和 Repository 查询；
- SSE 先读取当前权限下的首页，再提交 `200`，连接期间持续复验成员与可见性；
- 业务事件逐页串行交付，背压只合并空轮询信号；
- 每条流使用有界 Event ID/DomainEvent ID 集合，快照安装时重建该流去重基线；
- 客户端不解码、拼接、修改或比较不同流的 Cursor；
- Team Cursor 的签名密钥只存在服务端，支持带 Key ID 的轮换和有界旧 Key 验证；
- 快照、Cursor 和错误细节不公开不可见事件计数、成员身份、原始 Payload 或内部 Projection 行。

## 结果

- Team、Conversation 和 AG-UI 可以分别断线和恢复；
- 至少一次补发与 Event ID/DomainEvent ID 去重保证无重复展示；
- Team Generation 切换只刷新 Team 快照；
- Scope Epoch 阻止旧 Team 与旧 Conversation 的迟到结果污染当前工作台；
- 合并视图提供稳定展示顺序并保留各流权威边界。

## 验证

1. Team 与 Conversation 独立断线后各自使用最后已应用 Cursor 恢复，重放帧不重复展示，新帧不丢失；
2. AG-UI 使用同一 Idempotency Key 重放同一 Invocation Segment，文本增量只应用一次；
3. Team Cursor 过期后安装新 Generation 快照，并从 Snapshot Cursor 无缝继续；
4. Scope 切换后的旧 Team 迟到帧不写入新 Team Store；
5. 跨流合并按 DomainEvent ID 去重，展示顺序不声明 Global Sequence；
6. Stream/Scope 错配帧失败关闭并保持原 Cursor。

验证证据见 [M6-S02 三流 Cursor 与 Scope 恢复验证记录](../spikes/M6-S02-三流Cursor与Scope恢复验证记录.md)。

## 重新评估条件

- AG-UI 提供服务端耐久 Offset 与通用 GET Resume 协议；
- Team Event 迁移到 Kafka/Pulsar 等具有原生 Partition Offset 的事件日志；
- 产品需要跨 Team 聚合视图或跨区域全局事件顺序；
- Conversation Event 重建无法保留原 Position/Event ID；
- 浏览器需要多标签页共享一条 SSE 或 Service Worker 统一协调。
