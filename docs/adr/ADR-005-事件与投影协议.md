# ADR-005：DomainEvent、Outbox、Audit 与实时事件

> 状态：ACCEPTED<br>
> 日期：2026-08-05<br>
> 影响里程碑：M0–M6

## 背景

CrewScope 同时提供 AG-UI AgentRun 流、Conversation Event 流和 Team Event 流。业务事实、实时交互和投影更新需要稳定关联，前端需要处理断线、重复、乱序和 optimistic state。

## 决策

### 事实与投影

- PostgreSQL 领域聚合是业务事实源；
- 领域状态、DomainEvent 和 Outbox 在同一事务提交；
- Outbox Publisher 使用至少一次投递；
- ProjectionCheckpoint 保存投影分区和最后处理位置；
- AuditEvent 是追加写安全投影；
- Activity、Inbox、Notification 和 WorkGraph 是可重建读模型。

### 统一事件信封

AG-UI、Conversation Event 和 Team Event 共享：

```text
eventId
domainEventId
streamType
aggregateType
aggregateId
aggregateVersion
correlationId
causationId
occurredAt
schemaVersion
payload
```

一个 DomainEvent 进入多个流时保持相同 domainEventId。每个流生成独立 eventId 和 Cursor。

### Command Receipt

所有状态变更 Command 返回：

```text
commandId
domainEventId
committedVersion
correlationId
```

前端提交后展示 optimistic state。目标投影 Cursor 到达对应 domainEventId/committedVersion 后清理 optimistic state。超时后回读当前事实。AG-UI 的瞬时事件用于推理和工具进度，不覆盖领域状态。

### 顺序与幂等

- 消费者按 eventId 幂等；
- 聚合投影按 aggregateVersion 检测缺口；
- 缺口触发延迟重试或从领域事实重建；
- Cursor 是流内位置，不作为全局事务顺序；
- Schema 版本独立演进并保留向后读取能力。

## 结果

- 三条实时流可以关联、去重和恢复；
- Outbox 可以从 M0 开始支撑后续 Audit 与投影；
- 前端拥有确定的写入确认协议；
- AG-UI 与业务事实的职责清晰。

## 验证

1. 事务回滚时没有孤立 DomainEvent 或 Outbox；
2. 重复 Outbox 投递只生成一份有效投影；
3. 乱序事件触发版本缺口处理；
4. 前端断线后通过 Cursor 补齐事件；
5. 同一 DomainEvent 在 Conversation 与 Team 流中可以去重关联；
6. Projection 重建不修改领域事实。

## 重新评估条件

- Outbox 吞吐需要独立消息中间件；
- 引入 Kafka/Pulsar 和全局事件分区；
- 跨区域部署需要全局顺序或冲突解决；
- AG-UI 协议升级提供统一持久事件语义。
