## 背景与源码基线

M10 要让团队「越用越值钱」：Team 显式知识、仓库代码检索、成员偏好记忆三类数据进入 Agent 执行上下文。取证结论（S01 §2）：agentscope 2.0.0 无 `memory`/`extensions-*` 字面构件，RAG/Skills/Memory 基础类在 core（`SimpleKnowledge(EmbeddingModel + VDBStoreBase)` 等），聚合 jar 另带 mem0/ReMe/Bailian 等集成；agentscope 无 Checkpoint 概念。既有可复用资产：`ModelConnection` 凭据治理链（旋转/吊销立即生效）、`GitHubRepositoryImportWorker` 的 Claim/续租作业形状、`AgentMemoryPolicyReference`（现状悬空引用）、`JdbcWorkDeskRepositoryAdapter` 的 SQL 内联授权范式、既有 Session/AgentState/Checkpoint 恢复体系。

## 1. 三类数据、一个权威存储

| 数据 | 权威与来源 | 查询、更新责任 |
| --- | --- | --- |
| Team Knowledge | 人工维护/确认发布的团队约定；版本化权威事实（A02） | A02 管理，I01 派生索引，A01 检索 |
| Repository Index | 受管 Mirror 指定 commit 的派生视图；可整体重建（I01） | I01 建索引，A01 按目标 commit 检索 |
| 辅助记忆 | Team 内归属成员×Agent 的有界偏好；不替代会话恢复状态（I02） | I02 管理、按 Scope/所有者/TTL 组装，不先进向量库 |

决策：**CrewScope 自己的 PostgreSQL 是唯一权威状态**。agentscope core 类只作检索与组装能力；聚合 jar 内第三方记忆/检索集成不启用不实例化——不引入第二套 Memory/Vector 权威存储。辅助记忆不叫第二个 ConversationMemory；删除它只移除可选上下文，不破坏执行状态。三类数据不自动互相升级：执行结果/个人记忆/仓库内容升格为 Team 知识只能成为草稿，经披露检查与人工确认发布。

依赖统一走 BOM；新第三方依赖只进适配层；domain 零框架；新包按 `agentscope.knowledge` 职责命名。

## 2. 来源版本、生效失效与 Generation

- 知识发布创建不可变版本（版本号单调+内容哈希），提交即对**新**检索生效；草稿不可被检索命中。废弃/删除/Scope 收窄先在权威查询失效（下一版本或删除墓碑），索引侧变更事件异步清理；旧事件重放不复活旧版本——索引消费以权威当前有效版本为闸。
- 仓库索引键含 Organization/Team/RepositoryBinding/commit/分片策略哈希/embedding 模型修订；物理 Mirror 可复用，索引授权不以全局 RepositoryKey 划分。一次构建=一个 Generation，完成原子激活（单事务切 active 指针），失败保留旧代；保留最近 2 代（可配）供回退。检索只命中匹配任务目标 commit 的可用 Generation；无匹配显式缺失并降级，禁止默认分支最新内容冒充。
- 「保存成功」与「已可检索」是两个状态：保存回执（A02）与索引状态投影（I01：PENDING/INDEXED/FAILED+Generation）分开呈现。

## 3. 授权：向量检索不是权限绕过通道

- 检索发生在服务端，范围=`ExecutionScope ∩ Ownership`，与代码执行边界同源；Agent 能读到的知识必须是发起成员本人有权读到的。
- 授权谓词内联进 SQL（沿用 WorkDesk 范式：租户前缀×责任/归属交集），向量候选生成前先经授权+有效版本+可用 Generation 收敛——不做全局 Top-K 返回后过滤。缓存键含 Scope/授权版本/来源版本；权限变化不命中旧授权结果。
- ANN 内部扫描顺序不是授权证明；以真实 SQL、多 Scope 数据、查询预算与对外响应测试边界。成员停用/撤权按 ADR-038 持续授权语义：下一次检索/注入/外部发送前重验；无法安全移除已撤权上下文时中止或重建执行上下文。
- **已实现（M10-A01）**：统一检索服务交付本节前两条的检索侧——知识路（org+team 谓词+生效闸）与仓库路（org+team+binding 四坐标+ACTIVE Generation 门）全部内联进向量 nearest SQL 先于 Top-K，真 SQL 多租户夹逼/Generation 门/binding 隔离由 pgvector 集成测试与门控质量门禁承重（S01 冻结记录 §6 A01 列）；检索不缓存（缓存键约束留给 I02/F03 按需实现）；预览面为成员级数据面，`ExecutionScope ∩ Ownership` 的执行级交集归 I02 注入 Scope。

## 4. embedding Provider 与出站策略

- Provider 范围冻结（2026-09-30）：智谱 `embedding-3` 或阿里 `text-embedding-v4`（OpenAI 兼容、国内直连）；S01b 已实测选定 `text-embedding-v4` 并冻结维度 1024（批量上限 10、0.0005 元/千 Token 人民币；实测表见 S01 冻结记录 §3.2；智谱接入前须按该表补测）。
- 连接/凭据/AES-GCM/旋转/吊销/handle 链**原样复用** `ModelConnection` 治理；目录条目必须带生效价格行与数据策略声明（无生效价=`PRICE_UNAVAILABLE` 硬门槛）。verify（GET `/models`）只证传输+鉴权；embedding 能力校验=首条真实嵌入探针（维度+有限值+用量回显）。
- 已知库限制（`additionalBodyParams` 零消费者、`httpTransport` 唯一定制点）使 chat-completions 适配器不可复用：embedding 走独立最小 OpenAI 兼容客户端，复用凭据 handle 与出站策略。
- 索引与提炼向 Provider 发送内容前必须校验来源访问权与 Provider 数据策略允许；排除密钥文件是辅助手段非零秘密保证；禁止凭证或未授权源码出站。同维度不同模型不混用向量。
- **已实现（M10-I01a）**：`EmbeddingClient` Port+`OpenAiCompatibleEmbeddingClient`（独立最小客户端，S01 §3.2 冻结数字在 Port 强制）、目录 seed 的 DashScope `text-embedding-v4` 行（价格/数据策略 PROHIBITED）、`TeamEmbeddingService` 治理解析链（TEAM→ORG、生效价格硬门、数据策略门、逐 attempt `MODEL_USAGE_FACT_RECORDED(EMBEDDING)`）、verify 第二腿 `EmbeddingCapabilityProbe`（首条真实嵌入探针）。

## 5. pgvector 安装、迁移与退路

- 默认 Flyway 扫描不含 `CREATE EXTENSION vector` 与 `vector(n)` 列；纯 PostgreSQL 安装升级不受影响。vector 扩展与向量表/索引使用显式安装的独立位置与 Schema history；安装状态与检索开关分离，已安装后关闭检索仍继续校验/升级其历史。
- 提供已验证的可选镜像/覆盖配置（根 Compose 与 Team Beta 均覆盖），不强制 Digest、不加第五个默认服务、不引入独立向量数据库。切换镜像前备份并验证兼容（Alpine/Debian 卷不假设可原地复用）；索引可重建，权威知识/配置密钥/迁移历史不可丢。
- 未安装时普通启动成功，启用检索给可操作原因；已安装历史损坏不被降级吞掉。模型/维度/分片策略变更=新 Generation 重建、验证、切换；回退保留兼容旧代，不改旧迁移。最短启用/关闭/升级/恢复步骤进单机运维手册。
- **已实现（M10-I01a）**：独立迁移链 `db/migration-vector`（V1 扩装入 public、V2 向量表+HNSW cosine，history=`flyway_vector_history`）；`KnowledgeVectorMigrationRunner`（`SmartInitializingSingleton`，单规则门控「enabled 或历史已存在」，worker 跳过，失败 fail-fast）；`PgVectorKnowledgeEmbeddingStore`（文本字面向量绑定，租户谓词+生效闸先于 Top-K）；compose 覆盖×2 与运维手册「可选向量存储」小节。向量链 V3 `repository_chunk_embedding`（仓库分片向量表+HNSW cosine，跨链 FK 指向 V56 Generation）随 I01b 落位；控制面 API 与恢复 Runbook 已随 I01c 交付（2026-10-04）。

## 6. 持久作业、预算与质量

- 索引作业沿用 `GitHubRepositoryImportWorker` 形状（单表状态机+CTE `FOR UPDATE SKIP LOCKED` claim+状态推进续租+claim 后授权重放+单 worker 防重入），两处增强：单调 `claim_token` 代际使旧 claim 写入显式 fencing 拒绝（可观测，不静默）；分批 checkpoint 支持重启续传。资源上限（批量/并发/lease/Generation 分片总量）由 I01 冻结默认值。
- Prompt 组装四层优先级：Skill 指令（硬保留）→ 知识条目 → 仓库片段 → 辅助记忆；超预算自低层尾部裁剪，裁剪记录入注入清单。失败关闭（授权/业务预算）与显式降级（无索引/Provider 暂不可用，带原因码）严格分界，降级不伪装成检索无结果。
- 质量：S01 冻结标注集/K/Recall@K/无答案/版本准确性阈值与测量口径（版本准确性=1.0 无容差）；真实任务对照开/关检索各 3 次，冻结可接受回归范围；不以「有引用」证明更准确。
- **已实现（M10-I01b，作业与 Generation 前半）**：持久作业生产化——`knowledge_index_job` 单表状态机（QUEUED→CHUNKING→EMBEDDING→ACTIVATING→READY/FAILED/CANCELLED）双来源判别列+两 target 形状互斥 CHECK、claim CTE `FOR UPDATE SKIP LOCKED` 按 created_at、单调 `claim_token`（CAS 0 行=显式 FENCED 计数进遥测）、分批 checkpoint EXISTS 门+批尾续传、资源上限入配置（批≤10/单作业并发 1/lease 默认 30m 上限 1h/单 Generation 分片上限超限显式 FAILED 不截断）；Generation 写侧（V56 部分唯一索引 `ux_generation_one_active` 即激活指针，激活单事务切指针+保留 2 代+超窗旧代向量行同事务回收，失败只置本代 FAILED 绝不碰 ACTIVE）；双来源分片（代码 80 行窗/70 步长、Markdown 标题分块+超限二次切、知识条目整条一片超限显式拒绝、glob 排除进 ChunkingPolicyHash）；indexStatus 投影 PENDING/INDEXED/FAILED 派生计算不加列（契约 §5 已冻结）；A02 知识事件消费（refresh 门控/cleanup 不门控，权威生效闸不信任事件序）。检索消费（A01 已于 2026-10-04 交付，见 §3 标注）与控制面 API/恢复 Runbook（I01c，2026-10-04，见下）已交付；Prompt 预算组装已随 I02b 交付（见下）。
- **已实现（M10-I01c，控制面）**：统一作业控制面 HTTP API（`rebuilds`/`repository-builds`→202、`jobs` 列表/详情→200 成员级 no-store、`cancel`→200 同步三分，幂等=结构性——活作业部分唯一索引坍缩+取消终态幂等，不要求 IK/If-Match）；入队竞争收敛（适配器把 23505+活作业约束名翻译为专用异常，服务层 find-live 收敛到赢家，并发触发永不以 500 暴露）；binding 四坐标归属校验防跨组索引污染；DTO 不外泄 `claimToken`（Worker 内部围栏凭据）、透出 `claimedBy`/`leaseExpiresAt`（恢复第一客户）；开关矩阵（闸关 202 enqueued=0 不 503，读面恒可用，控制面恒装配）；keyset 读面 `(created_at,id)` 升序+V57 列表索引；恢复 Runbook 进运维手册「作业故障恢复」。契约见 [M10-仓库索引API契约](../api/M10-仓库索引API契约.md)。
- **已实现（M10-I02b，Prompt 预算组装）**：四层优先级（SKILL_INSTRUCTION 硬保留不进快照→KNOWLEDGE_ENTRY 3072→REPOSITORY_CHUNK 4096→MEMORY_PREFERENCE 1024，总 8192 硬上限 32768 超出拒启动、层和≤总额启动期 fail-fast）；两阶段裁剪纯函数（层内最长前缀尾裁 `"layer budget exceeded"`、层和超总额按 MEMORY→REPOSITORY_CHUNK→KNOWLEDGE_ENTRY 尾裁 `"total budget exceeded"`）；Token 估算冻结公式 `max(ceil(utf8Bytes/4), ceil(codePoints/3))` 下限 1（8192 预算 ⇒ 注入文本 ≤~24.6k ASCII，仍在 CodingSpecialistRound 30,000 字符界内）；被裁候选以 CANDIDATE 阶段入清单不丢证据；检索降级三码原样透传，授权/业务失败关闭不降级。契约见 [M10-Prompt注入与注入清单契约](../api/M10-Prompt注入与注入清单契约.md)。

## 7. 注入证据、反馈与可观测

- 每次模型调用前持久化注入清单（执行/attempt/片段 id+版本+哈希/裁剪/预算快照/降级原因码）；恢复新 attempt 新清单，旧清单不重计；模型声明引用只能关联本次清单集合，呈现层区分候选/注入/声明引用。历史证据展示重新授权。
- 反馈按（执行/片段/成员）幂等，不改写已发送 Prompt 与历史结果；用于统计与后续显式排除，不隐式全局废弃、不自动改排序。
- 用量事实按统一形状事件补齐（稳定调用 id/providerKey/modelId/connectionId+version/角色枚举含 EMBEDDING 与 DISTILLATION/attempt/token 四元组），由产生环节发射、F03 可重建聚合；缺失标 UNKNOWN 不按零；价格版本化带币种；软预算走 ADR-022 Inbox/飞书通道 team×月幂等去重。
- **已实现（M10-I02b，清单与注入）**：V59 `injection_manifest` 单表（幂等键 `uk(execution_id, attempt)`、复合 FK→task_execution RESTRICT、四 JSONB 列 CHECK 锁形状，纯 PG）；首次模型调用前 append 封存（冲突经 findByAttempt 收敛到先封者），round≥2/恢复按已封清单 INJECTED 四元组（type+sourceId+version+contentHash）过滤新鲜候选——注入⊆已封证据永不超封；接线仅 Coding Worker 链一点（openRound 组装先于 session open，失败关闭不留半开 session；注入 actor=任务创建者，撤权失败关闭 ADR-038），渲染块不可信声明句+三转义分区缀于原指令后；仅实际注入的记忆条目 touch（false/异常容忍），被裁条目不续期。引用查询与幂等反馈已随 I02c 交付（见下条）；「已注入≠已采用」呈现消费归 F01c。契约见 [M10-Prompt注入与注入清单契约](../api/M10-Prompt注入与注入清单契约.md)。
- **已实现（M10-I02c，引用查询与反馈）**：V60 两表（`injection_reference_feedback` uk（执行×四元组×成员）ON CONFLICT DO NOTHING 回读重放——member 无 FK 不阻 ADR-038 生命周期；`injection_claimed_reference` uk（execution,attempt）集合语义幂等——存储前规范排序去重，同集重放、异集 409 携已存回执）；三端点零开关门控（已封存证据是历史事实，I01c 闸关读面先例）——GET 三区呈现（stage+notApplicable 仅本人+claimed null/[] 区分）、POST feedback 锚定全部 attempt 清单 INJECTED 并集（CANDIDATE 从未进 Prompt 不予评判）、POST claimed ⊆ 单 attempt 清单（回执端点，模型侧生产接线不在本轮）；反馈不改写已发送 Prompt、不隐式全局废弃、不自动改排序——团队聚合与显式排除消费归 F03；权限=执行可见者（归属校验先于载荷评估，跨租户同形 404）；内容保留冻结：无 TTL 无清扫随 task_execution RESTRICT 生存期，清理留 F03/Q01。契约见 [M10-执行引用与反馈API契约](../api/M10-执行引用与反馈API契约.md)。

## 8. 辅助记忆边界

所有者键=organization+team+成员+Agent+策略版本；策略版本即 `AgentMemoryPolicyReference`（I02 交付策略实体承接悬空引用，Agent 配置链零改动）。只存冻结偏好结构（命名键值≤1KB），不留任意原始会话副本；默认 TTL 90 天滑动、每（成员×Agent）≤100 条、超限显式拒绝。清除防复活=单调 `clearance_generation`，旧代际写入拒绝；撤权立即不可读（ADR-038 语义），物理清理异步。查看/清除/开关后端进既有 Agent 设置，不新建独立菜单。

- **已实现（M10-I02a）**：策略实体=代码目录 `AgentMemoryPolicyCatalog`（`DEFAULT_POLICY_ID` 稳定 UUID，仅 DEFAULT id@v1 可解析，加版本=目录加条目，无策略表无 FK）；存储=V58 两表（owner 四元组唯一+单调代际，entry 七列空间键唯一——策略版本进键切版本开新空间，1KB 按字节口径 domain `getBytes(UTF_8)` 与 SQL `octet_length` 双侧一致）；清除防复活由适配器 owner 行 `FOR UPDATE` 代际闸承重（clear 后旧代际 upsert 抛 `OptimisticLockConflictException`，集成测试证伪复活）；写入即刷新 TTL，touch/list 端口就绪供 I02b（注入=使用才续期，查看不续期）；超限 CAPACITY_EXCEEDED 显式拒绝带计数（容量口径=当前策略空间，同 key 覆盖不占新槽）；本人查看/清除=GET/DELETE `/memory` 两端点（路径无 owner 参数，撤权即 403），同步回执结构性幂等；双层开关（部署 `crewscope.memory.enabled` 门新增模型向写入与 HealthIndicator，本人开关=配置的 `memoryPolicy` Optional 配即开，查看/清除/TTL 清扫不门）。零领域事件/零审计事件/不走 outbox（S01 未冻结要求，契约 §9 写明）。touch 调用方已随 I02b 交付（2026-10-04）：注入=使用才续期——仅实际注入条目 touch，被裁候选不续命；`memory.enabled=false` 时注入链不调 list 零引用（与「不新增模型向读写」一键一义）。I02c（引用反馈/呈现层/开关组合端到端）未实现。

## 9. 实现约束与验证

- 实现顺序与切片归属按主计划 §6.1；D01 只建公共地基（Scope/来源版本/Generation 合同+知识基础迁移），各包自交付迁移与测试。
- 必测：越权多路径（缓存/异步作业/历史引用）、重复乱序事件、commit/Generation 切换、force-push/解绑、并发旧 Worker 不污染、清除不复活、注入证据与实际片段一致、开关有效组合（§10.7 清单）与 Readiness 原因码、双安装路径（纯 PG 关闭态/增强开启）升级恢复。
- S01b 原型（真实 embedding 实测、隔离授权检索、隔离作业恢复）是可行性证据，不是功能验收；真实闭环验收在 Q01/Q02。
