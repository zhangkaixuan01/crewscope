# ADR-001：Task、TaskExecution、StepExecution 与 Lease

> 状态：ACCEPTED<br>
> 日期：2026-08-05<br>
> 更新：2026-08-14（M3-D08 以 V10 固化 TaskExecution Lease 数据库裁决）<br>
> 影响里程碑：M3–M6

## 背景

CrewScope 同时需要表达业务目标、执行尝试、步骤检查点、Worker 所有权、Agent 会话和失败重试。将这些状态放在同一个聚合会导致业务状态与运行状态互相覆盖，并使 Specialist Agent、Step 和 Worker 同时拥有恢复权。

## 决策

### Task

Task 表示业务目标，状态为：

```text
CREATED -> ACTIVE -> WAITING -> COMPLETED
CREATED / ACTIVE / WAITING -> CANCELLED
ACTIVE / WAITING -> FAILED
```

Task 关联当前有效 TaskExecution，根据执行、Review、Confirmation 和外部动作计算业务状态。

### TaskExecution

TaskExecution 表示一次执行尝试，承载：

- CREATED、READY、CLAIMED、PREPARING、RUNNING、WAITING、请求态、RECOVERING 和终态；
- Runtime、Worker、Claim Token、ExecutionLease、预算和失败分类；
- attempt、max_attempts 和 parent_execution_id；
- 当前 PlanVersion、PolicySnapshot 和 ExecutionWorkspace。

`WAITING` 是唯一等待主状态，独立等待原因表达 Runtime、协作、Review、确认、用户输入、外部执行、事件和人工处理。暂停与取消先进入请求态，再由 Worker 在安全点提交 `PAUSED` 或 `CANCELLED`。完成、失败和取消使用独立终态事实；失败只保留稳定失败分类和安全错误码。

失败重试只允许从 Task 当前指向的可重试失败尝试创建，生成 `attempt + 1`、携带 `parent_execution_id` 的新 TaskExecution，并继承原 `max_attempts`。原尝试保持不可变终态，同一 Task 的重试链不允许从历史尝试分叉。

### StepExecution

StepExecution 表示任务步骤，承载 Executor、输入、输出、状态、检查点和 Agent Session。MVP 的 Step 在所属 TaskExecution 的有效 Lease 内串行运行，使用乐观锁提交状态和结果。

### Lease

MVP 只创建 TaskExecution Lease。每次成功 Claim 生成一次性随机 Claim Token，数据库只保存 Claim Token Hash。TaskExecution 保存最后已提交 Fencing Token，每次 `READY -> CLAIMED` 在同一事务中严格递增一次；ExecutionLease 只绑定当前纪元，不自行分配 Fencing Token。Heartbeat、Progress、Complete、Fail、Cancel 和 Lease Sweeper 使用 `task_execution_id + attempt + runtime_id + worker_id + claim_token_hash + fencing_token + expected_version` 条件更新。`expected_version` 对应命令直接修改的事实：Heartbeat 和 Lease 续期使用 `ExecutionLease.lease_version`，Progress、Complete、Fail、Cancel 和恢复状态迁移使用 `TaskExecution.version`。Heartbeat 不修改 TaskExecution Version，避免周期性续租与执行检查点产生无意义冲突。Step 不独立 Claim 或续租，并在提交状态、检查点、AgentRun 或结果前校验所属 TaskExecution 的同一有效 Lease。

Claim Token 证明 Worker 持有本次随机领取凭据，Fencing Token 阻断已经失去租约的旧 Owner。续租不更换 Fencing Token；重新领取或恢复接管必须分配更大的 Fencing Token。Claim Token 明文只在成功领取响应中返回一次，不进入日志、事件、Artifact 或查询 API。

Lease 使用 `PREPARE` 和 `RUN` Phase。单次 TTL 下限均为 5 秒，PREPARE 上限为 15 分钟，RUN 上限为 10 分钟。Heartbeat 只更新 Lease 心跳、过期时间和 Lease Version。权威时间满足 `now >= expires_at` 时 Lease 过期。显式释放原因与 TaskExecution 的 Completed、Failed、Cancelled、Paused、Waiting、Manual Takeover 或 Worker Shutdown 状态闭合；`EXPIRED` 只由 Sweeper 提交。显式释放和过期释放是互斥终态。

Application Port 将 Claim 定义为 TaskExecution Fencing Token 递增、`READY -> CLAIMED` 与 PREPARE Lease 的原子提交，将结果释放定义为 TaskExecution 状态与 Lease 终态事实的原子提交。续租与 PREPARE-to-RUN 阶段切换使用独立 Port 方法，不提供通用 Lease Update 通道。

Phase 2 需要并行 Step 时，通过新 ADR 增加独立 Step Lease 协议。

V10 使用 `ux_execution_lease_active` 裁决每个 TaskExecution 的单活动 Lease，使用 `task_execution_id + fencing_token` 唯一键和正数约束固化所有权纪元。`ix_task_execution_ready_queue` 支持按 Organization、Priority、notBefore 和创建顺序领取，`ix_execution_lease_expiry` 支持 Sweeper 扫描活动过期租约。Claim Token 列固定为 64 位小写 SHA-256 Hash，表中没有明文 Token 列。数据库不创建 Step Lease 表。

### Specialist Agent

Coding Specialist 与 Reviewer Specialist 由 Durable Task Runtime 创建为 StepExecution。AgentScope `agent_spawn` 处理短时、可重算、无外部副作用的内部分析。任何 Artifact 修改、Worktree 修改和外部动作都进入 StepExecution 或 PlannedAction Worker。

## 结果

- 业务生命周期和执行尝试拥有独立事实；
- TaskExecution Lease 成为 MVP 唯一 Worker 所有权；
- Claim Token 与 Fencing Token 共同阻断旧 Worker 回写；
- 重试、恢复、成本和审计按 attempt 归属；
- Step 并行能力延后到真实需求出现后设计；
- AgentScope 子任务不承担平台耐久性。

## 验证

1. 两个 Worker 并发 Claim 只有一个成功；
2. 失效 Lease、旧 Claim Token 或旧 Fencing Token 无法提交 Step、AgentRun 和 TaskExecution 结果；
3. Complete 与 Sweeper 竞争只产生一个终态；
4. 新执行尝试不修改旧尝试终态；
5. AgentScope 子任务不能直接执行 Provider 写操作。

## 重新评估条件

- 一个 TaskExecution 需要并行运行多个长时 Step；
- Step 被分配到不同 Runtime 或不同 Worker；
- External Coding Runtime 要求独立步骤租约。
