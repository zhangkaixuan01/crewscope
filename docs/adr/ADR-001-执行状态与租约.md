# ADR-001：Task、TaskExecution、StepExecution 与 Lease

> 状态：ACCEPTED<br>
> 日期：2026-08-05<br>
> 影响里程碑：M3–M6

## 背景

CrewScope 同时需要表达业务目标、执行尝试、步骤检查点、Worker 所有权、Agent 会话和失败重试。将这些状态放在同一个聚合会导致业务状态与运行状态互相覆盖，并使 Specialist Agent、Step 和 Worker 同时拥有恢复权。

## 决策

### Task

Task 表示业务目标，状态为：

```text
CREATED -> ACTIVE -> WAITING -> COMPLETED
CREATED / ACTIVE / WAITING -> CANCELLED
ACTIVE / WAITING -> FAILED
```

Task 关联当前有效 TaskExecution，根据执行、Review、Confirmation 和外部动作计算业务状态。

### TaskExecution

TaskExecution 表示一次执行尝试，承载：

- READY、CLAIMED、PREPARING、RUNNING、WAITING、RECOVERING 和终态；
- Runtime、Worker、Claim Token、ExecutionLease、预算和失败分类；
- attempt、max_attempts 和 parent_execution_id；
- 当前 PlanVersion、PolicySnapshot 和 ExecutionWorkspace。

失败重试创建新的 TaskExecution，原尝试保持不可变终态。

### StepExecution

StepExecution 表示任务步骤，承载 Executor、输入、输出、状态、检查点和 Agent Session。MVP 的 Step 在所属 TaskExecution 的有效 Lease 内串行运行，使用乐观锁提交状态和结果。

### Lease

MVP 只创建 TaskExecution Lease。每次成功 Claim 生成一次性随机 Claim Token 和单调递增 Fencing Token，数据库只保存 Claim Token Hash。Heartbeat、Progress、Complete、Fail、Cancel 和 Lease Sweeper 使用 `task_execution_id + attempt + claim_token_hash + fencing_token + expected_version` 条件更新。`expected_version` 对应命令直接修改的事实：Heartbeat 和 Lease 续期使用 `ExecutionLease.lease_version`，Progress、Complete、Fail、Cancel 和恢复状态迁移使用 `TaskExecution.version`。Heartbeat 不修改 TaskExecution Version，避免周期性续租与执行检查点产生无意义冲突。Step 不独立 Claim 或续租，并在提交状态、检查点、AgentRun 或结果前校验所属 TaskExecution 的同一有效 Lease。

Claim Token 证明 Worker 持有本次随机领取凭据，Fencing Token 阻断已经失去租约的旧 Owner。续租不更换 Fencing Token；重新领取或恢复接管必须分配更大的 Fencing Token。Claim Token 明文只在成功领取响应中返回一次，不进入日志、事件、Artifact 或查询 API。

Phase 2 需要并行 Step 时，通过新 ADR 增加独立 Step Lease 协议。

### Specialist Agent

Coding Specialist 与 Reviewer Specialist 由 Durable Task Runtime 创建为 StepExecution。AgentScope `agent_spawn` 处理短时、可重算、无外部副作用的内部分析。任何 Artifact 修改、Worktree 修改和外部动作都进入 StepExecution 或 PlannedAction Worker。

## 结果

- 业务生命周期和执行尝试拥有独立事实；
- TaskExecution Lease 成为 MVP 唯一 Worker 所有权；
- Claim Token 与 Fencing Token 共同阻断旧 Worker 回写；
- 重试、恢复、成本和审计按 attempt 归属；
- Step 并行能力延后到真实需求出现后设计；
- AgentScope 子任务不承担平台耐久性。

## 验证

1. 两个 Worker 并发 Claim 只有一个成功；
2. 失效 Lease、旧 Claim Token 或旧 Fencing Token 无法提交 Step、AgentRun 和 TaskExecution 结果；
3. Complete 与 Sweeper 竞争只产生一个终态；
4. 新执行尝试不修改旧尝试终态；
5. AgentScope 子任务不能直接执行 Provider 写操作。

## 重新评估条件

- 一个 TaskExecution 需要并行运行多个长时 Step；
- Step 被分配到不同 Runtime 或不同 Worker；
- External Coding Runtime 要求独立步骤租约。
