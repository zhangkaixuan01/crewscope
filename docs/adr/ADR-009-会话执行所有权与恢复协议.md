# ADR-009：会话执行所有权与恢复协议

> 状态：ACCEPTED<br>
> 日期：2026-08-09<br>
> 影响里程碑：M2–M6<br>
> 验证记录：[M2-S02 会话并发与 Redis 恢复](../spikes/M2-S02-会话并发与Redis恢复验证记录.md)、[M2-I05 Redis AgentStateStore 与单活动实例](../testing/M2-I05-Redis-AgentStateStore与单活动实例.md)

## 背景

CrewScope 使用同一个 Personal Agent 实例服务多个 Conversation。每次调用通过 AgentScope `RuntimeContext.userId/sessionId` 选择独立状态槽，并在调用结束后把 `AgentState` 保存到 Redis。会话执行需要同时保证单个 Session 内的消息顺序、不同 Session 的并行能力、取消后的队列清理和进程重启后的状态续接。

AgentScope 2.0.0 提供两层进程内串行机制：

- `ReActAgent` 使用 `(userId, sessionId)` 组成调用键，通过 `AgentBase` 的尾链按订阅顺序串行调用；
- Harness Gateway 使用 `SessionTurnGate` 的公平 `Semaphore(1, true)` 按 Gateway Key 串行 Turn。

两层机制的状态都保存在当前 JVM。`RedisAgentStateStore` 保存完整状态值，读写使用普通 Redis `GET/SET`，没有执行租约、版本比较或分布式互斥。

## 决策

### 会话身份与顺序

CrewScope 使用持久化 `AgentRuntimeSession.agentScopeKey` 生成唯一执行键：

```text
userId    = versioned(organizationId, teamMemberId, personalAgentPrincipalId)
sessionId = versioned(conversationId, agentRuntimeSessionId)
ownerKey  = versioned(userId, sessionId)
```

- Call、Stream、Resume 和 Cancel 始终使用服务端解析的同一组键；
- 同一 `ownerKey` 的调用按服务端接受顺序进入 AgentScope；
- 不同 `ownerKey` 可以并行运行；
- HTTP 幂等、Message 序号和 Invocation 事实由 PostgreSQL 裁决，AgentScope FIFO 只保护运行时状态槽；
- 取消订阅释放进程内尾链，正式取消入口同时使用精确 Session 身份传播取消意图。

### M2 部署拓扑

M2 的 Agent 调用由一个活动的 CrewScope Server 实例执行。该实例拥有全部 Conversation Session 的运行权，滚动发布先停止接收新调用，再排空或中断并保存活动调用，旧实例退出后启动新实例。

Redis 保存状态和重启检查点。M2 使用环境级 Redis 所有权租约阻止两个 CrewScope Server 实例同时执行 Agent 调用；该租约只保护整个 M2 执行拓扑，不提供 Session 级并发执行能力。租约按随机进程 Token 原子续期和释放，失联后依靠有限 TTL 清理。启动时取得失败直接拒绝启动，运行时失去所有权后新调用失败关闭。

后续横向扩展采用带 fencing token 的分布式 Session Lease。Lease 至少包含 `ownerKey`、`ownerInstanceId`、单调 `fencingToken`、`expiresAt` 和 `version`。状态提交必须校验当前 fencing token，失效 Owner 无法覆盖新 Owner 的结果。会话粘滞路由只负责减少迁移，执行所有权继续由 Lease 裁决。

### Redis 状态与恢复

Redis Key 使用 CrewScope 专属、带环境和 Schema 版本的前缀：

```text
crewscope:{environment}:agentscope:v1:session:
```

AgentScope 每次调用开始时按 `(userId, sessionId)` 重载完整 `AgentState`，成功结果、用户 Interrupt 恢复和 Graceful Shutdown 检查点完成后保存整份状态。

恢复语义如下：

1. 新进程使用相同稳定 Session Key 读取最后一次成功保存的 `AgentState`；
2. 已完成 Turn 的用户消息和 Agent 回复一起恢复；
3. Graceful Shutdown 在活动调用安全点保存带中断标记的状态；
4. 硬中断恢复到最后一个 Redis 检查点，当前用户 Message 继续由 PostgreSQL 保存；
5. 应用层根据 Message、Invocation、TaskIntent 和幂等事实决定重新调用、继续或向用户说明续接状态；
6. Redis 写入失败使当前 Agent 调用失败，正式入口不把未保存回复提交为最终 Message。

M2 不为 AgentState 设置独立 TTL。Conversation 归档和 AgentRuntimeSession 清理流程显式删除状态；保留周期由后续数据生命周期策略统一配置。

AgentScope 2.0.0 在状态读取异常时记录警告并创建全新 `AgentState`。CrewScope 在 Invoke 和 Resume 的模型调用前依次确认当前实例所有权、Redis `PING`、目标 `agent_state` 解码及身份闭合、隔离写探针和所有权未丢失。已登记但缺少完整状态、状态损坏、身份不匹配、Redis 不可读写或所有权丢失统一按 `AGENT_STATE_UNAVAILABLE` 失败关闭。新状态槽也必须通过写探针，避免模型已经运行后才在保存阶段失败。

### 框架边界

- `AgentBase` 会在完成、错误和取消信号上释放会话尾链并删除当前尾节点；
- `SessionTurnGate` 的 Gate Map 按 Key 保留 `Semaphore`，Gateway Session 生命周期需要配套清理或限制高基数 Key；
- `HarnessAgent.interrupt()` 使用默认 Session，生产调用使用带 `RuntimeContext` 或显式 `userId/sessionId` 的精确中断能力；
- 两个独立 Agent/Gateway 实例拥有独立进程内 Gate，能够同时进入同一个 Redis 状态槽；
- Redis 整值保存采用最后写入覆盖，多实例同时处理同一 Session 会产生丢失更新风险；
- 单值保存的 Redis `SET` 与 Session Key 集合 `SADD` 是两个操作，M2 清理与枚举不能充当事务提交证据；AgentRuntimeSession 和 PostgreSQL Message 继续作为业务事实。

## 结果

- M2 具备清晰、可验证的单 Session FIFO 与跨 Session 并行语义；
- 取消、异常和进程切换有明确的运行权释放与恢复边界；
- Redis 状态恢复与业务事实恢复分层处理；
- M2 使用单活动执行实例获得确定的 Session 所有权；
- 横向扩展以带 fencing token 的 Session Lease 作为前置能力。

## 验证

1. 三个同 Session 调用按确定的订阅顺序进入 Model；
2. 两个不同 Session 在任一调用释放前同时进入 Model；
3. 活动调用取消后，下一个同 Session 调用立即进入；
4. 模型错误后，下一个同 Session 调用立即进入；
5. 两个 `SessionTurnGate` 实例可以同时取得相同 Key，证明 Gate 为 JVM 局部；
6. 新 Redis Client、新 AgentStateStore 和新 HarnessAgent 使用稳定 Key 恢复完整已提交上下文；
7. 相同 Session ID 在不同 User ID 下保持状态隔离；
8. 模拟硬中断后只恢复最后一个成功保存的检查点；
9. 测试使用受控 Publisher、Latch 和原子记录器推进状态，超时只用于死锁保护。
10. Spring Boot 只装配一个 RedisDistributedStore、AgentStateStore 和状态生命周期适配器；
11. 第二个活动实例启动失败，旧实例正常释放或租约过期后新实例能够接管；
12. 状态损坏、不完整、身份错配或 Redis 失联时模型调用次数为 0；
13. 归档或过期业务事实通过显式生命周期操作删除完整状态槽，AgentState 本身不设置 TTL。

## 重新评估条件

- CrewScope Server 需要两个及以上 Agent 执行副本；
- 引入独立 Agent Runtime Worker 或跨区域执行；
- AgentState 需要增量写入、CAS、版本合并或独立 TTL；
- Gateway Session 数量达到需要主动回收 Gate 的规模；
- M3 ExecutionLease 可以复用为 Conversation Session Lease。
