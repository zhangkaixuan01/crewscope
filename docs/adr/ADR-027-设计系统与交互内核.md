# ADR-027：设计系统与交互内核

> 状态：ACCEPTED<br>
> 日期：2026-09-12<br>
> 影响里程碑：M9-S01、M9-F01、M9-F03、M9-F05<br>
> 关联文档：[M9 执行清单](../plans/M9-产品体验重构与设计系统.md)、[M9-S01 Spike 记录](../spikes/M9-S01-设计系统交互内核与高亮选型验证记录.md)

## 背景

CrewScope 已完成 M8 的功能与工程收口，但前端仍缺少统一的设计 Token、反馈组件和动作发现模型。字号、间距、层级和断点存在大量散落值；状态流转在页面中以目标状态下拉框呈现；前端手抄领域状态机；Toast、Confirm、Tooltip 和 Skeleton 没有唯一实现。这些问题会让相同事实在不同页面产生不同操作路径，也会让后续 M9–M10 的界面重构持续产生漂移。

M9 只改变呈现和发现方式，不改变领域状态机、事件、权限、幂等、恢复和既有 API 语义。

## 决策

### 1. Token 合同

#### 1.1 文字阶梯

以下七档是唯一生产字号。正文默认 `14px`，生产代码禁止 `10px` 及以下；`11px` 仅允许登记在 Diff/代码行号白名单中。

| Token | 值 / 行高 | 用途 |
|---|---:|---|
| `--cs-text-xs` | `12px / 1.5` | 元信息、时间、辅助列 |
| `--cs-text-sm` | `13px / 1.55` | 密集表格正文、次要说明 |
| `--cs-text-base` | `14px / 1.6` | 正文默认 |
| `--cs-text-md` | `16px / 1.5` | 强调正文、窄屏输入框 |
| `--cs-text-lg` | `18px / 1.5` | 三级标题、卡片标题 |
| `--cs-text-xl` | `24px / 1.4` | 二级页面标题 |
| `--cs-text-2xl` | `32px / 1.3` | 一级标题、认证页标题 |

行高只允许 `--cs-leading-tight: 1.3`、`--cs-leading-normal: 1.5`、`--cs-leading-relaxed: 1.7`；字重只允许 400、500、600。计划正文早期出现的 `2xs/2xl` 命名与本表冲突时，以本表和 M9 §10.3 为准。

#### 1.2 间距、控件、层级和断点

```css
--cs-space-2: 2px;   --cs-space-4: 4px;   --cs-space-8: 8px;
--cs-space-12: 12px; --cs-space-16: 16px; --cs-space-20: 20px;
--cs-space-24: 24px; --cs-space-32: 32px; --cs-space-40: 40px;
--cs-space-48: 48px;
--cs-control-sm: 32px; --cs-control-md: 36px; --cs-control-lg: 40px;
--cs-touch-min: 44px;
```

层级只允许以下语义 Token，且顺序不可调换：

```css
--cs-z-base: 0;      --cs-z-raised: 300;   --cs-z-sticky: 400;
--cs-z-drawer: 500;  --cs-z-overlay: 600;  --cs-z-dialog: 700;
--cs-z-popover: 800; --cs-z-toast: 900;    --cs-z-tooltip: 1000;
```

CSS 媒体查询不能使用 CSS 变量。断点唯一真源为 `src/design/breakpoints.ts`：`sm=640`、`md=768`、`lg=1100`、`xl=1440`；CSS 使用对应字面值并写 `/* cs-bp: <name> */` 注释，JS/TS 使用 `useMediaQuery(CS_BREAKPOINTS.<name>)`。

#### 1.3 主题、密度和动效

根元素使用 `data-cs-theme="light|dark"` 与 `data-cs-density="comfortable|compact"`。暗色主题只覆盖语义色，不覆盖品牌色阶；紧凑密度只调整控件高度、`space-12/16/20/24` 和正文行高，不调整字号。首屏属性由 `index.html` 内联脚本写入，`preference.ts` 负责版本化持久化。

动效 Token 固定如下，并扩写 `tokens.css` 现有的 reduced-motion 块：

| Token | 值 | 用途 |
|---|---:|---|
| `--cs-transition-fast` | `120ms` | 悬停、焦点环、按钮态 |
| `--cs-transition-panel` | `180ms` | 展开、切换、Toast、Popover |
| `--cs-transition-state` | `220ms` | Drawer、Dialog、分栏、状态流转 |

曲线只允许 `--cs-ease-out: cubic-bezier(0.22, 1, 0.36, 1)` 和 `--cs-ease-in-out: cubic-bezier(0.4, 0, 0.2, 1)`。`prefers-reduced-motion: reduce` 下三档时长均为 `0ms`。

明暗主题的首批语义色对比度基线（WCAG AA 需要正文至少 4.5:1）如下，后续实现不得低于这些数值：

| 文字/语义色 | 背景 | 对比度 |
|---|---|---:|
| `#17202a`（正文） | `#ffffff` | 16.45:1 |
| `#445149`（次要文字） | `#ffffff` | 8.34:1 |
| `#5f6f66`（辅助文字） | `#ffffff` | 5.31:1 |
| `#ecf4ee`（暗色正文） | `#111814` | 16.09:1 |
| `#c1d0c5`（暗色次要文字） | `#111814` | 11.25:1 |
| `#9fb1a5`（暗色辅助文字） | `#111814` | 7.99:1 |
| `#9bd9ad`（成功） | `#183020` | 8.72:1 |
| `#9fc5f0`（信息） | `#14263a` | 8.57:1 |
| `#c8b6ef`（Agent） | `#29203d` | 8.33:1 |
| `#f3c98b`（警告） | `#3b2b16` | 8.77:1 |
| `#f2a3a3`（危险） | `#3b1c1c` | 7.70:1 |

### 2. 反馈组件是单一实现

| 能力 | 唯一 API | 约束 |
|---|---|---|
| 瞬时结果 | `useToast()` + `<ToastHost>` | 队列、并发合并、可选撤销、`aria-live="polite"`、键盘关闭 |
| 阻塞确认 | `useConfirm()` + `<ConfirmHost>` | Promise 返回；危险级别决定按钮样式；高风险可要求确认词 |
| 悬浮解释 | `BaseTooltip` | 悬停、焦点、触屏长按/点击；支持 `aria-describedby`；承载禁用原因 |
| 等待 | `BaseSkeleton` + `StatePanel` Loading | 首次加载使用骨架屏，续载使用就地 Loading |

禁止 `window.confirm/alert/prompt`、裸 `title=`、业务组件自建 `role="dialog"` 或自建焦点陷阱。`useFocusTrap()` 必须复用 `src/app/dialog.ts` 的 `isTopmostModal`。

偏好统一由 `src/app/preference.ts` 的 `usePreference()` 读写，键名为 `cs.pref.<scope>.<name>.v<N>`。`scope` 取 `device` 或 `account:<stable-id>`，Schema 版本无法解析、类型不匹配或值损坏时只回退默认值，不抛错、不清空其他键。可分享的筛选、排序、Cursor 和打开对象进入 URL；主题、密度、侧栏折叠、分栏比例、列宽和视图模式进入偏好存储。

时间统一由 `useRelativeTime()` 格式化：<60 秒显示“刚刚”，<60 分钟显示“X 分钟前”，<24 小时显示“X 小时前”，<7 天显示“X 天前”，达到 7 天及以上显示绝对时间 `YYYY-MM-DD HH:mm`。所有相对时间必须提供包含完整时间和时区的 Tooltip；解析失败回退原始值并记录一次诊断，不阻塞列表渲染。

基础组件迁移顺序固定为：Token/断点 → Button、Input、Select、Textarea → Badge、Tag、StatusBadge → Tooltip、Popover、Dropdown → Dialog、Drawer、Tabs → Table、Card、EmptyState、Skeleton → Toast/Confirm 宿主。每次迁移必须同提交更新 Story、Spec、门禁和视觉基线。

### 3. ActionRegistry 与动作范式

前端 `src/app/actionRegistry.ts` 是导航和执行交互的单例注册表，与后端 `domain/action` 的外部动作投递域无关。每个注册项包含 `id`、`label`、`group`、`shortcut`、`requiredPermission`、可见性函数和执行函数；快捷键命名空间固定为 `nav.*`、`object.*`、`execution.*`、`view.*`。命令面板、快捷键帮助和全局监听器都消费同一注册表。前端可见性不是授权边界，服务端每次执行仍按既有权限与并发规则复验。

状态流转采用“动词动作”而不是目标状态表单。WorkItem 当前全部 17 条边的标签、强度和撤销规则冻结如下：

| 当前 → 目标 | 用户文案 | 强度 | 撤销 |
|---|---|---|---|
| `BACKLOG → READY` | 准备开始 | 普通 | 否 |
| `BACKLOG → CANCELLED` | 取消工作项 | 高风险确认 | 否 |
| `READY → IN_PROGRESS` | 开始执行 | 普通 | 否 |
| `READY → CANCELLED` | 取消工作项 | 高风险确认 | 否 |
| `IN_PROGRESS → IN_REVIEW` | 提交评审 | 普通 | 是（回到进行中） |
| `IN_PROGRESS → BLOCKED` | 标记阻塞 | 中等 | 是（回到进行中） |
| `IN_PROGRESS → CANCELLED` | 取消工作项 | 高风险确认 | 否 |
| `IN_REVIEW → IN_PROGRESS` | 退回修改 | 中等 | 是（回到评审） |
| `IN_REVIEW → BLOCKED` | 标记阻塞 | 中等 | 是（回到评审） |
| `IN_REVIEW → DONE` | 标记完成 | 中等 | 否 |
| `IN_REVIEW → CANCELLED` | 取消工作项 | 高风险确认 | 否 |
| `BLOCKED → READY` | 重新排队 | 普通 | 否 |
| `BLOCKED → IN_PROGRESS` | 继续执行 | 普通 | 是（回到阻塞） |
| `BLOCKED → IN_REVIEW` | 重新提交评审 | 中等 | 是（回到阻塞） |
| `BLOCKED → CANCELLED` | 取消工作项 | 高风险确认 | 否 |
| `DONE → ARCHIVED` | 归档工作项 | 不可逆确认 | 否 |
| `CANCELLED → ARCHIVED` | 归档工作项 | 不可逆确认 | 否 |

撤销窗口固定为成功后 10 秒，仅适用于上表明确标记“是”的反向边。撤销调用正常流转命令，产生正常事件和 Audit；不新增状态、事件或隐藏中间态。取消、完成和归档等不可逆或已对外生效动作不提供撤销，只在执行前确认。

Review 结论的呈现强度固定为：`COMMENTED` 为弱动作（无需确认）、`APPROVED` 为主要正向动作、`CHANGES_REQUESTED` 为返工动作（需理由并二次确认）、`REJECTED` 为不可逆高风险动作（需理由、二次确认和确认词）。评论不改变 Review 状态机。

动态可用性由服务端返回 `availableActions[]`，静态状态机由后端生成产物提供。动态元素包含 `actionKey`、`targetStatus`、`enabled`、稳定 `reason`、`reasonLabel` 和可选 `remedy { actionKey, route }`。`reason` 只允许 `PERMISSION_REQUIRED`、`STATUS_NOT_ALLOWED`、`REVIEWER_NOT_ASSIGNED`、`DUTY_SEPARATION_CONFLICT`、`PREREQUISITE_GATE_PENDING`、`UNRESOLVED_BLOCKER`、`VERSION_CONFLICT`、`OFFLINE_OR_STALE` 八个枚举；有可执行下一步时提供 `remedy`，权限不足只提供责任方，不回显内部策略。

四个呈现面共享同一动作数据：状态徽章动作菜单为主入口；卡片主动作按钮用于唯一明确的下一步；看板拖拽提供同一目标动作的空间入口；`⌘K` 与列表快捷键提供键盘入口。不可执行动作仍可见但必须说明原因，越权用户不得因伪造前端响应获得授权。

## 结果与验证

- 组件只消费语义 Token，暗色/舒适密度/紧凑密度/reduced-motion 均有确定值。
- `StatusBadge` 保留现名，未传动作时行为与现有 36 个调用点兼容。
- 17 条 WorkItem 边和 4 种 Review 结论均有动作文案，撤销集合只包含已有反向边。
- M9-F01/F05 必须通过 Token、禁用原因、原生确认归零和键盘动作门禁；M9-I01 必须证明生成状态机与领域边集合一致。

## 重新评估条件

出现需要新增领域状态/事件、改变状态机边、改变权限裁决、引入新的全局反馈类型或更换 Vue/样式技术栈时，必须新增 ADR；单纯新增组件变体或页面调用不需要重新决策。
