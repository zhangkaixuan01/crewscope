# ADR-036：企业身份联邦与会话策略

> 状态：ACCEPTED（设计，待 M12-I01/F03 实现）<br>
> 日期：2026-10-12<br>
> 归属：M12-S01 合同冻结；OIDC 骨架现状勘察 2026-10-12（本 ADR §1 为对主计划 §1 基线的**事实修正**）<br>
> 关联决策：[ADR-025](ADR-025-本地密码与登录防护参数.md)（本地密码与登录防护，本 ADR 不改其参数）、[ADR-035](ADR-035-多租户隔离方案与迁移路径.md)（绑定底座归属）、[ADR-038](ADR-038-团队成员生命周期与责任转移.md)（账号级禁用撤销全部会话）<br>
> 影响里程碑：M12（I01/F03 主线；SAML/SCIM/MFA 为独立选入子范围）

## 背景

M12 主线交付 OIDC 登录与本地/SSO 账号策略。主计划 §1 基线称「仓库无 OIDC/identity 适配」——**S01 勘察修正：仓库已有可切换的 OIDC 登录骨架**（详见 §1）。本 ADR 冻结：身份键与绑定、身份策略与模式的关系、协议适配落点与库选型、会话策略与枚举、救援与撤销。

## 决策

### 1. 基线事实修正：OIDC 骨架已在（I01 是补齐，不是从零接入）

以下为 2026-10-12 源码事实（基线 `8d22a5a`），I01 以此为起点：

| 事实 | 位置 | 含义 |
| --- | --- | --- |
| `SecurityMode` 三态枚举（BOOTSTRAP/LOCAL/OIDC），非法值启动失败不降级 | `crewscope-server/config/SecurityMode.java` | 部署级认证形态已是显式配置 `crewscope.security.mode` |
| OIDC 模式分支：浏览器 Session + CSRF cookie + `.oauth2Login(withDefaults())`，且强制 `crewscope.security.oidc.organization-id` | `config/SecurityConfiguration.java` | OIDC 登录的 security 链装配已在，SSO 用户归入配置钉死的组织 |
| `spring-boot-starter-oauth2-client` 与 `spring-boot-starter-oauth2-resource-server` 已在 server 依赖；integration 模块亦有 oauth2-client | `crewscope-server/pom.xml`、`crewscope-integration/pom.xml` | **零新增依赖决策**：Boot 4.0.6 + Spring Security 7.0.5（BOM 管）reactive `OAuth2ClientConfigurer` 原生支持 |
| `AuthenticationSubjectExtractor`：UsernamePassword+BrowserSessionPrincipal → `AccountSessionSubject`；OAuth2AuthenticationToken+OidcUser → `ExternalAuthenticatedSubject` | `crewscope-server/security/` | 协议 token → 稳定 provider/subject 身份键的转换主干已在 |
| `login_identity`（V31）：`(provider, subject)` 唯一 + `(account_id, provider)` 唯一，provider 格式校验支持 issuer 路径段 | `db/migration/V31__*.sql` | **受信身份键持久层底座已在**（用户级外键挂 `user_account`） |
| `account_organization_binding`（V31）双唯一约束 | 同上 | 账号×组织×principal 绑定底座已在 |
| 测试骨架：`SecurityModeTest`、`SecurityConfigurationTest`、`AuthenticationSubjectExtractorTest` | `crewscope-server/src/test/` | OIDC 分支有单测底座 |

I01 的真实缺口因此是：首登账号开通路径（OIDC 首登时账号/绑定/principal 的创建语义）、身份策略维度（§3）、LoginDefense 衔接、救援流程（§5）、会话枚举 API（§4）、`/api/v1/auth/session` 对外部身份的响应面——**不是**引入 OIDC 库或建第二套登录链。

### 2. 身份键与绑定：受信 issuer + subject，不凭邮箱合并

- 外部身份键 = `login_identity (provider, subject)`，provider 为受信 issuer 规范化串（既有格式校验保留）；OIDC 首登绑定走 issuer+subject 命中或新建，**禁止邮箱相同自动合并**（主计划 §4.3 红线）。
- 一账号每 provider 恰一身份（既有 `(account_id, provider)` 唯一约束）；本地侧 `local_credential` 一账号一行（argon2id 写/bcrypt 兼容读维持）。
- 角色映射最小授权：外部身份不隐式获得任何 Team 写权限；ORG_*/Team 角色仍由组织内授权路径显式分配。

### 3. 身份策略是叠加维度，不是第四个 mode

- `crewscope.security.mode` 保持三态（bootstrap/local/oidc 部署形态）；M12 新增**账号认证策略**维度（工作名 `crewscope.security.identity-policy`：`local-only` / `sso-only` / `coexist`，默认 coexist），只在浏览器形态（local/oidc）上生效。
- `sso-only`：本地密码端点 fail-closed 拒绝并指向冻结的救援流程，**IdP 故障不静默退回本地密码**（§4.3 红线）；`local-only`：登录页不渲染 SSO 入口（M11 行为完全兼容）；`coexist`：双入口并存，`login_identity` 与 `local_credential` 各自独立可用。
- 未配置 OIDC 身份源时一切行为与 M11 一致（纯本地密码、无 SSO 入口）——「主线单机零额外配置」由本条承底。

### 4. 会话策略：不建第二套 Session；枚举用既有存储

- SSO 与本地登录共用 Spring Session Redis Indexed（`@EnableRedisIndexedWebSession`、`WebSessionServerSecurityContextRepository`、`BrowserSessionPrincipal`、TTL 12h、maxSessions 5）；OIDC 断言与本地凭据殊途同归到同一 SecurityContext 存储属性，不引入独立 token 体系。
- **会话枚举**：`ReactiveRedisIndexedSessionRepository.findByPrincipalName(principal)`（仓库集成测试 `BrowserSessionLifecycleM7I02IntegrationTest` 已实证该查询面）；principal 索引键 = `BrowserSessionPrincipal.getName()`（accountId UUID）。
- 单会话撤销 = 按 sessionId 定点删除；账号级撤销 = 既有 `security_version` 复检 + `BrowserSessionLifecycle.invalidateAll`（SpringSessionBackedReactiveSessionRegistry 先例），衔接 ADR-038 §3.1 账号级禁用语义。
- I01 暴露 `/api/v1/auth/sessions` 族（列表/单撤销，F03 会话管理页的数据面）；列表仅本人会话，不提供跨账号枚举。

### 5. 救援与撤销

- SSO-only 救援：冻结流程 = 运维级 bootstrap 形态（`crewscope.security.mode=bootstrap` 运维通道）或预置本地救援管理员账号（部署时配置，进 Runbook）；救援动作全程入 Audit。
- 撤销延迟可测：账号禁用 → `security_version` 递增 → 会话复检拒绝 + `invalidateAll` 清 Redis；IdP 侧登出/禁用的失效来源为下次令牌刷新或会话复检，延迟上限由 I01 测试钉死数值，不做「即时失效」无依据承诺。
- 协议攻击面（签名/issuer/audience/state/nonce/PKCE/重放/回跳）验证归 I01 与 Q01 固定攻击集；本 ADR 只冻结键、策略、会话与救援合同。

### 6. 协议适配落点与库选型（S01 必答，冻结）

- **落点裁定：`crewscope-server` 内 `server/security/oidc`（新建子包，ClientRegistration 装配、令牌校验配置、principal 转换接线）+ `application/identity`（策略/绑定/开通用例）；不进 `crewscope-integration`**。依据：①身份不是外部工作工具——integration 是 Lark/GitHub/工作项等外部系统适配，语义并列会复制安全面；②既有骨架（SecurityConfiguration/AuthenticationSubjectExtractor/login 端点族）全在 server，依赖方向不需要下探 integration；③策略与开通用例属 `application/identity` 既有包（`LoginResourceAdmission` 所在），复用其治理。
- **库选型：零新增依赖**——`spring-boot-starter-oauth2-client`（BOM 管版本，reactive 形态）已是事实依赖；不引入 nimbus 之外的独立 OIDC 库、不新建授权服务器。
- SAML/SCIM/MFA 为独立选入子范围，选入时各自补薄 ADR 与库选型（本 ADR 不预判）。

## 实施约束

- I01 不改 ADR-025 的密码/防护参数；LoginDefense 键位与限流语义对外部登录尝试同等生效（衔接方式 I01 细化）。
- `/api/v1/auth/*` 端点族是唯一登录入口：OIDC 回跳端点由 Spring Security 框架路径（`/login/oauth2/*`）承担，不在 AuthenticationController 之外另开第二入口。
- 前端不保存 IdP 密钥/客户端密钥；身份源配置归后端配置面（F03 只做状态展示与策略提示）。
