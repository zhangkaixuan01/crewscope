# ADR-008：可观测性与日志安全协议

> 状态：ACCEPTED<br>
> 日期：2026-08-07<br>
> 影响里程碑：M0–M6

## 背景

CrewScope 的 HTTP 请求、应用命令、数据库事务、DomainEvent、Outbox、投影和后续 Agent 执行需要使用稳定标识关联。平台同时处理凭证、代码、命令输出和 Provider 内容，日志与指标必须在提供诊断能力的同时保持低基数和安全边界。

## 决策

### Correlation ID

公开 HTTP 请求使用 `X-Correlation-Id`：

- 只接受一个规范小写、非 Nil UUID；
- Header 缺失、重复或非法时由服务端生成新 UUID；
- 服务端在所有响应中返回最终 `X-Correlation-Id`；
- Filter 将最终值写入 Exchange、Reactor Context 和日志 MDC；
- Controller、Application Command、Command Receipt、DomainEvent、Outbox、Projection 和 Audit 使用同一个最终值；
- 幂等重放返回首次提交的 Receipt 及其 Correlation ID，请求日志仍记录本次请求的 Correlation ID。

Correlation ID 用于关联同一业务意图的事实和活动，不作为租户范围、授权依据、幂等键、指标标签或 Trace 父子关系。

### Trace

服务端使用 OpenTelemetry 与 Micrometer Tracing：

- 只消费和产生 W3C `traceparent`；
- 合法上游上下文继续原 Trace，并为当前请求创建 Server Span；
- 缺失或非法 `traceparent` 时创建新 Trace；
- Trace ID 和 Span ID 进入结构化日志上下文；
- Trace 采样率通过环境变量配置，M0 默认 `1.0`；
- M0 建立进程内 Trace 与传播能力，不默认启用 OTLP 导出；
- 后续 HTTP、Provider、Connector 和 Worker 客户端通过标准注入继续 Trace。

Trace ID 表达技术调用链，Correlation ID 表达业务关联链。两者同时出现在请求完成日志中，不互相替代。

### 结构化日志

服务端控制台默认输出 Logstash JSON。业务日志使用 SLF4J 结构化 Key Value，字段名固定为 lower camel case。

请求完成日志只记录白名单字段：

```text
event
correlationId
traceId
spanId
method
route
status
outcome
durationMs
errorCode
failureType
```

- `route` 只使用 Spring 匹配后的路由模板，未匹配请求使用固定值；
- 不记录原始 URI、Query、Header、Cookie、请求体和响应体；
- 未知异常只记录稳定错误码与异常类型，不记录异常消息；
- 日志值移除 CR/LF 等控制字符并限制长度；
- `authorization`、`cookie`、`password`、`secret`、`token`、`credential`、`api-key`、密钥材料、密文、Nonce 和认证 Tag 按字段名统一替换为 `[REDACTED]`；
- Idempotency Key、Correlation ID、Trace ID 和业务对象 ID 不进入未知动态字段。

### 指标

M0 暴露 Spring Boot HTTP/JVM/连接池基线指标，并增加：

```text
crewscope.api.requests
crewscope.api.errors
crewscope.api.correlation.ids
```

- Request Timer 标签只包含 method、路由模板、status 和 outcome；
- Error Counter 标签只包含稳定 error code 和 status；
- Correlation Counter 标签只包含 `accepted/generated` 结果；
- 指标禁止使用 Correlation ID、Trace ID、Span ID、Idempotency Key、Organization ID、Principal ID、资源 ID、原始 URI、异常消息和凭证内容；
- Prometheus 继续作为 M0 唯一暴露的指标端点。

## 结果

- HTTP、命令、事件和投影可以通过 Correlation ID 关联；
- 上下游服务可以通过标准 Trace Context 延续调用链；
- 日志保留稳定诊断字段而不接收任意外部内容；
- 指标维持可控时间序列数量，不泄露租户和凭证信息。

## 验证

1. 合法 Correlation ID 被复用并写回响应；
2. 缺失、重复和非法 Correlation ID 被替换；
3. Reactor 异步边界内 MDC 保持最终 Correlation ID；
4. 合法 `traceparent` 的 Trace ID 在请求处理期间保持一致；
5. 请求日志只包含白名单字段，控制字符和敏感字段完成脱敏；
6. 成功、领域错误和未知错误生成低基数指标；
7. Prometheus、Health、Info 和配置端点保持既有安全暴露面。

## 重新评估条件

- 接入集中式 OTel Collector 和日志平台；
- 跨区域 Trace 采样需要 Tail Sampling；
- Provider 或 Agent Runtime 需要独立的敏感数据分级日志策略；
- 指标标签或路由数量接近 Prometheus 基数预算。
