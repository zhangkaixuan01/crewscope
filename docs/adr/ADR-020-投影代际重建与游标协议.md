# ADR-020：投影代际重建与游标协议

> 状态：ACCEPTED<br>
> 日期：2026-08-25<br>
> 关联决策：[ADR-005](ADR-005-事件与投影协议.md)、[ADR-007](ADR-007-API命令与并发协议.md)<br>
> 影响里程碑：M6

## 背景

CrewScope 的 Activity、Inbox 来源、Notification Intent 和安全查询视图由 DomainEvent 构建。投影逻辑升级、历史数据修复和运维故障恢复都需要重建读模型。在线代际必须在重建期间继续服务，新旧 Worker、历史重放和实时事件需要在至少一次投递下确定收敛。

现有 Outbox 保存分区内聚合顺序，没有可供历史重建截断的全局单调高水位。`occurredAt` 和 `eventId` 只负责同聚合版本内的确定排序，不表示全局提交顺序。

## 决策

### Projection Definition 与 Generation

每个可重建投影使用稳定 `projectionName` 和版本化 Projection Definition。Generation 由以下复合身份定位：

```text
organizationId + projectionName + generation
```

每个 `organizationId + projectionName` 最多存在一个 `ACTIVE` Generation 和一个处于 `BUILDING/VALIDATING` 的影子 Generation。当前读代际由独立 Projection Pointer 定位，读 API 不根据最大 Generation 或状态推断当前代际。

代际状态机为：

```text
BUILDING -> VALIDATING -> ACTIVE -> RETIRED
    |            |
    +----------> FAILED
    +----------> CANCELLED
```

`FAILED`、`CANCELLED` 和 `RETIRED` 是终态。重试创建新 Generation，不原地清空或复活终态代际。

### 影子重建启动

重建命令在单个数据库事务中创建 `BUILDING` Generation、RebuildJob、初始 Fencing Token 和 Audit/DomainEvent。Generation-aware Router 在每次投影消费时从持久化 Registry 解析当前接收代际，不使用进程启动时固定的消费者列表。

`BUILDING`、`VALIDATING` 和 `ACTIVE` 接收实时事件。影子代际登记后再执行历史扫描。登记前已提交的事件由历史重放处理，登记后的事件同时通过实时消费和历史扫描到达，Generation Receipt 负责去重。进程退出后从 Generation、Receipt 和 Checkpoint 继续，不依赖内存进度。

Router 先向 `ACTIVE` 代际投影，再按 Generation 升序处理 `BUILDING/VALIDATING` 代际，每个代际使用独立本地事务。影子缺口或失败时，在线代际的已提交 Receipt 保留，Outbox 投递保持可重试。历史重放补齐影子缺口，或 Supervisor 将影子代际终结后，下一次 Outbox 重试通过各代际 Receipt 收敛。

### 消费事务与顺序

消费幂等键为：

```text
consumerName + generation + eventId
```

Checkpoint 键为：

```text
organizationId + projectionName + generation + partitionKey
```

`partitionKey` 绑定 Aggregate Type 和 Aggregate ID。历史重放按 `partitionKey + aggregateVersion + occurredAt + eventId` 稳定排序。新分区首个事件版本为 `0`；已有分区接受当前版本中排在 Checkpoint 之后的事件，也接受 `lastAggregateVersion + 1`。更低位置按过期重放处理，更高版本进入 `PROJECTION_GAP`。

每个事件和代际在同一本地事务中执行：

```text
校验 Generation 状态与 Fencing Token
  -> 插入 Generation Consumer Receipt
  -> 创建或锁定分区 Checkpoint
  -> 校验 Aggregate Version 和同版本顺序
  -> 写入该 Generation 的投影副作用
  -> 推进 Checkpoint
  -> 提交事务
```

版本缺口、Projector 异常、Fencing 失效和数据库冲突均不保留 Receipt、投影副作用或 Checkpoint 推进。一个代际失败不回滚其他已提交代际的投影事务。Outbox 重试和历史重放共同完成缺口补齐；影子代际进入终态后不再阻止实时投递。

### 校验与切换

每个 Projection Definition 提供规范行编码和校验器。规范编码覆盖投影身份、业务主键、公开字段、源 Event ID/Version 和 Projection Schema Version，并按稳定业务键排序。校验保存：

- 期望行数与实际行数；
- 期望规范 SHA-256 与实际规范 SHA-256；
- 版本缺口数、失败分区和校验时间；
- Definition Version、Generation、RebuildJob 和操作者。

规范期望值由该投影的公开映射规则生成。忽略的事件和合并行按 Projection Definition 处理，不使用 DomainEvent 原始行数替代投影行数。抽样对比用于诊断，Count、SHA-256 和零缺口是进入 `VALIDATING` 的必要条件。

校验期间锁定目标 Generation，阻止该 Generation 的并发投影写入。进入 `VALIDATING` 时提升 Fencing Token。验证后到达的新事件使已保存的 Count/Hash 失效，必须重新校验。

原子切换事务使用固定锁顺序：

```text
锁定 Projection Pointer
  -> 锁定目标 Generation
  -> 重新计算当前规范 Count/SHA-256 并对比校验快照
  -> 将旧 ACTIVE 置为 RETIRED 并提升 Fencing Token
  -> 将目标 VALIDATING 置为 ACTIVE 并提升 Fencing Token
  -> 更新 Pointer 与乐观版本
  -> 追加 Audit/DomainEvent
  -> 提交事务
```

任一步失败时 Pointer 和在线代际保持原值。Worker 每次写入都校验 Generation 状态和 Fencing Token，切换前取得的旧 Token 无法完成迟到写入。切换并发期间新提交的 DomainEvent 按正常投影延迟通过 Outbox 收敛到切换后的 `ACTIVE` Generation。

### Cursor 与旧代际保留

所有基于可重建投影的 Cursor 绑定 Organization、业务 Scope、Projection Name、Generation、Projection Schema Version、过滤条件和流内位置。服务端先解析 Pointer，再校验 Cursor Generation。Generation 不一致时返回 `410 cursor_expired`，客户端清理该投影的本地页与乐观状态，拉取新代际快照后继续。

`RETIRED` Generation 在 Cursor 最长有效期、运维回滚观察期和 Worker Lease 上限全部结束后可以清理。清理是独立、可审计的管理命令，不位于切换事务中。

### Inbox 成员处置与 Audit

Inbox Source 和可见的 Inbox Item 属于 Generation 可重建数据。成员 `READ/ACTED/ARCHIVED` 处置使用稳定 Source Identity 作为权威事实，独立于 Generation 保存。查询在当前 Generation 来源上合并成员处置。重建、切换、失败和旧代际清理不删除成员处置。

AuditEvent 保持追加写权威历史，不参加 Generation 替换。重建命令、状态变更、校验结果、切换、取消、失败和清理都追加安全 Audit。

## 实现约束

- Generation、Pointer、RebuildJob、Receipt、Checkpoint 和投影行使用完整 Organization/Projection/Generation 外键；
- Partial Unique Index 约束单个 `ACTIVE` 与单个 `BUILDING/VALIDATING` Generation；
- Router 和 Worker 只使用持久化 Registry、Checkpoint、Receipt、Lease 和 Fencing Token 恢复；
- Router 固定优先处理 `ACTIVE` 代际，不让影子缺口延迟当次在线投影；
- 历史重放使用有界分页、分区并行和每分区串行，不以时间戳作为全局截断点；
- 重建、校验、切换和清理 API 仅向组织管理员开放，使用强确认、幂等命令、乐观版本和安全 Audit；
- 诊断信息公开 Projection Name、Generation、状态、Lag、Gap Count 和脱敏错误码，不公开原始 Payload、PII 或凭证。

## 结果

- 在线代际在重建失败、取消和进程退出时继续服务；
- 历史重放与实时投递可以重复到达并通过 Generation Receipt 收敛；
- 版本缺口和 Projector 失败不留下部分投影；
- 校验快照、原子 Pointer 和 Fencing Token 阻止未验证切换和迟到写入；
- Cursor 过期和快照刷新形成稳定客户端恢复契约；
- Inbox 成员处置和 Audit 权威历史不受投影代际替换影响。

## 验证

1. 实时双写、历史重放、重复重放和进程重启收敛为同一规范快照；
2. Aggregate Version 缺口回滚 Receipt、投影行和 Checkpoint；
3. Projector 异常回滚全部本地副作用；
4. 影子构建失败不修改 Pointer、在线代际和 Inbox 成员处置；
5. 原子切换后旧 Cursor 过期，旧 Generation Token 无法写入；
6. 校验后到达的新事件要求重新校验后切换。

验证证据见 [M6-S01 投影代际与影子重建验证记录](../spikes/M6-S01-投影代际与影子重建验证记录.md)。

## 重新评估条件

- 引入 Kafka/Pulsar 等具有耐久 Partition Offset 的事件日志；
- DomainEvent Store 引入可作为一致截断点的全局单调位置；
- 投影数据量超出单机 PostgreSQL 影子表和规范 Hash 能力；
- 跨区域部署需要多主切换、全局顺序或冲突解决；
- 旧代际需要支持一键回滚或长期可查。
