# ADR-028：个人工作台、统一搜索与契约边界

> 状态：ACCEPTED<br>
> 日期：2026-09-12<br>
> 影响里程碑：M9-S01、M9-A02、M9-A03、M9-F07、M9-I01<br>
> 关联文档：[M9 执行清单](../plans/M9-产品体验重构与设计系统.md)、[M9-S01 Spike 记录](../spikes/M9-S01-设计系统交互内核与高亮选型验证记录.md)

## 背景

当前根路径落在空对话框，WorkItem 查询按单个 WorkProject 返回，用户无法在登录后看到自己跨项目的责任、Review 和 Human Gate。系统也没有跨对象搜索，前端 DTO 与领域状态机存在手写镜像。M9 需要一个不引入第二套待办状态、不建立独立搜索服务的派生查询合同。

## 决策

### 1. 个人工作摘要

`WorkDeskSummary` 是查询时从既有 WorkItem、TaskExecution、Review、Human Gate 和 Inbox 投影派生的只读视图。它不新增 `read`、`handled` 或个人待办表，不改变任何领域状态。

响应字段固定为：

```text
scope { organizationId, teamId, projectId? }
generatedAt
sections[] { key, title, priority, total, items[] }
item {
  objectType, objectId, projectId?, title?, status, updatedAt,
  responsibilityRole?, needsAction, urgency, progress?,
  availableActions[], route
}
```

`title` 仅在当前成员有对象读取权限时返回；所有跳转使用稳定站内坐标，不构造外部 URL。`availableActions` 复用 ADR-027 的动态动作形状，仍不是授权边界。

首屏排序固定为：

1. 等我决策的 Human Gate；
2. 待我 Review 的条目；
3. 被我阻塞的他人工作；
4. 我负责且正在推进的 WorkItem/Task；
5. 我负责但尚未开始的工作；
6. 仅供知晓的动态和未读 Inbox 摘要。

同一优先级内按 `urgency`、截止时间、最近更新时间和稳定 ID 排序。`needsAction=true` 的条目始终排在 `false` 之前；排序不使用浏览器本地时间或客户端分页结果。

聚合范围是当前成员可访问的 Team，可选 WorkProject 和责任角色过滤。跨五个项目时仍按上述优先级合并；无项目、新成员、无责任、无权限和 500 条责任项都返回有意义的 section 与下一步，而不是空白页面。单成员最多返回 500 条责任项，超过部分在 section 中返回 `truncated=true` 和“打开工作页查看全部”的站内动作。

查询预算固定为：一次 HTTP 请求、最多 6 个有界查询分支、每个分支最多读取 501 行用于截断判断、响应最多 500 个责任项；数据库语句超时为 800ms，服务端 P95 目标为 400ms（10 万 WorkItem、500 条责任项、五项目 Scope）。所有分支共享既有 Ownership × ExecutionScope 权限入口，不在 `workdesk` 包中重写授权。

### 2. 统一搜索

全局搜索 v1 覆盖六类对象：`WorkItem`、`Conversation`、`Task`、`RepositoryBinding`、`Agent`、`TeamMember`。结果按对象类型分组，每类最多 20 条、总数最多 120 条。Settings 内的配置项搜索可以复用同一查询管道，但作为受权限保护的 `CONFIGURATION` 扩展，不改变全局六类对象的排序和预算。

搜索只从现有权威表派生，使用 PostgreSQL 的 `tsvector`/`pg_trgm` 与现有索引；不建立 Elasticsearch、独立索引服务或第二套对象目录。服务端先按 Organization、Team、Project 和成员权限过滤，再生成片段；不得把 Credential、Endpoint、宿主路径、Prompt、Secret 或任意外链放入结果。

查询规则固定为：

| 规则 | 合同 |
|---|---|
| 输入 | Unicode 规范化后最多 200 个 code point；空白只作为分词边界 |
| 排序 | 完全匹配 > 前缀匹配 > 词项匹配 > 模糊匹配；同级按对象权重、更新时间、稳定 ID |
| 预算 | 单请求、单游标；P95 目标 300ms，数据库超时 500ms |
| 游标 | 服务端签名，绑定 Scope、查询规范化值、排序版本和权限代次；过期返回稳定 `CURSOR_EXPIRED` |
| 片段 | 每项最多 160 个字符，命中片段只做安全文本高亮，不输出 HTML |
| 越权 | 结果数量、总数和是否存在隐藏对象均不向调用方泄露 |

超长输入、特殊字符、SQL 通配符和注入字符均按普通文本处理；查询失败返回稳定错误码和可重试提示，Provider 或数据库原文留在服务端边界。

### 3. 前后端契约与状态机生成

后端 Controller/DTO 通过 `springdoc` 生成 OpenAPI 3.1；生成文件由脚本写入 `crewscope-web/src/api/generated/`，前端领域类型从生成类型派生，视图模型仍可在页面层定义。CI 重新生成并与仓库内容比较，不一致即失败。生成范围覆盖分页/Cursor 信封、错误码、公开字段白名单和所有公开 DTO。

领域状态机与 OpenAPI 同批生成：从各聚合现有 `ALLOWED_TRANSITIONS` 导出状态集、合法边、终态、动作键和是否可撤销，写入 `src/api/generated/state-machines.ts`。生成器只读取公开状态，不泄露私有字段；M9-I01 首次运行必须记录后端集合与现有前端镜像的差异（当前 WorkItem 两份集合预期一致）。前端删除手写 `allowedWorkItemTransitions`。

生成产物只用于契约和动作发现。实际命令仍由服务端按权限、版本、责任链、Gate 和幂等规则裁决；伪造 OpenAPI 或状态机响应不能绕过任何校验。

## 结果与验证

- WorkDesk 五类 Fixture（新成员、单项目、跨五项目、500 条责任项、无权限）均有非空且可行动的首屏。
- 搜索六类对象的权限、撤权、空 Scope、超长输入、注入字符和预算上界有集成测试。
- WorkDesk、Work、Inbox、Review 的同一对象使用同一权威事实；对账测试禁止出现“工作台可见但详情无权”的结果。
- OpenAPI 与状态机生成产物纳入 CI 漂移门禁，前端手写 DTO 镜像和手写 WorkItem 状态机归零。

## 重新评估条件

新增搜索对象、需要全文搜索服务、需要个人可写待办状态、改变权限模型或改变领域状态机边集合时，必须新增 ADR。优化 SQL、增加既有索引或增加页面消费方不需要重新决策，但必须保持查询预算和公开字段白名单。
