# ADR-025：本地密码与登录防护参数

> 状态：PROPOSED<br>
> 日期：2026-08-28<br>
> 关联决策：[ADR-008](ADR-008-可观测性与日志安全协议.md)、[ADR-023](ADR-023-Team-Beta单机部署与发布验证协议.md)、[ADR-024](ADR-024-Account与Principal身份边界.md)<br>
> 影响里程碑：M7

## 背景

M7 为 CrewScope 增加开放本地账号。密码哈希同时消耗 CPU 和内存；参数过低会削弱离线破解成本，参数过高或无并发边界会让少量登录请求抢占对话、Task Worker 和 Agent 执行资源。账号查找、临时锁定和限流如果走不同公开响应或不同哈希路径，还会形成账号枚举信号。

Spring Security 7.0.5 提供 Argon2id、BCrypt 和 DelegatingPasswordEncoder。现有 Bootstrap Security 默认写入 BCrypt；M7 正式本地 Credential 尚未落地，因此可以在不迁移生产数据的前提下确定新的写入算法，并保留安全升级旧 Hash 的能力。

## 决策

### 密码编码

新建与修改的本地 Credential 使用带算法前缀的 Argon2id：

```text
id = argon2id
saltLength = 16 bytes
hashLength = 32 bytes
parallelism = 1
memory = 32768 KiB
iterations = 3
provider = Bouncy Castle 1.79
encoded prefix = {argon2id}$argon2id$v=19$m=32768,t=3,p=1$
```

DelegatingPasswordEncoder 以 `argon2id` 为当前写入 ID，同时保留经过批准的 BCrypt 和较弱 Argon2id Reader。成功认证后，`upgradeEncoding` 为 true 的 Credential 通过版本条件更新为当前参数；失败认证、锁定账号和未知账号不触发 Rehash。损坏、未知算法或不合规 Hash 失败关闭，并使用安全错误而非回显解析原因。

M7-D02 已将该方向性落地为领域规则：`LocalPasswordHash` 可读取 `{argon2id}` 与 `{bcrypt}` 编码且字符串表示始终脱敏；`LocalCredentialMetadata.create/rotate` 只接受当前 Argon2id Writer，历史 BCrypt 只能经持久化恢复后升级，不能作为新建或轮换目标。验证见 [M7-D02 LoginIdentity 与 LocalCredential 契约](../testing/M7-D02-LoginIdentity与LocalCredential契约.md)。

M7-D03 已将密码双预算、常见值拒绝集、两级限流、Hash 准入、Account 失败滑动窗口和 15 分钟临时锁定落为不受 Web/Redis 实现影响的领域契约。临时锁定与持久 `UserAccount.status=LOCKED` 分离；账号、Identity、Credential、密码和临时锁定内部原因统一折叠为不保留原因的 `invalid_credentials`，容量失败统一折叠为 `too_many_requests`。验证见 [M7-D03 注册与登录防护领域契约](../testing/M7-D03-注册与登录防护领域契约.md)。

M7-I03 已落地独立 `LocalCredentialStore`、Bouncy Castle 1.79 Argon2id Writer、批准的弱 Argon2id/BCrypt Reader、启动期 Dummy Hash、公平 100 ms 有界异步准入和双版本 CAS Rehash。Bootstrap 与本地 Credential 使用隔离的具名 PasswordEncoder；失败/锁定/未知/损坏路径不升级，旧密码认证产生的 Rehash 不覆盖并发改密。验证见 [M7-I03 本地密码编码与安全升级](../testing/M7-I03-本地密码编码与安全升级.md)。

M7-I04 已使用 Redis Lua 原子落地标识 10 次/15 分钟、受控网络 60 次/5 分钟、账号失败 10 次/15 分钟和临时锁定 15 分钟。注册/登录资源窗口隔离，两个资源只有共同允许时才消费；账号状态通过领域对象重新校验，成功只清账号失败。Redis 坐标使用版本化、用途分离 HMAC 和 Cluster Hash Tag，可信代理链从右向左解析，非可信来源的转发头完全忽略。异常、时间倒退和损坏结果统一失败关闭，指标只有固定枚举标签。验证见 [M7-I04 Redis 登录防护与临时锁定](../testing/M7-I04-Redis登录防护与临时锁定.md)。本 ADR 仍等待 M7-Q01 固定攻击集后转为 ACCEPTED。

### 密码输入预算

- 注册和改密接受 12–128 个 Unicode code point，UTF-8 编码后最多 512 byte；
- 登录使用相同的 128 code point / 512 byte 上限，超限输入在账号查询和昂贵哈希前拒绝；
- 密码保持用户提交的原始 code point 序列，不执行 trim、大小写转换或 Unicode 规范化；
- 不要求大小写、数字或符号组合；M7-D03 使用本地常见密码拒绝集和可测试策略补充强度边界；
- 密码字符、UTF-8 byte、Hash 和解析错误不进入日志、事件、Audit、Trace、指标或公开 DTO。

### 昂贵哈希准入

密码编码和验证在独立有界执行器运行，不占用 WebFlux Event Loop：

| 部署 Profile | 哈希并发 Permit | 选择依据 |
|---|---:|---|
| 2C2G | 2 | 选定参数双并发 P95 168.07 ms、峰值堆增量约 219 MiB |
| 8C16G | 4 | 四并发 P95 225.53 ms、峰值堆增量约 336 MiB，并为 Agent/Task 保留 CPU 与内存 |

Permit 公平获取，最多等待 100 ms。未取得 Permit 的请求不启动哈希，返回与账号存在性无关的 `429 too_many_requests` 和 1 秒 `Retry-After`。并发数由显式部署 Profile 配置；配置超过可用处理器数或超过 8 时启动失败，不能依据流量自动无界扩张。

### 登录尝试、锁定与枚举防护

每个通过输入预算的登录请求先执行 Redis 原子准入：

- 规范登录标识摘要：15 分钟最多 10 次；
- 受控网络摘要：5 分钟最多 60 次；
- 已知 Account 在 15 分钟窗口累计 10 次失败后临时锁定 15 分钟；成功认证清空 Account 失败窗口，限流使用的资源消耗窗口不因成功而清空；
- 只在请求来自配置的可信反向代理时解析转发地址；原始标识与网络地址不进入 Redis Key、指标或日志，使用部署密钥计算版本化 HMAC 摘要；
- Redis 不可用、计数脚本结果不完整或时钟异常时本地认证失败关闭。

在准入成功且输入预算有效时，每次认证恰好执行一次昂贵匹配：已知可用账号匹配其 Credential；未知账号、锁定账号、禁用账号和损坏 Credential 匹配部署启动时准备的当前参数 Dummy Hash。上述结果对匿名调用方统一为 `401 invalid_credentials`，具有相同 JSON 字段、缓存头和无账号字段响应。限流与哈希过载统一为 lookup-independent 的 `429 too_many_requests`。公开响应不说明账号不存在、密码错误、账号锁定、账号禁用或 Hash 损坏。

## 结果

- Argon2id 获得相对 BCrypt 的内存成本，并在两个目标 Profile 保持可接受的交互延迟；
- 8C16G 选择 4 而非 8 个 Permit，以约一半峰值堆占用换取平台执行资源余量；
- 旧 BCrypt Credential 可以渐进升级，不需要离线读取或批量重算密码；
- 输入预算、两级限流、账号锁定和全局哈希准入共同约束在线资源消耗；
- Dummy Hash 和统一公开失败关闭常见账号枚举路径，但 M7-Q01 仍需使用固定样本检验响应结构、日志和统计时延分布。

## 验证

参数矩阵、环境和原始结果见 [M7-S03 密码与登录防护验证记录](../spikes/M7-S03-密码与登录防护验证记录.md)，正式实现证据见 [M7-I03 本地密码编码与安全升级](../testing/M7-I03-本地密码编码与安全升级.md)和 [M7-I04 Redis 登录防护与临时锁定](../testing/M7-I04-Redis登录防护与临时锁定.md)。验证夹具覆盖：

- 当前 Argon2id 编码、较弱 Argon2id/BCrypt 读取与 Rehash 信号；
- code point 与 UTF-8 byte 双预算在哈希前生效；
- 10 次失败、15 分钟锁定和恢复；
- 已知/未知账号一致公开失败与等量 Hash 操作；
- 标识/网络窗口、到期恢复和无账号查找依赖的拒绝；
- Permit 满载后 100 ms 内拒绝且不启动额外工作。

## 接受与重新评估条件

本 ADR 在 M7-I03/I04 以真实 PasswordEncoder、Redis 原子脚本和有界执行器落地，并由 M7-Q01 固定攻击集通过后转为 ACCEPTED。出现以下情况时重新测量并以新 ADR 调整：

- JDK、Spring Security、Bouncy Castle、CPU 架构或实例规格变化；
- 单并发 P95 低于 75 ms 或高于 300 ms；
- 目标 Profile 的四并发 P95 超过 500 ms 或认证哈希峰值内存超过容器预算的 25%；
- 密码哈希库安全建议、攻击成本或合规基线发生变化。
