# ADR-035：多租户隔离方案与迁移路径

> 状态：单机合同 ACCEPTED；托管隔离候选比较 PROPOSED（选入托管扩展后按 §3 闭合，不以登记充作验收）<br>
> 日期：2026-10-12<br>
> 归属：M12-S01 合同冻结；现状盘点见 [M12-S01 组织归属盘点矩阵](../spikes/M12-S01-组织归属盘点矩阵.md)（本 ADR 的全部数字出处）<br>
> 关联决策：[ADR-038](ADR-038-团队成员生命周期与责任转移.md)（成员级撤权，组织级治理不重建其路径）、[ADR-033](ADR-033-WorkGraph关系模型.md)（关系表入治理清单）<br>
> 影响里程碑：M12（D01 基础范围；托管增量另立项）

## 背景

M12 主线是单 Organization 自托管四服务形态；多 Organization 托管是独立选入的扩展。全量盘点（2026-10-12，迁移 tip V67）证明：主链 159 张存活表中 129 张建表即带 `organization_id`（零 ALTER 后补、零 DROP、零 RENAME——归属无漂移史），加 `organization` 根表共 130 张组织作用域；29 张全局表（账号身份 3、平台目录 6、执行派生明细 17、机制设施 3）；向量链 2 张表均带组织列。应用层 `ExecutionScope ∩ Ownership` 与资源授权已在全部查询路径求交。

主计划 §4.1 立法前提：**隔离目标先于技术选型**；应用层边界始终是安全边界，不是性能优化；托管还必须有独立数据层隔离。本 ADR 把「现状盘点口径、单机合同、托管候选比较框架、迁移路径原则」一次冻结。

## 决策

### 1. 单机合同：显式接受应用层单防线

单机四服务形态**接受**以下合同，不引入数据层第二防线：

- 运行角色维持现状（应用账号即迁移账号的 Compose 初始化形态）；不要求用户配置 RLS/独立角色，`quickstart.sh` 默认路径不变。
- 组织边界=应用层求交（既有全部 Controller 已按嵌套组织路径鉴权）；开放注册钉死 `crewscope.registration.organization-id`，组织创建唯一入口维持启动期 seeder。
- Release Gate 第 2 条「企业能力未启用时不要求 IdP、集群、外部 Secret、TLS 或监控栈」由本合同承底。

这是**接受现状**的显式决策而非遗漏：单机单组织的威胁模型里数据层防线不改变攻击面结论，其成本（角色拆分、迁移工具、FORCE RLS）不转嫁给普通用户。

### 2. Organization 聚合建模口径（D01）

- `organization` 表六列（id/name/status/version/created_at/updated_at）即聚合状态面，D01 实体化聚合与 Repository **零新增列起步**，不预留托管字段。
- 组织创建/管理 API 属**托管增量**：单机主线不交付组织生命周期命令（A01 只做组织设置/角色/治理），避免单机形态出现无消费者的管理面。
- `account_organization_binding`（V31）是账号-组织绑定唯一底座（`(account_id, organization_id)` 与 `(organization_id, principal_id)` 双唯一，三 FK 全 RESTRICT）；ADR-036 与托管增量都复用，不建平行绑定。

### 3. 托管隔离候选比较框架（不裁定，选入后闭合）

选入托管扩展后，在以下三个候选中按维度矩阵决策，届时须产出隔离原型实测与证明义务清单（§4.1 全文有效）：

| 候选 | 隔离强度 | 迁移/回填成本 | 运行成本 | 主要证明义务 |
| --- | --- | --- | --- | --- |
| 共享 Schema + RLS | 策略级（错配即串数据风险） | 低（策略+角色，行不动） | 低（同库连接池） | §4.1 证明清单全文：非 superuser/BYPASSRLS 运行角色与迁移角色分离、FORCE RLS、上下文受信且失败关闭、池复用/异常回滚/异步作业/Worker 验证、真实运行角色双防线独立测试 |
| 独立 Schema（每组织一 schema） | 结构级 | 中（DDL 复制+目录表跨 schema 策略） | 中（schema 数量与连接池放大） | 等价隔离证据：目录表共享/复制策略、跨 schema 查询面（§3.3 派生 17 张 join 路径）不漏判 |
| 独立数据库 | 物理级 | 高（路由层+全量 DDL/回填/备份） | 高（连接与运维 N 倍） | 路由中间件或数据源路由的事务/回填/跨库对账证明 |

比较时必须覆盖盘点矩阵 §6 预勾选的全部面：129 带列表+向量 2 张（直接覆盖面）、§3.3 派生 17 张（join vs 增列/复合键）、§3.1 账号 3 张（跨组织共享例外）、§3.2 目录 6 张+§3.4 机制 3 张（平台共享面）、Redis 三键域与对象存储/工件（非 SQL 面强制纳入，不能只测 SQL）。性能不足不能成为无评审取消数据层防线的理由；性能数据由隔离原型实测产出，不拍脑袋。

### 4. 迁移路径原则

- **在已有数据上迁移，不重建归属**：矩阵 §1 的 159/130/29 口径与 §2/§3 逐表裁定是一切 M12 迁移的引用基线；发现表需要变更时先回到本 ADR 与矩阵裁定，不猜测归属。
- 编号从合并时实际最大值 +1 顺延（当前 tip V67；M10/M11 的未来编号不是已发布事实）。
- 大表回填是可续作业（分批+断点+约束验证），不进单个 Flyway 长事务；结构演进、回填、隔离切换拆阶段。
- 存量组织不全量回填默认组织；归属不确定的数据显式处理（§4.2 合同）。
- 回退三分法：兼容旧代码的变更 / 数据修复 / 完整备份恢复；不承诺任意迁移有可逆 down SQL。
- **归属不漂移断言**：D01 升级/恢复演练前后重跑 `python3 scripts/m12-s01-table-inventory.py`，矩阵 §5 五项断言逐项一致才算通过；新增表（V68+）在矩阵增补裁定，不算漂移。

## 实施约束

- D01 基础范围只做：聚合实体化+Repository+盘点矩阵复核+不漂移演练；任何隔离 DDL 都属托管增量，不得混入基础范围交付。
- 托管增量立项时，本 ADR §3 升级为完整比较+原型实测+决策记录（修订本 ADR 或追加 ADR，不静默改状态）。
