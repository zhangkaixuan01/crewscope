## 1. 目标

**把“功能和页面都有”变成“用户不用理解系统内部结构，也能可靠完成工作”。**

M9 提供设计系统、基础交互、动作模型和 Diff 等基础；M9b 收口实际使用路径及支撑它的后端逻辑。不是重做 M9，也不是只换文案。

迁移目标：熟悉 Multica 的用户能用一个项目低风险试用，日常创建/阅读/回访不退步，成果、证据、责任与安全下一步集中可见。不是复刻竞品全部能力，也不因有责任链就宣称已经更好用；关闭条件采用可重复的浏览器场景测试，见 §9.3。

验收方式按用户要求调整：不招募真人、不做访谈、理解度或迁移意愿测评，不把参与人数/用户主观评价设为关闭门槛。历史 M9 记录保留，但其中真人测评要求不再由 M9b 继承；业务中的人工审批/授权规则不因此取消，测试可由自动化操控不同身份验证。

优先解决三个核心阻断：

1. 默认远端 HTTP 部署下，注册等操作不能因 `crypto.randomUUID()` 缺失而失败。
2. 普通用户不再填写工作项唯一 Key，系统负责编号、幂等和创建后精确定位。
3. 空环境能通过页面完成 GitHub 授权绑定和仓库导入，不依赖预置数据、curl 或改库。

随后收敛首次配置、委托执行、审查发布、草稿、移动端和成员撤权。目标不是宣布全面超越竞品，而是吸收 Multica 的“描述并交给 Agent”和 Vibe Kanban 的“同一工作区完成执行与审查”，同时保留 CrewScope 的责任链与证据优势。

本期从用户与产品角度验收：**找得到入口、知道选了谁、操作产生预期结果、读得完整、出错能继续、离开后不丢工作、切身份不暴露别人内容。** 第二轮新增的搜索、选人、长对话、审查阅读标记与评论、个人通知等问题不能只按组件样式任务处理；证据与 23 页覆盖矩阵见 Review §10。

页面覆盖不是最终粒度：15 个一级菜单、9 个二级菜单及全局/搜索/账号/认证入口中的实际操作都按菜单 Review 清单验收；有按钮但参数/目标/结果不符、没有失败继续路径、缺少基本编辑，都不能关闭对应工作包。

本轮布局增量见 [全菜单布局与交互细节 Review](../reviews/M9b-全菜单布局与交互细节Review.md)：L01–L12 将已有 R 项细化到控件摆放、首屏、主次动作、列表/详情切换、窄屏和反馈位置。它与原逐操作清单共同验收，不是可选美化；43 项/15 包计数不变不意味着无需新增接线和回归工作。

## 2. 出口结果

- `quickstart.sh up` 仍是默认启动方式：四服务、源码构建、HTTP，无新增必须部署的服务。
- 只想对话的人，不被 GitHub、仓库和构建配置阻塞；需要 Coding 时才补相应配置。
- 创建工作项只需业务信息；项目短代号自动建议，仓库内部 Key 与外部账号 ID 自动处理。
- 连接模型、导入仓库、确认项目默认值后，日常任务不重复填写连接、策略、构建和配置修订。
- “交给 Agent”在一个操作流程内完成有权限的责任分配、预检和启动。
- 工作项聚合对话、执行、改动、测试、审查与交付；看板直接显示等待谁、为什么、下一步。
- 创建、切换与重试可靠：无猜 ID、旧响应串状态、丢响应后重复提交；跨页面配置不丢草稿。
- 审查与 PR 确认展示实际影响，不要求用户理解 Digest、ProviderBinding、ActionBundle。
- 真实团队能调整角色、停用/移除成员并交接责任，不以改库为正常操作。
- 本地自动化、真实 Provider、两个隔离测试账号和空账号首用场景分别记录；不以 mock、快照或静态计数替代真实后端浏览器证据，不要求真人参与。
- 搜索页与快捷搜索互不干扰；选人显示实际选择且不漏分页候选；批量操作逐项告知成功/失败，不把个人 Inbox 收纳当作完成审批。
- 长对话不丢消息和阅读位置；“已查看”只代表本人看过当前版本；评论始终绑定原目标，保存失败不关闭草稿。
- 普通成员能管理自己的通知；错误/禁用原因看得见，中文输入、键盘、触屏都能走完主流程。
- 工作项能编辑基本内容但不重写历史执行快照；模型连接停用后有安全重新启用路径；审计查询/导出与所见条件一致，导入和团队摘要的重读/重试/重新生成各有明确含义。

## 3. 范围与非目标

R01–R43 的全部修复/优化均有责任包和验收，映射见 §7。涉及新增 API、读模型、必要迁移及成员生命周期，因此**不沿用 M9“零领域增量”的限制**；仍优先复用既有模型与能力。新增共享内容阅读、个人固定/保存视图、发送意图与可信模型限制展示，并升级 Inbox 可恢复收纳；它们不是可选美化。

项目模型服务接入、GitHub 配置和构建方案采用“安全的默认值 + 可选高级设置”，不是取消配置能力。所有能力以当前页面实际可完成的路径描述。

- 不承诺所有模型、所有编程语言、任意构建脚本均可用。支持矩阵及不支持时的引导必须明确。

## 4. 核心使用与技术合同

### 4.1 普通路径不暴露内部标识

| 信息 | 用户交互 | 系统责任 |
| --- | --- | --- |
| 工作项编号 | 创建后只读显示，可复制 | 服务端事务内分配；并发、删除历史及幂等重放规则统一 |
| 项目短代号 | 名称先行，自动建议；高级选项可修改建议 | 冲突自动处理；确认使用后不可静默改变外部引用 |
| 仓库内部 Key | 不要求填写；显示 `owner/repo` | 结合外部稳定 ID 与授权 Scope 去重，不用短仓库名当唯一事实 |
| GitHub Account ID | 不要求查找/粘贴数字 ID | 根据凭据/安装验证真实身份，不能信任客户端自报身份 |
| 幂等键、Receipt、配置 Hash | 不要求输入或核对 | 同一用户意图复用原请求，按版本固定，诊断中可查看 |

复用已有 `WorkItemRepository.nextKey` 与项目事务锁；普通手工创建和 TaskIntent 确认不能保留两种分配算法。旧资源编号、链接、事件不重写。显式编号仅在确有需要的管理导入路径使用，不继续污染普通创建表单。

### 4.2 提交成功、读侧可见与执行完成是不同状态

创建 API 返回受权资源定位，或通过正式命令结果接口解析；首次与重放一致。不能按标题、列表差集或最近一条猜测结果。

命令状态至少区分：未提交、提交中、已提交等待同步、确定失败、结果未知待查询。网络超时不能直接当业务未发生；不得生成新命令键盲重试。修改 payload、切 Scope 或明确“再建一个”是新意图，但不能抹去旧未知命令；必须保留其恢复坐标，不能把修改当作旧操作未发生的证据。完整状态/恢复表及持久定位合同见配套契约 §2。

所有异步加载捕获 Scope 与请求代次，取消旧请求并在写状态前校验；请求取消不等于服务端命令撤销。页面卸载、切 Team/项目/连接及导入轮询均适用。

### 4.3 编排简化操作，不扩大授权

GitHub 的 Connection、Grant、ProviderBinding、RepositoryBinding 仍各司其职。页面提供连续步骤和实际授权摘要，应用服务编排并记录可恢复状态；外部调用不塞进一个长数据库事务。暂时失败后能按原意图继续，不要求用户辨认内部实体。

“交给 Agent”由服务端校验责任修改与执行权限，解析候选 Agent、仓库、默认分支、模型/构建版本并固定快照。分配与启动能够原子提交的部分在事务内完成；超出事务的准备动作通过已有耐久机制收敛。已有责任不能被默认值静默覆盖。

GitHub 交付仍先审核，再确认实际影响。内部校验 Review/版本/摘要/权限；事实变更使旧确认失效。外部结果 UNKNOWN 只查询对账，不盲重放 Push/PR。

### 4.4 配置一次，后续复用

- 模型：管理员配置连接名称、Endpoint、凭据与模型；成员使用已授权连接。不把单一硬编码 Catalog 当作完整模型管理。保留兼容 Adapter，新增受控 Provider/Catalog 管理及能力验证，不依赖复制个人密钥到全局环境变量。
- 私有模型代理：支持显式批准的内网地址范围，禁止任意成员进行任意网络探测；DNS/重定向、凭据转发、超时与响应大小都受约束。HTTP 页面不意味着模型凭据可以进入日志或持久化前端草稿。
- GitHub：默认配置不要求 Account ID/内部 Key。最小自部署路径允许明确命名的“使用已有凭据连接”，服务端自动识别身份、选择授权仓库并完成绑定；不把 Token 表单叫作已完成 OAuth 跳转。标准安装/重定向只在对应部署具备前提时展示，不将公网回调域名或 TLS 强加给仅对话和已有凭据路径。
- 构建：至少闭合既有 Maven/Java 17 与一种常见前端 Node 项目的受控方案，Node/包管理器支持版本由 S01 冻结。仓库识别给建议，用户确认后成为项目默认值；未知栈明确不支持或进入有权限的高级配置，不假装自动适配所有语言。
- 费用：缺价格显示未知/无法估算，不记成零。M9b 不做完整计费、模型自动路由与成本大盘。

### 4.5 以工作为中心组织界面

普通一级入口收敛为今日、工作、对话；待我处理可从 Today/通知进入，搜索保持全局可达。设置与团队管理按角色归组，保留旧深链接跳转，不通过删除入口掩盖现有能力。

工作项为用户的主对象，执行、尝试、责任快照仍为独立领域事实。工作区主视图是对话/输出与改动/测试，审查和交付在同一上下文；技术信息默认折叠，不取消诊断能力。

对话优先最新消息、输入和当前待确认事项；关联卡默认摘要，参与者按需展开。Agent 配置先选对象，再看模型/角色/状态，高级参数和历史后置。窄屏默认高效列表，复杂 Diff 按单栏/页签切换，不简单缩小桌面多栏。

### 4.6 成员生命周期提前，但不提前引入 WebSocket

原 M11-D02 的基础写侧移到 M9b-A07：角色变更、成员停用/恢复、移除、最后 Owner 保护、责任交接。先覆盖当前 HTTP、SSE、会话投影和 Worker 的持续鉴权。

M11-D02 保留 ID，但只负责新 WebSocket/在场通道对既有撤权事实的接入与回归，不重复建命令/表/API。ADR-038 主题不变，基础合同由 M9b 接受，M11 增补新通道。

### 4.7 对已有数据与部署兼容

所有迁移按实际合并序号追加，不改已发布迁移，不预分配版本。现有项目/连接/任务补默认值时不得偷偷改变权限、在途快照或历史编号；缺配置可明确待完善，不能阻止 API-only 启动。

接口及生成物同步更新。新增资源定位优先兼容扩展或版本化接口，不直接让旧回执消费者失效；普通表单不传旧 Key 后，服务端要有明确兼容与废弃策略。旧路由保留可验证跳转，权限与敏感字段扫描不能因页面合并而退出门禁。

### 4.8 看见的状态与操作必须可信

- **搜索与选择**：页面搜索/快捷搜索独立状态；已提交条件与输入草稿分开，cursor 绑定查询与 Scope。清空作废在途结果，同条件重试真正请求，续页失败保留已有内容。人员/Agent 按授权解析已选对象，类型过滤在分页之前，不因首 20 项没有匹配就宣称团队没有候选。
- **阅读与审查**：消息滚动按实际高度/消息锚点处理，支持长 Markdown、流式更新、加载历史；阅读进度按用户、执行、审查快照和文件内容版本隔离，不等于批准。行级评论在打开时固定文件/行/执行/Review/版本，切换不能静默改绑；无有效 Review 或未取得成功回执不能假装已保存。
- **批量处理**：点击时冻结明确选择与 Scope，有进度及逐项结果；成功项不盲重放，未知项先查结果。分页可保留选择，切筛选/团队如何处理必须可见；不能不告知就作用于隐藏对象。Inbox 收纳与实际审批/确认保持独立，真正业务动作优先。
- **反馈与时间**：禁用原因不能只在 `sr-only` 或 hover 中；有补救动作才显示重试，按业务命名。最后同步、断线、运行终态、刚保存、结果待同步明确区分；共享时钟更新相对时间和日界，休眠恢复重算，不因“刚刚”停留而误导等待判断。
- **输入与导航**：中文组合输入 Enter 不触发导航/选择；可见顺序与键盘顺序一致，顶层弹层独占 Esc/Tab，触屏能查看完整信息。Logo/首页统一；顶层导航只带允许的 Scope 参数，页面私有筛选不串页；Today 的跨项目范围明确显示。

### 4.9 本地内容、草稿与本人权限

主题/密度是设备偏好，最近对象标题、评论草稿、阅读进度不是。后者按账号/团队/对象隔离；登出、撤权后的清理/重新授权不能留下其他身份可读的旧标题。旧全局业务缓存需迁移或清除，不能原样改个 key 后继续展示。结构损坏或旧版布局偏好回退安全值，存储不可用不阻塞页面。

草稿覆盖对话、工作项评论、Diff 评论、审查意见、委托及非敏感设置。S01 明确各类采用临时保留、持久化或离开确认；并非全部永久落盘。只有确定提交成功才清空，切对象不能复用错草稿；凭据不持久化。保存期限、容量、清除与离线文案必须一致。

接受邀请后依据受权结果精确定位团队，不猜列表差集/名称。本人通知偏好从管理集成中拆出入口及必要的权限合同；普通成员仅操作本人，不能因此获得凭据/连接/他人投递的管理权限。沿用现有 NotificationPreference 能力，不扩大为新通知平台或完整飞书 OAuth 项目。

### 4.10 菜单操作闭环的必要增量

- 工作项基本编辑范围为标题、描述、优先级、标签和到期时间；编号只读，不顺带增加类型迁移/跨项目移动/删除。强版本、权限、变更记录与幂等齐备；目标更新不静默改写在途执行和历史审批，用户可明确选择后续重新执行/审查。
- 模型连接复用领域 activate，补应用/API/前端“验证健康后启用”；轮换凭据不能暗示已经启用，永久撤销不允许复活。停用前说明对默认配置、新执行与在途任务的实际影响。
- 审计普通查人/查对象不用抄 UUID，精确诊断过滤可作为高级能力；详情深链不依赖列表已翻到哪页。本期选定“导出已应用条件”：未应用修改时禁导出并提供应用入口，显示已应用范围，校验和提交使用同一冻结快照；条数/上限/可能截断明确，无用途复选框移除。详见配套契约 §5.2，不再并行实现多个导出语义。
- 飞书验证、映射确认、凭据轮换固定打开/提交时的对象与版本；切换作废旧确认，失败/未知保留原命令恢复。撤销连接/映射、通知重投逐项说明影响，不能以“全局已有弹窗”代替实际按钮接线。
- GitHub 导入按原 job 恢复读取、正确展示取消/失败/完成/未知；关闭不冒充取消。团队观测区分回读旧结果、恢复同次调用、生成最新摘要；首次无 invocationId 的失败也有安全下一步。

### 4.11 从 Multica 迁移时不能退步的日常合同

- **内容一致**：共享安全 Markdown 渲染覆盖聊天、工作说明、评论与行评；表格保留表头和行列，代码可复制，长内容只在本区域横滚。轻量预览即可，不放开任意 HTML 或远端图片自动加载。
- **发送意图**：普通评论与“让 Agent 处理”分开；显示目标、来源/版本、当前或新一轮执行及可能的调用。不能用自由文本 @ 冒充真实提及，不能静默注入在途执行或自动分享完整私聊。评论已成功、执行未成功时分别恢复。
- **个人回访**：支持受限的个人保存视图与固定工作/项目，先做本浏览器且说明同步范围。只保存允许的筛选定义/定位，不复制服务端业务事实；显式 URL 优先、账号/Team 隔离、撤权后不展示旧标题。
- **收纳可恢复**：R26 最终标准升级为浏览归档、恢复归档、重新标未读，不以“不可恢复”警告替代。本期默认恢复到 READ 并明确告知；重新标未读为持久 UNREAD/正版本，不删除历史行、不回滚源业务。F04 按配套契约 §5.1 状态表交付领域/API/投影、强版本、幂等、授权和旧客户端兼容，不能只改按钮。
- **模型限制可信**：输入长度、模型窗口、剩余 token、费用分别命名；没有真实来源时移除固定“预算 32,000”。模型限制来自 A03，历史用量绑定历史执行，未知不写 0。不新增计费/配额平台。
- **成果接回**：先显示本次产出、已验证/失败/未运行、风险/待决定、责任与下一步；每条证据固定到执行版本。运行结束不等于工作完成，模型自述不等于测试成功，PR 提交不等于合并。
- **简洁但诚实**：默认导航聚焦工作、对话和待处理，管理分组渐进展开；表单最少默认字段、诊断下沉、保留风险提示。附件未支持须说明文字/链接替代及适用范围，不能宣传为完整替代 Multica。

详细视觉规则、15 菜单增量与场景脚本见 [迁移 Review §5–§7](../reviews/M9b-Multica用户迁移体验Review.md)。它是原菜单清单的增量，不能覆盖掉之前的逐操作验收。首屏结构、当前执行选择、路由与返回默认规则以配套契约 §4 为准。

### 4.12 全菜单布局与位置合同

本节不是要求再增加一套页面。复用 M9 设计系统，以用户完成任务时的顺序调整现有内容；确定行为见 [配套契约 §4.3–§4.4](M9b-实现边界与验收契约.md)，逐菜单位置与证据见 [布局 Review §2–§4](../reviews/M9b-全菜单布局与交互细节Review.md)。

- 全局壳先修：工具栏控件不越界挤到页头，手机搜索可触达，折叠菜单保留名称；桌面日常导航与手机底栏一致，主题/密度归账号外观，不与核心入口抢位置。
- 设置分类/搜索结果分区，账号不再叠团队配置导航；9 个旧入口逐一保留权限、Scope 和安全返回。桌面按可用内容宽度降级，不能只看整个 viewport 宽度硬塞多栏。

- 详情有稳定位置和返回路径，不在长目录上/下方插入巨大表单；工作区当前执行选择与成果/主动作靠近，对话正文与输入优先。固定栏、离线条、键盘和安全区统一避让，不能以固定高度减数或缩小正文掩盖问题。
- 常规操作靠目标，保存/失败/未知反馈就地；危险操作独立分区并确认影响。联网/静态介绍不冒充配置健康，HTTP 不承诺 HTTPS，未实现的团队改名等能力不在提示中承诺。
- 保留现有色彩/字号 Token 与 AA 基线，紧凑模式不删操作；视觉顺序与键盘顺序一致。只换 CSS、删技术字段或重拍长截图不足以关闭本轮要求。
