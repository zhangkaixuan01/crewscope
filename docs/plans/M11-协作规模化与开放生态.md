## 1. 目标

M9/M9b 收口单个成员的使用体验与核心团队管理，M10 让 Agent 越用越懂团队，M11 解决**多个人同时在场**与**系统对外开放**两件事。

当前 CrewScope 的协作是"异步的、单向的"：实时通道只有 SSE，没有双向 WebSocket；两个成员同时编辑同一个 WorkItem 只能靠强 ETag 事后冲突；看不到谁正在看、谁正在改。工作项之间的依赖关系只存在于人的脑子里——`WorkGraph` 这个入口从 M1 起就挂在导航上作为永久禁用占位，是项目里唯一一个长期未兑现的承诺（M9 已将其移除，M11 负责真正交付）。

国际化与外部工具生态仍是后续价值方向，但不与本期 Web 协作主线捆绑验收。默认继续使用四服务、源码构建与 HTTP；WebSocket/MCP 等启用所需的代理设置随对应功能交付，不增加默认部署步骤。

M11 主线完成后具备前两项；后三项为独立可选扩展：

- 多个成员可以同屏协作，看到彼此的在场状态、正在输入与实时变更，冲突在发生前被看见而非发生后被回读；
- 工作项之间的阻塞、依赖、拆分关系成为一等公民，团队可以看清关键路径；
- CrewScope 可以通过 MCP 接入外部工具，也可以作为 MCP Server 被外部 Agent 使用；
- 界面完整支持中英双语，可面向开源社区与非中文团队发行；
- 提供桌面客户端，获得本地通知、全局快捷键与多窗口能力。

## 3. 范围与非目标

### 3.1 主线与可选范围

主线：实时协作、WorkGraph、成员生命周期与必要的职责重构。可选：MCP Client/Server、i18n、桌面端；分别记录选入状态与验收，不要求主线等待安装包签名或生态接入。MCP Client 和 Server 在 I02/F03 下拆成可独立验收的子范围，不新增虚假的父任务完成状态。

- 实时通道与三流事件协议（ADR-021）兼容共存，SSE 保留为降级通道；
- WorkGraph 关系是 WorkItem 的一等领域概念，进入事件流与审计，不是前端可视化糖；
- MCP 接入复用 AgentScope `extensions-protocol`，外部工具必须进入既有 Task Tool Policy 治理；
- 选做 i18n 时，服务端返回稳定错误码与安全参数，前端通过 `vue-i18n` 渲染本地化文案；服务端不返回已渲染的用户文案；
- 桌面端只做壳与本地能力增强，不分叉业务代码；
- **成员生命周期基础写路径已移至 M9b-A07 计划**，M9b 完成后供本期复用。D02 仅补 WebSocket 断连、在场信息清理、重连/降级重新鉴权及与原命令的集成测试；不再重复建成员命令、API 或责任交接体系。

### 3.2 非目标

- 多 Organization 与 SaaS 控制面（M12）；
- SSO / SCIM / MFA（M12）；
- 计费与配额（M12）；
- 移动端原生客户端（延后，PWA 优先）；
- 插件市场与任意第三方代码动态装载（MCP 是受控协议接入，不等于插件市场）；
- 富文本协同编辑（CRDT）——M11 只做在场与变更推送，不做字符级共同编辑。

## 4. 核心决策

### 4.1 WebSocket 是增强，不是替换

SSE 通道及其 Cursor/Generation 协议保持不变并继续作为权威恢复路径。WebSocket 只承载**低价值高频**信号（在场、正在输入、光标位置）与**变更通知**（"WorkItem X 已更新，请拉取"），不承载权威业务数据。连接失败时，权威更新与恢复继续使用 SSE；在场/输入等双向信号允许降级为不可用，并明确提示。不得声称仅有 SSE 就完整保留所有双向交互。

I01 同步交付内置 Web/Nginx 的 WebSocket Upgrade、Connection 与超时配置，沿用现有公开入口，不新增默认服务或公开端口；握手验证 Origin、Session 和资源授权，过期/撤权后断开或撤销相应订阅。通过四服务 HTTP 部署的真实浏览器验证，不仅测试直连 API。

这保证实时能力不会污染既有的耐久与恢复语义。

### 4.2 在场状态是易失的

在场、正在输入、正在查看只存在于 Redis，有 TTL，不落 PostgreSQL、不进 Outbox、不进 Audit。这类数据丢失的成本远低于持久化它们的成本。

### 4.3 WorkGraph 关系有限且有向

只支持三类关系：`BLOCKS`（阻塞）、`DEPENDS_ON`（依赖）、`SPLIT_FROM`（拆分自）。S01 冻结 BLOCKS 与 DEPENDS_ON 的方向和规范化方式，避免同一依赖以相反边重复存储；SPLIT_FROM 单独定义来源与环规则。关系创建校验无环，跨 WorkProject 校验两个端点权限。**不做通用图数据库**，关系存储在 PostgreSQL 邻接表，深度查询用递归 CTE 并设节点/深度/耗时上界。领域环检测之外还要有事务级并发控制，证明并发 A→B 与 B→A 不能各自检查通过；锁粒度、隔离级别或等价方案由 S01 验证。关键路径若无工期数据，应明确为拓扑阻塞链，不虚构排期估算。

### 4.4 MCP 外部工具受既有工具治理

外部 MCP 工具进入执行链路前必须：注册到 Team 级工具目录、由管理员启用、落入既有 Task Tool Policy、每次调用进入 Audit。本地 stdio 工具必须在受控 Sandbox 内启动，不允许把任意命令交给 API 宿主执行。远程 MCP Server 不在 CrewScope Sandbox 内，不能声称由本机沙箱隔离；需独立的出站地址、DNS/重定向、超时、响应大小与凭证控制，发送内容按工具授权最小化。

作为 MCP Server 暴露时，只暴露只读查询与明确的受权命令，认证复用既有身份与授权服务，但不能直接复用浏览器 Cookie/CSRF 或 Task Token 作为通用外部凭证。S01 冻结 audience、scope、到期、撤销和按调用重新授权；写命令继续走幂等、Human Gate 与审计，且**不暴露任何跨 Team 能力**。

### 4.5 i18n 不返回渲染后的服务端文案

服务端继续只返回稳定错误码与结构化参数，前端负责渲染。这既保持了既有 `ApiErrorResponse` 合同，又让新增语言不需要后端改动。中文为源语言，英文为首个目标语言。

### 4.6 桌面端不分叉业务代码

Tauri 包装既有 Web 构建产物，只增加本地通知、全局快捷键、多窗口、深链接与自动更新。任何"仅桌面可用"的业务功能都视为设计失败。

### 4.7 巨型类收口延续 M8-E01 方法

`OperationsController`、`GitHubConnectionApplicationService` 等实际仍有职责混杂的类按"先建 Characterization Test、再移动实现、公开合同不变"的既有方法拆分，与本里程碑的新增能力同批推进而非独立立项。

## 8. M11 Release Gate

1. 实时通道与 SSE 共存，WebSocket 不参与权威状态恢复，降级路径端到端可用；

9. 选做桌面时：认证/同源、深链接、平台签名和更新链单独验证，与所选 Web 功能一致；
10. `OperationsController` 等巨型类完成收口且公开合同零差异；
11. 成员的角色变更、移除与停用可用，最后一个 Owner 受保护，被移除成员的责任链无无主项且相应 Team 授权、实时订阅和在途执行权限及时失效；跨 Team 会话与账号级失效区分处理；
12. 三个隔离测试账号的同屏协作端到端验证通过，由自动化/代理浏览器操作，不招募真人；
13. M0–M10 全量固定攻击、故障、恢复、迁移与浏览器门禁零回归。

## 10. 实施细则（边界基线）

> **本节的详细程度低于 M9 §10 与 M10 §10，这是有意的。** M11 的主线 `I01` 实时通道及选入的 `I02` MCP、`F04` i18n、`I03` 桌面端按 §9 在各自 Spike 合同接受后细化到可领取粒度，现在把实现细节写死等于替 Spike 做决定。
>
> 因此本节只固化**三类不需要 Spike 也能确定的东西**：不许越的红线、不许重复的落点、不许漏的清单同步。凡标注「由 `S01` 细化」的条目，须在对应范围进入实现前给出答案；未选入扩展的研究不阻塞主线。

### 10.1 红线清单

| 红线 | 判定方式 |
|---|---|
| 实时通道不成为第二套鉴权 | WebSocket 连接**复用既有 Session 鉴权**，不引入独立 token 体系；订阅授权每次都走既有 `ExecutionScope ∩ Ownership` 求交 |
| 撤权一致 | Team 级变更统一更新会话权限投影、撤销对应订阅并约束在途执行；账号级禁用才失效全部会话。D02 与 I01 共用撤权协议，验证撤销到生效的时限 |
| 在场信息不泄漏资源标题 | 「谁在看什么」只对同样有权查看该资源的人可见；未授权者连资源存在性都不可推断（`Q01` 攻击集第 3 项） |
| WorkGraph 不引入环 | 领域环检测与事务级并发控制共同保证，验证相反边并发创建；不能只靠前端或单线程检查（§6 `D01`） |
| MCP 外部工具不绕过 Human Gate | 外部工具与内部工具走同一套授权与审计路径；工具清单变化必须显式重新授权 |
| 最后一个有效 Owner 不可移除、停用或降级 | 领域层拒绝并给出稳定原因码（`D02`） |
| 责任链不留无主项 | 移除、停用或降级时必须显式指定接收人或显式拒绝，有对账测试（`D02`） |
| M9/M10 的体验 DoD 不回退 | M11 新增的全部页面从第一版满足 M9 §10.10 十条 DoD |
| 已发布迁移不可变 | 按实际已发布迁移清单；M10 未来编号不是已发布事实 |
| 桌面端不分叉业务代码 | Tauri 只包装既有 Web 产物；任何「仅桌面端可用」的业务分支都要在 ADR 里单独论证 |

### 10.2 迁移边界

迁移号从合并时实际最大值 +1 顺延，不预留 V45/V46，也不把 M10 计划编号当成既成事实。

- D01：关系表、版本/索引及事件；并发环检测需要事务协议，不能只测单线程领域算法。
- D02：复用 M9b 已交付成员与责任交接结构；新通道若需持久化授权版本或投递坐标，须证明现有结构不足后追加，不重复生命周期迁移。
- I02（选做）：Team 工具注册、启用状态、凭证引用、工具清单版本等持久化明确归属，不再同时声称“零迁移”和“可能落库”。
- 在场/输入信号只在 Redis 带 TTL；业务关系与成员命令仍持久化并进入事件/Audit。
### 10.3 包与落点：三条「不要新建」

M11 最可能出现的偏差是**为已有概念新建平行包**。实测既有包中有三个正好覆盖 M11 的新能力：

1. **协作信号落既有 `application/collaboration/` 与 `domain/collaboration/`**（实测两者都存在）。**不要新建 `application/presence`**——在场、正在输入、实时变更广播都是协作信号的子类型；
2. **成员生命周期写侧由 M9b-A07 交付，落既有 `application/team/`**（已有 `AddTeamMemberCommand`、`MemberRoleRepository`、`TeamRoleRepository`、`TeamMemberRepository`、`TeamMembershipQuery`、`TeamMemberView`）。**不要新建 `application/membership`**——M11-D02 只消费既有命令产生的撤权事实，复用 `TeamCommandContext` 与 `TeamAccessContext`；不重新实现角色、移除、停用命令；
3. **MCP 接入落 `crewscope-agentscope` 新包 `io.crewscope.agentscope.mcp`**，依赖 `agentscope-extensions-protocol`（实测该模块存在）。**不要放进 `crewscope-integration`**——它是外部系统集成（GitHub / 飞书），而 MCP 是 Agent 工具面。

领域层规划新增包为：`domain/workgraph/`（`WorkItemRelation`、`WorkItemRelationType`、`RelationCycleDetector`、`BlockingChain`、`CriticalPath`）。**放新包而不是 `domain/workitem/` 的理由**：关系是工作项之间的结构，环检测与关键路径是图算法不变量，与单个工作项的生命周期无关；混进 `domain/workitem/` 会让那个已经很大的包继续膨胀（`BE-02` 的方向）。

其余层的落点沿用 M9 §10.5.3 的类名族，不再重复。server 侧计划新增 `CollaborationSignalController`、`WorkGraphController`，选做 MCP 时再增加相应入口。成员 Controller 复用 M9b-A07 的唯一实现，不再由 M11-S01 重新选择或新增平行入口。DTO 一律平铺在 `server/api/`。

### 10.4 导航与页面同步

从实际 router 与共享导航定义检查页面标题、权限、导航选中态和 390px 可达性，不再写死 18→21 或三份独立菜单清单。

主线预计新增 WorkGraph 页面；成员生命周期接在既有成员页，不另建页面。MCP 管理页仅在选做时加入；活跃会话界面属于 M12 身份范围，不计入 M11 菜单。组件沿用协作头像/输入指示、关系图及等价列表呈现。图规模、节点上限与超限降级由 S01 冻结。
### 10.5 i18n（`F04`）：一次性代价，两条不许违反的约束

1. **中文是源语言。** Key 从中文文案抽取，英文是翻译产物。反过来做（英文为源）会导致所有既有中文文案被二次翻译，语义漂移不可控；
2. **`labels.ts` 必须并入 i18n，不得留两套文案源。** M9 建立的 `src/domains/*/labels.ts` 在 `F04` 中改为 i18n Key 的映射表（枚举 → Key），而不是继续持有中文字面量。同时**必须保留 M9 的 `Record<Enum, string>` 类型约束**——它是「后端新增枚举值时 CI 必须红」的唯一保障，改成 i18n 后这个约束比翻译完整性更重要。

漏翻译门禁、语言切换的持久化（复用 `src/app/preference.ts` 的键命名约定）、日期与数字格式化的归属（与 `useRelativeTime` 的关系）——**由 `S01` 细化**。

### 10.8 由 `M11-S01` 必须给出答案的开放项
