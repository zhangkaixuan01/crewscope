## 1. 目标

M9 让单个成员用得顺手，M10 让 Agent 越用越懂团队，M11 解决**多个人同时在场**与**系统对外开放**两件事。

当前 CrewScope 的协作是"异步的、单向的"：实时通道只有 SSE，没有双向 WebSocket；两个成员同时编辑同一个 WorkItem 只能靠强 ETag 事后冲突；看不到谁正在看、谁正在改。工作项之间的依赖关系只存在于人的脑子里——`WorkGraph` 这个入口从 M1 起就挂在导航上作为永久禁用占位，是项目里唯一一个长期未兑现的承诺（M9 已将其移除，M11 负责真正交付）。

同时，产品当前无法面向非中文团队发行，也无法接入外部工具生态。

M11 完成后：

- 多个成员可以同屏协作，看到彼此的在场状态、正在输入与实时变更，冲突在发生前被看见而非发生后被回读；
- 工作项之间的阻塞、依赖、拆分关系成为一等公民，团队可以看清关键路径；
- CrewScope 可以通过 MCP 接入外部工具，也可以作为 MCP Server 被外部 Agent 使用；
- 界面完整支持中英双语，可面向开源社区与非中文团队发行；
- 提供桌面客户端，获得本地通知、全局快捷键与多窗口能力。

## 2. 出口结果

1. 双向实时通道上线，在场状态、正在输入、实时变更推送覆盖 Conversation、WorkItem 与看板；
2. WorkGraph 领域能力与可视化上线，支持依赖、阻塞、拆分三类关系与关键路径分析；
3. MCP 双向接入：CrewScope 作为 MCP Client 消费外部工具，同时作为 MCP Server 暴露受控能力；
4. 完整 i18n 层上线，中英双语覆盖全部界面文案与服务端可本地化错误消息；
5. 桌面客户端（Tauri）发布，复用既有 Web 构建产物；
6. **团队成员生命周期补齐**：角色变更、成员移除与停用成为一等领域命令，团队规模变化不再需要改库（`BE-11` 写侧）；
7. `BE-02` 的巨型编排类完成收口，Controller 与 ApplicationService 回到可维护规模；
8. 上述能力全部继承既有权限、审计、耐久与隔离语义。

## 3. 范围与非目标

### 3.1 本期范围

- 实时通道与三流事件协议（ADR-021）兼容共存，SSE 保留为降级通道；
- WorkGraph 关系是 WorkItem 的一等领域概念，进入事件流与审计，不是前端可视化糖；
- MCP 接入复用 AgentScope `extensions-protocol`，外部工具必须进入既有 Task Tool Policy 治理；
- i18n 采用"前端 `vue-i18n` + 服务端错误码本地化"双层方案，服务端不返回已渲染的用户文案；
- 桌面端只做壳与本地能力增强，不分叉业务代码；
- **成员生命周期的写路径**（角色变更、移除、停用）在本期补齐——M9 只做了读侧（`M9-A07` 的角色字段与主体目录），写侧需要新增领域命令、事件与权限判定，属领域增量，因此放在"从单团队到多团队"这个主题下一并处理。

### 3.2 非目标

- 多 Organization 与 SaaS 控制面（M12）；
- SSO / SCIM / MFA（M12）；
- 计费与配额（M12）；
- 移动端原生客户端（延后，PWA 优先）；
- 插件市场与任意第三方代码动态装载（MCP 是受控协议接入，不等于插件市场）；
- 富文本协同编辑（CRDT）——M11 只做在场与变更推送，不做字符级共同编辑。

## 4. 核心决策

### 4.1 WebSocket 是增强，不是替换

SSE 通道及其 Cursor/Generation 协议保持不变并继续作为权威恢复路径。WebSocket 只承载**低价值高频**信号（在场、正在输入、光标位置）与**变更通知**（"WorkItem X 已更新，请拉取"），不承载权威业务数据。连接失败时自动降级到 SSE，用户无感。

这保证实时能力不会污染既有的耐久与恢复语义。

### 4.2 在场状态是易失的

在场、正在输入、正在查看只存在于 Redis，有 TTL，不落 PostgreSQL、不进 Outbox、不进 Audit。这类数据丢失的成本远低于持久化它们的成本。

### 4.3 WorkGraph 关系有限且有向

只支持三类关系：`BLOCKS`（阻塞）、`DEPENDS_ON`（依赖）、`SPLIT_FROM`（拆分自）。关系创建时校验不产生环，跨 WorkProject 关系需要显式权限。**不做通用图数据库**，关系存储在 PostgreSQL 邻接表，深度查询用递归 CTE 并设上界。

### 4.4 MCP 外部工具受既有工具治理

外部 MCP 工具进入执行链路前必须：注册到 Team 级工具目录、由管理员启用、落入既有 Task Tool Policy、每次调用进入 Audit。外部工具默认不获得文件系统与网络的额外权限，仍在既有 Sandbox 边界内。

作为 MCP Server 暴露时，只暴露只读查询与明确的受权命令，认证复用既有 Token 机制，且**不暴露任何跨 Team 能力**。

### 4.5 i18n 不返回渲染后的服务端文案

服务端继续只返回稳定错误码与结构化参数，前端负责渲染。这既保持了既有 `ApiErrorResponse` 合同，又让新增语言不需要后端改动。中文为源语言，英文为首个目标语言。

### 4.6 桌面端不分叉业务代码

Tauri 包装既有 Web 构建产物，只增加本地通知、全局快捷键、多窗口、深链接与自动更新。任何"仅桌面可用"的业务功能都视为设计失败。

### 4.7 巨型类收口延续 M8-E01 方法

`OperationsController`（1084 行）、`GitHubConnectionApplicationService`（1145 行）按"先建 Characterization Test、再移动实现、公开合同不变"的既有方法拆分，与本里程碑的新增能力同批推进而非独立立项。

`F04`（i18n）是覆盖面最广但技术风险最低的任务，可在 W2 就开始文案抽取，与其他任务并行推进。

## 8. M11 Release Gate

1. 实时通道与 SSE 共存，WebSocket 不参与权威状态恢复，降级路径端到端可用；
2. 在场数据仅存于 Redis 且有 TTL，丢失不影响业务正确性；
3. 跨 Team 订阅与撤权后连接保持全部被阻断；

6. 外部 MCP 工具受 Team 工具目录与 Task Tool Policy 双重治理，全程可审计；
7. 作为 MCP Server 时不暴露跨 Team 能力；
8. 界面无硬编码用户可见文案，中英双语完整且英文布局不溢出；
9. 桌面端与 Web 端功能一致，无独占业务功能，更新有签名校验；
10. `OperationsController` 等巨型类完成收口且公开合同零差异；
11. 成员的角色变更、移除与停用可用，最后一个 Owner 受保护，被移除成员的责任链无无主项且 Session 与实时连接立即失效；
12. 三人同屏协作端到端验证通过；
13. M0–M10 全量固定攻击、故障、恢复、迁移与浏览器门禁零回归。

## 10. 实施细则（边界基线）

> **本节的详细程度低于 M9 §10 与 M10 §10，这是有意的。** M11 的四个大工作包（`I01` 实时通道、`I02` MCP、`F04` i18n、`I03` 桌面端）按 §9 必须在 `M11-S01` 之后再细化到可领取粒度，现在把实现细节写死等于替 Spike 做决定。
>
> 因此本节只固化**三类不需要 Spike 也能确定的东西**：不许越的红线、不许重复的落点、不许漏的清单同步。凡标注「由 `S01` 细化」的条目，`S01` 出口必须给出答案，未给出不得进入实现。

### 10.1 红线清单

| 红线 | 判定方式 |
|---|---|
| 实时通道不成为第二套鉴权 | WebSocket 连接**复用既有 Session 鉴权**，不引入独立 token 体系；订阅授权每次都走既有 `ExecutionScope ∩ Ownership` 求交 |
| 撤权即断连 | 权限变更必须在**同一路径**上同时失效 Session 与实时连接。`M11-D02`（成员移除）与 `M11-I01`（撤权断连）共用这条路径，**不得各写一套** |
| 在场信息不泄漏资源标题 | 「谁在看什么」只对同样有权查看该资源的人可见；未授权者连资源存在性都不可推断（`Q01` 攻击集第 3 项） |
| WorkGraph 不引入环 | 环检测在**领域层**完成，不靠数据库约束或前端校验（§6 `D01` 已定） |
| MCP 外部工具不绕过 Human Gate | 外部工具与内部工具走同一套授权与审计路径；工具清单变化必须显式重新授权 |
| 最后一个 Owner 不可移除或降级 | 领域层拒绝并给出稳定原因码（`D02`） |
| 责任链不留无主项 | 移除或降级时必须显式指定接收人或显式拒绝，有对账测试（`D02`） |
| M9/M10 的体验 DoD 不回退 | M11 新增的全部页面从第一版满足 M9 §10.10 十条 DoD |
| 已发布迁移不可变 | 含 M9 的 `V37`–`V39` 与 M10 的 `V40`–`V44` |
| 桌面端不分叉业务代码 | Tauri 只包装既有 Web 产物；任何「仅桌面端可用」的业务分支都要在 ADR 里单独论证 |

### 10.2 迁移边界

M10 用到 `V40`–`V44`。**M11 编号从合并时实际最大值 +1 顺延；按 M10 用满 `V44` 计，M11 从 `V45` 起。** 文件名主题部分不随编号变化：

| 文件 | 工作包 | 内容 |
|---|---|---|
| `V45__work_item_relation.sql` | D01 | `WorkItemRelation`（`BLOCKS` / `DEPENDS_ON` / `SPLIT_FROM`）及其索引 |
| `V46__team_member_lifecycle.sql` | D02 | 成员状态机所需的字段/事件投影（**仅当既有 `team_member` 表无法承载停用与责任转移记录时才需要；能就地扩展就不建新表**——由 `S01` 裁决） |

**零迁移的工作包**：`I01`（实时通道，在场数据放 Redis，带 TTL，不落库——§6 已定）、`A01`、`A02`、`I02`（MCP 注册若需持久化则并入 `V45` 之后的单独文件，由 `S01` 裁决）、`F01`–`F04`、`E01`、`I03`。

> **在场数据一律不进 PostgreSQL。** 它是高频写、短 TTL、可丢失的数据；写库会把协作信号变成数据库负载问题。这一条不需要 Spike。

### 10.3 包与落点：三条「不要新建」

M11 最可能出现的偏差是**为已有概念新建平行包**。实测既有包中有三个正好覆盖 M11 的新能力：

1. **协作信号落既有 `application/collaboration/` 与 `domain/collaboration/`**（实测两者都存在）。**不要新建 `application/presence`**——在场、正在输入、实时变更广播都是协作信号的子类型；
2. **成员生命周期写侧落既有 `application/team/`**（实测已有 `AddTeamMemberCommand`、`MemberRoleRepository`、`TeamRoleRepository`、`TeamMemberRepository`、`TeamMembershipQuery`、`TeamMemberView`）。**不要新建 `application/membership`**——`D02` 的三条命令（`ChangeTeamMemberRoleCommand`、`RemoveTeamMemberCommand`、`SuspendTeamMemberCommand`）与 `AddTeamMemberCommand` 必须同包，才能共用 `TeamCommandContext` 与 `TeamAccessContext`；
3. **MCP 接入落 `crewscope-agentscope` 新包 `io.crewscope.agentscope.mcp`**，依赖 `agentscope-extensions-protocol`（实测该模块存在）。**不要放进 `crewscope-integration`**——它是外部系统集成（GitHub / 飞书），而 MCP 是 Agent 工具面。

新建包只有一个：`domain/workgraph/`（`WorkItemRelation`、`WorkItemRelationType`、`RelationCycleDetector`、`BlockingChain`、`CriticalPath`）。**放新包而不是 `domain/workitem/` 的理由**：关系是工作项之间的结构，环检测与关键路径是图算法不变量，与单个工作项的生命周期无关；混进 `domain/workitem/` 会让那个已经很大的包继续膨胀（`BE-02` 的方向）。

其余层的落点沿用 M9 §10.5.3 的类名族，不再重复。server 侧新增 Controller：`CollaborationSignalController`、`WorkGraphController`、`McpServerController`、`TeamMemberLifecycleController`（或并入既有 `TeamController`——二选一由 `S01` 定，**不得两处都提供**）。DTO 一律平铺在 `server/api/`。

### 10.5 i18n（`F04`）：一次性代价，两条不许违反的约束

1. **中文是源语言。** Key 从中文文案抽取，英文是翻译产物。反过来做（英文为源）会导致所有既有中文文案被二次翻译，语义漂移不可控；
2. **`labels.ts` 必须并入 i18n，不得留两套文案源。** M9 建立的 `src/domains/*/labels.ts` 在 `F04` 中改为 i18n Key 的映射表（枚举 → Key），而不是继续持有中文字面量。同时**必须保留 M9 的 `Record<Enum, string>` 类型约束**——它是「后端新增枚举值时 CI 必须红」的唯一保障，改成 i18n 后这个约束比翻译完整性更重要。

漏翻译门禁、语言切换的持久化（复用 `src/app/preference.ts` 的键命名约定）、日期与数字格式化的归属（与 `useRelativeTime` 的关系）——**由 `S01` 细化**。
