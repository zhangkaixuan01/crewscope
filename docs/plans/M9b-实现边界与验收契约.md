- 主计划定义范围、依赖和关闭条件；本文件给出默认产品行为与跨包交接。Review 是问题证据，不是要求同时实现其中所有备选方案。
- 下文“必须/默认”是本期实现约束；技术实现可替换，但行为不得静默改变。需改变范围/授权/外部副作用/存储边界时，先更新主计划和受影响验收，再实施；不能自行以“更简单”删需求。

- 15 个父包仍按主计划依赖关闭；“先修共享组件”不等于调用页面已完成。所有验收无需真人参与。

实施阅读顺序固定为：主计划 §3/§5–§7/§11 → 本文件中切片涉及的合同与 C/D 项 → 对应 Review 菜单行和源码 → 已接受的正式 API/ADR。不要只读任务标题或最后一份 Review 就开工。主计划管范围与依赖，本文件管产品行为，正式 API/ADR 管技术表达，Review 管问题证据；后写的文档不自动推翻前者。发现矛盾时先在切片卡列明冲突、选择及受影响用例，并同步原规范；未消除的矛盾只阻塞受影响切片，不能选择最宽松的一版继续。

## 2. 命令与创建结果：禁止不确定时再造一份工作

### 2.1 最小结果合同

当前 [CommandReceiptResponse](../../crewscope-server/src/main/java/io/crewscope/server/api/CommandReceiptResponse.java) 和 [CommandReceiptStore](../../crewscope-application/src/main/java/io/crewscope/application/command/CommandReceiptStore.java) 不能直接向前端提供完整资源定位。A01 必须补**能跨进程重启/重放恢复的受权结果**，不是只在第一次 HTTP 响应附上内存里的 ID。

创建/编排需要表达：命令身份、已提交版本、结果对象类型与定位、阶段/尚未完成步骤、关联上下文；只返回该调用者当前可访问的信息。结果对象已创建但投影不可见，与命令未发生严格区分。直接响应和后续恢复读取应收敛到同一结果，不能让命令查询成为跨租户枚举入口。

F01 负责前端状态与原请求身份；A01 负责创建结果持久性；A02/A05/A07 负责各自导入/委托/邀请结果。S01 需在这些写侧开工前决定扩展回执还是受权结果端点，并记录旧客户端与旧回执如何读取。

| 状态/输入 | 允许动作及反馈 | 不允许 |
| --- | --- | --- |
| 尚未发送 | 可改字段、取消；提交时捕获账号/Scope/目标/版本/规范化载荷 | 每次渲染都换命令键 |
| 提交中 | 同一意图禁重复提交；可离开但保留最小恢复坐标 | 把关闭弹窗或 Abort 当业务撤销 |
| 请求已发但结果未知 | 查询原命令；仅在已证明相同命令安全重放时重用原键；显示“正在确认结果” | 换键“重试”、显示确定失败、让改过的载荷复用旧键 |
| 已提交，读侧未就绪 | 显示成功及等待同步，按返回坐标定点读取；等待预算到期后提供再次读取 | 猜列表最后一项、同名对象，或再执行创建 |
| 明确校验/授权拒绝 | 显示字段/权限原因；修正后是新意图 | 自动提权、清空无关输入 |
| 版本冲突 | 重新读当前事实，保留本地输入并展示差异；重新确认后新命令 | 静默 last-write-wins、盲重试旧版本 |
| 切账号/Scope/对象 | 旧响应不写入新页面；恢复原命令需重新授权 | 把原成功消息、回执/草稿附到新目标 |

**修改载荷不是“结果未知”的解决方式**：旧命令仍保留待确认记录，不能因为用户改字段就假定旧命令未发生。无幂等恢复能力的现有入口先补合同，不先加自动重试。

前端可保存恢复用的命令键、对象坐标、操作种类与时间；不保存凭据或完整秘密请求体。登录令牌/密钥表单在重开后需重新输入，但先查原命令事实，避免复制已提交配置。重试间隔、总等待预算、结果保留期及过期反馈在 S01 冻结为常量/服务端合同，不无限轮询。

### 2.2 编号和编辑边界

- 服务端统一普通创建与 TaskIntent 的项目锁/编号分配；取消、归档不回收号码。允许间隙，不承诺连续无缺号。
- UI 移除普通 Key 字段，旧显式 Key 请求按冻结的兼容规则校验，不能悄悄忽略后分配不同编号。旧资源 ID/Key/深链不重写。
- 基本编辑只包含标题、描述、优先级、标签、到期时间；省略字段与显式清空必须在 API 区分。复用创建边界校验，空标题/非法时间给字段错误。
- 本期默认 ARCHIVED 只读；其他状态能否编辑由服务端 availability/授权决定，不用状态名代替权限。DONE/CANCELLED 的内容编辑不重新打开业务。
- 保存不隐式改变责任、状态、历史输入快照或启动执行。并发修改先展示最新值/本地值，由用户选择重新提交，不自动合并覆盖。

### 2.3 核心表单的最小字段与成功落点

| 入口 | 展示顺序与默认值 | 提交/完成边界 |
| --- | --- | --- |
| 新建工作项 | 受权项目上下文 → 标题（唯一必填业务字段）→ 可选描述 → 折叠“更多选项”（类型、优先级、标签、到期时间）；沿用 TASK / MEDIUM，普通路径无 Key | 主按钮“创建工作项”，不叫“开始执行”；服务端确认后按受权结果进入该工作详情，显示编号；等待投影时保留该坐标，不退回列表猜结果 |
| 新建对话 | 当前范围 → 标题 → 可见范围；沿用 PRIVATE 默认，团队可见需明确选择并说明实际权限 | 主按钮“创建对话”；成功打开该对话并聚焦输入框，不自动发送、委托或转团队工作；不在本期顺带引入无标题自动建会话规则 |
| 编辑工作项 | 标题 → 描述 → 优先级/标签/到期时间；编号只读，类型不进入基本编辑 | “保存修改”只改 §2.2 的字段；成功留在原对象，失败保留输入，版本冲突不自动覆盖 |
| 委托 | 原工作/责任 → Agent 与有效配置摘要 → 必要缺项/冲突 → 意图及影响确认；已解析默认值不要求重复选择 | “仅分配”和“分配并启动”含义分开；配置缺失去补配置后返回，不自动提交；已分配但启动未完成按原结果继续 |

标题 trim 后校验；沿用工作项 240、对话 200 字符的现有 UI 上限，并由正式接口统一前后端边界，不能只靠 maxlength。标签 trim/去空/去重；未填到期时间为空，有值按明确显示的本地时区转成接口时间，回显不二次偏移。高级项折叠不清空已填值，非默认值在摘要中可见；缺少项目时先选择/引导建立受权项目，不把项目 ID 变成普通用户输入。

菜单、空态、快捷动作的新建入口必须打开同一套创建流程并传入合法 Scope，不各造简化版 API。[defaultActions.ts](../../crewscope-web/src/app/defaultActions.ts) 的 `create.work` / `create.conversation` 已在 A01 接入一次性 `create=1` 与 `useCreationEntry`，合法 Scope 就绪后消费参数并真正打开既有创建表单；仅到列表不算“新建”完成。导航动作不提交业务命令，创建完成后不因刷新/浏览器后退再次打开待提交表单或重放创建。

## 3. 委托与配置：默认值、责任和部分成功

### 3.1 冻结默认解析规则

每类配置只能有一个服务端 resolver；A03/A04 定义模型和构建的已有继承规则，A05 消费。统一优先原则：**本次显式且受权的选择 → 当前项目明确默认 → 已有合法继承规则 → 缺失并引导配置**。已有 Agent 绑定不能被无关项目默认强行覆盖；S01 为每个字段列具体来源和冲突规则，而不是把这句话机械用于所有字段。

返回有效值、来源、版本、可用性与不可用原因；无权限的候选不泄漏凭据/内部网络细节。页面预检是提示，提交时仍校验授权与版本；预检通过后配置改变应返回冲突/重新确认，不默默换成另一个模型/仓库。

### 3.2 意图与责任最小规则

| 用户意图 | 本期语义 |
| --- | --- |
| 创建工作项 | 只记录工作；标题即可，创建者按现有规则成为初始 Owner，不触发模型 |
| 仅分配 | 明确保存指定责任，不启动执行；既有 Owner 不默认替换为 Agent |
| 分配并启动 | 显示即将改变的责任、Agent、目标仓库/分支、有效模型/构建；后端验证后形成一次可恢复命令 |
| 发布评论 | 只落讨论记录；不因自由文本 @ 或关键词隐式启动 |
| 让 Agent 处理 | 显式选择授权目标和来源引用；明确继续哪条对话或开启哪次执行；不自动同时复制一份普通评论 |
| 已运行时补充要求 | 本期不新增热注入执行引擎；存讨论或走既有要求修改/后续新一轮入口，当前执行继续使用已冻结快照 |
| 要求修改 | 复用既有人审状态/权限和修复流程，不把普通评论当作批准/否决 |

已存在相同执行者可沿用；不同执行者/冲突责任需明确确认且有修改权，不自动释放旧责任。不能为了减少按钮取消原有人审门槛。

评论与启动、授权与导入等跨步骤失败分别显示已成事实及待继续步骤；本期**不做通用 Saga/流程平台**。事务内本地副作用一起提交，外部步骤用现有耐久机制。创建成功后准备失败回到原工作，不能重建工作项。Agent 已启动后不为“补保存评论”再次启动。

### 3.3 配置/导入闭环

默认 GitHub 路径为明确命名的已有凭据连接；识别身份 → 明确仓库/用途 → 建立真实 ProviderBinding → 导入 → 关联项目。连接存在不代表绑定可用，仓库列表可读不代表可写 PR。权限不足给缺少的用途与有权处理入口，不默认请求全部权限。

导入的 READY/FAILED/CANCELLED 是不同终态；状态读取失败是“未知”而不是修改 job 为 FAILED。恢复按原 job 定点读取，关闭面板不取消，明确取消调用既有命令；取消与完成竞争以服务端事实为准。完成只提供回原任务/仓库入口，**不会自动启动遗留草稿任务**。

模型 activate 使用当前凭据的健康/版本；旧凭据曾通过验证不等于新凭据健康。撤销不能恢复；停用对新执行/在途执行的影响由 A03 核对当前策略并明示，不能默认杀掉全部在途任务。

## 4. 工作区与路由：只能有一份当前上下文

### 4.1 默认信息结构

工作区首屏：工作标题/编号及状态 → 本次产出或当前待办 → 一个当前主动作与责任 → 概览/讨论/执行/变更与测试/审查与交付。技术回执、Hash、快照明细下沉；没有产出时显示运行/等待事实，不编造摘要。

只聊天的对话仍可独立存在，不强制转工作项；私人对话全文不自动进入团队工作。工作区显示关联证据时持续授权，不以“关联过”当作现在可读。

| 定位情况 | 默认行为 |
| --- | --- |
| URL 明确指向工作/Task/Attempt/Review | 校验 Scope 和关联关系后定位该对象；历史明确标注；错误坐标不能回退到另一个对象后继续写 |
| 一个工作只有一项 Task | 用服务端当前执行语义定位；查看历史不改变当前执行事实 |
| 多项 Task 或并行执行 | 展示数量/各自状态，不用 updatedAt 猜主任务；没有明确选择时执行相关写动作先要求选目标 |
| 无执行 | 显示“尚未启动”与有权可做动作，不伪造进度/空日志失败 |
| 目标失效/无权限 | 清敏感内容并给安全说明/返回；不通过扫描所有分页碰运气找目标 |

A06 返回工作状态与执行状态两个维度；F03 不把运行终态、测试结果、人审结果、PR 状态合并成一个绿色“完成”。无效确认不能因刷新/切页恢复可提交。

### 4.2 导航与配置返回

- 普通一级入口以今日/工作/对话为主，待处理与搜索持续可达；管理分组收起不等于删除菜单。23 页/15+9 菜单以**能力与旧路由**逐项追踪，重排后不要求仍有相同数量的顶层按钮。
- 继续复用现有路由与对象坐标，优先适配重定向；改变路径必须同时提供旧链接用例。URL 保存可分享定位，store 保存当前数据，F05 保存个人偏好/草稿，不互相成为第二份权威状态。
- 首载优先显式 URL，再加载本账号/Scope 的合法偏好，最后产品默认。顶层切菜单只带 Scope 白名单；对象/筛选参数由目标页面白名单重建，不能 spread 全部旧 query。
- 配置返回只接受站内已登记路由及受权对象坐标；不执行任意 returnTo URL，不把凭据/邀请 token/草稿文本写进 URL。会话失效后重新登录也要重新校验。
- 列表→详情→返回恢复筛选/排序/滚动/选中；关闭详情与浏览器后退各有确定行为。切 Team 清原对象坐标与选择，先处理脏输入，不自动转移草稿归属。

### 4.3 全局壳、列表与设置的确定布局

本轮证据与逐菜单目标见 [全菜单布局 Review](../reviews/M9b-全菜单布局与交互细节Review.md) L01–L12；下列为默认实现合同，不让实施者在“全展示/全隐藏”之间自由选择。

1. 桌面全局工具栏将搜索与通知/账号等工具分组，主题/密度进入账号外观；手机顶栏为导航、可收缩范围、搜索、通知，账号放导航菜单；底栏为今日/工作/对话。触屏无需快捷键也能搜索。工作模式不再另占一层与菜单重复的切换条。隐藏管理组不删除旧路由。
2. 工具栏按可见控件实际占位排布，固定高度不可让隐式行越界；长名称截断可展开，所有折叠图标链接有独立可访问名称和可发现的文字说明。范围与账号弹层限于视口内。
3. 配置目录只保留一层二级导航；窄屏使用当前分类选择器，搜索输入/字段结果不进入菜单横滚线。分类匹配与字段匹配分别命名，任一命中不能同时被总“无结果”否定。账号页面用自己的分区，不套团队配置目录。权限与 Scope 按 §4.2，不以布局变化扩大权限。
4. 桌面列表—详情并排仅在**扣除导航后的内容宽度**足够时启用，否则独立详情视图；窄屏必用单层列表/详情切换。不通过 CSS order/grid-row 将 DOM 中列表后方的详情视觉移到前面。返回保留列表上下文，换对象前处理草稿。
5. 普通列表首屏先范围/已应用条件、主操作、对象；详细筛选在窄屏收起，按钮显示条件数量，排序用单个选择器。选中才出现批量栏，说明范围与结果；筛选折叠不能隐藏有效条件或改变 §5.2 的查询/选择语义。
6. 设置默认顺序：模型先连接再目录，Agent 先对象再常用配置，成员先邀请/成员目录再恢复历史身份，仓库先项目默认仓库/分支/构建再来源说明；Setup 先目标与下一步，再可展开的完成项/健康详情。对应 A 包交付事实与操作，F04 不复制另一份配置表单。

### 4.4 动作、反馈、阅读与避让

- 同一活动区域只突出一个当前主动作，按状态/权限确定；创建、委托、审查、配置下一步分别属于不同阶段，不把“刷新”常驻为所有页主动作。讨论与执行明确分开，危险动作独立分区，确认流程仍遵守 §2–§3。
- 表单正文正常滚动，保存/错误/未知反馈归属同一对象区域；长表单的操作栏不得盖住字段，切对象后旧结果不变成新对象的提示。字段错误靠字段，命令错误靠动作，全局通知仅补充。
- 对话区域按实际容器可用高度分配，输入/发送不与固定底栏、安全区和软键盘重叠；手机不显示不可用的参与者侧栏控制。工作区执行选择器与标题/成果/下一步同处上部，历史选择始终显式，不能藏在全部 Diff/审查之后。
- 原有 AA 色彩/字号 Token 不回退；主内容不用诊断级小字，紧凑密度仅调整间距。选中、hover、只读状态和可点击动作可区分；未检查/未知不显示成功色。联网不等于连接可用，静态能力介绍不显示事实性的“已生效”。
- 正常路径中文业务词优先，技术 ID/版本保留在诊断；HTTP 凭据提交不宣称 HTTPS，缺少真实入口的能力不在提示里承诺。错误页在应用壳内不重复 main/h1/整屏高度；认证保留标签、密码规则和安全返回，不新增本期外能力。
- C15 几何/可达性以布局 Review §4 为基准；全页截图、元素存在、viewport 缩短均不能分别冒充首屏不遮挡、可点击和真实软键盘证据。以上可先按 D07 冻结分批交付，不新增父包依赖环。

### 4.6 URL、视图、历史与焦点的转移表

显式合法 URL > 当前账号/Scope 的合法已保存偏好 > 页面默认。**窄屏默认列表只作用于未指定视图的初次进入**；不能覆盖明确看板选择。若该视图无法在窄屏提供完整操作，应明确提示暂用列表，保留原选择，扩大窗口后恢复，不能静默写坏个人偏好。无效对象坐标与无效显示参数分开：对象失效按 §4.1 拒绝误定位；未知视图/排序参数可提示后回默认，且清理无效参数。

| 转移 | 路由/状态动作 | 必须保留或清理 |
| --- | --- | --- |
| 从列表打开对象 | 用户主动打开用 push；记录同 Scope 的来源列表与定位 | 保留已应用条件、排序、视图、加载位置和锚点；对象坐标以 URL 为准 |
| 关闭详情/返回列表 | 有可验证的本次列表来源时回该来源；直接深链/新标签进入则 replace 到同 Scope 合法列表，不盲目 history.back | 重读授权数据后恢复列表锚点；目标已移除则就近并提示，不能恢复越权缓存 |
| 切详情页签/同区筛选排序 | 默认 replace，避免每个控件制造一条后退记录 | 筛选/排序变更重置 cursor 与选择；不清除无关草稿 |
| 浏览器前进/后退 | 按历史 URL 重建，不能被晚到偏好覆盖 | 对象/版本重新校验，焦点移到新详情标题或返回的列表项；已不存在则落列表标题 |
| 宽窄切换/导航折叠 | 只重排布局，不 push/replace 业务历史 | 不改 Scope/对象/所选执行/未提交输入/阅读锚点；列表详情单层与并排规则仍适用 |
| 补配置往返 | 保存白名单来源与草稿坐标，成功/取消均提供返回 | 回原工作/对话后重新预检，失败可留配置页修正；绝不自动发送原任务 |
| 切 Team/账号或授权失效 | Team 切换先处理当前输入并清不适用参数；安全清理按 §6 | 撤权/登出不能被“有未保存输入”阻止；原恢复坐标不接到新身份 |

D07 必须登记每条路由允许的 Scope/对象/页签/视图/筛选/返回参数及规范化规则；这里只定语义，不发明新 query 名称。只允许目标页面声明的参数，不能把工作项/Review ID 顺带传进账号或模型页面。链接仍支持新标签打开；滚动恢复只在相同授权查询条件下使用，不能用当前全局 `scrollBehavior` 固定回顶冒充完成。焦点与滚动分别断言。

### 4.7 当前主动作的决策顺序与读模型交接

先检查身份/目标/版本，再检查命令状态，最后检查业务阶段；按下表从上到下匹配。表中动作是用户语义，不是要求另建通用工作流引擎或新 API 枚举。

| 优先条件 | 当前区域主呈现/动作 | 必须避免 |
| --- | --- | --- |
| 无权限、目标已失效或关联不合法 | 安全说明与返回受权列表/切范围 | 展示旧敏感内容，回退别的对象继续写 |
| 历史执行/快照视图 | 显式历史标记；有合法当前目标才提供“查看当前” | 将历史批准/PR 确认自动改绑当前；历史允许的评论等仍按原对象授权 |
| 命令提交中/结果未知/已提交待同步 | 显示所处阶段；未知时“确认结果”，待同步时定点重读 | 突出“再建一个/重新启动”；关闭页面被误解为撤销 |
| 版本冲突/原确认过期 | “查看最新并重新确认”，保留安全的本地输入 | 沿用旧批准/凭据验证证明，自动覆盖最新值 |
| 多 Task 未明确选目标 | “选择执行”，显示各项真实状态 | 按更新时间自动选一项后启动/审查 |
| 当前阶段必要配置/责任缺失 | 说明缺什么；有权则去补齐，无权则给明确联系/返回路径 | 无关缺项阻挡普通评论/只对话；把全部配置向导强制走一遍 |
| 正在执行 | 当前进度/等待事实及查看执行；已有受权停止/取消作为清晰可达次动作 | 把不能点击的“运行中”伪装主按钮，重复启动，隐藏必要停止入口 |
| 等待审查/要求修改/外部交付确认 | 突出服务端指定阶段的处理入口及固定证据；具体影响在确认处呈现 | 把“查看成果”当已经批准，把单一主动作理解为删掉拒绝/要求修改 |
| 尚未启动或终态 | 未启动且可执行才突出“交给 Agent”；终态先成果与验证，有合法后续动作才展示 | 失败即自动重跑、结束即宣称成功、凭空新增重开流程 |

A06 的摘要至少表达：受权对象/关联坐标、工作状态、当前/并行执行语义、等待原因及可显示责任、建议下一步目标、事实版本/观测时间；A05/各领域补动作可用性和不可用原因，A03/A04 补配置事实。F03/F04 负责展示，不从几段文案反推权限。正式字段/组合查询方案由相关 D 项冻结，不强制新增万能摘要接口；提交端始终重新校验，不因摘要中按钮可用而跳过授权。相互矛盾或过期的事实显示待更新，不合成绿色完成。

## 5. 收纳、筛选与导出：本期默认值在这里定清

### 5.1 Inbox 的可逆状态表（F04）

现有 [InboxDisposition](../../crewscope-domain/src/main/java/io/crewscope/domain/inbox/InboxDisposition.java) 以 ordinal 单调前进，且不接受持久 UNREAD。新增按钮之前必须一起调整领域、存储约束/重放、读侧计数和 API，而不是前端删行模拟恢复。

本期沿用 UNREAD/READ/ACTED/ARCHIVED 四个值，不另造订阅/提醒平台。采用以下最小用户合同；历史记录不能恢复出未记录的“归档前是否已读”。

| 动作 | 原状态 | 目标与结果 |
| --- | --- | --- |
| 标已读 | UNREAD | READ；其他非归档状态重复动作不倒退 ACTED |
| 标已处理 | UNREAD/READ | ACTED；仅个人收纳，不完成源任务/审批 |
| 归档 | UNREAD/READ/ACTED | ARCHIVED；保留版本与历史 |
| 恢复归档 | ARCHIVED | **READ**；按钮/反馈说明恢复到已读，不声称精确恢复历史状态 |
| 重新标未读 | READ/ACTED | UNREAD；产生持久版本，不删除 authority 行 |
| 在归档内标未读 | ARCHIVED | 默认先恢复再标未读；不能让“标未读”偷偷执行恢复 |
| 重放相同命令/目标状态 | 任意 | 原回执/幂等结果；不重复计数、不重复外部通知 |

无记录仍代表初始 UNREAD/v0；重新标未读是显式 UNREAD/正版本，两种情况均计未读。归档态的直接标已读/已处理不隐式恢复，应拒绝并提示先恢复；重复归档/已处理不重复产生副作用。归档视图打开详情不隐式恢复。旧客户端的已读/处理动作遇到新版逆向状态遵守强版本，不能因为旧 ordinal 更大就覆盖新状态。

若实现验证发现此兼容策略不可行，在 F04 收纳切片开工前提交替代状态表和迁移测试并更新本节；不能同时保留两个不同的恢复定义。源业务已关闭/无权限、历史投影重建、重复事件与两窗口竞争必须覆盖。

### 5.2 查询、选择与审计

- 筛选与排序在服务端授权集合上先应用，再分页；排序具稳定末级 ID，cursor 绑定 Scope/条件。首批候选无目标不能等同全目录无目标。
- 全选默认仅当前已加载可见集合，不宣称选中全部匹配。分页追加可保留选择；切筛选/Scope 清选择并说明，提交时冻结所选 ID 与版本；批次结果不随当前列表切换被改写。沿用既有批次数量上限，不无界提交。
- 审计本期采用 **“导出已应用条件”**：显示已应用范围摘要；表单有未应用修改时禁导出并提供“应用筛选”，不能用新表单验证旧请求。导出点击时冻结已应用条件/Scope/时区转换/上限；成功显示实际条数与可能截断，不声称浏览器已落盘。
- 无用途的审计复选框移除；不新增选中项导出。定点详情查询必须单独授权，不依赖列表页缓存。
- 清筛选回当前 Scope 的默认条件，不清除账号/团队，不保留隐藏筛选。导出/筛选失败保留表单和已读结果。

### 5.3 筛选生效时机与旧结果的显示

- Work/Today/Inbox/动态等普通列表：离散筛选和排序选择后立即应用；文本搜索以明确提交为准，中文输入法组合期间 Enter 不提交。不在同一页面混用“选了已生效”和“选了等应用”却不给提示。
- 搜索页与快捷搜索各自维护输入、已提交条件、结果、请求代次；关闭快捷搜索不清搜索页。快捷候选可防抖读取，但点击“搜索全部”才把当前文本提交到完整搜索页，不能把半输入自动改写完整页历史。
- 审计保留显式“应用筛选”，日期/用户等先编辑，应用后才是查询和导出范围；这条优先于普通列表的即时规则。当前对象目录内的筛选不影响团队搜索。
- 请求开始后可以保留旧结果，但须标明“正在更新/仍显示上次结果”，新条件不能配旧计数并声称是新结果。失败提供重试**本次已提交条件**和清晰原因；失败不是空集合，继续加载不得混入旧 cursor。
- 默认排序沿用各页合法业务语义，A06/D05 在开工前逐页冻结默认字段、方向、末级键、空值与时区；本契约不凭空把所有页改为更新时间倒序。共享控件不得改变服务端全量排序与计数口径。

## 6. 本地状态与安全内容：选择存什么比换 key 更重要

F05 建一套有 schemaVersion、账号、organization/team/project（按适用范围）、对象及版本的命名空间；不把业务文本写进设备偏好。服务端事实仍来自 API。

| 类型 | 默认保存/恢复规则 |
| --- | --- |
| 主题/密度 | 设备偏好，无业务内容；损坏回默认 |
| 非敏感对话/评论/审查/委托草稿 | 本浏览器按对象存，提交路径仅确认成功才清；显式丢弃、过期与安全清理另按本节执行；默认 7 天、最多 20 份、合计 2 MiB；超过配额不静默驱逐未提交输入，提示本次仅内存保留并提供清理 |
| 非敏感配置草稿 | 按对象保存必要字段；秘密字段剔除；是否持久化需字段白名单，不序列化整个表单对象 |
| 固定对象/命名视图 | 默认各最多 50 项；只存坐标/视图名/允许筛选/排序，不持久化对象标题和服务端内容；固定对象名称经当前授权查询后再显示 |
| 最近访问/已查看/阅读位置 | 按账号/Scope/执行版本隔离，设置容量和过期；“看过”不写成批准 |
| 凭据/令牌/密钥、秘密请求体 | 仅当前交互内存，关闭/登出按规则清除；禁止放 local/session storage、URL、日志或测试附件 |

这些是本期默认上限，不是部署必须配置项；S01 可在样本验证后记录理由调整数值，不能取消容量/失效/身份边界。存储被禁用/写满时仍可操作，必须明确不保证刷新恢复。

登出/切账号在显示新页面前清旧业务内存及持久缓存；撤权事件或授权失败先隐藏后清理。离线浏览器不能即时知道服务端撤权：重连/恢复身份必须重新校验后才展示旧内容，不能承诺跨离线设备瞬时擦除。共享浏览器隔离不等于对本机管理员加密保密。

渲染统一复用 SafeMarkdown，表格语义/代码复制扩展不能放宽危险 HTML/协议边界。外链只是链接，不等于 Agent 已抓取；图像/任意附件不因 Markdown 支持而自动放行。

### 6.1 关闭、取消、丢弃与提交的区别

| 用户动作/事件 | 确定行为 |
| --- | --- |
| 关闭弹窗、Escape、返回或切普通菜单 | 仅含非敏感输入时尝试保存本地草稿；保存成功才显示“草稿已保存在此浏览器”。不发业务命令、不默认丢弃，不要求每次重复确认；含秘密或保存失败适用下一行 |
| 无法持久化或含尚未提交秘密而主动离开 | 普通站内离开给“继续编辑 / 丢弃并离开”，不得提示假保存；浏览器关闭/崩溃不保证能拦截，不能承诺秘密刷新恢复 |
| 明确“丢弃草稿” | 非空内容二次确认，清当前对象的输入及该草稿，不清其他对象；它不撤销已发送命令，也不删除未知命令恢复坐标 |
| 打开已有草稿/远端数据晚到 | 先验证身份、目标和版本；初次恢复可用草稿，用户已经输入后不自动覆盖，提供显式恢复/对照选择；过期草稿不静默复活 |
| 提交成功 | 只清已被确认提交的草稿修订；提交等待期间继续输入的较新内容不误删。需要锁字段的表单在提交中明确只读 |
| 校验失败/网络失败/冲突/结果未知 | 保留符合存储规则的输入；未知命令与草稿分别管理，恢复结果前不把草稿当新请求发送 |
| 登出/切账号/撤权 | 安全清理优先，不弹“保存后再退出”阻止撤权；不为了草稿可恢复而保留上一身份内容，规则适用于其他标签页 |

“取消”文案必须说明对象：表单底部通常是“关闭”或“取消编辑”，导入/执行的“取消任务”才是业务命令。取消编辑默认按上表保护非敏感草稿；秘密字段关闭即清。新建但尚无对象 ID 的草稿按账号/Scope/创建意图隔离，不借用上一条记录 ID；准确命名空间和字段白名单由 D06 冻结。切 Team 可以保留原 Scope 的合规草稿，但不得在新 Team 展示；切账号按安全清理规则处理，两者不能混同。

## 7. 权限与升级：不把“简单”实现成全员管理员

- S01 基于 [auth.ts](../../crewscope-web/src/app/auth.ts) 与实际后端 AccessPolicy 列出“操作者 × Scope × 动作 × 对象状态”的矩阵，不能只写 Owner/Admin/Member 名称后由前端猜权限。
- 必测操作者：未登录、当前有效成员、只有读取权的身份、具备对应管理权的身份、另一 Team 成员、已停用/移除成员、仅个人连接所有者。按用例提供最小权限，不用全能账号覆盖普通流程。
- 本人通知/收纳/本地偏好不授予 providerManage；看得见 Agent 不等于能运行；能运行不等于能编辑 Agent/凭据；能审查不等于能推送所有仓库。
- A07 撤权必须先禁止新请求/后续执行授权，再处理责任交接；不等待批量交接完成才撤权。最后 Owner 并发保护、他 Team 会话不被误伤、恢复不复活旧确认分别测试。
- 迁移按实际序号追加，覆盖空库与有旧数据两条路径；编号、回执结果、Inbox、Provider/Catalog、构建默认值分别列旧→新行为。旧默认配置缺失不阻止 API-only 启动。
- 新前端上线前后端必须具备必需 API；缺能力时明确不支持，不能偷偷落回旧不安全写法。旧前端/新后端至少保留原受支持操作，生成 OpenAPI/客户端同步验证。
- 版本回退不承诺数据库可无损 down migration：新增可逆收纳数据可能被旧程序拒读，发布前明确是否仅支持前滚修复及备份恢复边界。禁止直接启动旧二进制并声称兼容，恢复演练只针对授权测试数据。

### 8.1 测试层级与执行范围
