## 1. 目标

**把「地基建成」变成「全部接线」**：Review 的核心结论是分层/token/类型已达 A 档，债务集中在一件事——**复制代替抽象**（模态外壳手写 25 份、下拉 6 套、查询工具 ≥7 份、双胞胎组件 6 组），加上交互反馈的结构性缺口（54 个文件可点无 hover、全站按压反馈 5 处）。本期不做新功能、不做视觉重设计，做三件事：

1. **同一交互只有一种行为**：模态、下拉、抽屉、键盘导航收敛到 base 层唯一实现。
2. **可点必有回应**：hover/按压/焦点反馈覆盖全部可交互元素，界面从「静态品质」获得「动态确认感」（灵动路线图第一、二档）。
3. **重复归零**：P1–P4 合计净删约 4000–5000 行（Review §8 总量估计），死代码与死样式清除。

## 3. 范围与非目标

### 3.1 本期必做

Review §8 路线图 P0–P5 全部条目 + §10.4 灵动路线图第一/二档 + §11.6 遗留观察中与体验相关的两条（主操作层级、brand-950/900 收编评估结论入 ADR 备忘即可）。F02 迁移与 P1 合并执行（动效随组件自动获得，§10.4 第二档）。

### 3.2 非目标

- 不新增产品功能、不改 API 契约、不动数据库——发现需要后端配合的项登记为切片卡偏差，不扩大范围。

- 不做 M12 扩展（托管/K8s/身份协议/观测）与 M11 可选项——独立立项。
- 不追求 §10.4 第三档「标志性瞬间」（依赖图拖拽弹性、消息入场动效）——登记为下一里程碑候选，避免本期战线过长。

## 6. 回归与基线纪律

1. 每批：`pnpm lint && pnpm test && pnpm check:q01 && pnpm build && pnpm test:e2e`；触碰视觉面的批次追加四 CI 独有门禁（design-tokens/enum-labels/sensitive/bundle）。
2. 视觉基线：仅 F01（层级修正）与 F02（模态动效落场帧）预期产生快照变更——逐批 `test:e2e:update` 并在完成记录列出重生成清单；其余批次快照必须零漂移（漂移即缺陷回查，不顺手 update——§5.4 教训）。
3. e2e fixture 连锁：F02 迁移若触碰 session 契约字段，按 M12-F03 教训同步全部 fixture（16 处先例）。
4. 不与任何 gate 栈/Docker 构建并发（Maven/Docker 纪律照旧；本计划预期零后端触达，全 reactor 不重跑，Q01 以 web 全家桶 + CI backend job 背书）。

## 7. 风险与缓解

| 风险 | 缓解 |
|---|---|
| F02 迁移半径大（24 文件×4 种行为变体） | 以 WorkProjectCreateDialog 为模板先迁 2 个文件打样验收，再批量；每切片全量 e2e |
| 迁移中丢失个别模态的特殊行为（如 MemberLifecycle 的 Esc 语义） | 迁移前逐模态登记行为清单（Esc/backdrop/焦点返回/滚动锁），迁移后逐条对照 |
| hover 全面铺开引入视觉噪音 | 只用既有 token（`--cs-surface-accent`/hairline→float 阴影档），不加新色新阴影值；design-tokens 门禁护栏 |
| 视觉基线与动效盲区误判 | §6-2 纪律：非预期漂移一律回查；动效验收靠 Q01 的 DOM 级断言，不靠截图 |
