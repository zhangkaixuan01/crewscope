## 1. 目标

把 Review 记分卡唯一的 C+（复用与重复控制）收敛到 A- 档：Review 的核心结论是后端底座（分层/事务/安全/观测）在 M10–M12 堆叠后保持 A 级，唯一显著退化是 M10 distiller 垂直链开了「复制代替抽象」的先例且未被纠正——同一形状的修复成本已缴三次（M10-Q02 缺陷 1/3 双份修复、债务周 B 第三次）。本期做三件事：

1. **先立闸门再动结构**：分层依赖门禁自动化（洋葱单向从「人工纪律」变「CI 拦截」），保证收敛期间与之后依赖纪律不破。
2. **最大单笔清偿**：distiller 垂直链四层收敛（~3,300 行中 ~70% 双份，预计净删 ≥2,000 行），恢复/消毒/usage 三件套抽 `StructuredDeliveryCall` 组件。
3. **小族顺手清零**：CursorCodec 基类、ModelSubject 合一；command 样板先评估后裁定（慎动面不盲动）。

## 5. 验收契约（逐包）

- **断言语义冻结**：所有既有测试断言不得为迁就重构而改语义——允许改 import/构造路径，不允许改断言值与断言意图（契约优先纪律，Review §6.2 形态保持）。C01 的 25 个债务周 B 用例是全里程碑的试金石。
- **行为等价证据链**：每包交付时列「定向测试 N/N + 模块 verify + 全 reactor（收批跑）」三层；C03 各切片另附 Knowledge/Skill 双侧断言对齐清单。
- **净删盘点**：C02/C03/C04/C05 累计净删行数按 PR diff 如实入档，达不成 §2 出口指标时在 Q01 如实说明原因，不以重排代码凑数。
- **openapi 指纹纪律**：凡触碰 `crewscope-server` api/ 包源码的批次（C04/C05 预期不触发、意外触发时），提交前重跑指纹检查并按需再生前端 `openapi.ts` 同笔提交。

## 6. 回归与基线纪律

1. 每批：定向测试 → 模块 `./mvnw -pl X -am verify`（连带模块用 `-Dsurefire.failIfNoSpecifiedTests=false`）→ 收批全 reactor 转后台（50 分钟量级，不与 Docker 内 Maven 并发）。
2. Q01 终验收：全 reactor + `crewscope-web` 全家桶（e2e 不与 4173 并发）+ m10-q02 gate 复跑。
3. 提交规则沿用：main 直推、英文正文+分节 bullet+`Test evidence:` 行、无 attribution trailer、提交前密钥扫描与 `git diff --check`。
4. Java 新文件自查：无占位方法、无未用 import、无死分支。

## 7. 风险与缓解

| 风险 | 缓解 |
| --- | --- |
| C03 是最大风险面（application 11 对含两个 500+ 行 Service） | 切片交付：值对象/Port 对先行建立参数化模式，Service 两对最后；任一切片受阻即独立回滚不影响已交付批 |
