## 1. 目标

两轮 Review 结论一致：底座已达发行水准（设计 token、状态机、焦点与动效基线、键盘基础件都在），问题集中在**跨页接线、页面空间配比、交互契约一致性与可访问语义**。M13b 是最后的体验收口，目标不是「修完清单」，而是：

> **任何用户在任何入口都不被卡住、不困惑、不丢上下文。**

三个具体层次：

1. **走完**：第一轮的四条断头路（纯 org 角色、TaskIntent 确认后、蒸馏 UUID、知识六开关）全部闭合；SSO/邀请与密码登录同权。
2. **舒展**：第二轮的空间配比欠账清偿——扫描页首条数据 ≤200px、对话消息区拿回主体、设置区单导航、内容宽度统一策略。
3. **稳当**：批量与单条同规、错误必有出路、选中态有语义、触控达标、术语统一——状态契约与可访问契约成为全站规则而非页面各自发明。

## 4. 勘察钉死的事实（设计据此，不重新验证）

**治理面**
- 无任何组织成员目录端点；唯一目录 `PrincipalDirectoryController` 路径含 `{teamId}`，SQL 按 team 过滤（纯 org 用户不在候选集）。
- `organization_role_grant` 后端已校验 principal 存在；账号删除后端 `resolveTarget` 已知 username/displayName，但 precheck 不回显 → 补目录后 UI 可换选人。
- 会话存 Redis（Spring Session），非 DB；登录两条链路均持有 `ServerWebExchange`，全库零 User-Agent 读取 → session attribute 即可，免迁移。
- 前端 `can()` 是纯字符串集合判断，天然支持 `org:*`；`navigationGroups` 加组织组只是加数据；登录落点无按权限裁决模式（需新逻辑）。
- org 权限仅三枚：`org:audit-read`（所有 ORG_*）、`org:govern`/`org:manage-settings`（非 AUDITOR）。

**知识面**
- 六开关全 env 级默认 false；`KnowledgeIndexStatusCatalog` 是 `ObjectProvider`，vector 关闭时不存在 → indexStatus 回退 PENDING。
- 索引页 15s 刷新已是 `useAutoRefresh` composable（含可见性暂停），可直接复用。
- 单条目重试原语 `KnowledgeIndexJobService.enqueueEntryRefresh` 已存在；作业按 entryId 过滤动四层（Controller/Filter/Service/JDBC 谓词）。
- 知识回滚需后端新命令（照 Skill 三层抄）；前端 `BaseVersionHistory` 已支持 `canRollback` props。
- 预算 Inbox 投影后端已有，但前端 `inboxSourceTypes` 缺 `'BUDGET'`，严格 oneOf 下预算项前端解析失败。
- 蒸馏 origin 在管理员审计折叠里有，真缺口是版本行与默认可见性。

**协作 / SSO**
- `resource_changed` 帧只带 scope + version；看板只订 presence；详情抽屉已有消费先例。
- `conversation_participant` 无读状态；`conversation.lastMessageSequence` 已有。未读需 V71 迁移（最新 V70）。
- Inbox `/counts` 端点已存在，铃铛加徽标纯前端。
- SSO 成功 handler 固定 302 `/`；前端 sessionStorage + principal 绑定是零后端方案。
- 邀请 proof 内存态；`acceptanceRecovery.ts` 的 sessionStorage+TTL+principal 绑定是现成母本。

**布局 / 交互 / 可访问性（第二轮）**
- 桌面 1440×900 内容区实为 1156×720（58 topbar + 82 context header + 40 padding）；多页 hero 使真实内容从 178–206px 才开始。
- Inbox 列表前 276px chrome；Knowledge/Skills 固定 5fr/4fr，未选中留 44% 空列；Operations 套 SettingsShell 损失 210px；Work 工具栏 150px；Observability 10 列且费用在第 8 列。
- 对话页默认左 24%/右 22% + 消息列 740px 上限 + 气泡 `min(82%,620px)` + 结构块默认展开（R51）。
- 批量按钮直接 `runTarget`，无二次确认与批次撤销（单条路径规则完整，批量是唯一绕过面）。
- 命令面板 `role="listbox"` 内是普通 button，`recentItems` 不在键盘顺序；成员页「添加已有用户」实际只能选停用成员重新加入。
- 全站 `scrollBehavior: { top: 0 }` 同时破坏列表返回位置与设置页锚点；复制反馈三种形态、失败多数静默；局部错误重试契约不统一。

## 6. 关键契约（实施前冻结）

1. **未读语义**：`unreadCount = max(0, lastMessageSequence − lastReadSequence)`；回执只增不减；AGENT 不计；列表返回查看者视角。
2. **组织成员目录**：只返回本组织 ACTIVE binding 的 USER；`org:audit-read` 可读；排序 displayName；`{items,nextOffset,nextCursor}`；不回显 email。
3. **设备摘要**：服务端解析 UA 为「浏览器 · OS」短串，原文不存；缺失显示「未知设备」。
4. **SSO returnTo**：白名单路由（扩展 `restorableRouteNames`）；sessionStorage 带版本、TTL 10 分钟、principal 绑定；不走 query（防开放重定向）。
5. **知识开关端点**：只读布尔，不暴露 env 名；关闭态文案单一来源。
6. **回滚**：以历史版本为源发布新 revision，不删中间版本；ETag + Idempotency-Key。
7. **扫描页布局**：任何列表页首条数据距 context header ≤200px（1440×900）；页面 hero 不得在列表页出现；工具栏 ≤56px。
8. **危险操作契约**：单条与批量同规——不可逆动作必须二次确认；可逆动作必须有可见撤销入口（10 秒，键盘可达）；批量必须明示影响范围（N 项）。
9. **状态契约**：error/offline 面板必须带重试或显式「不可恢复」原因；刷新有旧数据时保留内容（stale-while-refresh）；切换数据源不整块清空。
10. **可访问契约**：选中/当前状态必须有语义（aria-pressed/aria-current/aria-checked），不得只靠 class；禁用原因必须可见或可聚焦获取；表单错误必须 `aria-describedby` 关联；移动端交互目标 ≥44px（含图标按钮与 select）。
11. **术语契约**：中文为主；面向用户的枚举一律经 `labels` 映射，原始枚举只在「技术详情」折叠出现；同一概念只保留一个叫法（建立 `docs/product/术语表.md` 或等价物）。
