## 1. 目标与当前事实

默认形态是单 Organization 自托管、四服务 Compose。数据库已存在 Organization、大量 organization_id 与应用层 Scope/权限边界；M12 不是从零增加租户列，也不能把已有授权称为不存在。

现状基线（2026-10-12 全量代码勘察，S01 盘点以此复核为起点；S01 复核后的修正以 [盘点矩阵](../spikes/M12-S01-组织归属盘点矩阵.md) 与 ADR-036 §1 为准）：159 张表中 130 张为组织作用域（129 张带 `organization_id` + `organization` 根表，全部建表自带、零后补零漂移；迁移至 V67）；`organization` 表自 V1 存在（id/name/status 等六列）但**无领域聚合、无管理 API**——全部 Controller 只有嵌套子资源路径，开放注册被 `crewscope.registration.organization-id` 静态配置钉死在单组织，组织创建唯一入口是启动期 seeder 裸 SQL；账号-组织绑定底座 `account_organization_binding` 已在（V31，account×org×principal 唯一）。会话为 Spring Session Redis Indexed（`BrowserSessionPrincipal`、12h TTL；按 principal 枚举 `findByPrincipalName` 已有集成测试实证）；**OIDC 登录骨架已在仓库**（`SecurityMode` 三态 bootstrap/local/oidc、OIDC 分支 `oauth2Login`、`AuthenticationSubjectExtractor` 双分支转换、V31 `login_identity` (provider,subject) 底座、oauth2-client 依赖已在 classpath；I01 是补齐首登开通/策略/救援/枚举而非从零接入）——integration 模块仅 `provider.{lark,github,workitem}` 的勘察事实不变，OIDC 适配不落 integration；仓库**无硬配额**（仅 M10 软预算提醒 `TeamBudgetAlertService` 与两个局部硬限制先例：`ClaimQuotaRepository`、`workspace_write_budget_usage`）、**无账号删除与全量数据导出**（仅审计 bounded export）；角色体系仅 PlatformRole（USER/OPERATOR）与 TeamRoleKey 两层。前端无组织设置页与组织域 store（identity store 组织名硬编码占位字符串）。

主线增强企业单机使用：Organization 设置、OIDC、配额/用量、数据治理与基础 SLI。多 Organization 托管、K8s、SAML/SCIM/MFA、外部观测平台分别选入；未验收不能声明支持，主线不等待未选入的扩展。

默认仍为 PostgreSQL、Redis、API（含 Worker）、Web；源码构建、HTTP 与 `quickstart.sh up` 不变。企业能力未启用时不要求 IdP、集群、外部 Secret、TLS 或监控栈。公网和企业集成的安全配置按实际风险说明，不变成所有用户的安装前置。

非目标：计费/支付、跨 Organization 知识共享、跨区域复制、自动扩缩容成本优化、SOC2/ISO 认证流程本身。

## 4. 核心合同

### 4.1 隔离目标先于技术选型

应用层 `ExecutionScope ∩ Ownership` 与资源授权始终是安全边界，不是性能优化。托管还必须有独立数据层隔离。S01 比较共享 Schema + RLS、独立 Schema、独立数据库，ADR-035 接受后才能实施；候选方案不能在正文被写成已定事实。

若选择 RLS，至少证明：

- 应用数据库角色不是 superuser、BYPASSRLS 或可绕过策略的表所有者；运行角色与迁移角色分开，必要时 FORCE ROW LEVEL SECURITY。当前简单 Compose 的初始化/应用账号不能直接当作有效 RLS 运行角色。
- 租户上下文来自受信身份与授权，在同一事务/连接内设置；缺失上下文失败关闭。验证连接池复用、异常回滚、异步作业、Worker 和平台运维任务，不能依赖残留的会话变量或未验证请求头。
- 盘点租户表与全局目录，定义复合外键、读写策略和特权入口；不笼统要求所有表新增组织列。向量/搜索/对象存储、Redis 与任务运行环境也必须纳入隔离，而非只测 SQL。
- 用真实运行角色分别测试应用授权独立生效、数据层隔离独立生效及两者同时启用；不能用 superuser 测试得出 RLS 已有效的结论。

如果选用其他方案，必须给出等价隔离证据。性能不足不能成为无评审地取消数据层防线的理由。单机模式保持现有边界；必要的数据库角色调整由升级工具处理，不能要求用户先手工配置 RLS。

### 4.2 在已有数据上迁移，不重建组织归属

先列出现有表、organization_id、全局表、Scope 与外键，再确定真正缺失的字段。已有组织不能全部回填为默认组织；归属不确定的数据须显式处理，不猜测。

按扩展结构、分批回填、约束验证、隔离切换拆阶段；大表回填是可续作业，不藏进单个 Flyway 长事务。文件数量由风险决定，不固定“四步四文件”。后续编号取合并时实际最大值 +1；M10/M11 的未来编号不当作已发布事实。

回退计划区分兼容旧代码、数据修复和完整备份恢复，不承诺任意迁移都有可逆 down SQL。托管扩展需覆盖旧单机升级、失败中断、恢复以及既有组织归属保持。

### 4.3 企业身份不建立第二套 Session

主线先交付 OIDC，身份策略为仅本地、仅 SSO 或共存；SAML/SCIM/MFA 独立选入。账号绑定采用受信 issuer + subject，不仅凭邮箱自动合并；角色映射遵循最小授权，不隐式提升到 Team 写权限。

SSO-only 下 IdP 故障不能静默退回本地密码。冻结恢复管理员、人工救援和锁定保护流程；本地账号路径在仅本地/共存策略下继续可用。验证签名、issuer/audience、state/nonce/PKCE、重放、回跳与会话撤销。

IdP 禁用、SCIM 删除的失效来源、轮询/事件机制和延迟上限必须可测，不能无依据承诺即时失效。账号级禁用撤销全部会话；单 Team 撤权沿用 M11 的范围规则。MFA 丢失设备与恢复码策略在选入时单独验收。

### 4.4 原子准入与异步计量分开

配额配置及准入预占是权威控制事实；用量报表才是派生统计。

1. 受理命令时原子检查并预占，与任务创建同一事务或采用经过证明的等价协议；幂等重试不重复占用，避免多个请求同时读到剩余额度后全部通过。
2. 成功、失败、取消后结算/释放；Lease 过期、消息重投和崩溃有对账。异步事件报表不能作为唯一硬限制。
3. Token/存储最终用量未知时，预占有界预算或明确超额政策。没有上界只能称软预算，不承诺绝对硬上限。缺少价格时标未知，估算不是账单。
4. 下调限额不强杀合法受理的执行，新请求遵守新限额，在途遵守已接受预算。月份/时区、预占结转、缓存 Token 和重试计量须有明确定义。
5. 统计与告警走 Outbox/既有 Inbox、飞书；不暗含新邮件 Provider。准入故障时新受限请求失败关闭，统计故障不误伤已有执行。

### 4.5 K8s 重新验证执行边界

当前 Compose 是 API 合并 Worker、API 直连 Docker Socket，不是旧 Socket Proxy 拓扑。该单机高权限信任假设不能直接用作托管安全结论。

选做 I02 时，在独立可选模块中引入 K8s Client，默认构建不包含。ADR-039 定义 Worker/Job/Pod 生命周期、控制面权限、租户代码与凭证、网络出站、持久卷及节点恢复。Pod 消失后仍须通过 Lease/Fencing/Checkpoint 防止重复副作用；不能仅用“不低于当前 Compose”代替明确的托管隔离目标。

### 4.6 默认可用的基础 SLI

先冻结首 Token 延迟、排队时长、执行成功率、API P95、通知送达率和检索延迟的样本口径、排除项、时间窗、目标与错误预算。默认从既有指标/事件事实获取，不要求 Grafana 或新增观测服务。

按 Organization 下钻使用授权查询，不把租户 ID 放入无限基数的公共指标标签。容量报告写明硬件、模型、数据量、并发、瓶颈及阈值；50/200/500 并发可作为目标形态样本，不能成为每台普通单机的强制规格。

## 8. M12 Release Gate

主线（单机四服务，全部必验）：

1. 存量归属不漂移：升级/恢复前后现有 Organization、Team、资源归属与授权一致，已有授权不被静默变更或重置（D01 基础范围盘点为证据源）；
2. 四服务安装、存量升级与完整恢复通过；企业能力未启用时不要求 IdP、集群、外部 Secret、TLS 或监控栈，`quickstart.sh` 默认路径不变；
3. 本地/OIDC 账号策略（仅本地、仅 SSO、共存）与受信绑定可用；签名、issuer/audience、state/nonce/PKCE、重放、回跳与会话撤销验证通过；SSO-only 下 IdP 故障不静默退回本地密码，救援走冻结流程；
4. 配额原子准入与异步计量分开：并发受理不超占、幂等重试不重复占用、成功/失败/取消结算与释放、崩溃对账、月份切换与下调限额不杀在途；未配置配额不改变默认使用路径；
5. 数据治理闭环：授权导出/保留/删除覆盖主库、派生索引、向量、文件、凭证与备份保留（含 M11 WorkGraph 关系表），不宣称删行即全副本清除；高风险操作有确认、幂等与 Audit；
6. 基础 SLI 默认四服务可取：首 Token 延迟、排队时长、执行成功率、API P95、通知送达率、检索延迟有冻结的口径/窗口/目标与错误预算；组织下钻走授权查询，公共指标低基数；
7. Org 角色与 Team 角色正交：Org Admin 不自动获得 Team 写权限；账号级禁用撤销全部会话与实时通道连接（衔接 ADR-038 §3.1 事件链），单 Team 撤权沿用 M11 范围规则；
8. F01/F02/F03 前端：组织设置、配额用量、身份源与活跃会话页面覆盖六态、键盘、390px 与 Axe；失败与救援可操作；前端不保存 IdP 密钥；
9. M0–M11 全量门禁零回归（含实时协作、WorkGraph、成员撤权链与既有攻击/故障集）。

扩展（仅选入后必验，未选入不以未运行充作通过）：

10. 托管隔离：至少两个真实 Organization 验证数据、执行、缓存、向量索引、凭证、用量、审计与备份隔离；数据层与应用层防线独立测试（RLS 按 §4.1 证明清单，superuser 测试不作数）；组织切换清理 Store/缓存且不串数据；
11. K8s（I02）：真实集群验证 Helm、节点/Pod/控制面/存储故障恢复，无重复副作用（Lease/Fencing/Checkpoint 仍为权威）；不以本机 Docker 代替；默认构建无 K8s Client；
12. SAML/SCIM/MFA：各自完成协议攻击集、生命周期与恢复（MFA 丢失设备与恢复码）；失效来源、机制与延迟上限可测；
13. 外部观测：采集/仪表盘/告警链路单独验证，不进入默认服务列表。

证据文件为 `docs/testing/M12-Q02-Release-Gate.md`，按上列编号逐条给证据，包含 Revision、选入配置、迁移/角色、环境、命令、结果及脱敏 Artifact；结果枚举沿用 M11（待执行/通过/失败/需授权或环境/不适用并说明理由）。未做托管或集群验收时只能称单机主线通过，不能称双形态全部完成。

### 10.2 落点与不可越界项

- Organization 角色与 Team 角色正交，Org Admin 不能自动获得所有 Team 写权限；ORG_* 角色词汇层新建，不并入 PlatformRole/TeamRoleKey。
- 组织用例落 `application/organization`（现状不存在，属新建）；`domain/organization` 聚合由 D01 按盘点结论实体化，不为规划目录提前复制实体。
- 配额用例与预占落 `application/quota`（新建），基础 SLI 扩展既有 `application/observability` 与 `server/observability`；强制准入与只读观测不混用。
- 企业身份适配复用既有 Session（`server/security`）、`application/identity`（`LoginResourceAdmission` 所在包）与 Audit。**仓库现状 integration 模块只有 `provider.{lark,github,workitem}`，无 identity 包**——OIDC 协议适配落点（`server/security` 下新包 vs integration 新 `identity` 包）由 S01 按依赖方向与「身份不是外部工作工具」的语义冻结，正文不预设。
- K8s 为独立可选 Maven 模块；默认 Jar 无 K8s Client，运行关闭时不依赖集群。
- 前端复用既有 scope store、偏好与 M9 设计系统；组织域新建 `src/domains/organization/`（gateway/store/types/labels 四件套照 21 个既有域惯例），配额域同理；页面从实际 router/navigation 派生检查，不锁定菜单数或依赖未选入的 i18n。
- 数据治理包括主库、派生索引、文件（`ArtifactStore`）、凭证和备份保留；不能宣称数据库删行就等于所有副本立即清除。
- 新增代码延续 M11-E01 收口纪律：新 ApplicationService/Controller 从第一版按职责拆分并先建特征化测试，不制造下一个巨型类（BE-02 方向）。

### 10.6 配置形态与有效组合

配置键沿用 `CREWSCOPE_` compose 插值惯例；启用条件和原因统一由后端 Readiness/配置端点提供，不让用户猜组合：

| 配置 | 未配置/关闭语义 |
| --- | --- |
| OIDC 身份源（issuer/client 等） | 纯本地密码登录，登录页无 SSO 入口，M11 行为完全兼容 |
| 账号策略（仅本地/仅 SSO/共存） | 默认共存；仅 SSO 时本地密码端点拒绝并指向冻结的救援流程，不静默放行 |
| 配额配置行 | 受理路径零变化（默认不配置=无配额），用量页显示未配置态 |
| 组织设置/治理 | 页面按权限渲染；无 ORG_* 角色分配时仅创建者可见只读态 |
| 托管切换器/K8s | 单机形态不渲染切换器；默认构建无 K8s Client |

必测组合：纯本地（M11 全兼容）；OIDC+本地共存；仅 SSO+IdP 故障（新请求拒绝、救援可用、不静默退回）；配额未配置；配额+在途+下调限额；治理操作中身份撤销；单机形态确认无切换器。

### 10.9 「不要这样做」清单

| # | 偏差写法 | 正确做法 |

### 10.10 S01 的必答项

主线：现有表/组织归属清单（以 §1 勘察基线复核）；运行角色和授权职责；OIDC 身份键、策略与救援、协议适配落点与库选型；原子预占/释放/结算及资源上界；导出/删除/保留协议；SLI 数值与容量样本；ORG_* 角色词汇与 UI 权限；图表基元选型；会话枚举 API 形态；UI 权限、负责人及子任务拆分。
