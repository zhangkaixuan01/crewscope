# M12：企业化与多租户治理执行清单

> 状态：未开始，方向基线；S01 后细化，不能直接作为可领取清单。<br>
> 前置：M11-Q02 Web 主线，不依赖可选桌面/MCP/i18n。<br>
> 粒度：保留 12 个父工作包，单机主线与托管/K8s 等扩展分别验收。<br>
> 更新：2026-09-19；仅调整计划，不表示实现。共用 [M10–M12 计划规则](README.md#9-m10m12-计划规则)。

## 1. 目标与当前事实

默认形态是单 Organization 自托管、四服务 Compose。数据库已存在 Organization、大量 organization_id 与应用层 Scope/权限边界；M12 不是从零增加租户列，也不能把已有授权称为不存在。

主线增强企业单机使用：Organization 设置、OIDC、配额/用量、数据治理与基础 SLI。多 Organization 托管、K8s、SAML/SCIM/MFA、外部观测平台分别选入；未验收不能声明支持，主线不等待未选入的扩展。

默认仍为 PostgreSQL、Redis、API（含 Worker）、Web；源码构建、HTTP 与 `quickstart.sh up` 不变。企业能力未启用时不要求 IdP、集群、外部 Secret、TLS 或监控栈。公网和企业集成的安全配置按实际风险说明，不变成所有用户的安装前置。

## 2. 主线与可选出口

| 范围 | 交付出口 | 验收关系 |
| --- | --- | --- |
| 主线 | 当前 Organization 设置/授权审计、数据导出/保留/删除、OIDC 与本地账号策略、原子配额与用量、基础 SLI | 单机四服务独立通过 Q01/Q02 |
| 托管扩展 | 多 Organization 管理、数据/执行/缓存/凭证/索引/用量隔离 | D01、A01、F01 的增量及独立隔离验收 |
| K8s 扩展 | 可选执行适配模块、Helm、持久卷/网络/节点故障恢复 | I02；托管时另依赖托管隔离增量 |
| 身份扩展 | SAML、SCIM、MFA | I01/F03 下的独立子范围，各自验收 |
| 观测扩展 | 外部采集、Grafana 等仪表盘与告警出口 | I03 下选入，不进入默认服务列表 |

K8s 与多 Organization 是独立选择，不能因为启用其中之一就强制另一个。范围登记必须写明选入项、负责人、预算和验收入口；状态分别为未选入、待执行、通过或失败，不用一个总 PASS 掩盖未验证形态。

## 3. 非目标与兼容原则

非目标：计费/支付、跨 Organization 知识共享、跨区域复制、自动扩缩容成本优化、SOC2/ISO 认证流程本身。

核心业务功能不因单机部署而缺失；没有多租户选择器是形态简化，不是取消企业设置。已有 API、事件、责任链、Lease/Fencing/Checkpoint/Outbox 语义保持兼容。M11 i18n 如已选入，新增文案同步翻译；未选入不成为 M12 前置。

## 4. 核心合同

### 4.1 隔离目标先于技术选型

应用层 `ExecutionScope ∩ Ownership` 与资源授权始终是安全边界，不是性能优化。托管还必须有独立数据层隔离。S01 比较共享 Schema + RLS、独立 Schema、独立数据库，ADR-035 接受后才能实施；候选方案不能在正文被写成已定事实。

若选择 RLS，至少证明：

- 应用数据库角色不是 superuser、BYPASSRLS 或可绕过策略的表所有者；运行角色与迁移角色分开，必要时 FORCE ROW LEVEL SECURITY。当前简单 Compose 的初始化/应用账号不能直接当作有效 RLS 运行角色。
- 租户上下文来自受信身份与授权，在同一事务/连接内设置；缺失上下文失败关闭。验证连接池复用、异常回滚、异步作业、Worker 和平台运维任务，不能依赖残留的会话变量或未验证请求头。
- 盘点租户表与全局目录，定义复合外键、读写策略和特权入口；不笼统要求所有表新增组织列。向量/搜索/对象存储、Redis 与任务运行环境也必须纳入隔离，而非只测 SQL。
- 用真实运行角色分别测试应用授权独立生效、数据层隔离独立生效及两者同时启用；不能用 superuser 测试得出 RLS 已有效的结论。

如果选用其他方案，必须给出等价隔离证据。性能不足不能成为无评审地取消数据层防线的理由。单机模式保持现有边界；必要的数据库角色调整由升级工具处理，不能要求用户先手工配置 RLS。

### 4.2 在已有数据上迁移，不重建组织归属

先列出现有表、organization_id、全局表、Scope 与外键，再确定真正缺失的字段。已有组织不能全部回填为默认组织；归属不确定的数据须显式处理，不猜测。

按扩展结构、分批回填、约束验证、隔离切换拆阶段；大表回填是可续作业，不藏进单个 Flyway 长事务。文件数量由风险决定，不固定“四步四文件”。后续编号取合并时实际最大值 +1；M10/M11 的未来编号不当作已发布事实。

回退计划区分兼容旧代码、数据修复和完整备份恢复，不承诺任意迁移都有可逆 down SQL。托管扩展需覆盖旧单机升级、失败中断、恢复以及既有组织归属保持。

### 4.3 企业身份不建立第二套 Session

主线先交付 OIDC，身份策略为仅本地、仅 SSO 或共存；SAML/SCIM/MFA 独立选入。账号绑定采用受信 issuer + subject，不仅凭邮箱自动合并；角色映射遵循最小授权，不隐式提升到 Team 写权限。

SSO-only 下 IdP 故障不能静默退回本地密码。冻结恢复管理员、人工救援和锁定保护流程；本地账号路径在仅本地/共存策略下继续可用。验证签名、issuer/audience、state/nonce/PKCE、重放、回跳与会话撤销。

IdP 禁用、SCIM 删除的失效来源、轮询/事件机制和延迟上限必须可测，不能无依据承诺即时失效。账号级禁用撤销全部会话；单 Team 撤权沿用 M11 的范围规则。MFA 丢失设备与恢复码策略在选入时单独验收。

### 4.4 原子准入与异步计量分开

配额配置及准入预占是权威控制事实；用量报表才是派生统计。

1. 受理命令时原子检查并预占，与任务创建同一事务或采用经过证明的等价协议；幂等重试不重复占用，避免多个请求同时读到剩余额度后全部通过。
2. 成功、失败、取消后结算/释放；Lease 过期、消息重投和崩溃有对账。异步事件报表不能作为唯一硬限制。
3. Token/存储最终用量未知时，预占有界预算或明确超额政策。没有上界只能称软预算，不承诺绝对硬上限。缺少价格时标未知，估算不是账单。
4. 下调限额不强杀合法受理的执行，新请求遵守新限额，在途遵守已接受预算。月份/时区、预占结转、缓存 Token 和重试计量须有明确定义。
5. 统计与告警走 Outbox/既有 Inbox、飞书；不暗含新邮件 Provider。准入故障时新受限请求失败关闭，统计故障不误伤已有执行。

### 4.5 K8s 重新验证执行边界

当前 Compose 是 API 合并 Worker、API 直连 Docker Socket，不是旧 Socket Proxy 拓扑。该单机高权限信任假设不能直接用作托管安全结论。

选做 I02 时，在独立可选模块中引入 K8s Client，默认构建不包含。ADR-039 定义 Worker/Job/Pod 生命周期、控制面权限、租户代码与凭证、网络出站、持久卷及节点恢复。Pod 消失后仍须通过 Lease/Fencing/Checkpoint 防止重复副作用；不能仅用“不低于当前 Compose”代替明确的托管隔离目标。

### 4.6 默认可用的基础 SLI

先冻结首 Token 延迟、排队时长、执行成功率、API P95、通知送达率和检索延迟的样本口径、排除项、时间窗、目标与错误预算。默认从既有指标/事件事实获取，不要求 Grafana 或新增观测服务。

按 Organization 下钻使用授权查询，不把租户 ID 放入无限基数的公共指标标签。容量报告写明硬件、模型、数据量、并发、瓶颈及阈值；50/200/500 并发可作为目标形态样本，不能成为每台普通单机的强制规格。

## 7. 执行波次

1. W1：S01、D01 基础范围；盘点现有组织事实，冻结主线合同。
2. W2：A01、A02、F01、F02；组织设置、数据治理、原子配额可用。
3. W3：I01、F03、I03；OIDC 与基础 SLI 可用。
4. W4：Q01、Q02；单机主线独立验收。

托管隔离、K8s 与身份协议扩展各自立项。是否选入由用户需求、原型证据、运维成本和资源预算决定，不为凑齐大版本而引入。后置到新里程碑时同步依赖与未交付状态，不自动转为后续主线的隐含前置。

## 8. 验收矩阵

主线必验：现有 Organization/Team 权限和数据归属保持；四服务安装、存量升级与完整恢复；本地/OIDC 策略与会话；配额预占/结算/对账；授权用量与基础 SLI；导出、删除、保留和人工救援；F01/F02/F03 前端及既有全量回归。

扩展追加：

- 托管至少用两个 Organization 验证数据、执行、缓存、向量索引、凭证、用量、审计和备份隔离；数据层与应用层独立测试，组织切换不串数据。
- K8s 使用真实集群验证 Helm、节点/Pod/控制面/存储故障，不能以本机 Docker 代替。
- SAML/SCIM/MFA 分别完成协议攻击集、生命周期与恢复；外部观测单独验证采集/告警链路。

计划证据文件为 `docs/testing/M12-Q02-Release-Gate.md`。每份记录包含 Revision、选入配置、迁移/角色、环境、命令、结果及脱敏 Artifact。未做托管或集群验收时只能称单机主线通过，不能称双形态全部完成。

## 9. 任务粒度与发布规则

S01 后将所选 D01 隔离增量、A01 数据治理、I01 协议子范围、I02 拆成可领取任务，记录责任人和验收。保留 12 个父 ID，不以一个父任务状态隐藏其未完成子范围。

主线与扩展可分别接受合同、上线和延期；启用选项必须同时具备 API/UI、权限、配置、升级、关闭及恢复说明。普通用户仍按当前 [单机运维手册](../runbooks/Team-Beta单机运维手册.md) 使用产品。

## 10. 实施细则（方向边界，非执行细则）

### 10.1 落点与不可越界项

- Organization 角色与 Team 角色正交，Org Admin 不能自动获得所有 Team 写权限。
- 组织用例可落 `application/organization`，先核对既有模型；不为了规划目录复制 Organization 实体。
- 配额用例与预占落 `application/quota`，基础 SLI 扩展既有 `application/observability`；强制准入与只读观测不混用。
- 企业身份适配复用 integration/identity、既有 Session、权限与 Audit，不再造第二套账号生命周期。
- K8s 为独立可选 Maven 模块；默认 Jar 无 K8s Client，运行关闭时不依赖集群。
- 前端复用既有 scope store、偏好与 M9 设计系统；页面从实际 router/navigation 派生检查，不锁定 21 个菜单或依赖未选入的 i18n。
- 数据治理包括主库、派生索引、文件、凭证和备份保留；不能宣称数据库删行就等于所有副本立即清除。

### 10.2 ADR 与契约产物

以下均为待交付文件，不是已经完成的证据；编号主题以计划索引唯一映射为准。

- ADR-036《企业身份联邦与会话策略》：OIDC 主线及各协议扩展，身份绑定、撤销和救援。

### 10.3 S01 的必答项

主线：现有表/组织归属清单；运行角色和授权职责；OIDC 身份键、策略与救援；原子预占/释放/结算及资源上界；导出/删除/保留协议；SLI 数值与容量样本；UI 权限、负责人及子任务拆分。

选入扩展：隔离方案与查询代价、连接池/异步任务原型、真实数据回填/恢复；SAML/SCIM/MFA 的库选型和失效上限；K8s 的生命周期/存储/网络/控制面；各形态资源预算与独立验收入口。

已经确定的是安全与兼容目标，尚未确定的是技术选型；不在正文写死实现、再在附录称其全部未定。
